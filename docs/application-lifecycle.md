# 独立应用启动与系统管理

应用宿主负责整套系统的启动、诊断和退出，网页只作为交互入口。关闭浏览器页面后应用继续运行；托盘或“设置 → 系统运行”中的“退出整个应用”会回收语音服务、工作进程和 DSH（代理执行宿主）。

## 构建与运行

首次准备业务环境与网页依赖；已有可用运行环境时可跳过准备步骤：

```powershell
.\scripts\setup.ps1 -Python D:\DevTools\Python312\python.exe -Analysis
npm ci
```

在项目根目录构建：

```powershell
.\scripts\build-launcher.ps1 -Python D:\DevTools\Python312\python.exe
```

双击项目内 `.runtime/launcher/VoiceTerminal/VoiceTerminal.exe`（独立应用程序）。目录模式的整个文件夹需保留；应用复用本机业务 Python（程序运行环境）、Node.js（JavaScript 运行环境）及现有模型目录。打包使用独立环境，只收集启动程序依赖，不收集语音模型。

程序自动定位项目根目录，优先使用 `--python`（业务解释器路径），其次使用项目 `.venv/Scripts/python.exe`（项目虚拟环境），最后查找本机 Python。可通过启动参数指定 `--root`（项目根目录）和 `--config`（本机配置文件）。

需要明确指定业务解释器时：

```powershell
.\.runtime\launcher\VoiceTerminal\VoiceTerminal.exe --python D:\DevTools\Python312\python.exe --config config/local.yaml
```

`scripts/build-launcher.ps1`（打包脚本）在 `.runtime/launcher-build`（独立打包环境）安装 `scripts/requirements-launcher.txt`（启动程序依赖清单），使用 PyInstaller（可执行程序打包工具）的目录、无控制台模式生成程序。`-SkipWebBuild`（跳过网页构建）仅用于已经完成网页构建的情况。可执行程序、网页构建产物、模型和日志均不提交到 Git（版本控制系统），从源码检出后重新准备、构建。

源码入口：

```powershell
.\scripts\start.ps1 -Python D:\DevTools\Python312\python.exe
.\scripts\start.ps1 -Python D:\DevTools\Python312\python.exe -Dev
```

普通启动要求已执行 `npm run build`（网页构建）；缺失时提供内置诊断页。`-Dev`（开发模式）使用 Vite（前端开发服务器）热更新。`-NoTray`（无托盘）、`-NoBrowser`（不自动打开浏览器）、`-NoWeb`（后端调试）、`-NoWorker`（使用外部语音识别进程）和 `-NoAnalysis`（停用分析）用于调试。外部进程不负责回收。

托盘菜单提供“打开工作台”“系统运行”“打开日志目录”和“退出应用”。桌面套壳、完整便携分发、自动升级和开机启动不属于当前版本；业务依赖仍由本机环境提供。

## 启动与状态

宿主先建立托盘和轻量网页服务、打开浏览器，再检查配置并逐步启动语音识别、分析、语音服务、按需声纹和 DSH。所有启用组件结束启动尝试后，蒙版收起或显示失败诊断。核心失败时保留入口和已成功组件，可选组件失败允许降级使用。

应用宿主直接拥有语音识别、分析和语音服务进程；语音服务中的现有管理器直接拥有声纹与 DSH 进程。受管模式在语音服务开始监听后，由宿主请求管理器启动 DSH；独立后端调试保留原启动行为。语音识别与声纹启动等待上限为 60 秒，分析与语音服务为 180 秒，DSH 使用有效配置中的启动超时。进程启动后还要通过应用层健康检查，才能报告就绪。

网页服务优先绑定 `127.0.0.1:5173`（本机网页地址）；冲突时分配空闲端口。实际地址保存在 `.runtime/application/instance.json`（当前实例入口），重复启动打开既有入口。业务端口被未知进程占用时拒绝接管。

“系统运行”页每两秒更新组件状态、PID（进程标识）、运行时长、CPU（中央处理器）占用、常驻工作集与私有提交内存。两项总量均按唯一受管进程去重，并包含组件子进程。工作集包含当前驻留物理内存的共享页，不等于独占物理内存或正在执行任务的内存；私有提交是系统已承诺提供后备的私有内存，不等于当前物理占用。初始化后闲置页面可以移出工作集，重新使用模型时工作集也可能回升，不能将其下降理解为模型已卸载。

内存使用 MiB（二进制兆字节）及 GiB（二进制吉字节），按 1024 进制显示。网页服务与宿主共享进程，在线模型和 TTS（语音合成）只展示能力状态。Windows（操作系统）的私有提交来自进程内存计数；缺少该计数的平台显示不可用，不将虚拟地址空间当成提交量。旧启动程序缺少新增字段时，网页提示更新启动程序并重启。

页面同时展示进程创建时间、最近采样时间和语音服务内部能力。能力失败但进程仍存活时继续显示真实占用；进程退出后清除旧指标。启动等待期间暂缓业务接口轮询和语音连接；重新打开或刷新页面先读取快照，再订阅状态事件。事件流断开期间每两秒读取快照。

宿主网页接口：

- `GET /api/v1/application/snapshot`（应用快照）。
- `GET /api/v1/application/events`（SSE，服务器推送事件）。
- `POST /api/v1/application/components/{id}/retry`（失败组件恢复）。
- `POST /api/v1/application/exit`（整个应用退出）。

接口只绑定回环地址，网页操作校验来源与应用会话，子进程报告使用独立凭据。日志与公共状态不包含桥接令牌或模型密钥。

快照字段约定：

| 字段 | 中文说明 |
| --- | --- |
| `instance_id` / `revision` | 本次应用实例标识 / 单调递增的状态版本 |
| `state` / `phase` / `started_at` | 整体运行状态 / 当前阶段 / 应用启动时间（秒） |
| `startup_complete` / `core_available` / `stopping` | 全部启动尝试已结束 / 核心能力可用 / 已进入退出流程 |
| `completed_components` / `total_components` | 已完成尝试的启用组件数 / 启用组件总数 |
| `voice_api_url` / `voice_ws_url` | 语音服务接口地址 / 语音实时通信地址 |
| `capabilities` | 语音服务内部能力及其可用状态 |
| `sampled_at` / `total_memory_rss_bytes` | 指标采样时间（秒） / 去重后的受管进程工作集之和（字节） |
| `total_memory_private_commit_bytes` | 去重后的受管进程私有提交内存之和（字节），不可用时为空值 |
| `components` | 组件运行信息列表 |
| `id` / `name` / `state` / `phase` / `error` | 组件标识 / 中文名称 / 状态 / 当前阶段 / 最近错误 |
| `enabled` / `required` | 组件已启用 / 属于核心启动依赖 |
| `pid` / `created_at` / `uptime_seconds` | 进程标识 / 进程创建时间（秒） / 运行时长（秒） |
| `memory_rss_bytes` / `cpu_percent` / `sampled_at` | 常驻工作集（字节） / 中央处理器占用百分比 / 指标采样时间（秒） |
| `memory_private_commit_bytes` | 组件所属进程的私有提交内存（字节），不等于当前物理占用 |
| `shared_with` / `external` | 共享进程的组件标识 / 使用外部调试进程 |
| `retry_allowed` / `retrying` | 当前允许恢复 / 正在等待或执行恢复 |

组件状态为 `waiting`（等待启动）、`starting`（启动中）、`ready`（就绪）、`disabled`（停用）、`failed`（失败）、`blocked`（依赖不可用）、`external`（外部进程）和 `stopped`（已退出）。整体还包含 `degraded`（降级运行）和 `stopping`（退出中）。不可用指标为 `null`（空值），不保留已退出进程的旧占用。中央处理器占用按进程累计执行时间的采样差计算，多核进程可超过 100%。

## 故障与退出

DSH 保留现有有限自动重启，其他组件手动重试。恢复语音识别、分析或语音服务时停止当前监听与播报，重新连接业务并保持待机；不自动重播语音或重新执行模型动作。

退出先禁止新工作、恢复操作和 DSH 自动重启，再触发命名事件正常关闭；总退出预算为 15 秒，其中为最终状态发布、网页和托盘清理预留 1 秒，剩余预算耗尽后强制回收受管进程树。Windows Job Object（作业对象）在宿主异常退出时回收整棵进程树。持久设置、任务和归档保留，退出不强制执行新的模型交接整理。

语音服务收到命名事件后，通过私有标准输入管道通知 DSH，触发其现有资源清理流程；无须依赖控制台信号。托盘宿主、语音服务及声纹/DSH 子进程均以无终端窗口方式启动。

诊断日志位于 `logs/application.log`（宿主日志）、`logs/application-bootstrap.log`（启动检查日志）和 `logs/application-组件标识.log`（组件进程日志）。

## 诊断操作

| 表现 | 处理方式 |
| --- | --- |
| 缺少网页构建产物 | 在项目根目录执行 `npm run build`（构建网页），重试网页组件，再重新打开工作台。 |
| 找不到业务 Python 或环境检查失败 | 查看启动检查日志，修复既有业务环境；需更换解释器参数时退出应用，再用 `--python`（业务解释器路径）重新启动。 |
| 业务端口被未知进程占用 | 确认占用进程归属并处理冲突后重试。宿主不会接管该进程或按端口结束程序。 |
| 核心组件失败 | 保留托盘和诊断页，从“系统运行”恢复失败组件；语音服务有进程不代表其核心能力已可用。 |
| 可选组件失败 | 工作台显示降级提示；从运行页重试，DSH 手动恢复会重置有限自动重启计数并重新核验桥接与关联会话。 |
| 开发网页失败 | 查看 `application-dev.log`（开发网页日志），修复环境或 5173 端口冲突后重新启动应用入口。开发模式的管理服务优先使用 8764 端口。 |

重试按组件串行执行，同一组件恢复期间拒绝重复请求。语音服务进程失败时先回收其委托子进程，再重建语音服务和委托组件；声纹恢复重新连接并校验特征。退出后的页面保留“应用已退出”提示，再次使用需从程序入口启动。

## 验证入口

生命周期定向回归、成品现场检查和验收边界见[运行与质量门槛](operations-and-quality.md#独立应用生命周期验收)。构建成品后直接执行一次启动、运行页使用、退出和再次启动；不能以运行支架启动的后端代替成品验收。实际日志、截图和机器测量留在本机 `logs/`（日志目录）、`reports/`（诊断产物目录），测试结果随实现提交记录到 Git 历史。
