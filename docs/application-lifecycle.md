# 独立应用启动与系统管理

Tauri 2（桌面框架）负责窗口、托盘、单实例以及 Python（后端运行环境）服务管理进程；应用宿主继续负责业务组件的启动、诊断、恢复和退出。正式根入口启动桌面后退出，各进程只有一个直接生命周期所有者。关闭正式桌面窗口隐藏到托盘，显式退出回收语音服务、工作进程和 DSH（代理执行宿主）。主产品及界面开发只支持桌面窗口；独立后端调试入口不提供界面。

桌面构建与日常命令见[桌面应用开发与分发说明](desktop-application.md)，唯一组件路径、覆盖发布及备份规则见[本地目录与覆盖发布](local-layout.md)。当前目录迁移与实机入口验证见[本地整理验收](local-layout-acceptance-20261008.md)；此前产品验收及未完成的实机检查见[桌面验收记录](desktop-acceptance.md)。下面分别说明桌面正式入口与保留的源码调试入口。

## 构建与运行

已有正式安装时，先校验唯一业务环境，再准备根目录的前端开发依赖：

```powershell
.\scripts\setup.ps1 -SkipInstall -SkipDsh
npm ci
```

在项目根目录构建原生桌面程序和根启动入口；Rust（原生构建工具）位于 `.local/tools/rust/`，MSVC（微软原生编译工具）使用现有系统安装。构建产物进入 `.local/build/`（受控构建缓存）：

```powershell
npm run desktop:build
npm run desktop:start
```

本机成品入口为 `.local/VoiceTerminal.exe`（精简启动程序），交付包解压后使用包根目录同名入口。入口从安装位置解析程序、运行环境、模型和独立数据目录；不通过当前工作目录或系统搜索路径选择业务解释器。组件路径统一由第二版 `portable.json`（便携配置）提供；`release.json`（发布清单）记录构建编号及摘要。正常运行不读取第二份启用副本。

## 源码开发与无界面调试

```powershell
npm run dev       # 真实业务桌面热更新，固定 5173 端口。
npm run dev:ui    # 独立桌面样例，固定 5174 端口，不需要 Python（后端运行时）或模型。
npm run desktop:start  # 同一正式入口启动已发布静态本体。
# 后端调试：只启动受管业务组件，不打开窗口、浏览器或托盘。
.\scripts\start.ps1
```

源码调试通过同一正式入口显式传入 `--dev`（热更新开关）与 `--source-root`（源码目录），只替换业务源码和界面输入；组件位置、数据、单实例、托盘和退出逻辑与普通正式启动一致。缺少正式安装时先执行本地发布。普通模式与源码调试冲突时提示退出已有实例后重启。前端演示使用隔离缓存，可与正式程序并行；`npm run dev:ui`（演示开发）负责构建演示宿主，双击 `.local/VoiceTerminalUIDemo.exe`（演示入口）直接运行已构建的演示宿主。工作区根目录直接决定路径，不读写系统定位记录。

双击后直接打开最终主窗口，再在同一窗口内加载服务；不建立独立准备窗口。正式与演示宿主都等待本地主页面加载完成，再从后台线程启动各自服务，保持界面线程可响应。主页面刷新不会重复启动服务；窗口已请求退出时，不再建立服务。演示入口不启动构建任务，重复双击由宿主的单实例逻辑唤回当前窗口；正式程序的托盘与退出行为保持原有约定。

## 启动与状态

界面服务在私有 `ready`（就绪消息）中向原生宿主发送 `launch_token`（60 秒、单次使用的入口凭据）。`/desktop-entry`（受控入口）建立本实例 Cookie（会话凭据），再以统一加载页进入界面。普通根地址仅显示“请通过桌面程序打开”，不签会话；资源、运行配置及宿主管理接口都校验会话。开发服务同样保护 HMR（热更新）升级连接。

产品与样例入口先调用 `desktop_status`（桌面状态命令），验证 `ready`（界面服务就绪）、`error`（启动错误）、`frontend_mode`（产品或样例模式）、`role`（正式、安装器或演示职责）和 `development`（显式源码调试标识），然后动态加载对应界面。产品随后获取宿主配置；后端尚未就绪时先显示真实启动状态，能力失败但设置接口仍可用时允许修复设置。

正式业务初始化前，桌面先按当前随包清单检查完整语音环境、全部模型和代理组件。任何必需组件缺失、文件集合或大小不符、待更新时，原生组件管理页保持可用，整体语音及业务服务不启动。Voice Server（语音服务）启动时快速核对清单、文件集合和大小；模型与代理组件启动时仍做完整文件摘要校验。环境安装、导入及更新继续执行完整摘要校验。旧组件卡片显示“更新、导入、跳转”，新安装按当前清单准备；不提供旧模型运行适配。功能开关不免除安装组件的门槛，细节见[必需组件更新](model-resource-updates.md)。

桌面先创建最终主窗口，立即显示应用图标、“应用启动中”、当前组件、进度条与“跳过”按钮。原生首屏、受控入口、网页首屏、桌面核验和产品等待页共用图标、样式与布局，错误沿用同一布局。“跳过”进入设置中的本地组件页，逐项显示等待、加载、就绪与失败；后台启动继续，语音操作仍等待完整启动及核心能力可用。最早首屏的跳过选择传递到产品界面，仍完成原生权限核验。

全部必需安装组件就绪后，宿主提供轻量网页入口，通过私有标准输入／输出管道报告入口就绪，桌面接管后才开始业务初始化。环境检查通过后先创建语音服务轻量接口，恢复凭据并从原管理器提前启动 DSH（代理执行宿主）；再按实时资源预算加载语音识别、分析工作进程和语音本地模型，最多三路重型加载。语音本地模型一路包含关键词唤醒、语音活动检测与按配置启用的声纹；其内部保留依赖顺序。模型分支结束后汇合受管依赖状态、建立唯一会话并核验代理绑定。所有启用功能结束启动尝试后，加载页收起或显示故障；核心失败时保留入口与已成功组件，已就绪资源的运行期旁路故障按既有策略处理，不绕过版本或完整性门槛。

DSH（代理执行宿主）不占三路模型通道，也不按模型的处理器、提交内存或显存预算等待。仅物理内存使用率达到 95% 时暂停创建代理进程，每秒采样，回落后继续；采样不可用时允许启动。内存排队不消耗代理的实际启动超时。资源不足或必要采样缺失时，模型加载减少并发至串行，设置与状态接口仍保持可响应。完整规则与验收边界见[启动调度梳理](startup-optimization-plan.md)及[并行启动验收](startup-parallel-acceptance.md)。

应用宿主直接拥有语音识别、分析和语音服务进程；语音服务中的现有管理器直接拥有声纹与 DSH（代理执行宿主）进程。受管语音服务在轻量生命周期内启动代理后台任务，独立后端沿用完整初始化路径。组件启动限时使用有效配置中的工作进程及代理超时；模型排队在实际放行前不计时，创建后还须通过应用层健康检查才报告就绪。退出取消未放行任务，已有进程继续由原所有者回收。

宿主与语音运行时共用核心能力的就绪状态：`READY`（已就绪）、`RUNNING`（运行中）、`STREAMING`（流式传输中）和 `CONNECTED`（已连接）。开始监听时 KWS（关键词唤醒）进入运行状态，停止监听后回到就绪状态；两者都保持语音服务可用。真实能力失败会显示具体的故障组件，恢复后清除旧错误。停止监听关闭会话识别连接后，“模型计算”仍通过独立只读连接探测 ASR（语音识别）工作进程，不因会话待机而误报模型故障。再次启动 KWS 监听时保留已确认的识别能力状态，唤醒命中后才重建 ASR 会话并重新验证模型；识别服务确实不可用时仍保留其错误状态。

静态界面服务优先绑定 `127.0.0.1:5173`（本机网页地址）；冲突时分配空闲端口。桌面通过私有管道获得实际地址，重复启动由原生单实例逻辑唤回窗口。当前实例信息写入用户数据的 `state/application/instance.json`（实例记录）；源码业务调试默认使用正式数据中的同一路径。业务端口被未知进程占用时拒绝接管。

“系统运行”页每两秒更新组件状态、PID（进程标识）、运行时长、CPU（中央处理器）占用、常驻工作集与私有提交内存。两项总量按进程标识及创建时间去重，包含组件子进程、桌面外壳与网页渲染进程。工作集包含当前驻留物理内存的共享页，不等于独占物理内存或正在执行任务的内存；私有提交是系统已承诺提供后备的私有内存，不等于当前物理占用。初始化后闲置页面可以移出工作集，重新使用模型时工作集也可能回升，不能将其下降理解为模型已卸载。

内存使用 MiB（二进制兆字节）及 GiB（二进制吉字节），按 1024 进制显示。网页服务与宿主共享进程，在线模型和 TTS（语音合成）只展示能力状态。Windows（操作系统）的私有提交来自进程内存计数；缺少该计数的平台显示不可用，不将虚拟地址空间当成提交量。旧启动程序缺少新增字段时，网页提示更新启动程序并重启。

页面同时展示进程创建时间、最近采样时间和语音服务内部能力。能力失败但进程仍存活时继续显示真实占用；进程退出后清除旧指标。`voice_api_ready`（轻量业务接口已监听）为真后可读取和保存设置，语音组件仍可显示等待或加载；启动期间保存的关键词、静默及声纹设置在会话调度器初始化完成时自动应用，后续保存即时应用，不要求开启对话。录音、会话开始、重置和模式切换继续受完整启动门禁保护。重新打开或刷新页面先读取快照，再订阅状态事件；事件流断开期间每两秒读取快照。

本地组件页把排队、模型加载、重试提交和后台恢复统一显示为“启动中”，继续呈现当前阶段，操作按钮暂时禁用并使用正常加载样式。加载期间不显示上一轮错误，也不把尚未建立连接的模型健康检查结果当作启动失败；宿主明确报告失败后才显示错误和重试入口。所属进程开始或完成新一轮加载、重试，或进程身份发生变化时移除对应模型的旧采样，组件结束启动或重试后立即重新读取；迟到的旧请求不能覆盖新采样。正常运行转为故障时保留同一进程已有的运行错误原因。按配置停用的组件仍显示“已停用”。

宿主网页接口：

- `GET /api/v1/application/snapshot`（应用快照）。
- `GET /api/v1/application/events`（SSE，服务器推送事件）。
- `POST /api/v1/application/components/{id}/retry`（失败组件恢复）。
- `POST /api/v1/application/exit`（整个应用退出）。

接口只绑定回环地址，网页操作校验来源与应用会话，子进程报告使用独立凭据。日志与公共状态不包含桥接令牌或模型密钥。

快照字段约定：

| 字段 | 中文说明 |
| --- | --- |
| `instance_id` / `revision` | 本次应用实例标识 / 单调递增的状态版本 |
| `state` / `phase` / `started_at` | 整体运行状态 / 当前阶段 / 应用启动时间（秒） |
| `startup_complete` / `core_available` / `stopping` | 全部启动尝试已结束 / 核心能力可用 / 已进入退出流程 |
| `completed_components` / `total_components` | 已完成尝试的启用组件数 / 启用组件总数 |
| `voice_api_url` / `voice_ws_url` | 语音服务接口地址 / 语音实时通信地址 |
| `voice_api_ready` | 轻量业务接口已监听，可访问设置；不代表模型或语音会话已就绪 |
| `capabilities` | 语音服务内部能力及其可用状态 |
| `sampled_at` / `total_memory_rss_bytes` | 指标采样时间（秒） / 去重后的受管进程工作集之和（字节） |
| `total_memory_private_commit_bytes` | 去重后的受管进程私有提交内存之和（字节），不可用时为空值 |
| `components` | 组件运行信息列表 |
| `id` / `name` / `state` / `phase` / `error` | 组件标识 / 中文名称 / 状态 / 当前阶段 / 最近错误 |
| `enabled` / `required` | 组件已启用 / 属于核心启动依赖 |
| `pid` / `created_at` / `uptime_seconds` | 进程标识 / 进程创建时间（秒） / 运行时长（秒） |
| `memory_rss_bytes` / `cpu_percent` / `sampled_at` | 常驻工作集（字节） / 中央处理器占用百分比 / 指标采样时间（秒） |
| `memory_private_commit_bytes` | 组件所属进程的私有提交内存（字节），不等于当前物理占用 |
| `shared_with` / `external` | 共享进程的组件标识 / 使用外部调试进程 |
| `retry_allowed` / `retrying` | 当前允许恢复 / 正在等待或执行恢复 |

组件状态为 `waiting`（等待启动）、`starting`（启动中）、`ready`（就绪）、`disabled`（停用）、`failed`（失败）、`blocked`（依赖不可用）、`external`（外部进程）和 `stopped`（已退出）。整体还包含 `degraded`（降级运行）和 `stopping`（退出中）。不可用指标为 `null`（空值），不保留已退出进程的旧占用。中央处理器占用按进程累计执行时间的采样差计算，多核进程可超过 100%。

整体状态另有 `core_phase`（核心能力阶段）：`ready`（就绪）、`starting`（加载中）与 `failed`（失败）。加载中是瞬态，不写作启动失败；只有终态失败才进入恢复入口。运行期组件故障不再弹出全屏启动画面，改为页面横幅加“本地组件”入口；全屏启动画面只属于尚未完成启动和正在退出两种情形。详见[能力就绪与能力级恢复](capability-readiness-and-recovery.md)。

## 故障与退出

DSH 保留现有有限自动重启，其他组件手动重试。恢复语音识别、分析或语音服务时停止当前监听与播报，重新连接业务并保持待机；不自动重播语音或重新执行模型动作。语音服务进程**仍在运行**时，恢复优先走能力级重建：只重建出问题的能力（音频、识别、主模型、合成、唤醒、声纹），不重启语音服务进程，也不中断其他能力；只有进程已经退出（`poll()` 非空）或能力级恢复失败时才回落到整进程重建。

宿主对语音服务的健康检查按能力分档：`STARTING` 等加载中状态只把组件显示为“启动中”并暂时拦截主监听，不判核心能力失败；一次探测异常不再立刻判死，需连续多次且持续超过宽限期（默认 3 次、6 秒）才进入故障。能力加载期间用户点击开始会话会被拦截并记住意图，能力就绪后自动开始监听；用户主动停止会撤销该意图。`application.log` 现在记录每次停止请求的组件与原因（`app-exit`、`component-retry:组件`），事后可以区分退出、重试与回收。

退出先禁止新工作、恢复操作和 DSH 自动重启，再触发命名事件正常关闭；总退出预算为 15 秒，其中为最终状态发布、界面服务清理预留 1 秒，剩余预算耗尽后强制回收受管进程树。Windows Job Object（作业对象）在宿主异常退出时回收整棵进程树。持久设置、任务和归档保留，退出不强制执行新的模型交接整理。

语音服务收到命名事件后，通过私有标准输入管道通知 DSH，触发其现有资源清理流程；无须依赖控制台信号。桌面宿主、语音服务及声纹/DSH 子进程均以无终端窗口方式启动。

正式与源码业务的桌面诊断日志统一位于 `.local/cache/logs/`（运行日志目录），包括 `application.log`（宿主日志）、`application-bootstrap.log`（启动检查日志）和 `application-组件标识.log`（组件进程日志）。前端演示的日志位于 `.local/cache/ui-demo`（演示缓存与日志目录）；日志均属于可回收缓存，不进入用户数据备份。

该目录保留 100 MiB 总预算（`VOICE_LOG_BUDGET_MB`，`0` 关闭）：所有 `*.log`／`*.jsonl` 及其轮转备份共享一个上限，超出后按最旧优先逐个剔除已经安静下来的文件（`VOICE_LOG_MIN_AGE_SECONDS`，默认 60 秒），由进程启动、每次轮转和周期巡检（`VOICE_LOG_SWEEP_SECONDS`，默认 300 秒）触发。被存活进程打开的文件在 Windows（操作系统）上无法回收，会跳过并在日志中记录原因。明细见[本地 TTS 可观测性与日志容量](local-tts-observability-20261015.md)。

## 诊断操作

| 表现 | 处理方式 |
| --- | --- |
| 缺少界面构建产物 | 本地执行 `npm run desktop:publish`（发布正式本体），或用分发安装器保留数据重装；源码调试使用同一解析结果重试。 |
| 找不到业务 Python（后端解释器）或环境检查失败 | 查看启动检查日志并校验 `.local/portable.json`（便携配置）；需要替换运行环境时，在项目临时区构建完整候选，经覆盖发布换入固定位置。 |
| 检测到未完成更新事务 | 退出所有实例后重新执行 `npm run desktop:publish`（覆盖发布），先恢复或收尾事务，再启动；保留事务所需的临时组件。 |
| 业务端口被未知进程占用 | 确认占用进程归属并处理冲突后重试。宿主不会接管该进程或按端口结束程序。 |
| 核心组件失败 | 保留托盘和诊断页，从“系统运行”恢复失败组件；语音服务有进程不代表其核心能力已可用。 |
| 运行期某个能力加载中 | 组件显示“启动中”、主页按钮显示“组件启动中”并暂时拦截开始会话；加载完成后自动开始，不需要手动重试。 |
| 运行期某个能力失败 | 页面顶部横幅指明能力名称，从“本地组件”页只恢复该能力；不必重启语音服务进程，ASR、声纹与代理会话保持不断。 |
| 必需组件缺失、损坏或待更新 | 保持在组件管理页，从对应卡片更新或导入当前版本；全部组件完整摘要检查通过后再启动。 |
| 已就绪旁路的运行期故障 | 按既有故障策略显示状态并从运行页重试；DSH（代理执行宿主）手动恢复会重置有限自动重启计数并重新核验桥接与关联会话。 |
| 桌面热更新服务失败 | 查看 `application-dev.log`（界面开发日志），修复环境或 5173 端口冲突后重新启动应用入口。开发模式的管理服务优先使用 8764 端口。 |

重试按组件串行执行，同一组件恢复期间拒绝重复请求。语音服务进程失败时先回收其委托子进程，再重建语音服务和委托组件；声纹恢复重新连接并校验特征。能力级恢复入口为 `POST /api/v1/application/capabilities/{能力标识}/retry`（能力标识：`audio`、`asr`、`llm`、`tts`、`kws`、`speaker`），组件级入口仍为 `POST /api/v1/application/components/{组件标识}/retry`。退出后的页面保留“应用已退出”提示，再次使用需从程序入口启动。

## 验证入口

生命周期定向回归、成品现场检查和验收边界见[运行与质量门槛](operations-and-quality.md#独立应用生命周期验收)。构建成品后直接执行一次启动、运行页使用、退出和再次启动；不能以运行支架启动的后端代替成品验收。实际日志、截图和机器测量留在本机 `.local/cache/logs/`（日志目录）、`.local/cache/reports/`（诊断产物目录），测试结果随实现提交记录到 Git 历史。
