## 检查结论

项目的主要占用来自**本机资源与生成产物混放、历史运行环境副本、验收浏览器目录及不受控备份**。源码本身不需要大规模搬迁。应先建立受保护数据与组件清单，收缩可重建副本，再统一产物输出位置和保留策略，最后调整源码文档及脚本分组。

按用户补充的精简要求，常态目标收敛为：**1 份当前正式程序、1 套现用模型、各组件各 1 套必要运行依赖，用户持久数据最多保留 1 份滚动备份**。模型、环境依赖及源码不制作常规整目录备份。构建或更新可以短暂生成暂存副本，验证成功后退出；常态不保留多份回退环境或发布版本。不同功能模型、不同组件的依赖闭包及开发专用工具仍分别管理，不能把它们误判为同一资源的重复副本。

- 完整扫描得到 **965,307 个普通文件、148,088 个普通子目录，逻辑总量 79.76 GiB（85.64 GB）**。
- `.runtime/`（本机运行目录）为 **72.01 GiB，占 90.3%**，有 942,416 个普通文件和 60 个直接子目录；本机资源区已成为主要管理问题。
- Git（版本控制）跟踪 **573 个文件、6.05 MiB**。源码跟踪路径最深为 6 层；`apps/desktop/target/`（原生编译输出目录）占 7.07 GiB，不能把整个 `apps/`（应用目录）都当成源码占用。
- 对 **8 MiB（兆字节）以上、大小相同的 706 个候选文件**执行 SHA-256（内容摘要）校验，对 636 个独立文件标识读取约 42.40 GiB；找到 **150 组重复内容**。剔除硬链接重复路径后，独立重复内容为 **28.13 GiB**。这说明存在明显副本问题；其中部分副本仍承担运行、构建或回退职责，不能直接把这个数当成可删除量。
- 另外确认 **4.60 GiB 的重复路径属于 Hard link（硬链接）**。例如两条 2.56 GiB 的显卡版 Torch（张量计算库）安装包路径指向同一文件标识，删除其中一条不会释放 2.56 GiB。
- 普通文件路径最深达到 **194 层（包含文件名，父目录为 193 层）**，最长绝对路径 **2,618 个字符**，共有 **2,599 个路径达到或超过 260 字符**。补充使用 Windows（操作系统）扩展路径完成旧备份扫描后，无遗留读取错误。

大小口径：`GiB`（二进制吉字节）为 1,073,741,824 字节，`GB`（十进制吉字节）为 1,000,000,000 字节。表中目录大小均为普通文件逻辑长度之和，未重复遍历 Junction（目录联接）或符号链接；登记了 22,358 个重解析点。目录汇总会包含硬链接的多条路径，不能直接等同磁盘实际分配空间。父目录与子目录表格不能重复相加。大文件摘要检查覆盖指定候选范围，没有声称对全部近百万文件做内容去重。

过渡期先按这些用途治理既有 `.runtime/`（本机运行目录）内容，完成兼容配置后再迁出大型资源。同盘移动只改变组织位置，**本身不释放磁盘空间**；释放空间来自退出确认无用的副本、缓存和归档。

- 前端共享界面 `interface/`（共享组件）、`product/`（产品逻辑）及 `ui-demo/`（演示逻辑）已有边界，保持这个结构。
- Python（后端语言）包保留根目录 `voice_terminal/`（业务包）。暂不引入 `src/`（源码根目录）迁移，避免为目录外观改动全部导入、打包和测试。
- `apps/server/`（服务启动入口）与 `voice_terminal/server/`（服务业务实现）分别承担入口及实现，名称相近不能据此判为重复代码。
- 原生编译输出如需外置，应同时改构建参数、演示入口定位、开发启动、发布脚本及其测试；初期保持 `apps/desktop/target/`（现有编译目录）兼容。
- `scripts/`（脚本目录）可逐步分为开发、构建、诊断与实验。根目录已公开的脚本先保留兼容入口；搬动脚本时须重新核对 `$PSScriptRoot`（脚本所在目录）和 `Path(__file__).parents`（按脚本位置定位仓库）等相对路径。
- `docs/`（文档目录）后续按架构、开发、运维、发布与必要历史分组。先修链接与建立索引，再分组搬迁，避免同时引入大量失效路径。

- 本机资源根目录应由一个统一路径入口解析，现有 `VOICE_PROGRAM_ROOT`（程序根目录变量）、`VOICE_INSTALL_ROOT`（安装根目录变量）、`VOICE_DATA_DIR`（用户数据目录变量）及启动参数共同使用同一结果；若新增本机资源参数，需在脚本与原生宿主中统一实现，不能只改一处。

| 对象 | 建议生成方式与保留策略 |
| --- | --- |
| 源码历史 | 使用 Git（版本控制）的提交、分支或版本标签；不复制整仓作为常规备份。 |

| 浏览器验收目录 | 每任务创建，退出进程后在清理阶段回收；截图、检查结果与报告单独保存。失败目录短期保留并注明原因。 |
| 构建工作目录 | 按任务临时生成，成功发布后退出工作及部署暂存目录；保留源码、依赖锁定记录及必要失败诊断，不长期保留多份业务运行环境。 |
| 发布版本 | 常态只保留当前正式组合及其所需组件；更新期间的旧版本在验证成功后退出。 |
| 下载与安装包 | 默认安装验证后回收；明确需要离线重建时保留一份共享缓存，配合版本锁文件和摘要，不制作缓存备份。 |

| 验收资料 | 结论及必要证据留在正式文档或专门证据区；截图、故障注入环境和临时脚本采用不同保留周期。 |

备份枚举必须显式处理 Junction（目录联接）、符号链接与 Hard link（硬链接），禁止盲目展开链接目标；目标不能落在来源内部，来源清单排除备份、依赖和构建输出目录。目录联接可保存重建信息，恢复时按新位置重建。Windows（操作系统）系统凭据还需记录其本机存储方式，不能把备份了 `.env.local`（本机环境文件）当成已经备份全部凭据。

每次整理生成 Dry run（仅预览）清单，字段至少包含 `path`（规范化绝对路径）、`category`（目录用途）、`reason`（处理依据）、`logical_bytes`（逻辑大小）、`file_id`（文件标识）、`protected_by`（保护它的入口或清单）、`action`（保留／迁移／退出）、`sha256`（必要文件内容摘要）和 `restore_hint`（恢复方法）。默认只预览，执行仅针对已经审阅的具体白名单，检查最终绝对路径在指定范围内，不遍历目录联接。
