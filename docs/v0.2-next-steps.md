# 后续目标和验收计划

当前代码审计、本机 Worker 回放和本计划的软件实现已经完成。v0.2 是当前主开发和验收路径，下一步围绕“真实 Bidi、自然语音、真实设备、发布判断”收集缺失证据。运行时默认配置暂时保留 v0.1，直到这些证据足以支持默认配置切换。

## 当前起点

- v0.1 默认链路可运行，控制器、ASR health、TTS 降级、播放队列和前端协议已有自动化回归。
- v0.2 的 Smart Turn、SenseVoice、预测、只读工具预取、generation/revision 隔离、Bidi direct、旧播放窗口兼容、回声消除/降噪降级、受保护真人插话、播放快照、字幕保守结算和断连恢复已有确定性测试。
- 本机 ASR Worker、Analysis Worker 和 v0.2 真实进程回放已验证；回放使用内存播放器。
- 当前自动化基线以 [`docs/v0.2-validation.md`](v0.2-validation.md) 和 [`docs/voice-interruption-bidi-execution.md`](voice-interruption-bidi-execution.md) 最后一次完整运行输出为准；不要沿用本文件早期的 Python 76/前端 9 项数字。
- 当前账号的 MiniMax Bidi 字段、句子时间重置和取消屏障已经完成短文本 smoke test；未完成的证据是完整多轮稳定性、自然语音统计、耳机/扬声器声学行为及第三方服务长期稳定性。

## 目标一：自然语音基准

准备至少 20 条带人工核对文本的中文自然语音，覆盖短句、连续表达、停顿、修正、查询和多轮对话。每条输入在相同配置和相同硬件条件下分别运行 v0.1、v0.2，记录：

- CER 和最终文本完整性；
- 误结束、漏结束和 60 秒封口次数；
- 结束确认至首个实际播放的 p50/p95；
- SenseVoice 回退率；
- 预测采用/丢弃、工具预取/复用和文件变化情况；
- Voice Server、ASR Worker、Analysis Worker 的 CPU、内存和队列峰值。

结果只提交统计摘要和输入编号，不提交原始 PCM、API Key 或完整远程响应。

通过条件：v0.2 没有明显的文本、结束判断或资源退化；每个异常都能关联到 ASR、Analysis、provider 或本地调度的具体原因。

## 目标二：真实设备

分别使用耳机和扬声器验证：

1. 讲话期间的 partial/final 和自然停顿；
2. 播放开始前续说；
3. 播放已经开始后的中断；
4. 连续多轮、`session.stop`、断连和重新启动；
5. 60 秒上限后的新轮以及旧 PCM 清理。
6. 播放中真人讲话与风扇、键盘、敲击、桌面碰撞等固定噪声的区分；确认只在处理后语音满足约 250 ms 门控时插话。
7. 中断历史只包含可靠 `heard_text`，重叠内容标为不确定，明确未播放尾部不进入 LLM 已传达上下文。

必须以播放器实际回调和人工听感为准。内存播放器的 `audio_played_ms` 只能作为软件队列证据，不能代替设备首音时间。

通过条件：没有旧轮音频泄漏、没有不可恢复卡死，耳机和扬声器的中断行为均可解释且可重复。

## 目标三：第三方服务稳定性

在限流窗口稳定、配置和模型固定的条件下，使用短文本和长文本复测 MiniMax Bidi：

- 已收到部分 PCM 后连接关闭；
- provider 未发送 close frame；
- `task_continue` 发送节奏、`task_flush`/`task_flushed` 和 `task_cancel`/`task_canceled` 顺序；
- `subtitle_type=word_streaming` 的实际字段、时间单位、累计/增量形式和多轮重置；
- `2205` 是否返回可关联的被拒绝片段；
- 长文本排空和 `turn.completed`；
- rate limit、超时和网关错误的降级状态。

每次记录 provider 错误类别、已返回/已播放音频摘要和文本是否完整提交，区分云端限制与本地逻辑故障。

## 目标四：v0.2 发布判断

在前三项证据完成后，再判断是否将 v0.2 切换为默认运行配置。判断必须同时满足：

- 旧 turn、旧 generation、旧 revision、旧工具结果和旧 PCM 不污染新轮；
- 自然语音和设备测试没有未解释的明显退步；
- Analysis 不可用、ASR 断连、TTS 失败和 stop/reconnect 均可恢复；
- provider 稳定性和成本限制在可接受范围；
- 文档、协议类型、配置和测试保持一致。

即使满足条件，也要先保留独立回滚开关，再考虑修改默认配置。默认配置切换需要单独的验收结论，不会因为代码路径完成而自动发生。

## 明确不做的扩展

当前后续目标不包括本人声纹注册、本地强制对齐模型、HTTP TTS 迁移、长期记忆、RAG、shell 工具、文件写操作、外部账号操作、自动切换账号区域或浏览器采集音频。AEC、降噪和受保护自动插话已经属于本计划的实现范围；它们的真实设备验收按本文件目标二执行。

## 执行规则

- 先读取实际代码、配置和当前 health，不用旧报告数字代替运行证据。
- 每个修复必须有复现条件、最小修改和回归测试。
- 默认配置暂不切换 v0.2，不停止用户已经运行的服务。
- 不提交密钥、原始 PCM、完整敏感上下文或未经处理的远程响应。
