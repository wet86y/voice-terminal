# DSH（代理执行宿主）分发依赖核对

当前采用 npm（包管理器）在线安装配置声明的精确 DSH（代理宿主）版本。唯一配置为 config/dsh/runtime.lock.json（宿主版本配置）；安装、运行和升级规则见 [DSH 包安装与迁移](dsh-npm-distribution.md)。

| 工具或环境 | 当前项目使用方式 | 检测范围 |
| --- | --- | --- |
| WebView2（微软网页引擎） | 系统自动更新版 | 原生入口检测并提供官方依赖引导 |
| Node.js（脚本运行环境） | 用户安装的 Windows x64（64 位系统）版本 | 正式启动、组件安装和服务重试检测实际版本、架构及可执行性；要求从宿主配置读取 |
| npm（包管理器） | 与 Node.js（运行环境）一起提供，明确调用脚本入口 | 安装、更新和修复前检测；正常启动使用已安装宿主入口 |
| pnpm（插件包管理器） | 在工作区随宿主安装，版本沿用工具配置 | 启动包装入口明确传给动态插件管理，不依赖全局安装 |
| Python（后端运行环境） | Voice Server（语音服务）维护的私有解释器 | 语音组件校验；代理子进程搜索路径优先指向当前工作区解释器 |
| PowerShell（命令环境） | 优先第 7 版，可回退系统第 5.1 版 | 保留按能力使用，不新增基础启动依赖 |
| Git（版本控制工具） | 部分代码托管来源插件和代码操作使用 | 按功能需要，不作为基础启动前置条件 |

Node.js（脚本运行环境）缺失或不符合配置时复用官方安装引导。用户安装后重新检测会重新查找位置、执行版本与架构探测。新目标需要更高版本时先满足依赖，再准备和替换组件；依赖检测失败不改动现用宿主。

官方桌面包与旧物理包保留识别及诊断接口；其随包环境只描述历史来源，新程序要求迁移至当前目标组合。C++（编译语言）桌面运行库由独立受信缓存提供，不再从旧 DSH（代理宿主）桌面包收集。
