# 模型运行环境配置指南

本说明随本体展开到 `data/docs`（用户说明目录），可交给用户自己的配置代理。

## 程序内配置入口

运行环境统一放在本地组件页的 Voice Server（语音服务）条目，与模型使用相同的“下载／导入／跳转”操作。下载时一次检测并补齐基础服务、识别、活动检测、精修、结束判断、声纹、关键词唤醒和模型下载的全部依赖；不再要求用户选择依赖组。本机已有且符合版本、文件和加载条件的依赖优先复用，现用兼容显卡构建继续保留。所有组件安装就绪后隐藏批量导入入口。

各模型的“下载”操作只下载并校验固定版本的模型文件；无需先安装 Python（运行环境）。ModelScope（魔搭模型平台）与 Hugging Face（模型托管平台）模型均使用原生文件下载器。模型文件完整后，运行依赖仍由 Voice Server（语音服务）统一配置。

下载阶段、总字节进度、取消操作和失败原因显示在对应组件卡片中。语音运行环境在下载前先核验本机依赖和缓存，扣除已复用依赖、有效缓存及内置包，再汇总本次需要下载的解释器和依赖包大小；切换依赖包时进度连续累计。下载完成后继续在同一卡片显示组装、检查和启用阶段。

程序启动时先检查语音运行环境、全部模型和代理组件。组件不完整时直接进入本地组件管理页，语音与业务服务暂不启动；由用户手动下载或导入缺失组件。运行环境与不同模型可以同时下载，只有同一组件的重复任务会被阻止。各任务使用独立暂存目录，下载、解包和校验可以并行，启用资源时依次替换文件。原先已运行的服务只在启用时短暂停止并恢复；在组件管理页配置资源不会自动启动服务。

组件尚未就绪或仍在下载时，侧栏“模型管理”和组件页“配置接口密钥”都可以使用。提前填写 DeepSeek（语言模型服务）和 MiniMax（语音合成服务）的 API Key（接口密钥），保存到当前 Windows（系统）用户的凭据库；配置文件仅保存凭据引用，留空保留已有密钥。两家服务分别保存也可以。全部组件就绪但密钥缺失时，程序进入模型管理页，填写完成后点击“启动程序”。启动前只检查密钥是否已配置及能否读取，不会联网判断密钥有效性或账户额度。

显卡环境由用户按需自行准备。组件页不再提供独立显卡登记或额外检测入口；模型的显卡选项依据现用进程的实际后端能力与模型加载结果显示。

## 目录与启动渠道

- 开发版本读取当前项目 `.local`（本机资源），保持现用 `cu128`（CUDA 12.8）环境。
- 分发版本的中央处理器解释器位于工作区 `runtimes/python/python.exe`（私有后端解释器）。基线为 CPython（官方实现）3.12.10、Windows x64（64 位）。
- 用户显卡环境位于 `runtimes/python-gpu/python.exe`（独立显卡解释器）。复制整个私有解释器目录，使用相对搜索路径；普通虚拟环境和 Conda（环境管理发行版）不能直接作为可移动环境。
- 模型位于 `models`（模型目录），配置、历史和关键词进入 `data`（用户数据）。缓存与安装文件进入 `cache`（缓存）及 `tmp`（暂存）。

## 固定版本与兼容候选

| 用途 | 中央处理器组合 | 英伟达显卡组合 |
| --- | --- | --- |
| 识别、活动检测、精修 | PyTorch（张量框架）2.11.0+cpu、torchaudio（音频库）2.11.0+cpu、FunASR（模型框架）1.4.14 | PyTorch 2.11.0+cu128、torchaudio 2.11.0+cu128、FunASR 1.4.14 |
| 结束判断、声纹 | ONNX Runtime（推理库）1.24.3 | onnxruntime-gpu（显卡推理库）1.24.4，CUDA 12 / cuDNN 9（英伟达计算与神经网络库） |
| 关键词唤醒 | Sherpa-ONNX（语音模型运行库）1.13.7 | 兼容 CUDA 12 / cuDNN 9 的 Sherpa-ONNX 1.13.8+cuda12.cudnn9；以实际推理检测为准 |

中央处理器组合已锁定官方来源、大小与摘要。本轮已在指定测试工作区完成完整中央处理器依赖组装、启用及全部依赖加载检查，并验证 FSMN-VAD（语音活动检测）模型文件可以独立下载、校验且不修改运行环境。全部模型的实际推理和显卡关键词组合仍须通过程序的实际推理检测。

完整固定依赖和摘要见 `app/config/runtime/voice-runtime.lock.json`（中央处理器依赖锁）。不要在同一个解释器中同时安装 onnxruntime 与 onnxruntime-gpu（中央处理器和显卡推理包）。共享分析进程需要同时具备精修和结束判断的依赖；共享语音进程需要活动检测、唤醒与声纹依赖，即使其中部分模型选择中央处理器。

## 给配置代理的操作步骤

1. 复制官方可嵌入解释器或可移动私有解释器到 `runtimes/python-gpu`，安装文件必须在工作区内。`python312._pth`（解释器搜索路径文件）只包含 `python312.zip`、`.`、`DLLs`（标准扩展库目录）、`Lib`、`Lib/site-packages` 和 `import site`，不写外部绝对路径。复用系统安装的解释器时，必须保留 `DLLs`（标准扩展库目录），否则 `_socket`（网络基础扩展）等模块无法加载。
2. 在该解释器下按上表安装显卡依赖，保留其运行所需动态库。代理的下载缓存指向工作区 `cache/pip`，临时目录指向 `tmp/process`。使用 CPython 3.12 的 Windows 64 位预编译包，避免在用户设备编译。
3. SmartTurn（结束判断）显卡模型还需要 `models/analysis/smart-turn/smart-turn-v3.2-gpu.onnx`，固定提交与摘要在本体资源清单中；保留中央处理器模型及 `preprocessor_config.json`（预处理配置）。其他模型沿用原有锁定文件。
4. 程序默认使用 `runtimes/python`（现用私有环境）。直接配置该环境后重启程序，启动检查和模型工作进程读取现用后端能力；现有开发环境已包含显卡运行库，不需要登记即可继续使用。若自行维护独立 `runtimes/python-gpu`（显卡环境），须由配置代理完成对应的进程解释器接入，单独创建该目录不会自动切换程序。
5. 能够实际使用显卡的模型才显示显卡运行选项。环境或模型文件改变后重启相关组件，核对实际运行位置和失败原因。移动工作区后保持私有环境的相对路径。

## 检测命令

在工作区执行以下 PowerShell（命令环境）命令，命令使用工作区内的解释器：

```powershell
& './runtimes/python-gpu/python.exe' -I -B -c "import torch; print(torch.__version__, torch.cuda.is_available()); x=torch.ones((8,8),device='cuda'); print((x@x).sum().item()); torch.cuda.synchronize()"
& './runtimes/python-gpu/python.exe' -I -B -c "import onnxruntime; print(onnxruntime.__version__, onnxruntime.get_available_providers())"
```

第二条只确认提供程序声明；实际是否使用显卡，以模型加载结果和组件条目的运行位置为准。

## 恢复

显卡启动失败时，模型加载器尝试中央处理器回退并显示原因。若整个显卡解释器进程不能启动，宿主重新使用中央处理器环境。运行依赖缺失时，从 Voice Server（语音服务）条目一次补齐完整环境。更换显卡环境前关闭语音服务并保留可用的回退环境。配置中断保留下载缓存，再次配置从固定资源摘要对应的断点恢复。

## 微软网页引擎

程序使用系统 WebView2 Evergreen Runtime（自动更新网页引擎），不随包携带固定引擎。缺失时由启动入口提供微软官方引导，安装完成后重新启动。

## 代理组件所用工具

分发使用的官方 DSH（代理执行宿主）桌面组件自带 Node.js（脚本运行环境）和 pnpm（包管理器）。程序通过官方桌面命令入口启动网页宿主，插件管理使用随包工具；基础启动无需全局安装 Node.js、npm（包管理器）或 pnpm。项目的私有 Python（运行环境）由 Voice Server（语音服务）统一维护，DSH（代理执行宿主）子进程的 PATH（可执行文件搜索路径）优先加入该解释器及其脚本目录，代理终端的 Python 命令使用项目环境。

PowerShell（命令环境）优先使用第 7 版，缺失时可回退至 Windows（操作系统）自带的第 5.1 版。Git（版本控制工具）用于部分外部插件安装和代码操作；需要这些功能时再安装。用户让代理处理其他项目时，相关项目自己的构建工具和依赖仍需按项目要求准备。DSH（代理执行宿主）的 Office（文档处理）工具保留官方随包的专用运行环境。
