# 模型运行环境配置指南

本说明随本体展开到 `data/docs`（用户说明目录），可交给用户自己的配置代理。

## 程序内配置入口

运行环境统一放在本地组件页的 Voice Server（语音服务）条目。新安装使用“下载／导入／跳转”，已有组件与随包版本不一致时使用“更新／导入／跳转”。下载或更新时一次检测并补齐基础服务、识别、活动检测、精修、结束判断、声纹、关键词唤醒和模型下载的全部依赖；不再要求用户选择依赖组。本机已有且符合当前版本、文件和加载条件的依赖优先复用，经过当前版本检测的显卡构建继续保留。所有组件安装就绪且没有待更新内容后隐藏批量导入入口。

各模型按新版程序内的固定清单下载并校验当前目标版本。ModelScope（魔搭模型平台）与 Hugging Face（模型托管平台）模型均使用原生文件下载器。普通模型的文件可先独立下载，运行依赖由 Voice Server（语音服务）统一配置；新版 FSMN-VAD（语音活动检测）安装或更新还会通过同一任务检查完整运行环境，补齐轻量检测依赖。对应下载计划会显示连带的依赖配置。处理器模式默认自动选择校验通过的未量化 ONNX（开放神经网络交换格式）模型，显卡运行继续使用新组件内的原浮点权重。

下载阶段、总字节进度、取消操作和失败原因显示在对应组件卡片中。语音运行环境在下载前先核验本机依赖和缓存，扣除已复用依赖、有效缓存及内置包，再汇总本次需要下载的解释器和依赖包大小；切换依赖包时进度连续累计。下载完成后继续在同一卡片显示组装、检查和启用阶段。

组件启用或任务结束后会立即刷新卡片。活动任务每两秒补查状态，空闲每十秒刷新，窗口恢复焦点时也会补查；页面显示实际成功读取组件清单的时间。全部组件和接口密钥就绪后，点击“启动程序”直接进入启动动画，不需要退出重进。启动画面只显示当前组件名称，所有组件共用一条进度条；Voice Server（语音服务）快速核对文件集合和大小，模型与代理组件仍执行完整摘要校验。校验可取消；发现异常的组件会回到管理页等待修复。

Windows（系统）文件短暂被其他进程占用时，程序在文件校验后最多等待 5 秒重试启用，等待期间可以取消。超时或取消保留下载断点与原有缓存；点击“重试下载”继续，完整且摘要匹配的分片直接启用，无需重新下载该文件。

程序启动时先检查语音运行环境、全部模型和代理组件。任一组件缺失、文件集合或大小不符、待更新时，直接进入本地组件管理页，整体语音与业务服务暂不启动；完成全部当前组件的下载或导入并校验成功后才可使用，不提供旧模型运行适配。运行环境与不同模型可以同时下载，只有同一组件的重复任务会被阻止。各任务使用独立暂存目录，下载、解包和校验可以并行，启用资源时依次替换文件。原先已运行的服务在启用时停止，全部组件都就绪后才恢复；最后一次替换保留旧备份至服务入口恢复检查通过，再删除旧目录。失败时保留或恢复旧文件供重试，旧组件仍不能绕过当前版本门槛。在组件管理页首次配置资源不会自动启动服务。

组件尚未就绪或仍在下载时，侧栏“模型管理”和组件页“配置接口密钥”都可以使用。提前填写 DeepSeek（语言模型服务）和 MiniMax（语音合成服务）的 API Key（接口密钥），保存到当前 Windows（系统）用户的凭据库；配置文件仅保存凭据引用，留空保留已有密钥。两家服务分别保存也可以。全部组件就绪但密钥缺失时，程序进入模型管理页，填写完成后点击“启动程序”。启动前只检查密钥是否已配置及能否读取，不会联网判断密钥有效性或账户额度。

显卡环境由用户按需自行准备。组件页不再提供独立显卡登记或额外检测入口；模型的显卡选项依据现用进程的实际后端能力与模型加载结果显示。

## 麦克风、扬声器与唤醒词

麦克风和扬声器使用 Windows（操作系统）指定的默认输入与输出设备。请在系统声音设置中选择所需设备，重新启动程序后生效。程序不保存设备名称或编号；旧 `local.yaml`（本地配置文件）中的 `audio.input_device`（麦克风选择）和 `audio.output_device`（扬声器选择）会自动忽略，更换电脑无需手动删除这些字段。运行期监听、声纹录制和语音播放使用相同的系统默认设备规则。

KWS（关键词唤醒）模型保持在 `models`（模型目录），用户生成的唤醒词保存在 `data/config/kws`（关键词配置目录）。在“唤醒与静默”页面保存唤醒词时，会校验并生成对应文件；首次启用或关键词文件缺失、损坏时，即使文字未改动也会重新生成。旧版本出现“文件必须位于受管生成资源目录内”时，更新程序后再次保存即可。

KWS（关键词唤醒）开始监听后，本地组件页显示绿色“运行中”。READY（就绪）、RUNNING（运行中）、STREAMING（流式传输）和 CONNECTED（已连接）均按正常可用状态呈现；进程退出、模型加载或运行失败仍会显示具体错误。

注册主人声纹时，按页面引导完成三段录音，三段均显示“已完成”且录制结束后即可点击“保存声纹”。模板自动按“第 1 段”“第 2 段”“第 3 段”命名。保存成功后，页面显示已注册模板；质量检查或保存失败会显示原因，并保留当前会话的片段供重录或重试。已保存资料可以在重启后加载，原始录音只暂存在内存，取消、退出或更新程序后需要重新录制尚未保存的三段。

声纹“运行模式”和“仅主人可打断”切换后自动保存并立即应用。主人确认阈值与连续主人放宽量通过两条滑块编辑；放宽量范围为 0–0.20，默认 0.10，连续主人阈值为主人阈值减去放宽量且最低为 0。调整滑块后点击页面“保存声纹阈值”按钮提交，松手不会自动保存。待机时显示“主人打断已启用”，播放时验证回声保护，正常后显示“已生效”；资料、声纹进程或回声消除不可用时显示具体原因。声纹模式关闭时也可单独启用主人打断。

关键词唤醒、灵敏度和最终静默时长保存后直接应用；人格资料与自定义指令保存后用于当前会话的后续模型请求。组件加载期间保存的设置会在加载结束后自动生效，无须再开启一轮对话。模型运行设备仍需重新启动应用，以实际加载的推理后端为准。

## 目录与启动渠道

- 开发与分发使用同一正式程序及工作区布局；本机工作区为项目 `.local`（本机资源目录）。只重新构建缓存不会更新日常运行本体，还须执行本地发布。
- 当前使用的解释器位于工作区 `runtimes/python/python.exe`（私有后端解释器）。处理器基线为 CPython（官方实现）3.12.10、Windows x64（64 位）；经过验证的现有 `cu128`（CUDA 12.8 显卡组合）环境可由组件配置器保留并补齐依赖。
- 新显卡环境先在 `tmp`（暂存目录）准备独立候选，完整核验后通过组件管理页导入。单独创建 `runtimes/python-gpu`（自定义候选目录）不会切换程序；普通虚拟环境和 Conda（环境管理发行版）不能直接作为可移动私有环境。
- 模型位于 `models`（模型目录），配置、历史和关键词进入 `data`（用户数据）。缓存与安装文件进入 `cache`（缓存）及 `tmp`（暂存）。

## 固定版本与兼容候选

| 用途 | 中央处理器组合 | 英伟达显卡组合 |
| --- | --- | --- |
| 识别、活动检测、精修 | PyTorch（张量框架）2.11.0+cpu、torchaudio（音频库）2.11.0+cpu、FunASR（模型框架）1.4.14 | PyTorch 2.11.0+cu128、torchaudio 2.11.0+cu128、FunASR 1.4.14 |
| 处理器轻量活动检测 | funasr-onnx（轻量语音推理包）0.4.3、ONNX Runtime（推理库）1.24.3 | 保留原浮点检测权重，由实际运行偏好选择 |
| 结束判断、声纹 | ONNX Runtime（推理库）1.24.3 | onnxruntime-gpu（显卡推理库）1.24.4，CUDA 12 / cuDNN 9（英伟达计算与神经网络库） |
| 关键词唤醒 | Sherpa-ONNX（语音模型运行库）1.13.7 | 兼容 CUDA 12 / cuDNN 9 的 Sherpa-ONNX 1.13.8+cuda12.cudnn9；以实际推理检测为准 |

中央处理器组合已锁定官方来源、大小与摘要。本轮在隔离工作区对新增轻量检测运行栈完成正式版本组装，42 组真实流式输入全部通过；处理器会话和未导入大型语音框架的断言通过。真实 FSMN-VAD（语音活动检测）模型更新、损坏候选拒绝、旧目录清理和设置保留也通过验收。全部模型的实际推理和显卡关键词组合仍以程序中的加载和推理结果为准；详细研究记录及验收证据保存在项目文档中。

完整固定依赖和摘要见 `app/config/runtime/voice-runtime.lock.json`（中央处理器依赖锁）。不要在同一个解释器中同时安装 onnxruntime 与 onnxruntime-gpu（中央处理器和显卡推理包）。共享分析进程需要同时具备精修和结束判断的依赖；共享语音进程需要活动检测、唤醒与声纹依赖，即使其中部分模型选择中央处理器。

## 给配置代理的操作步骤

1. 在 `tmp/python-gpu-candidate`（显卡环境候选目录）准备官方可嵌入解释器或可移动私有解释器，不直接改写正在使用的环境。`python312._pth`（解释器搜索路径文件）只包含 `python312.zip`、`.`、`DLLs`（标准扩展库目录）、`Lib`、`Lib/site-packages` 和 `import site`，不写外部绝对路径。复用系统安装的解释器时，必须保留 `DLLs`（标准扩展库目录），否则 `_socket`（网络基础扩展）等模块无法加载。
2. 在候选解释器下按上表安装显卡依赖，并补齐当前锁定清单全部六组依赖及轻量检测包，保留运行所需动态库。代理的下载缓存指向工作区 `cache/pip`，临时目录指向 `tmp/process`。使用 CPython 3.12 的 Windows 64 位预编译包，避免在用户设备编译。
3. SmartTurn（结束判断）显卡模型还需要 `models/analysis/smart-turn/smart-turn-v3.2-gpu.onnx`，固定提交与摘要在本体资源清单中；保留中央处理器模型及 `preprocessor_config.json`（预处理配置）。其他模型沿用原有锁定文件。
4. 候选须具备 `runtime.json`（当前运行环境登记）和 `manifest.json`（完整文件清单），按当前锁定版本完成依赖加载和摘要校验。通过 Voice Server（语音服务）卡片的“导入”入口提交候选；管理器会再检查并事务替换 `runtimes/python`（现用私有环境），失败保留原环境。仅修改包文件或创建一个显卡目录不代表已通过启动门槛。
5. 全部必需组件均为当前版本且校验通过后，再启动程序并核对实际运行位置。能够实际使用显卡的模型才显示显卡运行选项；环境或模型文件变化会使相关能力检测需要重新验证。移动工作区后保持私有环境的相对路径。

## 检测命令

在工作区执行以下 PowerShell（命令环境）命令，命令使用工作区内的解释器：

```powershell
& './tmp/python-gpu-candidate/python.exe' -I -B -c "import torch; print(torch.__version__, torch.cuda.is_available()); x=torch.ones((8,8),device='cuda'); print((x@x).sum().item()); torch.cuda.synchronize()"
& './tmp/python-gpu-candidate/python.exe' -I -B -c "import onnxruntime; print(onnxruntime.__version__, onnxruntime.get_available_providers())"
```

第二条只确认提供程序声明；实际是否使用显卡，以模型加载结果和组件条目的运行位置为准。

## 恢复

模型加载的设备回退遵循现有推理策略，但不会绕过组件当前版本和完整性要求。已验证的显卡环境在更新时继续复用；核心库不能复用或其文件摘要失败时，配置器报告错误并保留原环境，不自动换入处理器运行库。解释器或完整依赖无法加载时，通过 Voice Server（语音服务）条目修复或导入已验证的当前完整环境。配置中断保留下载缓存，再次配置从固定资源摘要对应的断点恢复。

旧版本出现 `model_credentials_save not allowed by ACL`（保存接口密钥命令被访问控制列表拒绝）时，需要更新正式程序本体。退出旧程序后运行新安装器，选择原工作区目录完成保留数据的重装，再进入“模型管理”保存密钥，并在失败的组件卡片点击“重试下载”。重装保留用户数据、组件与下载缓存。

## 微软网页引擎

程序使用系统 WebView2 Evergreen Runtime（自动更新网页引擎），不随包携带固定引擎。缺失时由启动入口提供微软官方引导，安装完成后重新启动。

## 代理组件所用工具

分发使用的官方 DSH（代理执行宿主）桌面组件自带 Node.js（脚本运行环境）和 pnpm（包管理器）。程序通过官方桌面命令入口启动网页宿主，插件管理使用随包工具；基础启动无需全局安装 Node.js、npm（包管理器）或 pnpm。项目的私有 Python（运行环境）由 Voice Server（语音服务）统一维护，DSH（代理执行宿主）子进程的 PATH（可执行文件搜索路径）优先加入该解释器及其脚本目录，代理终端的 Python 命令使用项目环境。

PowerShell（命令环境）优先使用第 7 版，缺失时可回退至 Windows（操作系统）自带的第 5.1 版。Git（版本控制工具）用于部分外部插件安装和代码操作；需要这些功能时再安装。用户让代理处理其他项目时，相关项目自己的构建工具和依赖仍需按项目要求准备。DSH（代理执行宿主）的 Office（文档处理）工具保留官方随包的专用运行环境。
