# 本地目录与覆盖发布

本文说明统一正式程序的固定工作区布局及本地发布。开发和用户使用相同入口与本体；源码调试只显式替换业务与前端输入。分发程序已变为独立安装器，详见[统一正式程序与分发安装器](unified-product-installer.md)与[当前交付](current-release.md)。源码由 Git（版本控制）保留历史；`.local`（本机资源目录）不提交。

本机迁移、清退、体积与实机验收结果见[本地目录整理与覆盖发布验收](local-layout-acceptance-20261008.md)。

```text
项目根目录/
├─ apps/、voice_terminal/、integrations/  当前业务源码
├─ config/、tests/、scripts/、docs/       模板、测试、工具与当前资料
├─ node_modules/                        包管理器标准开发依赖
└─ .local/
   ├─ VoiceTerminal.exe                 正式入口
   ├─ VoiceTerminalUIDemo.exe           前端演示入口
   ├─ portable.json                    唯一路径配置
   ├─ Verify-Package.ps1               当前安装的完整摘要校验
   ├─ 使用与环境说明.md                自包含交付说明
   ├─ app/                             当前正式程序与项目插件
   ├─ runtimes/python/                 后端运行环境
   ├─ runtimes/dsh/                    生产代理宿主，内含脚本解释器
   ├─ runtimes/webview2/               旧私有网页引擎，保留文件但不使用
   ├─ models/                          当前必要模型集合
   ├─ data/                            真实持久数据
   ├─ backups/user-data/               最多一份滚动持久数据备份
   ├─ build/desktop/、frontend/、dsh/   唯一受控构建缓存
   ├─ tools/rust/、testing/            原生工具链及轻量测试工具
   ├─ cache/                           日志、渲染配置及可回收缓存
   ├─ tmp/                             更新与测试暂存
   └─ releases/                        明确导出的最新交付包
```

`schema=2`（第二版格式）的路径字段固定如下。构建编号和 SHA-256（内容摘要）只进入清单；它们不参与目录命名。

| 字段 | 固定值 | 中文说明 |
| --- | --- | --- |
| `schema` | `2` | 便携配置格式 |
| `app` | `app` | 当前程序目录 |
| `python` | `runtimes/python/python.exe` | 唯一后端解释器 |
| `models` | `models` | 必要模型集合，不同业务模型各保留所需资源 |
| `dsh` | `runtimes/dsh` | 生产代理宿主 |
| `webview2` | `null`（不使用私有引擎） | 使用系统网页运行引擎，旧文件保留 |
| `data_dir` | `data` | 唯一真实用户数据 |

Node（脚本解释器）由代理宿主的 `runtime.json`（运行清单）内 `node`（解释器相对路径）解析。源码业务只切换程序目录，复用上述业务组件与数据。演示只创建前端进程，复用脚本解释器和网页引擎，不启动业务服务。

常用命令：

```powershell
npm run dev                  # 真实业务桌面开发
npm run dev:ui               # 前端演示开发
npm run desktop:start        # 已发布静态正式程序
npm run desktop:build        # 固定构建目录，包含界面和原生程序
npm run desktop:publish      # 构建、校验、停机检查、固定目录换入、验证、回收
.\scripts\start.ps1          # 无界面后端，使用同一业务环境
.\.local\Verify-Package.ps1  # 校验当前正式安装全部清单与文件摘要
.\.local\runtimes\python\python.exe -B -X utf8 scripts/test-backend.py -q # 后端测试
```

以上命令在项目根目录执行。正式程序唯一入口为 `.local/VoiceTerminal.exe`（正式启动程序）；关闭正式窗口只是隐藏到托盘，发布或备份前使用应用菜单、托盘或“设置 → 系统运行”的退出操作，等待业务进程结束。

发布前退出正式业务和源码业务实例，关闭演示窗口。发布仍通过现有 npm（包管理器）命令执行；正在使用待更新文件时会拒绝换入并原位恢复。普通代码发布只替换 `app`（程序）和根入口；插件属于程序包，模型及环境复用。运行组件的下载、导入、配置与维护由正式程序的组件管理页面承担；分发安装器及本地本体发布不更新这些组件。

事务采用同盘重命名。候选校验完成后将旧组件暂移到 `tmp/publish/old`（事务旧组件），再将新组件换入固定路径；因此旧清单之外的文件不会残留。最终校验成功即回收旧组件。失败则反向恢复旧组合。`tmp/update-transaction.json`（更新事务记录）区分准备、换入和已提交状态；下一次发布先恢复或收尾，不覆盖未完成事务。正式宿主与本体替换共用工作区互斥句柄，阻止运行中覆盖和并发发布。

存在未完成本体事务时，正式根入口及再次安装先恢复或收尾，再准备业务；桌面宿主和源码入口在读取未完成组合前拒绝启动。

常规发布不生成整包备份，也不保留历史正式版本。明确交付时执行：

```powershell
.\.local\runtimes\python\python.exe -B -X utf8 scripts/package-desktop.py
```

导出只收集清单声明的当前程序、四类组件、根入口及便携配置，覆盖 `.local/releases/VoiceTerminal-latest.zip`（最新交付压缩包）。真实数据、构建缓存、工具、日志及临时目录不进入交付包。安装资源完成验证后回收，不长期保留多份离线环境。

重要用户数据由下列命令备份。先退出业务实例，确保数据库与状态已经落盘：

```powershell
.\.local\runtimes\python\python.exe -B -X utf8 scripts/local-admin.py backup
```

白名单包括配置、人格、声纹、会话历史、代理状态、工作区、导入文件及持久状态；排除依赖目录、模型、缓存、日志和字节码。先生成并核对新备份的每个摘要，再替换旧备份，常态最多一份有效备份。`backup.json`（备份清单）记录权威数据来源、相对路径、字节数和摘要；凭据文件只作为私密文件复制，不展示内容，系统凭据存储保持原状。恢复时先将备份复制到隔离目录，核对摘要，再停机恢复需要的数据文件。

当前个人配置位于 `data/config/`（本机配置）、`data/persona/`（人格资料）和 `data/speaker/`（声纹资料）；会话、代理状态及导入内容分别位于 `data/history/`、`data/dsh/` 和 `data/imports/`。以上路径相对于 `.local`（安装根目录）。源码 `config/`（配置模板）用于提供默认值和补齐缺失文件；已有用户设置继续从数据目录读取。

一次性迁移工具为 `scripts/migrate-local-layout.py`（旧布局迁移工具）。它保护现用持久数据、去重旧来源，将唯一旧内容保存到 `data/imports`（迁移导入区），随后同盘搬迁现用资源并修复受控构建缓存内的联接。正常入口不读取旧组件选择副本，也不搜索另一套解释器或模型位置。迁移和清理记录保留在数据状态与本次验收文档中。

删除必须使用规范化后的具体工程内路径，核对保护对象，不跨出工程。重解析点只删除联接本身，不遍历目标；长路径采用 Windows（操作系统）扩展路径。删除前先通过正式入口、数据完整性与备份恢复验收。

构建缓存固定在 `.local/build`（构建目录）内；`prepare-build-cache.py`（缓存版本管理工具）登记锁与工具链摘要。DSH（代理宿主）锁变化后清除未跟踪的旧依赖及输出，保留上游检出和源码修改；原生各渠道输出保持固定位置，依赖变化由 Cargo（原生包管理器）判断并增量重新编译，登记新锁不整体删除其他渠道。自动测试成功后回收夹具及测试临时目录，失败时留下必要诊断。

前端开发缓存分置于 `cache/vite-product/`（业务开发缓存）、`cache/vite-demo/`（演示开发缓存）和 `cache/vitest/`（界面测试缓存）；后端测试缓存位于 `cache/pytest/`。它们都是可回收产物，不是业务数据或第二套运行环境。日常更新使用 Git（版本控制）保存源码历史，再执行覆盖发布；无需先生成交付压缩包，也无需复制旧程序、模型或运行环境。

发布使用约 24 MiB（兆二进制字节）的临时标准库工具，在换入前释放正式解释器占用；不复制张量及模型依赖，成功后回收。即使正式解释器目录在更新中断时暂时缺失，下次发布也先使用保留的临时工具恢复事务。项目临时区的已验证大组件直接同盘重命名换入，不再复制候选。
