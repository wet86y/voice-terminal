# TTS（语音合成）运行模式

Voice Server（语音服务）负责文本提交、合成调度、播放和打断结算。`tts.backend`（语音后端）只接受 `minimax`（MiniMax 在线语音）与 `aniflive`（本地语音）。本地模型来自已验证登记，并保存 `local_model_revision`（精确模型版本）；旧 VoxCPM（旧模型）选择只在迁移入口转换为通用基底，旧音色与录音保留。

查看设置和保存播放目标分开。运行中切换等待当前播报及续写租约结束，失败恢复原选择与参考；8 GiB（吉比字节）设备先卸载旧模型再加载新模型。试音及切换暂停监听，并恢复原监听意图。MiniMax 默认模型与音色继续沿用现有设置；可选本地组件缺失不触发普通启动下载。

## MiniMax 在线模型与音色

打开“设置 → 语音与音色”，将语音播放目标选为“在线 API（网络语音接口）”，即可配置在线模型与音色。Turbo（低时延模式）对应 `speech-2.8-turbo`，HD（高音质模式）对应 `speech-2.8-hd`。音色 ID（音色标识）使用 MiniMax 账户中的 ID；系统音色、克隆音色、生成音色及官方以后新增的音色类型都按 ID 查询，不以本地类别表或 ID 前缀限制。

模型选择与音色 ID 由同一个“保存”按钮提交。保存时服务端使用已配置的 MiniMax API Key（接口密钥）调用官方 `get_voice`（查询音色）接口的 `all`（全部类型）结果验证 ID；密钥只在服务端使用，不会发送到前端。ID 未找到、密钥未配置或查询失败时会显示错误，当前已保存的模型和音色保持不变。成功后设置会跨重启保留，并用于后续播报；若当前有语音事务，选择先保存并在事务结束后生效。客户端切换失败时会恢复原配置和客户端。

“试音”按钮位于“保存”左侧，使用固定示例文本“你好，很高兴认识你。现在开始测试这个音色，我会用自然的语气清楚地说话。”直接请求所选 MiniMax 模型与输入的音色 ID，并通过程序播放器播放结果；试音不会保存设置。需要已配置 API Key（接口密钥）和可用的程序播放器。点击“官方音色库”可打开 [MiniMax 音色管理控制台](https://solutions.minimaxi.com/voices)，查看系统、克隆和生成音色及其 ID。新字段缺失的旧设置沿用现有 MiniMax 模型和音色初始化。

用户主动点击在线或本地音色试音、播放已保存样音时，播放器按当前操作键放行，不受 `quiet_hours`（被动静默时段）限制；普通助手播报仍遵循被动静默策略。试音仍须在监听停止且已有播报结算后运行，避免与实时语音会话争用本地音色任务。

## 本地首音直接播放

AnifLive（本地语音）输出为 32 kHz（千赫兹）单声道 16 位 PCM（脉冲编码音频）。播放器初始起播与恢复储备为 0；通过播放许可后交给设备回调。首个非空网络音频块到达后可额外等待 0～200 ms（毫秒），默认 0、步长 1；等待期间独立接收音频。网络到达、交付播放器及首次设备输出分别计时，单字节网络分片仍按最初到达时刻计时，交付时保持采样对齐。

音色库下的显卡高性能默认关闭；开启会停用并取消事件预热。后续分块优化默认开启，对应 48 个语义标记；关闭恢复 96 个。这不是推理步数，旧推理质量档位已移除。设置对下一回答生效，活动回答与续写保持参数和参考快照。

## 本地引擎配置与升级

AnifLive（本地语音）由应用按需启动、监督和关闭，使用自动回环端口、工作区认证和进程创建时间校验。组件任务下载固定依赖与权重，在目标机器导出计算图并生成引擎；实际加载和短长句、流式验证通过后才登记。不同显卡或依赖身份不符的引擎不能直接套用。

旧 audio.cpp（原生语音框架）及补丁制作入口已退役；本体更新仅精确退役能确认归属的两份 VoxCPM 权重及相应登记，旧运行目录、音色、录音和备份保留。AnifLive 固定来源、自动配置方法和引擎兼容规则见[接入记录](../development/aniflive-integration.md)。

## 后端切换时的采样率

`tts.sample_rate`（活动输出采样率）随后端切换：AnifLive 固定为 32 kHz（千赫兹）；MiniMax 沿用已保存的在线采样率。`tts.online_sample_rate`（在线输出采样率）独立保存，本地模型的原生采样率不覆盖它。切回在线后同步恢复播放器与在线客户端时钟。

在线 TTS profile（语音配置档案）保存在线采样率；`doctor --online`（在线诊断）也使用它检查 MiniMax 连接。播放器忙碌时延迟执行的本地换率仅适用于本地后端，不能覆盖在线采样率。

连接或 `task_started`（任务已启动）确认前发生临时网络故障，或 MiniMax 返回可重试的 `408`、`425`、`429`、`5xx` 状态码时，客户端会丢弃失效连接并新建连接重试一次。文本提交后不会自动重发，避免网络中断时重复播报；认证、参数等明确拒绝不会重试。只有错误明确指向不支持的音色情绪字段时，才会去掉该可选字段后重新建连。

## 音色编辑与参考音频

AnifLive（本地语音）采用参考录音克隆，支持上传、转写校对、试音、保存、启用和恢复模型默认参考。参考录音需为 3～10 秒清晰音频及准确转写；保存原采样率单声道副本用于参考处理，16 kHz（千赫兹）副本用于转写，低采样率原件同样保留。参考语言与转写随音色版本保存。

试听使用临时参考；结束、失败或取消后恢复正式参考。音色与素材在途引用受租约保护，不能回收正在播报或续写的素材。AnifLive 当前支持使用音色库登记的情绪参考标记；标记存在多个强度档位时，可以继续调整强度。不提供纯设计或混合设计音色流程。

## 播放期间的用户打断

播放期间，打断候选必须同时满足 FSMN-VAD（流式语音活动检测模型）持续报告语音，以及 AEC（声学回声消除）保护路径确认近端语音。默认至少累计 500 毫秒有效近端语音后才确认打断。中间的静音或非近端语音不计入时长；候选语音结束时会清零。

此门槛由 `BargeInGate.min_speech_ms`（播放打断最短有效人声时长，毫秒）独立控制；普通输入仍使用 `vad.min_speech_ms`（普通输入最短有效语音时长，毫秒），两者互不影响。普通打断和“仅主人打断”均使用 500 毫秒门槛。

启用 `speaker.owner_only_barge_in`（仅主人可打断）时，还必须满足现有的当前候选声纹授权规则。声纹提前确认不能绕过 500 毫秒门槛；达到门槛但主人身份尚未授权时，播放继续，控制器仍等待该候选的有效声纹结果，并沿用既有等待期限、连续主人策略及初始临时授权规则。AEC 保护不可用时，仍按既有策略抑制未保护的播放打断。

该时长只限制正在播放时的打断确认，不改变普通输入、语音端点、声纹推断窗口或识别阈值，也不保证声纹推断必定在 500 毫秒内完成。咳嗽、叹气等声音若持续被近端语音检测器和 FSMN-VAD 判为语音达到门槛，仍可能触发打断；目前不使用 SenseVoice（语音理解模型）事件标签过滤打断候选。

## 锁定文本块的最小长度

`sentence_window`（短句窗口调度）保持当前块和最多一块预取文本，`sentence_prefetch_ms`（预取提前量）默认 3000 毫秒。每次从可改队列取下一块时，按原顺序合并完整文本段，达到 `tts.sentence_min_effective_chars`（锁定文本块最少有效字符，默认 10）后一起提交。中文、字母和数字逐字符计数，标点、空白与符号不计；原文和标点全部保留，恰好 10 个有效字符即满足下限。模型文本生成结束后，不足下限的最后一块正常提交，短回答不等待补字。

未凑齐下限的文本仍留在本地可改队列，只有语音合成成功接受合并块后才推进 `sent_chars`（不可修改前缀字符数）。LLM（大语言模型）可见的 `current_clause`（当前锁定块）和 `prefetched_clause`（下一预取锁定块）按同一提交块投影，各块可能包含多个短句；`revisable_tail`（可改尾巴）从实际提交边界之后开始。尾巴改写后重新入队的文本使用相同的合并规则。首段的 400 毫秒分段兜底只释放分段缓冲，尚未达到有效字符下限时仍等待后续文本或生成结束；其他调度模式继续使用原有规则。

例如“明白，老大。我这边一切正常，运行稳定，随时听你调度。”依次提交为“明白，老大。我这边一切正常，”（11 个有效字符）和“运行稳定，随时听你调度。”（10 个有效字符）。该下限保证每个非结束块的文本长度；实际播放时长仍由语音合成结果决定。

参数必须为正整数，读取后传给在线语音客户端；修改本地配置后重新启动程序生效。正式程序未设置本地覆盖时使用程序包中的默认值 10，已有个人设置继续保留。该能力只控制文本合并与锁定边界，不负责检验模型改写内容是否与已播内容语义重复。

## 模型推理期间的提交边界

有效 LLM（大语言模型）请求在生成上下文前，通过 `SpeechInferenceBoundary`（推理语音边界）关停新的文本提交，并等待正在执行的 `send_text`（发送文本）与 `sent_chars`（已提交字符数）推进一起结算。空心跳和空二等信箱不进入保护期；正常请求、有效系统检查和协议恢复请求均使用同一保护期。

请求准备阶段按“语音服务已经返回的总音频时长减去设备实际播放位置”计算剩余音频，包含尚未进入播放器的服务端音频缓存。达到 3000 毫秒时不追加锁定；不足时，已有可改的旧语音事务可以先补交一个文本块，沿用至少 10 个有效字符的完整段合并规则，结束尾块可以不足 10 字符。已经占满当前块与预取块的两块窗口、用户正在讲话、事务不可改或没有可提交文本时不补块。等待期间已有音频补足缓冲，会撤销额外补块许可。准备等待上限为 2 秒；超时后仍须等待已经开始发送的块结算，才能冻结真实边界。

上下文生成后到本次结果应用完成，所有语音事务都禁止继续提交新文本，已合成音频的接收和播放继续进行。请求结束后解除冻结并恢复常规播放调度，长回答不必等待下一次模型请求才能继续播放。停止、重置、模型失败、取消和异常退出均需释放本次请求独立票据；旧请求的释放不能解锁新请求。已经取出但尚未发送的旧文本块，在修订导致 `epoch`（尾巴版本）变化后被丢弃。

模型通过 revision（尾巴修订）替换当前播报事务的完整未提交尾巴，尾巴为空、已有文本全部锁定时也可续写。修订权限不要求用户轮次与原播报轮次一致，截图、后台回传及后续讲话均按当前事务的有效边界受理。原播报的模型文本生成与本地原始文本分段入队完成后开放修订，正在发送时关闭窗口。请求快照在准备阶段结束后生成，应用修订时再次确认 `speech_id`（事务标识）、`output_generation`（输出代数）、`sent_chars`（已提交字符数）、`text`（原计划文本）和 `text_revision`（修订版本）一致，失效则拒绝。speak（新播报）仅在输出空闲时创建事务，忙碌请求即使等到播放完成也不补执行；cancel（取消）空文本停止、带文本停止并替换。请求前的补块仅提交旧事务已有文本，不恢复 speak 的追加或替换能力。成功修订通过 `speech.tail_rewritten`（尾巴修订事件）同步完整文本与版本，前端据此更新展示。`revision_source_turn_id`（最近修订来源轮次）和 `revision_request_id`（最近修订来源请求）独立记录，原播报的轮次归属保持可追溯。

取消替换的旧音通过播放器独立过渡缓存收尾，不再接受旧服务追加。`replace_grace_ms`（替换过渡上限毫秒）默认600，旧正值兼容读取但实际不超过600；小于500时按3∶2压缩两个阶段。正常振幅在300毫秒降至30%、500毫秒归零，新音就绪则旧音最多30毫秒收尾后接新音30毫秒淡入；旧采样不足提前结束，新音迟到允许静音，不恢复旧队列。600毫秒限制软件出口，与设备已提交尾音和合成服务清理超时分开。用户停止、确认打断、播放权限撤销和重置立即清除过渡。实际输出同时用于回声参考和音量显示；降音量源区间归入 `uncertain_text`（传达不确定文本）。活动事务只使用本事务的实际对齐结果提供 `speech.delivery`（实际传达记录）。

实际设备音频播放完成后保留 1 秒续写资格，模型看到 `speech.state=continuation`（播放已结束的续写窗口）和 `continuation_mode=rewrite_tail`（允许尾巴修订）。窗口内取得权限的有效推理保留自己的独立票据，即使结果在截止后返回仍可修订；截止后的新请求不能借用其他在途请求的票据。窗口到期且没有在途权限或待播尾巴后恢复 `empty`（输出空闲），同一用户轮次也可正常创建新播报。新用户轮次不撤销资格；明确取消、确认打断、输出代次变化或会话失效仍撤销旧资格。

发送管线仍在时沿用原队列修订；发送管线已经关闭时，新尾巴独立暂存，等待旧音频真实播放并完成结算后，沿用原语音后端、音色快照和推理参数创建后继播放段，只合成新尾巴。该 1 秒是受理窗口，不是固定接播等待；已准备好的内容立即接播，已受理尾巴不会因结算较慢而丢失。旧播放段只记录自身实际听到的文字，后继段另行结算；模型可见的累计文字前沿保留创建该段前的固定已播放前缀，不通过文本重叠猜测删减后继文字。窗口持有的音色与本地模型租约在接播交接或窗口退出时释放；整体替换语音后端继续受切换屏障保护，须等待续写窗口及其在途请求退出。

日志 `speech.inference_frozen`（推理边界已冻结）记录 `request_id`（模型请求标识）、`speech_id`（语音事务标识）、`sent_chars`（冻结时已提交字符数）、`remaining_ms`（准备开始时剩余音频）、`target_ms`（缓冲目标）和 `prefill`（补块结果）。`speech.inference_released`（推理边界已释放）记录该请求释放后是否还有其他保护票据。3 秒缓冲及一个文本块不保证覆盖任意长的模型推理；缓冲耗尽时允许暂停，不能继续提交旧尾巴改变已冻结边界。

## 本地音频参考时钟与异常片段保护

“智能语音调节”总开关与能力登记继续生效，见[语音调节架构](../architecture/speech-controls.md)。AnifLive（本地语音）的语气引导来自当前音色已登记的情绪标记，标记有多个档位时才提供强度调节；语速与音量使用本地处理，保音高语速处理器不可用时隐藏语速入口。不注入旧模型风格前缀。输出时钟、字幕与打断结算使用当前实际采样率和输出采样数。

更换设备或采样率时，`AudioPreprocessor.reclock_reverse`（重设回声参考时钟）必须丢弃旧队列与残留帧。每份参考数据携带来源采样率和代次；已经出队的旧代次也不能按新时钟重新解释。AEC（回声消除）仍按麦克风采样率处理参考帧。

本地语音输出设有异常长段预算，超出预算或未完成的音频不能作为成功分段提交。它是传播风险保护，不是通用音质分类器：时长正常的错误音色、点击或短静音仍可能通过，流式检测也无法撤回用户已经听到的片段。任务式试音只有拿到完整结果后才能判废；关闭请求或释放上下文不等于原生任务一定立即停止计算。根因定位仍需要真实异常样本和逐事件边界。

## 只读状态

`GET /api/v1/tts/status`（语音状态接口）返回 `backend`（当前后端）、`local_model`（本地模型编号）、`revision`（精确版本）、`loaded_model`（实际驻留模型）、`models`（已登记候选及可用状态）和 `load_state`（加载状态），不暴露本机路径。可用状态依据构建身份和验证收据，模型卡片只归属实际驻留模型。旧 `worker: {"state":"stopped"}`（旧式进程兼容字段）保留；AnifLive 的受管推理进程另按实际身份统计。

`TtsBackendRouter`（后端路由）与 `EpisodeSpeechOutput`（语音事务输出）按回答租约绑定客户端；播报和续写结束后才切换或释放模型。`PUT /api/v1/product/settings/tts`（语音设置接口）保存播放目标及本地选项；`/api/v1/tts/voices/aniflive`（本地音色接口）只开放当前共享音色库，旧模型接口拒绝访问。

`tts_profile_id`（语音配置标识）继续用于读取和恢复已有配置，模型分配不能擅自更换它。

## 本地合成日志

AnifLive（本地语音）记录 `session_ready`（会话就绪）、`segment_timing`（文本段时延）、`first_pcm_timing`（首块网络时延）及 `first_pcm_consumed`（首块交付时延）。`controller.turn_latency`（轮次时延）继续区分首文本、首块音频、首次播放及总耗时。

音频流结束后还需核对服务端会话及全部已提交文本段的成功终态。部分音频后的服务端失败不能作为完整播报结算；取消与异常退出均释放会话和参考租约。完整构建日志和本机资源报告保存在受管缓存，不将模型文件大小或 PyTorch（张量库）缓存量当作 TensorRT（推理引擎）实际显存。
