# TTS（语音合成）运行模式

Voice Server（语音服务）把已提交的文本块交给当前 `tts.backend`（语音运行后端）合成，并负责文本分段、调度、播放、中断结算和历史记录。后端有两种：`minimax`（MiniMax API 在线语音接口，默认）和 `voxcpm1`（本地 VoxCPM 的兼容路由名，实际模型由 `tts.local_model` 在第一代 `voxcpm1` 与第二代 `voxcpm2` 之间选择）。设置页可在“语音与音色”页切换后端与本地模型，切换在运行中事务化执行，失败时回滚到原选择。当前默认配置仍使用 `speech-2.8-hd`（在线语音模型）和 `female-shaonv`（在线音色）；模型分配不能更改当前 TTS profile（语音配置）。本地后端的模型、音色库、优化开关与实测数据见[本地 TTS 集成](local-tts-integration-20261014.md)。

所选后端的依赖未配置或不可用时，服务会报告错误：`minimax` 需要可用的 MiniMax API（在线语音接口），`voxcpm1` 需要本地模型权重与 `.local/runtimes/audiocpp`（原生推理服务）就绪。两者互相独立，一端不可用不影响另一端。

## 后端切换时的采样率

`tts.sample_rate`（当前播放器及合成输出采样率）随活动后端变化：本地 VoxCPM1 使用 16 kHz，VoxCPM2 使用 48 kHz；MiniMax 在线合成使用配置文件中的在线采样率，默认 32 kHz。运行时另存 `tts.online_sample_rate`（在线合成采样率），本地模型原生率不会覆盖它。切回 MiniMax、启动时回退到在线后端或应用产品设置时，播放器和在线客户端都恢复在线采样率。

在线 TTS profile（语音配置档案）保存在线采样率；`doctor --online`（在线诊断）也使用它检查 MiniMax 连接。播放器忙碌时延迟执行的本地换率仅适用于本地后端，不能覆盖在线采样率。

连接或 `task_started`（任务已启动）确认前发生临时网络故障，或 MiniMax 返回可重试的 `408`、`425`、`429`、`5xx` 状态码时，客户端会丢弃失效连接并新建连接重试一次。文本提交后不会自动重发，避免网络中断时重复播报；认证、参数等明确拒绝不会重试。只有错误明确指向不支持的音色情绪字段时，才会去掉该可选字段后重新建连。

## 音色编辑与参考音频

本地音色卡片点击“编辑”后，标题中的名称原位切换为输入框；保存成功后收起编辑区。仅修改名称时保留已有样音、音色来源和设计参数，无须重新生成样音。

二代模型支持三种创建方式：纯设计只填写音色设计描述，试音后保存生成的目标样音；混合设计同时填写描述并添加参考音频，试音后保存目标样音并保留克隆源素材；纯音色克隆只添加参考音频，可直接保存原始素材，不要求先试音。创建方式按描述和附件自动判断。名称可以留空，保存时会按方式自动命名为“设计音色”“混合音色”或“克隆音色”。

一代模型只支持纯音色克隆，必须填写参考音频对应的准确转写文本；二代克隆的转写可以留空。设计和混合设计须在当前描述、源素材、转写、试音正文与推理步数下完成试音；这些参数变化后，需重新试音再保存。若保存按钮不可用，编辑区会说明缺少的内容或操作。

第二代模型的音色设计与音频转写并排显示；第一代模型只显示转写。文本域复用项目指令编辑区的紧凑样式，默认高度为 42 像素，可向下拖动放大，超出可见范围的内容在框内滚动。

参考音频在两栏下方独占整行：无附件时显示添加窗口，支持选择文件或拖入文件；有附件时同一区域切换为播放器，提供播放／暂停、可拖动进度条、“开始校对文本”和删除按钮。删除附件后恢复添加窗口，并清空原转写。自动识别的迟到结果继续受人工校对保护。

## 播放期间的用户打断

播放期间，打断候选必须同时满足 FSMN-VAD（流式语音活动检测模型）持续报告语音，以及 AEC（声学回声消除）保护路径确认近端语音。默认至少累计 500 毫秒有效近端语音后才确认打断。中间的静音或非近端语音不计入时长；候选语音结束时会清零。

此门槛由 `BargeInGate.min_speech_ms`（播放打断最短有效人声时长，毫秒）独立控制；普通输入仍使用 `vad.min_speech_ms`（普通输入最短有效语音时长，毫秒），两者互不影响。普通打断和“仅主人打断”均使用 500 毫秒门槛。

启用 `speaker.owner_only_barge_in`（仅主人可打断）时，还必须满足现有的当前候选声纹授权规则。声纹提前确认不能绕过 500 毫秒门槛；达到门槛但主人身份尚未授权时，播放继续，控制器仍等待该候选的有效声纹结果，并沿用既有等待期限、连续主人策略及初始临时授权规则。AEC 保护不可用时，仍按既有策略抑制未保护的播放打断。

该时长只限制正在播放时的打断确认，不改变普通输入、语音端点、声纹推断窗口或识别阈值，也不保证声纹推断必定在 500 毫秒内完成。咳嗽、叹气等声音若持续被近端语音检测器和 FSMN-VAD 判为语音达到门槛，仍可能触发打断；目前不使用 SenseVoice（语音理解模型）事件标签过滤打断候选。

## 锁定文本块的最小长度

`sentence_window`（短句窗口调度）保持当前块和最多一块预取文本，`sentence_prefetch_ms`（预取提前量）默认 3000 毫秒。每次从可改队列取下一块时，按原顺序合并完整文本段，达到 `tts.sentence_min_effective_chars`（锁定文本块最少有效字符，默认 10）后一起提交。中文、字母和数字逐字符计数，标点、空白与符号不计；原文和标点全部保留，恰好 10 个有效字符即满足下限。模型文本生成结束后，不足下限的最后一块正常提交，短回答不等待补字。

未凑齐下限的文本仍留在本地可改队列，只有语音合成成功接受合并块后才推进 `sent_chars`（不可修改前缀字符数）。LLM（大语言模型）可见的 `current_clause`（当前锁定块）和 `prefetched_clause`（下一预取锁定块）按同一提交块投影，各块可能包含多个短句；`revisable_tail`（可改尾巴）从实际提交边界之后开始。尾巴改写后重新入队的文本使用相同的合并规则。首段的 400 毫秒分段兜底只释放分段缓冲，尚未达到有效字符下限时仍等待后续文本或生成结束；其他调度模式继续使用原有规则。

例如“明白，老大。我这边一切正常，运行稳定，随时听你调度。”依次提交为“明白，老大。我这边一切正常，”（11 个有效字符）和“运行稳定，随时听你调度。”（10 个有效字符）。该下限保证每个非结束块的文本长度；实际播放时长仍由语音合成结果决定。

参数必须为正整数，读取后传给在线语音客户端；修改本地配置后重新启动程序生效。正式程序未设置本地覆盖时使用程序包中的默认值 10，已有个人设置继续保留。该能力只控制文本合并与锁定边界，不负责检验模型改写内容是否与已播内容语义重复。

## 模型推理期间的提交边界

有效 LLM（大语言模型）请求在生成上下文前，通过 `SpeechInferenceBoundary`（推理语音边界）关停新的文本提交，并等待正在执行的 `send_text`（发送文本）与 `sent_chars`（已提交字符数）推进一起结算。空心跳和空二等信箱不进入保护期；正常请求、有效系统检查和协议恢复请求均使用同一保护期。

请求准备阶段按“语音服务已经返回的总音频时长减去设备实际播放位置”计算剩余音频，包含尚未进入播放器的服务端音频缓存。达到 3000 毫秒时不追加锁定；不足时，已有可改的旧语音事务可以先补交一个文本块，沿用至少 10 个有效字符的完整段合并规则，结束尾块可以不足 10 字符。已经占满当前块与预取块的两块窗口、用户正在讲话、事务不可改或没有可提交文本时不补块。等待期间已有音频补足缓冲，会撤销额外补块许可。准备等待上限为 2 秒；超时后仍须等待已经开始发送的块结算，才能冻结真实边界。

上下文生成后到本次结果应用完成，所有语音事务都禁止继续提交新文本，已合成音频的接收和播放继续进行。请求结束后解除冻结并恢复常规播放调度，长回答不必等待下一次模型请求才能继续播放。停止、重置、模型失败、取消和异常退出均需释放本次请求独立票据；旧请求的释放不能解锁新请求。已经取出但尚未发送的旧文本块，在修订导致 `epoch`（尾巴版本）变化后被丢弃。

模型通过 revision（尾巴修订）替换本轮事务的完整未提交尾巴，尾巴为空、已有文本全部锁定时也可续写。原播报的模型文本生成与本地原始文本分段入队完成后开放修订，正在发送时关闭窗口。请求快照在准备阶段结束后生成，应用修订时再次确认 `speech_id`（事务标识）、`output_generation`（输出代数）、`sent_chars`（已提交字符数）、`text`（原计划文本）和 `text_revision`（修订版本）一致，失效则拒绝。speak（新播报）仅在输出空闲时创建事务，忙碌请求即使等到播放完成也不补执行；cancel（取消）空文本停止、带文本停止并替换。请求前的补块仅提交旧事务已有文本，不恢复 speak 的追加或替换能力。成功修订通过 `speech.tail_rewritten`（尾巴修订事件）同步完整文本与版本，前端据此更新展示。

实际设备音频播放完成后保留 1 秒续写资格，模型看到 `speech.state=continuation`（播放已结束的续写窗口）和 `continuation_mode=rewrite_tail`（允许尾巴修订）。窗口内取得权限的有效推理保留自己的独立票据，即使结果在截止后返回仍可修订；截止后的新请求不能借用其他在途请求的票据。窗口到期且没有在途权限或待播尾巴后恢复 `empty`（输出空闲），同一用户轮次也可正常创建新播报。取消、打断、轮次或会话失效撤销旧资格。

发送管线仍在时沿用原队列修订；发送管线已经关闭时，新尾巴独立暂存，等待旧音频真实播放并完成结算后，沿用原语音后端、音色快照和推理参数创建后继播放段，只合成新尾巴。该 1 秒是受理窗口，不是固定接播等待；已准备好的内容立即接播，已受理尾巴不会因结算较慢而丢失。旧播放段只记录自身实际听到的文字，后继段另行结算；模型可见的累计文字前沿保留创建该段前的固定已播放前缀，不通过文本重叠猜测删减后继文字。窗口持有的音色与本地模型租约在接播交接或窗口退出时释放；整体替换语音后端继续受切换屏障保护，须等待续写窗口及其在途请求退出。

日志 `speech.inference_frozen`（推理边界已冻结）记录 `request_id`（模型请求标识）、`speech_id`（语音事务标识）、`sent_chars`（冻结时已提交字符数）、`remaining_ms`（准备开始时剩余音频）、`target_ms`（缓冲目标）和 `prefill`（补块结果）。`speech.inference_released`（推理边界已释放）记录该请求释放后是否还有其他保护票据。3 秒缓冲及一个文本块不保证覆盖任意长的模型推理；缓冲耗尽时允许暂停，不能继续提交旧尾巴改变已冻结边界。

## 本地音频参考时钟与异常片段保护

更换设备或采样率时，`AudioPreprocessor.reclock_reverse`（重设回声参考时钟）必须丢弃旧队列与残留帧。每份参考数据携带来源采样率和代次；已经出队的旧代次也不能按新时钟重新解释。AEC（回声消除）仍按麦克风采样率处理参考帧。

本地语音输出设有异常长段预算，超出预算或未完成的音频不能作为成功分段提交。它是传播风险保护，不是通用音质分类器：时长正常的错误音色、点击或短静音仍可能通过，流式检测也无法撤回用户已经听到的片段。任务式试音只有拿到完整结果后才能判废；关闭请求或释放上下文不等于原生任务一定立即停止计算。根因定位仍需要真实异常样本和逐事件边界。

## 只读状态

`GET /api/v1/tts/status` 返回当前生效的 `backend`（`minimax` 或 `voxcpm1`）、`local_model`（本地模型选择）、`loaded_model`（已驻留的本地模型，未驻留时为 `null`）、`models`（两款本地模型各自的可用与已加载状态）、`load_state` 以及当前音色状态；响应不包含任何本机文件路径。响应仍保留 `worker: {"state": "stopped"}`（旧式本地工作进程兼容字段），产品快照中的 `tts_worker`（本地语音工作进程状态）同样固定为已停止：本地合成由 `runtimes/audiocpp`（原生音频推理框架）服务承载，不再创建 Python 侧的本地合成工作进程。历史 CosyVoice（本地语音合成）实现已归档，旧设置的 `cosyvoice` 后端继续归一化为 `minimax`。

`TtsBackendRouter`（语音后端兼容路由）与 `EpisodeSpeechOutput`（语音事务输出）的 `bind/release`（绑定／释放）接口在 `backend: "voxcpm1"` 时启用本地分支并管理本地租约（租约清零后才释放本地客户端）；`minimax` 时继续使用在线客户端。后端与本地模型的运行中切换通过 `PUT /api/v1/product/settings/tts` 执行，成功后事务保存并同步运行配置；本地音色库操作使用 `/api/v1/tts/voices/{model}` 系列接口。

模型分配接口保留 `tts_profile_id`（当前 TTS 语音配置 ID）用于读取和恢复现有配置。请求可以省略该字段以沿用已保存的配置；尝试更换时会被拒绝。

## 本地合成日志

本地后端的每次合成按 `turn=`（轮次）、`speech=`（语音事务）和 `session=`（随机生成的事务内日志标识，不作为原生续接状态）关联，`segment=`（句段编号）在同一会话内递增。`agent.trace kind=TTS_STARTED/TTS_COMPLETED/...` 给出轮次状态机，`controller.turn_latency` 给出该轮的 TTS 时序（`tts_text_to_first_audio_ms`、`tts_checkout_ms`、`speech_end_to_first_pcm_ms` 等）。字段清单、失败事件与开关见[本地 TTS 可观测性](local-tts-observability-20261015.md)。

VoxCPM2 当前正式流式合成固定关闭跨段声学续接：每段保留 `voice_ref`（音色克隆参考音频）及其 `reference_text`（参考音频转写），不提交 `prompt_audio`（续接提示音频）或 `continuation_id`（续接状态标识）。旧配置中的 `acoustic_continuation`（跨段声学续接开关）保留兼容，但本地客户端实际能力为关闭。原因及同文本性能数据见[停用续接提示的性能复核](../testing/local-tts-reference-only-20261017.md)；此前按标点重锚定的测试记录见[句末重锚定方案 B](../testing/local-tts-continuation-reanchor-20261017.md)。
