# 本地模型运行设备

设置页中的“本地模型设备”可以分别配置 Paraformer（流式语音识别）、SenseVoiceSmall（语音识别与分析）、Voice Server FSMN-VAD（语音活动检测）、KWS（关键词唤醒）、SmartTurn（语音结束判断）和 CAM++（当前默认的可选声纹模型）。必需运行资源缺失、损坏、待更新或完整文件摘要检查失败时，程序进入本地组件管理页；启用声纹时，CAM++ 还须通过自身的资源及模型检查。版本和恢复规则见[程序升级与必需组件更新](model-resource-updates.md)。

每个模型可选择：

- **自动**：可用且显存充足时先尝试 NVIDIA CUDA（GPU 计算平台）；模型加载失败或显存不足时回退 CPU（中央处理器）。
- **仅 CPU**：强制在 CPU 上运行。
- **GPU（CUDA）**：请求在 GPU 上运行。启动失败时回到保存设备选择时记录的上次成功设备，并在设置页显示原因。

更改保存到 `.local/data/config/product-settings.json`（设备偏好文件），需要重新启动整个应用后生效。页面资源摘要和组件行使用宿主同一次采样的 `resource_processes`（去重进程资源明细）。流式识别、语音分析、声纹与代理工作进程各自计量；桌面窗口、渲染进程、应用宿主、界面、环境检查和主语音服务合并为 Voice Server（语音服务）。主语音检测、唤醒模型共享语音服务进程；结束判断共享语音分析进程，只注明资源计入位置，避免重复展示占用。

列表分组的原始字节数之和与顶部总量严格一致，显示为 MB（兆字节）／GB（吉字节）后可能有四舍五入差异。常驻内存是进程当前在物理内存中的工作集；提交内存是进程私有提交量，两者不能混作同一种物理占用。未取得有效测量时直接隐藏该指标；合法的零占用保留。模型行的资源包含所属进程及其子进程，不能解读为模型权重独占大小。

## 后端接入与状态读取

设备设置已接入后端：`PUT /api/v1/product/settings/compute`（保存本地模型设备偏好）写入设备选择并返回 `restart_required`（需要重启）；`GET /api/v1/product/compute-status`（读取硬件与运行状态）读取 GPU 能力、工作进程健康状态、实际设备和进程常驻内存。ASR（自动语音识别）、分析、Voice Server（语音服务）及声纹工作进程从同一份产品设置加载设备偏好。

设备偏好保存后，当前存活的模型不会热迁移；必须完整重启应用，所有工作进程才会按新偏好重新加载。重启前，设置中的“保存后的运行偏好”和“当前实际设备”可能不同。以健康状态返回的 `device`（实际运行设备）与 `service`（服务状态）判断是否已切换，不能只看保存的偏好。

本地组件页的刷新会通过 `GET /api/v1/product/compute-status?refresh=true`（重新检测设备环境）重新运行隔离探测。PyTorch（张量框架）执行实际显卡矩阵运算；ONNX Runtime（模型推理运行时）还核对节点执行记录，拒绝静默回退。关键词唤醒检查专用显卡运行库与物理显卡。逐模型再检查所需模型资源和配置；CAM++（当前默认声纹模型）与 SmartTurn（语音结束判断）还通过独立解释器加载实际模型、执行特征推理，并核对显卡卷积或矩阵节点。检查结果随模型文件或能力采样更新失效，单纯提供程序声明或通用矩阵检查不能放行实际模型。独立声纹进程也预加载随包显卡运行库。

未通过时不提供可选显卡项，接口也拒绝保存显卡偏好。组件未就绪或正在刷新环境时，设备选择和保存暂时锁定；保存包含显卡偏好的配置前重新验证环境。历史已保存但现已不可用的显卡偏好显示为禁用项，允许改回自动或中央处理器。

`gpu_dedicated_bytes`（进程专用显存字节）从 Windows（操作系统）GPU Process Memory（显卡进程内存）性能计数器读取，不初始化推理框架；多适配器按进程合并，共享进程与子进程按进程标识、创建时间去重。读取失败保留未知，不能用整张显卡已用量代替应用占用。接口实现依据 [PdhAddEnglishCounterW（加入性能计数器）](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhaddenglishcounterw) 与 [PdhGetFormattedCounterArrayW（读取实例计数数组）](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcounterarrayw)。

CPU（中央处理器）模式的 FSMN-VAD（语音活动检测）可按策略使用已校验的轻量 ONNX（开放神经网络交换格式）模型；GPU（图形处理器）请求继续使用原 PyTorch（深度学习框架）后端，不将量化的 SenseVoice ONNX 候选作为默认模型。每个模型当前可用的运行设备以状态接口逐项结果为准，模型性能和资源测量见[本地模型设备基准](../testing/local-model-compute-benchmark.md)及[内存优化报告](../testing/memory-optimization-20261010.md)。

## GPU 推理后端与环境更新

Voice Server（语音服务）现按中央处理器必需依赖、audio.cpp（语音合成引擎）可选依赖和显卡可选依赖三个卡片管理。显卡卡片使用独立的固定依赖清单，在现用解释器中替换配套张量框架与音频扩展，不增加模型副本或要求第二套解释器。安装、版本门禁和接口字段见[语音服务运行依赖卡片](runtime-dependency-components.md)。

语音运行环境由“本地组件”页中的 Voice Server（语音服务）条目统一管理，更新会覆盖六组运行依赖并在独立目录验证。系统保留已登记且校验通过的 GPU（图形处理器）构建；PyTorch（深度学习框架）、torchaudio（音频扩展）和 ONNX Runtime（模型推理运行时）的版本、文件摘要及加载检查不通过时，更新失败并保留原环境，不以 CPU（中央处理器）依赖覆盖已验证的 GPU 依赖。独立的 `runtimes/python-gpu`（专用显卡环境）也不作为 CPU 运行环境的替换目标。用户可在组件卡片中选择“更新”“导入”或“跳转”到固定来源，不能通过旧版依赖继续启动服务。

完整依赖分组和事务规则见[运行资源管理与内存优化](runtime-resource-management.md)及[统一正式程序与分发安装器](unified-product-installer.md)。更新本身不保证所有模型都能用 GPU；应用对每个模型执行隔离的实际设备检查，未通过时不会保存 GPU 偏好，也不静默将 GPU 请求报告为 GPU 成功。

`CUDA_MODULE_LOADING=LAZY`（CUDA 模块延迟加载策略）属于 CUDA（显卡计算平台）运行库的模块加载行为，不构成独立的模型权重迁移或可叠加的内存收益。实际效果取决于运行库与进程环境；显存计量以状态接口和基准工具提供的逐进程指标为准。

内存管理当前实现和未启用的优化候选见[运行资源管理](runtime-resource-management.md)；逐模型输入、输出和内存对照见[内存优化报告](../testing/memory-optimization-20261010.md)。

SenseVoiceSmall 及其内部 FSMN-VAD（语音活动检测）始终使用同一设备。FunASR（语音识别工具包）通过 device="cuda" 或 device="cpu" 选择运行位置，具体以加载结果和设置页健康状态为准。

正式程序和源码业务共用上述后端组件与 `.local/models/`（当前模型集合）。SmartTurn（语音结束判断）显卡模式还需要同修订的单精度显卡模型；模型变化先在项目临时区构建完整候选，再通过 `ModelsRoot`（模型组件候选参数）与相应环境一起发布。运行库版本、真实显卡验证、程序与模型组件统一切换及分段计时见[流式识别延迟与图形处理器支持](asr-latency-and-cuda.md)。
