# 桌面开发与分发

开发和用户日常运行同一正式程序；分发入口是独立安装器。架构、目录、重装与迁移规则见[统一正式程序与分发安装器](unified-product-installer.md)，成品与验收记录见[当前交付](../releases/current-release.md)。

本地正式入口为 `.local/VoiceTerminal.exe`（正式程序），安装器为 `.local/releases/installer/VoiceTerminalSetup.exe`（分发安装程序）。组件路径读取工作区 `portable.json`（第二版布局配置），均使用系统 WebView2（网页运行引擎）。`.local/VoiceTerminalUIDemo.exe`（前端演示入口）继续使用独立缓存。在项目根目录运行：

```powershell
npm run desktop:start        # 与双击同一正式入口，读取已发布静态本体
npm run dev                  # 显式源码调试，沿用正式环境与用户数据
npm run dev:ui               # 构建演示宿主，只启动界面服务
npm run desktop:build        # 构建到缓存，不换入正式本体
npm run desktop:prepare      # 按内容准备统一程序包，不安装
npm run desktop:publish      # 准备程序包并事务换入本机正式本体
npm run desktop:dist         # 准备程序包并构建独立分发安装器
npm run desktop:deliver      # 本机更新与安装器共用一份程序包
npm run github:release:local # 同包本机更新并公开发行
.\.local\Verify-Package.ps1  # 原生固定本体摘要校验，无后端环境也可执行
```

常规入口会按输入与产物内容复用有效阶段；组合交付使用单一命令，避免重复组包和安装。完整步骤及精确复用参数见[开发、构建与同包交付流程](../development/desktop-pipeline.md)。

### 项目本地 Rust 工具链

桌面原生构建使用项目本地的 Rustup（Rust 工具链管理器）和 Cargo（Rust 包管理与构建工具），位置为 `.local/tools/rust/`。`scripts/build-desktop.ps1`（桌面构建脚本）会直接调用 `.local/tools/rust/cargo/bin/cargo.exe`，并将 `CARGO_HOME`（Cargo 主目录）和 `RUSTUP_HOME`（Rustup 工具链状态目录）指向同一项目目录，因此不要求把 Cargo 永久加入系统 `PATH`（命令搜索路径）。优先使用上方的 `npm run desktop:build`（桌面构建命令），它会配置好这些路径。

在未配置环境的 PowerShell（命令行）中直接运行 `cargo` 可能出现“找不到命令”；只调用项目里的 `cargo.exe`、却未设置项目的 `RUSTUP_HOME`，也可能因读取到用户级空工具链目录而报“未选择默认工具链”。这不代表项目本地工具链缺失。需要手动运行 Cargo 命令时，在项目根目录先为当前 PowerShell 配置项目路径：

```powershell
$env:CARGO_HOME = (Resolve-Path '.local/tools/rust/cargo').Path
$env:RUSTUP_HOME = (Resolve-Path '.local/tools/rust/rustup').Path
$env:Path = (Resolve-Path '.local/tools/rust/cargo/bin').Path + [IO.Path]::PathSeparator + $env:Path
cargo --version
```

这些环境变量只影响当前 PowerShell 进程；不需要修改全局环境变量或重新下载已存在的项目工具链。

发布前退出工作区业务实例。本体发布与安装器重装均保留用户数据、编号、模型、运行环境及其登记。组件维护在正式程序内执行；“应用更新”页面读取官方发行清单，按固定大小与摘要校验安装器后进入同一工作区安装事务。备份白名单和完整环境导出工具见[本地目录与覆盖发布](local-layout.md)。

修改源码后，仅构建缓存不会更新 `.local/app`（日常启动的已发布本体）。完整更新必须把新统一包发布到 `.local`（本机工作区），再用同一包构建分发安装器；最终核对本机 `app/release.json`（本体清单）、`package-info.json`（程序包记录）及 `delivery.json`（安装器交付记录）的构建编号和摘要。当前交付状态以[当前交付](../releases/current-release.md)及这些实际清单为准。

完整语音运行环境、全部模型及代理组件均为业务启动的必需项。旧组件卡片显示“更新、导入、跳转”，复用下载及导入链路；任一缺失、损坏或待更新组件都会阻止整体语音服务启动。组件更新采用候选校验、暂停服务、目录切换及失败恢复，全部当前组件校验通过后才允许继续使用。新安装组件直接使用当前清单，不提供旧模型运行适配。详见[组件更新说明](model-resource-updates.md)。

启动预检只显示当前校验组件，并由全部启用组件共用一条累计进度条。Voice Server（语音服务）按清单核对完整文件集合与大小，不在启动时读取文件内容；它按已盘点文件数推进进度，模型及 DSH（代理执行宿主）按已校验字节推进，仍完整校验 SHA-256（安全散列摘要）。Voice Server 的完整摘要校验仍用于安装、导入和更新。

桌面窗口负责单实例、托盘、加载状态、受管子进程及退出预算。关闭正式产品窗口隐藏到托盘；产品菜单或托盘中的退出操作会停止全部所属组件。演示只启动前端，不能启动语音服务、代理业务或麦克风。真实开发与正式程序共用业务端口和数据，启动前先退出另一个业务实例。

产品托盘右键菜单提供“悬浮窗模式”。启用后主工作台隐藏，透明、无边框、无系统阴影、置顶的浮窗复用 VoiceOrb（语音动效组件），整体缩放为 50%。颜色、跳动、波纹及状态尺寸沿用主页同一组件和样式，运行状态、会话活动标志和五频带音量严格镜像工作台，不根据字幕另行推断动效状态。原 300×282 的主体占位缩为 150×141，另在下方预留 39 像素字幕区，总窗口为 150×180。主界面仍持有唯一语音控制器，向浮窗发布动效及纯语音字幕，间隔至少 34 毫秒。

单击主体切换麦克风静默与录制；静默仅发送 `session.stop`（停止输入），正在播报的助手回复继续播放，再次点击沿用 `session.start`（开始录制）直接交给 ASR（自动语音识别）。为区分双击，单击按系统双击间隔延后确认，最短 500 毫秒；双击仅打开工作台主页，不额外切换录音；按下后移动超过 6 个 CSS（层叠样式表）像素即启动原生拖动，未移动到阈值的松手仍按点击处理。关闭浮窗或托盘“打开工作台”也可恢复主窗口。每次启动默认显示工作台，不保存上次浮窗模式。程序各网页窗口均禁止右键默认菜单，托盘菜单保留。

字幕气泡参考主页配色并独立绘制圆润尾巴：用户尾巴固定于气泡右上端并略向左倾，助手尾巴固定于左上端并略向右倾，均向上指向悬浮主体。尾尖、两侧和连接处使用圆弧过渡，位置不随文本长度或滚动进度向中部移动。气泡整体上移 8 像素以贴近悬浮主体。宽度随文字增长，最大 126 像素，小于窗口总宽度；文字固定一行，超长时隐藏滚动条并水平滚动。识别时居中本次新增或修订片段；播报时按 `speech.progress.playback_caption`（语音进度中的纯文本对齐片段）居中当前词或句，采用设备输出位置估算，不按全文长度比例提前滚动。没有词级对齐时使用句级边界，音频未开始时不推进。结束后保留 2.5 秒自动收起。字幕仅来自语音转写和实际播放队列，不读取运行时聊天列表；截图、图片附件、工具消息、空白及异常字幕同时在前端和原生边界过滤。

浮窗页面使用独立原生权限，只允许读取快照、接收事件、启停语音输入、拖动和切换窗口；正式程序构建闭包只收集主界面、管理页和浮窗入口，不收集演示页。

正式程序通过已构建界面运行；源码开发由受管前端服务提供热更新。网页资源、启动凭据和管理操作绑定本实例；普通浏览器访问服务地址只显示桌面入口说明。服务默认使用回环地址。
