# 在线切换、自动停听与状态提示

程序通过统一的运行操作契约呈现切换状态。右下角复用现有提示样式，卡片宽度随内容自然收缩，圆形转圈与文字居中排列；进行中显示组件名称和当前阶段。组件装卸、核验以及监听恢复完成后，显示“系统已就绪”，停留 300 毫秒后以 160 毫秒淡出。失败提示保留到用户关闭，组件详情继续提供具体错误。普通保存提示、操作提示和错误提示按纵向排列，避免互相覆盖。

## 当前入口梳理

| 操作 | 实际生效边界 | 监听行为与提示 |
| --- | --- | --- |
| Paraformer、emotion2vec、CAM++ 运行设备 | 详情行“保存”只提交该模型编号和目标设备；接口接纳后立即返回，后台串行执行模型子进程退出、目标进程加载、设备与真实推理预热核验、设置持久化；失败回滚旧设备 | 复用运行操作状态卡；暂停新输入，原先未监听则继续未监听，原先已监听则成功后恢复；详见[设备热切换生命周期](compute-device-hot-switch.md) |
| Paraformer（语音识别）双路精修、emotion2vec+ base（情绪背景）、YAMNet（声学事件）开关 | 装卸、预热、实际状态核验、保存后生效；失败恢复原模型 | 自动暂停；操作结束后恢复操作前状态；统一切换提示 |
| TTS（语音合成）本地模型、在线／本地后端、在线模型与音色 | 暂停输入，等待已有回答、合成和播放器输出结束，再加载及预热；失败恢复原后端 | 自动暂停；恢复操作前状态；等待、切换、恢复阶段均显示 |
| 音色生成与试音、在线试听、样音播放 | 覆盖整个后台任务，包括实际播放完成或取消后的音频释放 | 自动暂停；结束后恢复原状态；后台接受请求不代表完成 |
| 声纹注册现场录音、现场测试 | 覆盖麦克风采样、音频评分与设备释放 | 自动暂停；原生录音线程退出后才恢复原状态 |
| 关键词唤醒设置 | 新工作线程成功建立并换绑后生效；已有运行链保留到换入 | 保留原有即时更新方式；显示运行操作状态 |
| 声纹模式与参数、快速／深度推理模式 | 运行配置更新后，按各自下一心跳或后续请求边界生效 | 保持监听；显示切换状态 |
| 热词索引 | 新索引准备、保存和原子换入完成；已开始的语句继续使用原词表 | 保持监听；显示索引切换状态 |
| 会话重置与清除 | 原有归档、衔接和会话结算完成 | 使用原有会话规则，统一显示操作状态 |
| 组件恢复／能力恢复 | 宿主确认真实进程及能力状态 | 宿主提供同一状态契约，显示“重启中”及终态；服务断连不等于恢复完成 |
| TTS 推理步数、本地合成参数、启用本地音色 | 保存配置，下一回答使用新值 | 保留现有保存与生效提示，不额外暂停 |
| 参考文件导入、参考文件转写、已录文件声纹评分 | 文件处理完成 | 保持原有并行能力；文件转写显示任务状态 |
| FSMN-VAD、KWS、SmartTurn 设备偏好；接口密钥、人格资料 | 未开放热切换的设备项重启应用后生效；接口密钥按其服务规则生效；人格资料在新会话载入 | 显示保存及生效时机，不报告为已经完成热切换 |
| 运行期间组件下载、导入、共享环境安装与显卡检测 | 下载、候选完整验证仍使用任务进度；固定目录换入时保留主页面，原生宿主交接并恢复后端 | 复用热切换状态卡，持续到实际启动终态及资源事务收尾；失败留在原页面并可重试，不回到首次启动画面 |
| 首次启动、工作区迁移与程序本体更新 | 各自的启动或跨进程交接生命周期 | 保留首次启动、维护与目标工作区核验，下载完成不等于模型已就绪 |

旧模型分配应用接口当前固定拒绝调用；遗留的 `restartState`（模型服务重启状态）不作为现有在线切换入口。

## 资源维护与页面连续性

同一原生窗口完成首次启动后，模型、代理宿主及共享环境的资源换入不再导航管理页或启动页。需要释放文件占用时仍会停止并重建业务宿主；页面保留当前分区和编辑状态。`runtime_recovery`（原生运行期恢复快照）通过桌面事件发布，并每两秒补查，独立于可能暂时离线的网页宿主。离线时暂停业务连接；入口握手后重新订阅应用状态，模型加载期间继续显示热切换卡。卡片只在实际启动尝试结束并完成资源事务后结束。

网页来源、实例专属 Cookie（网页会话凭据）只在当前原生进程内存及私有控制管道中交接，不进入状态接口或磁盘。新宿主及开发代理必须重新取得原端口的独占监听，失败时保留页面并显示恢复错误，不静默改绑地址。旧请求和旧事件不能覆盖新连接代次。源码开发的 HMR（源码热更新）连接也按本次连续会话恢复，计划内重启不会刷新页面。

首次启动仍检查必要启动条件；受控资源激活仅允许验证本次处于 `swapped`（目录已换入、尚待提交）阶段的事务，不把它误判为遗留安装。程序本体事务、遗留事务、强制修复、解释器及接口配置门禁继续有效。候选在下载或导入阶段已经完整验证，恢复时不重复进入原生首次启动盘点；新宿主仍执行真实组件加载。恢复失败先停止候选宿主再回滚，原来缺少其它模型的降级实例允许分项补齐组件。

## 自动暂停与恢复

占用输入设备的操作共用一个按预约顺序执行的暂停队列。开始时只记录原先是否监听：原来未监听，完成后仍不监听；原来正在监听，全部操作完成后再恢复监听。暂停期间不增加专门的恢复控制入口，主页面和悬浮窗的监听控件暂时禁用。恢复期间仍属于处理中。

连续预约操作共用第一次暂停前的状态，操作之间不主动恢复麦克风。试音及语音模型切换等待已有回答和输出结束，保留现有停止输入边界以及正在进行的回答、播报作用域。取消任务会等待所属合成／录音资源退出，再归还输入；请求取消不能跳过收尾。应用关闭、明确停止或重置边界会撤销旧的自动恢复。原模型恢复失败时保持停止，恢复监听失败会明确报告错误。

音色任务在返回 `202`（已接纳）之前同步预约，防止已接受的试听被后来的模型切换越过。语音设置接口现在等待该次切换完成，成功返回 `pending=false`（本次设置已经生效）；进度通过实时快照持续更新，不再以旧的后台排空任务代表本次切换。

## 通用状态契约

`runtime_operations`（运行操作列表）随语音运行快照和应用宿主快照发布。界面只依赖以下公共字段，不按业务事件名称判断开始或结束。

| 字段 | 中文说明 |
| --- | --- |
| `id` | 操作唯一标识；不同操作、进程实例不会复用 |
| `revision` | 同一操作的递增修订号，用于丢弃迟到状态 |
| `target` | 能力或组件的稳定标识 |
| `label` | 组件或本次操作的中文名称 |
| `state` | `running`（进行中）、`succeeded`（成功）、`failed`（失败）、`cancelled`（取消） |
| `phase` | 阶段编号；现有阶段包括等待、暂停、装卸、核验、回滚、恢复监听和就绪 |
| `detail` | 当前阶段中文说明；新阶段可以直接提供文案，无需修改弹窗组件 |

`input_paused`（操作暂时占用输入）覆盖排队、工作和恢复阶段；`listening_requested`（操作前的监听状态）供界面保持会话布局。它们不生成大模型调度事件、不进入语义历史、不改变声学二等信箱的四秒消费规则。

后续新增音频操作时，使用 `runtime_operation`（运行操作作用域）登记名称、阶段以及是否暂停输入；异步任务在接受时调用 `reserve`（同步预约）。组件恢复由宿主在重试开始与实际终态之间发布相同契约。前端不需要为新模型增加独立的弹窗判断。终态保留有上限，页面重连可恢复进行中的操作，历史成功不会重新弹出。
