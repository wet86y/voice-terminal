# 语音服务运行依赖卡片

Voice Server（语音服务）展开后显示三个运行依赖卡片，沿用组件页的安装计划、下载、导入、来源跳转、进度及取消入口。

| 卡片 | 资源编号 | 安装规则 |
| --- | --- | --- |
| CPU（中央处理器）运行依赖 | `voice-runtime-cpu`（基础运行依赖编号） | 必需；保留 `voice-server`（原语音服务资源编号）入口兼容。一次配置现有六个基础依赖组 |
| audio.cpp（语音合成引擎）运行依赖 | `tts-audiocpp-runtime`（原生语音运行包编号） | 可选；沿用现有固定官方归档和随包补丁，本地 VoxCPM（语音合成模型）共用 |
| GPU（图形处理器）运行依赖 | `voice-runtime-gpu`（可选显卡运行依赖编号） | 可选；按独立清单把现用环境的两个张量依赖替换为显卡构建，仍支持中央处理器推理 |

分类下载中的两个可选依赖默认不勾选。缺少或需要更新它们，不会独立阻塞语音服务的基础依赖门禁。原有 TTS（语音合成）功能条件继续适用：需要一个可用的本地合成后端，或配置好的在线语音接口；选择本地合成时仍需要原生运行包。

## 安装与模型共享

基础安装继续使用 `config/runtime/voice-runtime.lock.json`（基础依赖锁）。可选显卡依赖使用 `config/runtime/voice-gpu.lock.json`（独立显卡依赖锁），仅覆盖 `torch==2.11.0+cu128`（显卡版张量框架）和 `torchaudio==2.11.0+cu128`（配套音频扩展）。官方文件大小、地址和 SHA-256（安全散列摘要）均固定；`scripts/lock-voice-gpu.py`（维护者更新工具）按基础版本查询官方索引，不下载大型安装包。

新安装继续使用 ONNX Runtime（模型推理运行时）和 Sherpa-ONNX（关键词语音推理运行时）的中央处理器依赖。历史已验证的显卡组合保留原有兼容复用规则，不强制移除已有显卡推理库。

两个解释器依赖卡片始终事务替换 `runtimes/python`（现用解释器目录）。候选先在工作区临时目录准备；从已校验环境复用依赖，替换张量框架前按安装文件记录清除候选中的旧包和元数据，避免中央处理器版与显卡版混装。随后检查固定版本、模块加载、实际中央处理器张量计算、动态库来源及完整文件清单。下载、取消或候选检查失败时保留原环境；启用阶段继续使用现有暂停服务、原子交换和回滚事务。

Paraformer（流式识别）、SenseVoice（整句精修）和 CAM++（声纹识别）始终使用原模型目录和权重，不额外下载、复制或转换模型。显卡依赖安装完成不自动更改模型设备偏好。用户刷新设备环境后，按实际检测结果选择显卡运行位置；完整重启应用后生效。没有兼容驱动、显卡架构不受支持或真实推理失败时，不把回退至中央处理器报告为显卡成功。

## 后端接口与字段

`resource_inventory`（桌面资源清单接口）的语音服务条目通过 `runtime_components`（运行依赖子卡片）返回三个卡片；`voice_environment_status`（环境状态接口）通过 `components`（运行依赖卡片）返回同样结构。前端把子卡片纳入统一资源查找与任务刷新，父级进程资源仍只计量一次。

| 接口或字段 | 中文说明 |
| --- | --- |
| `resource_install_plan`、`resource_download`、`resource_import`、`resource_open_source` | 安装计划、下载、导入及打开来源；均支持两个新增卡片编号与原生运行包编号 |
| `voice_environment_plan`、`voice_environment_configure` | 环境计划与配置；`group`（安装分组）支持 `cpu`（基础依赖）、`gpu`（显卡依赖）、`audiocpp`（原生语音依赖）及原有基础分组入口 |
| `required` | 是否参与整体启动门槛；两个可选卡片为否 |
| `parent_resource_id` | 所属语音服务组件编号 |
| `runtime_ready`、`can_start` | 该卡片运行依赖已就绪，不代表所有模型已通过真实显卡推理 |
| `update_available` | 该已安装依赖需要更新；可选卡片的该字段不作为基础依赖门禁 |
| `gpu_profile` | 现用环境登记的显卡构建组合；基础依赖更新据此保留显卡能力 |
| `lock_sha256`、`gpu_lock_sha256` | 基础依赖锁与可选显卡依赖锁的独立摘要 |
| `gpu_environment_probe` | 逐模型真实显卡推理检测；显卡卡片安装后可直接使用现用解释器，无需手动登记第二套环境 |

显卡锁变化会让显卡卡片显示待更新，并使其设备能力失效；基础依赖仍按自己的锁判断。历史独立显卡环境的登记文件可以保留，现用环境完成显卡卡片安装后优先使用现用解释器。

本次真实设备验证及边界见[GPU（图形处理器）运行依赖验证](../testing/voice-gpu-runtime-20261017.md)：相同权重在两种设备上的识别输出一致，声纹向量余弦相似度约为 0.999999；单次耗时不作为稳定性能承诺。
