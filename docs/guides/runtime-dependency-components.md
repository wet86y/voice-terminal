# 语音服务运行依赖卡片

Voice Server（语音服务）的环境状态包含 CPU（中央处理器）基础依赖、GPU（图形处理器）可选依赖和 AnifLive（本地语音引擎）隔离依赖。AnifLive 隔离依赖由本地 TTS 组件使用；产品页将其显示在 AnifLive-TTS 卡片中，组件维护接口仍将其登记为可选运行依赖。

| 卡片 | 资源编号 | 安装规则 |
| --- | --- | --- |
| CPU（中央处理器）运行依赖 | `voice-runtime-cpu`（基础运行依赖编号） | 必需；保留 `voice-server`（原语音服务资源编号）入口兼容。一次配置现有六个基础依赖组 |
| GPU（图形处理器）运行依赖 | `voice-runtime-gpu`（可选显卡运行依赖编号） | 可选；同一解释器中按进程隔离处理器与显卡张量包，只有实际使用显卡的进程选择显卡构建 |

AnifLive 独立运行依赖编号为 `tts-aniflive-runtime`（AnifLive 隔离依赖资源编号），仅由本地 AnifLive 模型使用。它安装在独立的 `runtimes/aniflive-tts`（AnifLive 隔离环境目录），不与共享 Python 解释器依赖混装；运行状态页将它归入本地 TTS 组件卡片。

分类级下载和一键下载只包含必需 CPU（中央处理器）环境，不包含 GPU（图形处理器）与 AnifLive 隔离依赖。CPU 主清单覆盖六组、111 个固定预编译包，产品运行诊断沿用这份完整闭包；开发和模型导出工具使用各自清单。TTS（语音合成）启动门禁以保存的播放目标为准：在线目标需要其接口密钥，本地目标需要指定模型及 AnifLive 隔离运行依赖均就绪，不自动切换其他可用后端。程序更新在组件缺失、待更新或服务未启动时仍可从管理页执行。

## 安装与模型共享

基础安装继续使用 `config/runtime/voice-runtime.lock.json`（基础依赖锁）。可选显卡依赖使用 `config/runtime/voice-gpu.lock.json`（独立显卡依赖锁），仅覆盖 `torch==2.11.0+cu128`（显卡版张量框架）和 `torchaudio==2.11.0+cu128`（配套音频扩展）。官方文件大小、地址和 SHA-256（安全散列摘要）均固定；`scripts/lock-voice-gpu.py`（维护者更新工具）按基础版本查询官方索引，不下载大型安装包。

新安装继续使用 ONNX Runtime（模型推理运行时）和 Sherpa-ONNX（关键词语音推理运行时）的中央处理器依赖。历史已验证的显卡组合保留原有兼容复用规则，不强制移除已有显卡推理库。

两个解释器依赖卡片始终事务替换 `runtimes/python`（现用解释器目录）。候选先在工作区临时目录准备；从已校验环境复用依赖，替换张量框架前按安装文件记录清除候选中的旧包和元数据，避免中央处理器版与显卡版混装。随后检查固定版本、模块加载、实际中央处理器张量计算、动态库来源及完整文件清单。下载、取消或候选检查失败时保留原环境；启用阶段继续使用现有暂停服务、原子交换和回滚事务。

安装显卡构建后，`Lib/cpu-packages`（处理器独立依赖目录）保留基础锁指定的处理器张量框架和音频扩展；历史环境包含显卡版 ONNX Runtime（模型推理库）时，也在该目录配置其处理器构建。默认解释器搜索路径优先选择这个目录，只有显式使用显卡的工作进程在导入前移除该优先路径。解释器、其他依赖和模型继续共享，不复制另一套完整运行环境。已加载的张量后端不能在同一进程内替换；受管识别与分析服务的显卡失败回退通过处理器进程重建完成。

旧共享显卡环境缺少独立处理器包时，基础依赖卡片显示需要更新；配置事务会补齐包并验证来源、版本及处理器计算，完成后恢复就绪。导入显卡环境必须同时包含当前锁定的独立处理器包；缺失时在激活前拒绝导入并保留现用环境，提示先在来源程序更新依赖再重新导出。离线导入不会暗中联网补包，也不会把显卡张量构建当成处理器环境直接启动。

Paraformer（语音识别）、emotion2vec+ base（情绪背景）和 CAM++（声纹识别）的显卡依赖安装沿用各自受管模型目录和权重，不为设备切换另建模型副本。双路精修的离线模型跟随主识别实际设备；YAMNet（声学事件模型）首版固定处理器。显卡依赖安装完成不自动更改模型设备偏好。用户刷新设备环境后，按实际检测结果选择显卡运行位置；完整重启应用后生效。没有兼容驱动、显卡架构不受支持或真实推理失败时，不把回退至中央处理器报告为显卡成功。替换模型、独立开关及资源迁移见[音频增强说明](audio-enhancements.md)。

## 后端接口与字段

`resource_inventory`（桌面资源清单接口）的语音服务条目通过 `runtime_components`（运行依赖子卡片）返回环境依赖记录；`voice_environment_status`（环境状态接口）通过 `components`（运行依赖卡片）返回相同状态。前端把 CPU／GPU 依赖放在语音服务下，并把 AnifLive 隔离依赖归到本地 TTS 卡片；父级进程资源仍只计量一次。

| 接口或字段 | 中文说明 |
| --- | --- |
| `resource_install_plan`、`resource_download`、`resource_import`、`resource_open_source` | 安装计划、下载、导入及打开来源；支持 AnifLive 模型与隔离运行依赖编号 |
| `voice_environment_plan`、`voice_environment_configure` | 基础与显卡运行环境计划及配置；`group`（安装分组）支持 `cpu`（基础依赖）、`gpu`（显卡依赖）及原有基础分组入口 |
| `required` | 是否参与整体启动门槛；GPU 与 AnifLive 隔离依赖为可选项 |
| `parent_resource_id` | 所属语音服务组件编号 |
| `runtime_ready`、`can_start` | 该卡片运行依赖已就绪，不代表所有模型已通过真实显卡推理 |
| `update_available` | 该已安装依赖需要更新；可选卡片的该字段不作为基础依赖门禁 |
| `gpu_profile` | 现用环境登记的显卡构建组合；基础依赖更新据此保留显卡能力 |
| `cpu_overlay_lock_sha256` | 处理器独立依赖与基础锁的校验摘要；旧共享显卡环境缺少该摘要时需要迁移 |
| `tensor_cuda_build` | 健康状态中报告该进程是否已加载显卡张量构建；用于回退时重建纯处理器进程 |
| `lock_sha256`、`gpu_lock_sha256` | 基础依赖锁与可选显卡依赖锁的独立摘要 |
| `gpu_environment_probe` | 逐模型真实显卡推理检测；显卡卡片安装后可直接使用现用解释器，无需手动登记第二套环境 |

显卡锁变化会让显卡卡片显示待更新，并使其设备能力失效；基础依赖仍按自己的锁判断。历史独立显卡环境的登记文件可以保留，现用环境完成显卡卡片安装后优先使用现用解释器。

本次真实设备验证及边界见[GPU（图形处理器）运行依赖验证](../testing/voice-gpu-runtime-20261017.md)：相同权重在两种设备上的识别输出一致，声纹向量余弦相似度约为 0.999999；单次耗时不作为稳定性能承诺。
