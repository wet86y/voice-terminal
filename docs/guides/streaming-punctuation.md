# 实时中文标点接入

流式 Paraformer（语音识别模型）的每个新增文本窗口先经过实时中文标点，再进入界面、声纹准入和文本信箱。该通道默认启用；短文本默认使用 CPU（中央处理器），不新增第三方运行依赖。

## 固定模型接口与适配

本地解释器为 `.local/runtimes/python/python.exe`（便携运行环境），FunASR（语音模型框架）为 1.4.14。固定使用 `.local/models/funasr/punc_ct-transformer_zh-cn-common-vad_realtime-vocab272727`（实时模型目录）的 `config.yaml`（模型配置）、`model.pt`（权重）和 `tokens.json`（词表）。配置必须声明 `CTTransformerStreaming`（流式 CT 标点模型）；旧 `CTTransformer`（离线 CT 标点模型）不会替代它。

适配依据锁定版本的 `funasr/models/ct_transformer_streaming/model.py`（流式标点实现）和 `funasr/auto/auto_model.py`（通用推理封装）。该版本的行为是：

- `generate(input=delta, cache=cache, data_type="text")`（调用增量文本推理）每次都必须显式传入调用方持有的缓存。`delta`（新增文字）不能是累计全文；识别模型与标点模型使用独立实例和独立缓存。
- `cache["pre_text"]`（待保留的前文）由模型更新。返回的 `text`（新增输出）包含新文字，以及可能属于上一块末字的前导标点；直接追加即可，不能再次拼入前文。
- `is_final`（结束标记）在这个实时标点实现中未被读取。空字符串调用可能报空张量错误或空串索引错误，不能用作最终刷新。
- 模型删除每块最后一个输出标点，却在 `punc_array`（预测数组）里保留该预测。单字的数组可能是二维，读取末项前统一展平。

适配层只对非空新增正文调用模型；识别最终块仍先执行 Paraformer（语音识别模型）的音频缓存刷新。随后使用最后一次非空标点预测中的“。”或“？”补齐句末，无明确句末预测时规则补“。”。规则补齐有单独日志和计数，不能当作模型正确识别了陈述句。模型推理已回退的轮次保留原文，不再补模型或规则标点。

## 线程、输出与生命周期

```text
音频小块（通常20毫秒）
  → 识别输入累计到480毫秒窗口
  → Paraformer（流式识别）新增文字
  → CTTransformerStreaming（流式标点）新增文字及跨块标点
  → 累计转写与带音频范围的增量片段
  → 原有识别通信协议
  → UI（用户界面）/声纹准入/TranscriptSegmenter（转写分句器）
  → USER_SEGMENT_UPDATED（用户分句更新事件）及原有信箱调度
  → LLM（大语言模型）推理
```

识别和标点都在现有单线程 `asr-inference`（识别专用执行通道）里串行执行；标点处理每个模型窗口，包括单个通信包里批量到达的多个窗口。事件循环等待原生调用完成，不在界面或采音线程执行标点，也不增加异步结果重排。

`asr.partial`（累计草稿）和 `asr.final`（累计最终文本）的协议保持兼容。`segments[].text_delta`（带音频范围的文字增量）同步使用经过标点的结果，避免声纹过滤路径仍累计无标点原文。最终音频刷新无新增词时，可以增加一个只含句末标点的片段，沿用已有空最终识别片段的音频范围规则。

正文一致性检查会拒绝把累计前文再次作为新增文字返回的异常结果，改用本窗原始识别文字。合法重复词仍然保留，如连续两个“好”不会被猜测性去重。原有累计文本接收和增量片段修订号继续负责接收端的重复事件处理。

缓存按识别子轮次隔离，在最终输出、`turn.finish`（识别轮次清理消息）、连接关闭和推理异常时清除。请求取消仍沿用原生完成屏障：先等待正在执行的识别/标点结束，再释放缓存。工作进程关闭时回收执行通道和标点模型。

## 加载、设备与异常

`model_loader.py`（按需模型加载器）识别 `CTTransformerStreaming`（实时标点模型）、`SANMVadEncoder`（语音边界感知编码器）及其精确配置，沿用固定版本、源码摘要校验和权重内存映射适配。版本、源码或配置不匹配时，按既有加载器策略退回完整注册。

```yaml
asr:
  punctuation_enabled: true # punctuation_enabled（实时标点开关）。
  punctuation_device: cpu # punctuation_device（设备）：cpu（中央处理器）/cuda（图形处理器）/auto（自动）。
```

标点默认选 CPU（中央处理器），不随识别模型的显卡偏好强制改成 CUDA（图形处理器加速）。显式选择 CUDA（图形处理器加速）时，仍通过现有设备候选和真实预热机制验证，失败后尝试 CPU（中央处理器）；自动模式复用现有识别后端的硬件探测与资源门槛。

模型缺失、配置为离线模型或加载/预热失败：识别工作进程继续可用，标点通道报告 `DEGRADED`（原文回退），加载不在每个音频块上反复重试；修复配置/模型后重启工作进程。推理失败：仅当前识别子轮次改走原文，保留此前已经输出的标点前缀，并清空该轮标点缓存；其他轮次继续尝试标点。

识别工作进程的 `health`（健康查询）新增 `punctuation`（标点通道状态）：

| 字段 | 中文说明 |
| --- | --- |
| `model` | 固定实时模型标识 |
| `status` | 启动就绪、原文回退，或关闭 |
| `model_loaded` / `model_warmed` | 权重已加载 / 已完成真实推理预热 |
| `requested_device` / `device` | 请求设备 / 实际设备 |
| `load_error` / `last_error` | 加载或设备回退原因 / 最近一次推理回退原因 |
| `startup_timings_ms` | 依赖导入、模型构造与权重加载、真实预热耗时，单位毫秒 |
| `rule_finalizations` | 无明确模型句末预测时规则补句号的累计次数 |

就绪状态描述模型启动状态；单轮推理回退应结合最近错误及日志查看。每次识别响应的 `latency.punctuation_ms`（本次标点通道处理耗时，毫秒）独立于 `latency.model_ms`（识别模型推理耗时，毫秒），同时包含在原生处理和工作进程服务耗时内。

## 使用与恢复

`asr.punctuation_enabled`（实时标点开关）和 `asr.punctuation_device`（标点运行设备）由当前工作区配置读取。正式资源随模型组件目录管理；缺少模型、配置为离线标点模型或加载／预热失败时，识别工作进程继续运行并将状态设为 `DEGRADED`（原文回退）。修复资源或配置后重启识别工作进程；推理过程中的异常只让当前识别子轮次回退为原文，并清理该轮标点缓存。

健康查询中的 `punctuation`（标点通道状态）字段含义见本页“加载、设备与异常”表。端到端测试和人工验收边界见[测试、启动与现场验收入口](../testing/operations-and-quality.md)。
