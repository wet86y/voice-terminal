# 统一正式程序与分发安装器

开发和用户日常使用同一套正式入口、桌面宿主、业务代码、静态界面、工作区布局与组件管理。当前代码包版本为 `0.9.6`，以 `build`（构建编号）进一步区分产物；公开发行资产暂仍为 0.9.5。当前交付与验收记录见[当前交付](../releases/current-release.md)。

本地组件页的 Voice Server（语音服务）展开后显示 CPU（中央处理器）必需依赖、audio.cpp（语音合成引擎）可选依赖和 GPU（图形处理器）可选依赖三张卡片。显卡卡片复用现有 `runtimes/python`（Python 运行环境）替换 PyTorch（深度学习框架）和 torchaudio（音频扩展），不增加第二套解释器或模型权重。设置和启动前管理器共用“用途分类 → 组件 → 组件详情”三级界面及下载、导入与进度流程。语音基础环境更新校验全部六组必需依赖；已验证的显卡运行库不会被 CPU 依赖覆盖。分类卡片的下载按钮先列出资源状态、计划内容与共享依赖，确认后并行启动适用任务，由资源管理器协调共享环境。在线密钥及账户用量放在 DeepSeek 和 MiniMax 对应组件详情；独立“模型管理”页已移除。全部必需组件安装就绪后隐藏批量导入入口。显卡运行以现用模型工作进程的实际后端能力为准；安装规则见[语音服务运行依赖卡片](runtime-dependency-components.md)，设备配置见[运行环境配置指南](模型运行环境配置指南.md)。

## 运行与构建

| 命令或入口 | 中文说明 |
| --- | --- |
| `.local/VoiceTerminal.exe` | 本地正式入口，双击读取工作区内已发布本体 |
| `npm run desktop:start` | 与双击同一正式入口，不重新构建或加载源码 |
| `npm run dev` | 同一正式入口显式启用源码热更新，传入 `--dev`（调试开关）与 `--source-root`（源码目录） |
| `npm run desktop:publish` | 构建并组装统一程序包，事务替换正式本体，保留用户数据与组件 |
| `npm run desktop:dist` | 先组装正式包，再嵌入独立安装器 |
| `npm run desktop:prepare` | 按输入与产物内容准备产品包，不安装 |
| `npm run desktop:deliver` | 产品包、分发安装器和本机更新统一完成一次 |
| `npm run github:release:local` | 同一发行包更新本机并公开发行，自动回下载核验 |
| `scripts/distribute-desktop.ps1 -SkipProductBuild` | 使用上次本地发布的同一程序包构建安装器 |
| `npm run dev:ui` | 构建并运行隔离的前端演示，不启动业务后端 |
| `VoiceTerminal.exe --exit` | 请求同一工作区已有正式实例正常退出 |
| `VoiceTerminal.exe --verify-package` | 原生逐文件验证固定本体，不要求后端环境 |

正式程序包在 `.local/build/program-package/program.zip`（统一本体归档）；外层 `program-package.json`（固定文件清单）涵盖正式入口、宿主、界面、业务和支持文件。`app/release.json`（本体清单）的 `components`（组件登记）属于工作区状态，重装时保留并重新核验。安装器不内嵌完整后端环境、代理宿主或用户数据；本体换入后由[兼容性组件](../architecture/compatibility-component.md)强制修复配置及受管组件，必要时下载补齐。CAM++（声纹嵌入模型）作为声纹升级种子权重随本体交付。声纹升级规则见[CAM++分发升级](../releases/campplus-distribution-upgrade-20261012.md)。产品和安装器复用原生依赖编译缓存，产物和构建戳按入口职责分别保存。

本地发布使用统一程序包事务更新 `.local`（本地工作区）的应用本体；分发发布把同一程序包嵌入 `.local/releases/installer/VoiceTerminalSetup.exe`（普通分发安装器）。两种更新入口都继续执行强制兼容处理：先修复，确认非法的组件清除后重建，无效配置回退默认，故障注册资料、音色及活动会话按规则归档。全部必需条件通过实际复核后才交接正式程序。下载中断保留新版及修复进度，不回退旧的不兼容组合。缺失可选组件仍非阻塞。当前已交付产物的版本与验收记录见[当前交付](../releases/current-release.md)；上述兼容流程需随新版构建交付后生效。

## 路径与接口

根入口只读取自身目录的 `portable.json`（工作区布局），桌面宿主只从自身 `app`（本体目录）解析上一级工作区。普通启动不查找源码项目、不读写系统工作区定位记录；整体移动工作区后可直接启动。系统定位旧记录与私有网页引擎旧文件保留，但不再使用。

第二版布局固定为 `app`（本体）、`runtimes/python`（语音环境）、`runtimes/dsh`（代理宿主）、`models`（模型）、`data`（用户数据）、`cache`（缓存）、`tmp`（暂存）与 `backups`（备份）。保留现有 `workspace_id`（稳定编号），缺失时补齐。所有正式实例使用系统 WebView2（网页运行引擎）；布局的 `webview2`（私有引擎字段）转为 `null`（不使用私有引擎）。

`desktop_status`（桌面状态接口）的 `role`（入口职责）包括 `product`（正式程序）、`installer`（安装器）、`ui-preview`（演示）。`development`（源码调试标识）只描述显式调试。`workspace_info`（工作区信息接口）统一返回 `root`（工作区根目录）、`data_dir`（用户数据）、`version`（产品版本）及 `can_manage`（管理能力）。管理页和产品页在挂载后调用 `desktop_page_ready`（页面就绪确认），供迁移校验；安装交接只等待首个受控窗口。

交接确认文件的轮询读取允许写入及删除共享，避免 Windows（操作系统）文件句柄阻止正式端原子替换。正式端遇到短暂文件占用时在 3 秒内重试确认写入；持续失败记录到 `cache/logs/startup-handoff-error.json`（窗口交接错误日志）。分发端仍核对一次性凭据、正式进程创建时间和可执行文件路径，确认成功后退出。

同一工作区的普通模式与源码调试模式共享单实例标识；模式冲突提示退出已有实例后重启。运行期间持有本体互斥句柄，防止安装器检查占用后又被产品启动。

## 安装与恢复

### 必需组件与启动门禁

新工作区安装按当前正式程序随包的组件清单准备语音运行环境、模型和 DSH（代理执行宿主），必需组件由分发器完成验证与修复。日常启动只检查必要入口、所选模型的文件及版本元数据、配置和事务状态，不遍历完整运行环境或代理目录，也不计算模型完整 SHA-256（内容摘要）。缺失、待更新或加载失败只阻止依赖它的功能，其他功能继续准备，并引导用户进行完整性维护；解释器缺失或未收尾事务时保留管理界面。组件卡片继续提供“更新”“导入”和“跳转”，不以不匹配版本执行对应推理。

Voice Server（语音服务）必需基础环境的更新计划覆盖以下六组依赖：`voice-core`（语音服务基础依赖）、`torch-cpu`（深度学习框架及处理器语音依赖）、`onnx-cpu`（处理器模型推理运行时）、`sherpa-cpu`（处理器唤醒运行时）、`modelscope-download`（模型下载依赖）和 `onnx-vad`（轻量语音活动检测依赖）。可选 GPU 依赖使用独立锁，只替换 PyTorch 与 torchaudio 两个固定包；基础环境更新会保留已安装的显卡组合。候选环境中旧包先按安装记录清除，再校验版本、文件和实际加载，失败时事务保留旧环境。ONNX Runtime（模型推理运行时）和 Sherpa-ONNX（关键词语音推理运行时）继续使用 CPU 依赖。用户可以从组件卡片更新、导入，或跳转到固定官方来源。

环境或模型更新先在候选位置下载、解包并验证，再通过事务替换旧资源。新资源启用成功后才刷新组件清单；失败时恢复旧目录，并按当前清单重新判断旧资源是否仍可启动。只有旧目录符合当前版本及完整摘要要求时才恢复此前服务；若它仍过期、不完整或损坏，则保持整体服务停止并进入组件管理。更新进行中不允许重复触发；任务沿用既有进度、取消、失败原因及重试交互。完成更新后，正式启动只检查必要入口、配置及事务状态，不重复读取刚验证过的环境、模型及代理完整内容。

共享原有启动页布局、图标动画、进度条和错误按钮。安装器仅开放安装、状态、取消与退出命令，流程为：选择目录、检查权限及空间和占用、暂存展开、校验、事务启用、创建桌面快捷方式、启动正式程序、确认窗口、退出安装器。允许空目录或第二版已有工作区，拒绝无关非空目录。缺少系统网页引擎时先复用原生安装引导。

展开与校验可取消；启用、快捷方式及交接阶段禁止取消。失败启用按 `tmp/update-transaction.json`（本体替换日志）恢复旧程序；中断后下次安装或正式入口启动先恢复。快捷方式或交接失败保留已安装程序，重试继续相应步骤。同一程序包也会重新展开，可以修复损坏本体。重装替换固定本体，并通过同一事务离线安装CAM++（声纹嵌入模型），卸载旧WeSpeaker（旧声纹模型）资源及已确认的旧根/专属注册档案，同步模型总清单与组件登记。既有CAM++档案、工作区编号、其他用户数据、其他模型和环境保留。失败或未提交中断按日志恢复旧本体、模型及旧档案；成功提交后回收旧内容。保留模型文件按组件安装收据重新核验：收据登记内容与磁盘一致时按实际内容重新登记并继续安装，旧模型摘要不符且缺少有效收据确认时，保留整套原模型、原清单与声纹资料，暂缓声纹迁移但允许本体升级；本体清单的 `deferred_migrations`（暂缓迁移记录）保留原因。之后在新版组件管理修复模型，再次运行安装器完成迁移。新程序包或声纹种子自身校验失败仍拒绝启用。

快捷方式直接指向工作区正式入口。只覆盖本程序标记且目标匹配的快捷方式；名称冲突使用工作区名称及编号区分。

工作区切换可启动已有正式工作区；空目标从当前已发布本体初始化，随后按本体的当前组件清单安装必需资源，不复制用户数据或旧工作区的已安装组件。整体迁移由正式入口的辅助模式执行，先停服务、复制和核验受管内容，再等待目标真实管理页或产品页挂载，更新快捷方式后清理原工作区。失败保留原数据及事务记录。旧迁移事务先恢复或结束，再进行布局兼容转换。

退出未完成迁移后，如果目标目录及其事务文件已经不存在，原工作区的 `data/state/workspace-task.json`（迁移来源引用）可能仍停留在准备阶段。启动和重装仅在目标目录明确不存在、原目录身份与工作区编号一致、原程序仍存在、没有关联辅助或目标进程、且没有提交或清理标记时跳过这条失效引用；保留原记录供诊断，不创建旧目标、不自动继续迁移。目标仍存在但事务文件丢失、有效目标事务、已提交事务、身份不匹配、程序缺失、读取权限错误或损坏记录仍按原有恢复门禁处理。

代理宿主使用配置驱动的 npm（包管理器）精确版本安装，Node.js（脚本运行环境）由官方依赖引导检测；pnpm（插件包管理器）在工作区准备并明确传给宿主。运行包的安装锚点与配置档负责依赖解析。旧物理包和官方桌面包继续识别、诊断及导入导出，在当前新目标下必须迁移后启动。只解除已确认目标的旧受管联接，用户配置和物理依赖保留。配置、插件适配与已安装升级规则见 [DSH 包安装与迁移](dsh-npm-distribution.md)。

## 更新边界

“应用更新”页面从官方发行地址读取更新清单，用户启动更新后下载并核对安装器大小及完整摘要，再交给同一正式程序包的本体安装事务。更新清单保持官方直接获取；已有可信摘要的安装器文件可以使用公共加速来源。安装器同时用于首次安装与保留用户数据、模型及运行环境的重装。下载来源与回退规则见[国内镜像与原站回退](download-sources.md)。

自动化测试入口、隔离安装验收步骤和现场用户检查顺序见[测试、启动与现场验收入口](../testing/operations-and-quality.md)。

完整性维护使用 `--repair-config`（当前构建维修入口），与 `--app-update-config`（程序更新入口）分开。分发器成功安装后会把自身保存到 `maintenance/VoiceTerminalSetup.exe`（当前版本校验分发器），并在 `maintenance/installer.json`（版本、构建及文件摘要记录）保存匹配身份；应用更新下载独立暂存于 `tmp/app-update/VoiceTerminalSetup.exe`（更新分发器）。更新安装成功后再将新分发器写入维护目录。校验只启动与本地版本、构建及文件摘要匹配的分发器；维护目录没有可用的当前版本分发器时，关于页才下载固定对应版本，不自动下载最新发行。正常本体完整时维修跳过本体重新展开，再用兼容性组件检查和修复其它受管内容。
