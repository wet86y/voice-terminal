# 屏幕双图输入

> 2026-10-14 已完成统一上下文修订：图片与文本共同组成稳定运行历史。“不重复发送”指不重复追加观察消息，后续模型请求仍在原位置保留图片块；DSH（后台执行宿主）自动接收视觉内容。详见 [图片与文本统一上下文修订](screen-input.md)。

主模型通过 `capture_screen`（按需截屏动作）请求观察当前屏幕；`arguments.request`（执行标记）固定为真。动作与后台唤醒独立，只有整份模型决策通过本地校验后才执行。系统心跳自身不会持续截屏，图片到达也不是新的用户发言。

DSH（后台执行宿主）根代理也提供无参数的 `capture_screen`（按需截屏工具）。当当前任务需要查看前台界面时，插件通过已鉴权的内部接口调用同一个 `ScreenCaptureService`（屏幕捕获服务），把校验后的全局图和局部图保存到 DSH 默认附件库，并作为原生图片块放入当前工具结果。截图归属于 DSH 会话，不新增 Voice（语音）用户发言；调用失败会返回设置关闭、捕获组件不可用、并发捕获或超时等明确错误。该能力受同一“屏幕图像”开关控制，模型仍须支持图片；最终模型路由按实际图片能力校验。收到图片本身不触发再次截图，只有用户要求更新或需要新的时点状态时才再次调用。

## 上下文提交与去重

捕获成功先建立观察消息；首次有效模型请求冻结时，将该消息提交到有序历史并认领待处理结果。网络失败不撤销已提交输入，之后到达的文字或截图排在它后面；尚未冻结的截图可以被新捕获替换，或随会话生命周期取消。相同截图身份在重试与协议恢复中复用原图片包和附件引用；两个不同捕获事件即使像素相同，仍保留为两个观察事件。

共享 `ScreenCaptureService`（屏幕捕获服务）在内存中按 `source`（来源：LLM 语音主模型或 DSH 桌面后台代理）及 `scope`（范围：LLM 会话或 DSH 激活）分别保存未消费图片。捕获成功完成时启动 5 秒 `TTL`（最长有效期），使用单调时钟计时，仅约束未消费图片；消费后立即解除限制。同一来源和范围在图片未消费期间再次调用时复用或保留原图，不执行新的物理捕获，也不重复写入 LLM 截图记录。LLM（语音主模型）请求包含图片并被模型供应方接受时视为已消费，立即解除限制；请求失败时保留原图供重试。DSH（桌面后台代理）在截图响应成功交付内部接口调用方时视为已消费，随即允许下一次截图，不增加消费回执字段。未消费图片超过 5 秒后，下一次明确截图动作可以重新捕获，旧待处理图按现有替换流程处理；捕获失败不建立未消费状态。LLM 与 DSH 的状态互不影响；原生物理捕获仍共用单任务保护，避免捕获重叠。

DSH（代理执行宿主）使用其原生附件库和上传缓存，不与主模型的私有文件映射混用。请求前按最终模型供应方和模型标识检查视觉能力；不支持图片的纯文本路由必须明确拒绝，不能静默丢弃截图。预算超限时保留原材料并报告失败，不能把单独删除图片报告成成功的上下文整理。

## 捕获规则与配置

正式产品界面已移除“屏幕图像”设置页。按需截图和会话中的截图消息仍可使用。服务端 `screen_capture`（屏幕输入配置）及 `PUT /api/v1/product/settings/screen-capture`（保存截图设置接口）仍保留；应用内不再提供修改这些配置的页面。

目标屏幕由系统前台窗口决定；窗口跨屏时选择相交面积最大的显示器。鼠标只参与局部中心选择，不能切换目标屏幕。所有位置及尺寸使用物理像素。

| 当前情况 | 局部中心 |
| --- | --- |
| 光标可见，位置在目标屏幕内 | 鼠标位置 |
| 全屏覆盖，光标隐藏、推测锁定或位置不可用 | 屏幕中心 |
| 普通窗口，光标隐藏或位置不可用 | 客户区与目标屏幕相交区域中心 |
| 鼠标位于另一块屏幕 | 前台窗口相交区域中心 |

独占全屏由系统通知信号辅助判断；全屏覆盖和无边框全屏不等于已确认独占。系统没有通用的游戏准心位置接口，因此中心模式是近似准心位置。隐藏且限制在应用范围内是锁鼠线索，单独的鼠标捕获或限制区域不能证明锁鼠。

捕获使用 DXcam（桌面抓屏库）0.3.0 的 DXGI（桌面复制接口）。后台固定线程单次取得整屏帧，从同一帧裁剪局部区域；边缘补黑，图像发生变化后重试一次，整体超时3秒。接口失效会重建，原生调用未结束前不启动第二个抓取任务。受保护画面可能不可见，不能把纯黑画面本身判为接口错误。

每次按需捕获重新枚举显示器输出，比较抓取前后的完整显示器布局，并核对输出帧尺寸。`center_source`（局部中心来源）的枚举为 `cursor`（鼠标）、`screen_center`（屏幕中心）、`window_center`（客户区相交区域中心）；`crop_rect`（完整裁剪矩形）及 `valid_region`（有效画面区域）均为桌面物理坐标，允许负数。`activation_generation`（捕获作用域代次）用于丢弃生命周期结束后的结果，`elapsed_ms`（捕获与编码毫秒耗时）随尺寸、字节数及摘要记录。

DSH 工具的 `capture`（捕获事实）对象复用屏幕捕获服务字段；图片编码只由插件转成附件，不进入模型可见文本：

| 字段 | 中文说明 |
| --- | --- |
| `capture_id` | 本次捕获的稳定标识 |
| `captured_at` | 捕获时间，Unix 秒时间戳 |
| `monitor_bounds` | 目标显示器的桌面物理边界，顺序为左、上、右、下 |
| `executable` | 前台应用可执行文件名 |
| `center_point` | 局部图中心的桌面物理坐标，顺序为横坐标、纵坐标 |
| `crop_rect` | 局部图在桌面上的完整裁剪矩形，顺序为左、上、右、下 |
| `valid_region` | 局部图中来自真实显示器画面的区域；补黑区域不计入 |
| `center_source` | 局部中心来源：`cursor`（鼠标）、`screen_center`（屏幕中心）或 `window_center`（窗口中心） |
| `fullscreen` | 前台窗口是否覆盖目标显示器 |
| `exclusive` | 系统报告的独占显示信号；未知时为空 |
| `lock_inferred` | 是否依据鼠标隐藏和范围限制推测锁鼠 |
| `cursor_visible` | 捕获时鼠标是否可见 |
| `cursor_in_monitor` | 捕获时鼠标是否位于目标显示器 |
| `capture_detected` | 系统是否检测到其他程序捕获画面 |
| `clip_bounds` | 系统限制的鼠标范围；未知时为空 |
| `notification_state` | 系统通知状态；未知时为空 |
| `elapsed_ms` | 抓屏与编码耗时，单位毫秒 |
| `attachments` | 图片附件列表；`attachment_id`（附件标识）、`role`（全局或局部）、`mime_type`（媒体类型）、`width` / `height`（图片宽高）、`bytes`（字节数）、`sha256`（内容摘要）和 `base64`（图片编码） |

服务端 `screen_capture`（屏幕输入配置）及其保存接口使用以下字段；设置保存格式为第13版，旧版本补默认值。

| 字段 | 中文说明与默认值 |
| --- | --- |
| `enabled` | 按需截屏开关，默认开启 |
| `crop_width` / `crop_height` | 局部宽高，默认960×640，分别允许256–2048物理像素 |
| `global_max_edge` | 全局图最长边，默认1920，允许1280–4096像素；不放大小图 |
| `app_overrides` | 应用中心规则列表 |
| `executable` | 可执行文件名，忽略大小写精确匹配，不接受路径或通配符 |
| `mode` | `auto`（自动）、`cursor`（鼠标中心）、`center`（中心模式）；无效鼠标位置仍回退 |

全局图为 JPEG（有损图像格式），质量85；局部图为 PNG（无损图像格式）。模型与前端使用同一组成品，不额外归档显示器原始分辨率图。

## 心跳、请求与界面

`SCREEN_CAPTURE_READY`（截图完成事件）进入普通待处理事件，不使用4秒二等信箱。每个会话最多一个捕获任务和一个未认领结果；更新替换尚未认领的旧结果。原请求冻结认领后，协议恢复和网络重试复用同一双图包。停止监听、结束激活、关闭开关和重置会话会使在途捕获失效，清理待发送结果；已显示的图片气泡保留。

当前正式支持 DeepSeek（模型服务）`deepseek-flash`（模型）的响应接口。首次请求冻结时将独立 `user`（用户角色）观察消息提交到有序历史，说明文字与两份 `input_image`（图片内容块）一起保留在后续请求的原位置。优先上传并复用 `file_id`（文件标识），上传不可用则固定使用 `Base64 data URL`（内嵌图片地址）。DSH（后台执行宿主）同步上下文时自动取图并生成原生图片引用，模型无需再决定读图。保留的聊天接口也支持对应图片格式。

聊天条目新增 `screen_capture`（屏幕截图类型），以截图标识作为稳定身份，沿用服务端顺序号。气泡显示全局与局部双图、时间及实际状态：待发送、已发送、发送失败；只有模型HTTP（网络请求）接口接受后才标为已发送。缩略图可打开查看器，支持图片切换、适应窗口、实际像素、缩放、平移、复位及键盘关闭。窄屏上下排列。

实时 `conversation.append`（会话追加事件）与初始会话快照使用相同的条目类型支持，均保留 `screen_capture`（屏幕截图类型）。这样实时到达的截图会立即建立图片气泡，并通过 `conversation.image.read`（当前会话取图命令）加载双图；后续发送状态更新原气泡，不需要重载会话。

聊天快照只携带附件描述。客户端通过已有 WebSocket（双向通信）发送 `conversation.image.read`（当前会话取图命令），参数为 `conversation_id`（会话标识）和 `attachment_id`（附件标识）。服务器只允许当前会话，返回 `conversation.image`（图片分块事件）。分块字段：`index`（从零开始的分块序号）、`total`（总块数）、`mime_type`（媒体类型）、`data`（每块最多65536字符的图片编码）；失败返回 `error`（错误说明）。客户端核对长度及摘要，转换为 Blob URL（浏览器内存对象地址）。

断线立即终止未完成取图，连接恢复后重试；已加载图片不随短暂断线撤销。气泡退出显示、重置或卸载时释放对应内存地址。没有归档会话查看接口。

## 编码保存与归档

附件描述包含 `attachment_id`（附件标识）、`role`（`global`全局／`local`局部）、`mime_type`（媒体类型）、`width` / `height`（成品宽高）、`bytes`（解码字节数）和 `sha256`（内容摘要）。`base64`（图片编码）只保存于独立图片记录，不复制进每次状态快照。

当前会话检查点引用持久图片序列；临时文件保存在受管会话目录的 `screen-images`（图片缓存目录），可由编码重新构建。会话结束前检查点可靠保存后可清理真实文件，编码记录保留以支持恢复。

完整 `source.json`（聊天归档）保存图片编码；`voice.md`（可读文本归档）及整理的文字投影只保留说明、附件标识和尺寸。整理请求在接口边界另外解析原图为原生视觉块，最终长期摘要不包含编码，也不自动加载归档图片进入新会话。归档成功并确认完整后清理旧会话临时文件；失败保留材料。DSH 默认附件库按其既有持久规则保存真实文件，本次不限制该库。日志不包含图片编码，令牌估算不对编码运行文本分词。
