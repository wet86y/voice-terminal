# 组件设置与分类管理

组件设置采用“用途分类 → 组件 → 组件详情”三级展开。设置页与启动前的组件管理器共用分类、资源状态和详情内容；启动前不再提供独立的“模型管理”页面。旧版 `models`（模型管理）页面链接会转到组件设置。

## 分类与状态摘要

| 分类卡片 | 包含内容 | 中文说明 |
| --- | --- | --- |
| 语音识别 | Paraformer、FSMN-VAD、SmartTurn、CTTransformerStreaming | 流式与离线双路识别、语音活动检测、语音轮次判断和流式标点补全 |
| 语音合成 | VoxCPM 本地模型、MiniMax 在线 API | 本地语音模型与在线语音服务分开管理 |
| 推理执行 | DeepSeek 在线 API、DSH | 在线推理服务与代理执行宿主 |
| 拓展组件 | KWS、CAM++、热词修订、emotion2vec+ base、YAMNet | 关键词唤醒、声纹、识别结果修订、情绪背景与声学信箱 |
| Voice Server（语音服务） | Voice Server | 本地 Python（后端解释器）与共享语音运行环境 |

分类卡片收起时，标题右侧复用子组件的状态和资源摘要：常驻内存与提交内存显示在同一区域；只有模型报告了大于零的显存占用时，才在该区域附带显存数值。分类值只汇总子组件独占进程或加载增量，避免把同一进程记入多张卡。分类状态会汇总子卡生命周期：有子组件正在启动时显示“启动中”，运行可用时显示“运行中”，阻塞启动的组件故障时显示“错误”；Voice Server（语音服务）的可选依赖不改变基础服务状态。页面总状态只把明确阻塞启动的故障计为“部分组件不可用”：必需资源失败、没有可用替代项的语音合成故障，或标记为启动门禁的能力故障。未配置的可选在线服务、没有受管必需资源的非阻塞条目以及可选依赖故障不阻塞总状态；这类条目仍在对应子卡显示自身状态。下载期间收起态显示分类汇总进度。展开分类后，组件行显示各自的运行状态和资源状态；运行中组件显示有效的内存、提交内存及显存测量。展开某个组件详情可查看版本、资源来源、运行位置及该组件可用的配置。展开和收起按钮都带有文字与箭头。

启动期间，模型健康检查的临时未就绪采样会显示为“启动中”。`startup_complete`（启动流程完成标记）变为 `true` 时，页面立即重新读取模型健康状态，丢弃启动期间发起的迟到采样；“计算”与兼容入口“系统运行”页面保持五秒一次的补查。组件真实启动超过后端配置的工作进程启动时限，仍会按启动超时显示为失败，需查看对应组件日志确认原因。

顶层分类和组件行都将状态及资源摘要放在名称右侧，不在名称下方另占一行。常驻内存、提交内存和有效的显存占用在同一资源区域呈现；没有显存测量或报告为零时隐藏显存，且仅将 CUDA（显卡计算平台）模型的进程测量分配给相应组件。展开后的次级组件摘要使用统一的最小高度，在线额度、运行状态和操作按钮不会使同级卡片高矮不齐。详情仅展示标题和摘要中没有的信息，例如版本、运行位置、进程标识和处理器占用；运行时、内存或显存已经在组件摘要出现时不再重复。已安装版本与目标版本相同时只显示“当前版本”，只有两者不同才并列显示。组件标题已标明资源名称且运行信息可用时，详情不重复显示资源名和“已安装”状态。

进程状态与文件资源状态分别展示：进程异常不代表资源文件损坏，资源已安装也不代表相应进程当前正在运行。尚未启动相关进程或系统尚未提供采样时，不会显示虚构的内存占用数值。音频分析共享进程不作为独立组件卡展示，其可归属的内存用量分配到当前加载的分析模型；显存只按模型进程的有效正值测量展示。

分析模型必须同时匹配当前进程编号与创建时间，才会承接该进程的共享资源。模型状态尚未返回、身份已过期、模型已停用或实际设备信息缺失时，无法归属的余量暂计入现有 Voice Server（语音服务）卡片；状态同步后自动转归对应模型，不增加共享环境卡，也不重复计量。显存只归属明确报告 CUDA（显卡计算平台）的模型，其余已知显存保留在暂计余量中。缺失或无效的指标保持未知；只有常驻内存、提交内存、显存三项余量都明确为零时，才省略该余量记录。

## 安装、导入与进度

所有分类的顶层下载、导入及资源任务进度均只统计必需资源。可选资源缺失、启动或任务失败只在对应子卡片展示，仍可单独下载、导入和重试；可选组件运行后的有效内存指标继续纳入分类汇总。

Paraformer（语音识别模型）的“双路精修”使用独立的 `paraformer-offline`（离线精修模型可选资源）权重，对应 `dual_pass`（双路精修开关）设置。它的安装与开关位于同一增强区域：组件清单中的 `can_start`（模型文件与运行依赖已具备启用条件）通过且无需更新后才显示开关；前端 `ready`（显示开关的就绪状态）必须来自这项系统检查，不能只凭文件存在或安装收据判定。缺失、损坏、待更新或依赖未就绪时显示下载、导入和跳转按钮。安装任务的进度、取消与失败重试留在此区域，完成后重新读取组件检查，不自动修改 `dual_pass`（双路精修开关）的选择。流式模型是必需资源，其原有下载区域独立保留；离线精修是可选资源，不计入分类顶层的必要下载数量。

有缺失或待更新资源时，可下载分类卡片提供“下载组件”和“导入”入口。语音合成分类包含可互相替代的本地与在线后端，因此不提供分类级下载或导入按钮。Voice Server（语音服务）分类的顶层下载和导入操作只统计必需的 CPU（中央处理器）依赖；只缺少可选的 audio.cpp（本地语音合成引擎）或 GPU（图形处理器）依赖时，顶层不显示这些操作，但对应子卡片仍保留各自的下载、导入和跳转入口。展开分类后，每个可安装组件行会显示对应资源的“下载”或“更新”、重试下载、导入及“跳转”操作；安装中的任务显示该资源的进度与取消操作。资源就绪后可展开组件详情，查看状态与配置，不会再显示旧式的分类下载清单按钮。

“组件分类”标题右侧固定提供“一键下载”和“资源导入”。一键下载直接创建原生后台任务，先验证并补齐 CPU（中央处理器）完整环境，再并行处理清单中的必需模型、当前已开启的音频增强资源和 DSH（执行宿主）；不包含本地语音合成模型、audio.cpp（原生语音框架）或显卡依赖。Node.js（脚本运行环境）与 npm（包管理器）沿用分发器现有检测和引导，组件下载按清单中的版本范围复用系统环境，不额外携带私有版本。页面切换不影响任务，已验证有效的内容继续复用；CPU 环境失败时停止后续调度，独立模型失败时其余任务继续，最后汇总失败项。资源齐全后仍保留导入入口。

点击分类下载会先生成安装计划并显示确认界面；确认后会并行启动该计划中适用的下载任务。在线 API（程序接口）、内置能力及没有独立文件的热词修订不会创建下载任务。单个资源也可以从组件行独立下载或重试。所有任务共享四个传输通道，组件替换串行执行。

每个任务仅显示一条进度。分类收起时只汇总同一阶段的数据：仍有传输时显示下载，传输结束后显示校验，两个阶段分别统计字节，不相加或加权。展开分类后隐藏分类汇总条，改为逐个显示资源任务进度。安装、等待文件释放等阶段没有真实可量化数据时显示不定进度。失败后自动恢复会显示轮次，最多三轮，恢复间隔为一秒、三秒；取消和不可恢复错误会停止重试。

展开 Voice Server（语音服务）分类会直接显示三张运行依赖卡片：CPU（中央处理器）基础运行时为必需依赖，覆盖六组、111 个固定预编译包；audio.cpp（本地语音合成引擎）和 GPU（图形处理器）运行时为可选依赖。两款本地 VoxCPM（语音合成模型）运行时共用 audio.cpp，但模型下载只处理自身文件，不预检或安装框架；框架由独立卡片下载，模型和框架均达到当前版本要求后才具备运行条件。框架任务不显示为模型任务。当前 `local-tts`（本地语音合成进程）采样对应整个 `audiocpp_server.exe`（audio.cpp 服务进程），无法拆分运行库与模型；常驻内存、提交内存和显存只显示在实际加载的 VoxCPM 卡，audio.cpp 卡不重复计量。CPU 基础环境卡显示语音主进程余量。显卡依赖安装完成不改变设备偏好。各依赖卡片均可单独下载、导入或跳转，分类级操作只包含必需 CPU 环境。

设备切换选项只用于 Paraformer（语音识别）、emotion2vec+ base（基础版情绪模型）和 CAM++（声纹模型）；离线精修设备跟随主识别，YAMNet（声学事件模型）首版固定处理器。其他模型显示实际运行位置，不提供 CPU／GPU 切换控件。

双路精修、emotion2vec+ base（情绪背景）和 YAMNet（声学事件）使用统一的左右开关组件，分别放在语音识别或拓展组件对应模型卡中。三项设置独立持久化，启动前与运行中共用；切换会暂停监听，完成装卸、预热和核验后恢复原监听意图，失败时回滚设置。双路精修所需离线资源作为可选资源按需管理，不在主流式模型详情中展开独立模型卡；本地 TTS（语音合成）模型仍归入语音合成分类。切换过程使用应用现有的右下角提示卡样式。共享进程内存分配到当前加载的分析模型，不再显示单独的音频分析共享运行环境行。详细行为、可选资源及旧配置迁移见[音频增强说明](audio-enhancements.md)。

资源安装计划中的字段如下：

| 字段 | 中文说明 |
| --- | --- |
| `resource_id` | 固定资源编号，用于选择受信任的资源定义 |
| `model_bytes` | 模型文件允许的最大字节数 |
| `shared_resources` | 该资源依赖的共享资源清单 |
| `optional` | 可选下载项标记 |

这些字段用于说明安装计划，不会取代后端对固定来源、版本和文件摘要的校验。

## 语音合成：VoxCPM 与 MiniMax

展开语音合成分类后显示三张组件卡片：VoxCPM2、VoxCPM1 与 MiniMax 在线 API（程序接口）。启动检查以已保存的播放目标为准：在线目标需要密钥，本地目标需要所选模型和框架均就绪；其他可用后端不会自动替代当前选择。启动前管理页可显式选择并保存播放目标，保存不启动服务。运行中的目标在“语音与音色”页切换；尚未加载到内存但文件和运行条件均就绪的模型仍可选择。

运行中切换及试音会自动暂停监听，结束后恢复操作前状态；右下角共用转圈与阶段提示。组件恢复也通过相同契约显示重启进度。入口和生效边界见[在线切换说明](runtime-switching.md)。

- **VoxCPM2（本地语音合成模型）** 与 **VoxCPM1（本地语音合成模型）**：分别显示已安装、已就绪、待安装或需更新状态。两个模型共用 audio.cpp（原生音频推理程序）；模型文件和共享运行程序全部就绪后，相应模型才标记为已就绪。详情中安装版本、运行信息和处理器占用合并为一行。下载不会自动切换当前播放后端。本地 TTS 正在运行时，整个 `local-tts`（本地语音合成进程）采样归到当前已加载的 VoxCPM 卡；语音合成顶层卡汇总该模型数据。
- **MiniMax 在线 API（语音接口）**：组件摘要使用两行显示服务端识别到的计费类型。Token Plan（令牌订阅套餐）上行标为“用量：5h/周额度”，下行只显示语音使用的 `general`（通用模型）额度并加粗；响应中的 `video`（视频模型）数据不用于语音摘要。接口没有周额度数据时自动改为“五小时限额”，只显示五小时余量。按量计费密钥若公开接口返回余额则显示“余额”和加粗金额，否则提示在控制台查看。详情区用于填写 API Key（接口密钥），输入框宽度收窄并与“保存密钥”按钮对齐；运行位置显示为“在线服务”。在线服务不产生模型下载文件。在线模型 Turbo（低时延模式）／HD（高音质模式）和音色 ID（音色标识）在“设置 → 语音与音色”页修改；保存时服务端校验音色 ID，试音和 MiniMax 音色管理控制台入口也在该页，详见 [TTS 运行说明](tts-runtime.md#minimax-在线模型与音色)。

尚未安装的本地模型可在各自卡片中下载、导入或打开来源页面；缺少 MiniMax 密钥时展开该卡片填写 API Key。语音合成分类卡片本身不要求同时安装两种本地模型。

MiniMax 密钥类型由服务端根据密钥前缀识别：`sk-cp` 开头的密钥按 Token Plan（令牌订阅套餐）处理，查询官方返回的套餐额度；其他密钥按普通按量 API Key 处理。Token Plan 将模型与五小时／周百分比放在第二行，数值加粗；没有周额度字段时只显示实际返回的五小时限额，不补造周额度。不同语音合成方式可并存；任一本地模型或在线 API（程序接口）已就绪时，其余未配置或未就绪的可选卡片不标红，下载操作仍可用。

普通按量计费密钥会自动识别；若接口响应包含账户余额则显示，未返回余额时提示到控制台查询。界面不会把订阅限额误显示为普通余额。MiniMax 官方资料：[Token Plan（令牌订阅套餐）](https://platform.minimaxi.com/subscribe/coding-plan?code=H2y7yU1UUd&source=link)；[付费服务协议](https://platform.minimaxi.io/protocol/paid-agreement)。

## DeepSeek 在线服务与额度

DeepSeek 在线 API（推理接口）的组件摘要分两行显示官方账户余额接口实际返回的余额与非零赠金余额，金额加粗，并提供查询或刷新入口；赠金余额为零时隐藏对应列。展开组件详情后，可填写或更新 API Key；余额摘要保留在组件卡片行内，不展开多余的原始响应字段。

## 密钥与用量查询

DeepSeek 和 MiniMax 的密钥都可以在各自组件详情中配置。密钥写入当前 Windows（操作系统）用户的系统凭据库，设置文件仅保存凭据引用，前端只接收“已配置”状态。留空提交不会清除已有密钥。启动前管理器没有在线服务运行时接口，摘要会提示“启动应用后可查询账户用量”；启动应用后，组件卡片行内可通过本机服务端代理查询支持的用量。

启动前管理器分别显示资源任务、音频增强设置和接口凭据的错误。增强设置读取失败不会遮蔽缺组件、缺密钥或凭据保存失败的说明；凭据保存失败时，对应服务表单保留密钥草稿并显示局部错误。刷新成功会清除已恢复的增强错误，组件和接口配置仍按当前状态决定是否允许启动。

服务端用量接口为 `GET /api/v1/models/credentials/{provider}/usage`（查询固定在线服务账户用量）。`provider`（服务商编号）当前为 `deepseek`（DeepSeek）或 `minimax`（MiniMax）；响应中的 `data`（公开账户统计）不包含密钥。服务端会过滤服务商响应中的敏感字段，并遮蔽响应中回显的密钥文本。MiniMax 响应还包括以下识别字段：

| 字段 | 中文说明 |
| --- | --- |
| `billing_mode` | 计费方式：`token_plan` 表示 Token Plan 订阅套餐，`pay_as_you_go` 表示普通按量计费 |
| `usage_supported` | 当前密钥是否支持通过已接入的公开接口查询额度 |
| `usage_note` | 计费识别与额度查询范围说明 |

网络错误、密钥无效、账号类型不支持查询或服务商没有返回可识别的额度字段时，界面显示说明或错误，不影响资源文件状态。MiniMax Token Plan 的额度字段以服务商本次实际响应为准；未知字段使用带有原字段名的中文说明展示。

## 旧页面入口

“模型管理”单独页面已移除。DeepSeek 和 MiniMax 的密钥编辑与用量摘要均在各自组件中管理；启动前管理器复用相同密钥编辑界面。语音运行环境和本地模型资源仍由用途分类卡片管理。
