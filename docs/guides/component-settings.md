# 组件设置与分类管理

组件设置采用“用途分类 → 组件 → 组件详情”三级展开。设置页与启动前的组件管理器共用分类、资源状态和详情内容；启动前不再提供独立的“模型管理”页面。旧版 `models`（模型管理）页面链接会转到组件设置。

## 分类与状态摘要

| 分类卡片 | 包含内容 | 中文说明 |
| --- | --- | --- |
| 语音识别 | Paraformer、SenseVoiceSmall、SmartTurn、CTTransformerStreaming | 流式语音识别、语音理解、语音轮次判断和流式标点补全 |
| 语音合成 | VoxCPM 本地模型、MiniMax 在线 API | 本地语音模型与在线语音服务分开管理 |
| 推理执行 | DeepSeek 在线 API、DSH | 在线推理服务与代理执行宿主 |
| 拓展组件 | KWS、CAM++、FSMN-VAD、热词修订 | 关键词唤醒、声纹、语音活动检测和识别结果修订 |
| Voice Server（语音服务） | Voice Server | 本地 Python（后端解释器）与共享语音运行环境 |

分类卡片收起时，标题右侧复用子组件的状态和内存展示样式：常驻内存／提交内存显示在同一组，显存独立显示；分类值只汇总子组件独占进程或加载增量，避免把同一进程记入多张卡。分类状态会汇总子卡生命周期：有子组件正在启动时显示“启动中”，运行可用时显示“运行中”，阻塞启动的组件故障时显示“错误”；Voice Server（语音服务）的可选依赖不改变基础服务状态。页面总状态只把明确阻塞启动的故障计为“部分组件不可用”：必需资源失败、没有可用替代项的语音合成故障，或标记为启动门禁的能力故障。未配置的可选在线服务、没有受管必需资源的非阻塞条目以及可选依赖故障不阻塞总状态；这类条目仍在对应子卡显示自身状态。下载期间收起态显示分类汇总进度。展开分类后，组件行显示各自的运行状态和资源状态；运行中组件显示可取得的内存、显存指标。展开某个组件详情可查看版本、资源来源、运行位置及该组件可用的配置。展开和收起按钮都带有文字与箭头。

启动期间，模型健康检查的临时未就绪采样会显示为“启动中”。`startup_complete`（启动流程完成标记）变为 `true` 时，页面立即重新读取模型健康状态，丢弃启动期间发起的迟到采样；“计算”与兼容入口“系统运行”页面保持五秒一次的补查。组件真实启动超过后端配置的工作进程启动时限，仍会按启动超时显示为失败，需查看对应组件日志确认原因。

顶层分类和组件行都将状态及内存指标放在名称右侧，不在名称下方另占一行。展开后的次级组件摘要使用统一的最小高度，在线额度、运行状态和操作按钮不会使同级卡片高矮不齐。详情中的当前安装版本、运行时、运行位置、进程标识、处理器占用和显存合并为一行；已安装版本与目标版本相同时只显示“当前版本”，只有两者不同才并列显示。组件标题已标明资源名称且运行信息可用时，详情不重复显示资源名和“已安装”状态。

进程状态与文件资源状态分别展示：进程异常不代表资源文件损坏，资源已安装也不代表相应进程当前正在运行。尚未启动相关进程或系统尚未提供采样时，不会显示虚构的内存占用数值。

## 安装、导入与进度

有缺失或待更新资源时，可下载分类卡片提供“下载组件”和“导入”入口。语音合成分类包含可互相替代的本地与在线后端，因此不提供分类级下载或导入按钮。Voice Server（语音服务）分类的顶层下载和导入操作只统计必需的 CPU（中央处理器）依赖；只缺少可选的 audio.cpp（本地语音合成引擎）或 GPU（图形处理器）依赖时，顶层不显示这些操作，但对应子卡片仍保留各自的下载、导入和跳转入口。展开分类后，每个可安装组件行会显示对应资源的“下载”或“更新”、重试下载、导入及“跳转”操作；安装中的任务显示该资源的进度与取消操作。资源就绪后可展开组件详情，查看状态与配置，不会再显示旧式的分类下载清单按钮。

点击分类下载会先生成安装计划并显示确认界面；确认后会并行启动该计划中适用的下载任务。已就绪项目会被跳过，在线 API、内置能力及没有独立文件的热词修订不会创建下载任务。共享依赖由资源管理器协调，避免多个本地模型重复安装相同运行程序。单个资源也可以从组件行独立下载或重试。

分类收起时，进度按已跟踪资源的完成字节数汇总展示；展开分类后隐藏分类汇总条，改为逐个显示资源任务进度。已完成、失败和进行中的任务会参与可计算的分类汇总；如果任务没有可用的总字节数，则仍显示阶段和任务状态，不估算百分比。

展开 Voice Server（语音服务）分类会直接显示三张运行依赖卡片：CPU（中央处理器）基础运行时为必需依赖；audio.cpp（本地语音合成引擎）和 GPU（图形处理器）运行时为可选依赖，不阻塞基础语音服务启动。两款本地 VoxCPM（语音合成模型）都依赖 Voice Server 分类内同一份 audio.cpp；下载模型时安装计划会先核对并准备这项共享依赖，模型和依赖都就绪后才标记为可用。当前 `local-tts`（本地语音合成进程）采样对应整个 `audiocpp_server.exe`（audio.cpp 服务进程），无法从现有指标中拆分运行库与模型；本地 TTS（语音合成）运行时，常驻内存、提交内存和显存只显示在实际加载的 VoxCPM 卡，audio.cpp 卡保留依赖状态而不重复显示用量。CPU 基础环境卡显示语音主进程余量。GPU 依赖卡展示安装与就绪状态；GPU 推理的进程内存和显存计在对应模型卡，不复制为 GPU 依赖卡用量。批量计划默认包含必需的 CPU 运行时，可选项目需用户勾选；每张卡片也可单独下载、导入或跳转。只有必需的 CPU 依赖缺失或待更新时，Voice Server 顶层才显示下载和导入入口。

设备切换选项只用于 Paraformer（流式识别）、SenseVoiceSmall（精修模型）和 CAM++（声纹模型）；其他模型显示实际运行位置，不提供 CPU／GPU 切换控件。

资源安装计划中的字段如下：

| 字段 | 中文说明 |
| --- | --- |
| `resource_id` | 固定资源编号，用于选择受信任的资源定义 |
| `model_bytes` | 模型文件允许的最大字节数 |
| `shared_resources` | 该资源依赖的共享资源清单 |
| `optional` | 可选下载项标记 |
| `forcePlan` | 资源文件已存在但共享依赖仍需补齐时，继续生成安装计划 |

这些字段用于说明安装计划，不会取代后端对固定来源、版本和文件摘要的校验。

## 语音合成：VoxCPM 与 MiniMax

展开语音合成分类后显示三张组件卡片，VoxCPM2、VoxCPM1 与 MiniMax 在线 API 中任一可用后端就绪即可满足语音合成配置：

- **VoxCPM2（本地语音合成模型）** 与 **VoxCPM1（本地语音合成模型）**：分别显示已安装、已就绪、待安装或需更新状态。两个模型共用 audio.cpp（原生音频推理程序）；模型文件和共享运行程序全部就绪后，相应模型才标记为已就绪。详情中安装版本、运行信息和处理器占用合并为一行。下载不会自动切换当前播放后端。本地 TTS 正在运行时，整个 `local-tts`（本地语音合成进程）采样归到当前已加载的 VoxCPM 卡；语音合成顶层卡汇总该模型数据。
- **MiniMax 在线 API（语音接口）**：组件摘要使用两行显示服务端识别到的计费类型。Token Plan（令牌订阅套餐）上行标为“用量：5h/周额度”，下行只显示语音使用的 `general`（通用模型）额度并加粗；响应中的 `video`（视频模型）数据不用于语音摘要。接口没有周额度数据时自动改为“五小时限额”，只显示五小时余量。按量计费密钥若公开接口返回余额则显示“余额”和加粗金额，否则提示在控制台查看。详情区用于填写 API Key（接口密钥），输入框宽度收窄并与“保存密钥”按钮对齐；运行位置显示为“在线服务”。在线服务不产生模型下载文件。

尚未安装的本地模型可在各自卡片中下载、导入或打开来源页面；缺少 MiniMax 密钥时展开该卡片填写 API Key。语音合成分类卡片本身不要求同时安装两种本地模型。

MiniMax 密钥类型由服务端根据密钥前缀识别：`sk-cp` 开头的密钥按 Token Plan（令牌订阅套餐）处理，查询官方返回的套餐额度；其他密钥按普通按量 API Key 处理。Token Plan 将模型与五小时／周百分比放在第二行，数值加粗；没有周额度字段时只显示实际返回的五小时限额，不补造周额度。不同语音合成方式可并存；任一本地模型或在线 API（程序接口）已就绪时，其余未配置或未就绪的可选卡片不标红，下载操作仍可用。

普通按量计费密钥会自动识别；若接口响应包含账户余额则显示，未返回余额时提示到控制台查询。界面不会把订阅限额误显示为普通余额。MiniMax 官方资料：[Token Plan（令牌订阅套餐）](https://platform.minimaxi.com/subscribe/coding-plan?code=H2y7yU1UUd&source=link)；[付费服务协议](https://platform.minimaxi.io/protocol/paid-agreement)。

## DeepSeek 在线服务与额度

DeepSeek 在线 API（推理接口）的组件摘要分两行显示官方账户余额接口实际返回的余额与非零赠金余额，金额加粗，并提供查询或刷新入口；赠金余额为零时隐藏对应列。展开组件详情后，可填写或更新 API Key；余额摘要保留在组件卡片行内，不展开多余的原始响应字段。

## 密钥与用量查询

DeepSeek 和 MiniMax 的密钥都可以在各自组件详情中配置。密钥写入当前 Windows（操作系统）用户的系统凭据库，设置文件仅保存凭据引用，前端只接收“已配置”状态。留空提交不会清除已有密钥。启动前管理器没有在线服务运行时接口，摘要会提示“启动应用后可查询账户用量”；启动应用后，组件卡片行内可通过本机服务端代理查询支持的用量。

服务端用量接口为 `GET /api/v1/models/credentials/{provider}/usage`（查询固定在线服务账户用量）。`provider`（服务商编号）当前为 `deepseek`（DeepSeek）或 `minimax`（MiniMax）；响应中的 `data`（公开账户统计）不包含密钥。服务端会过滤服务商响应中的敏感字段，并遮蔽响应中回显的密钥文本。MiniMax 响应还包括以下识别字段：

| 字段 | 中文说明 |
| --- | --- |
| `billing_mode` | 计费方式：`token_plan` 表示 Token Plan 订阅套餐，`pay_as_you_go` 表示普通按量计费 |
| `usage_supported` | 当前密钥是否支持通过已接入的公开接口查询额度 |
| `usage_note` | 计费识别与额度查询范围说明 |

网络错误、密钥无效、账号类型不支持查询或服务商没有返回可识别的额度字段时，界面显示说明或错误，不影响资源文件状态。MiniMax Token Plan 的额度字段以服务商本次实际响应为准；未知字段使用带有原字段名的中文说明展示。

## 旧页面入口

“模型管理”单独页面已移除。DeepSeek 和 MiniMax 的密钥编辑与用量摘要均在各自组件中管理；启动前管理器复用相同密钥编辑界面。语音运行环境和本地模型资源仍由用途分类卡片管理。
