# 流式识别延迟与图形处理器支持

Paraformer（流式识别模型）当前使用官方低延迟分块 `chunk_size=[0,8,4]`（480 毫秒输入窗口、240 毫秒前瞻）；`encoder_chunk_look_back=4`（编码器历史块回看数）与 `decoder_chunk_look_back=1`（解码器历史块回看数）保持不变。累计转写、尾部刷新与设备选择沿用同一识别流程；完整重启识别工作进程后，新的运行配置生效。固定版本及运行环境见[模型运行环境配置指南](模型运行环境配置指南.md)和[本地模型运行设备](local-model-compute.md)。

识别工作进程通过一条专用原生执行通道串行执行模型加载、预热与实际推理。启动时用独立静音缓存预热完整音频窗及空最终刷新；真实计算成功后才报告就绪。显卡预热或加载失败时按当前策略回退至处理器模型并保留原因。原生调用结束后才处理取消和缓存清理。

## 分段耗时字段

| 字段及中文说明 | 含义 |
| --- | --- |
| `sent_at_monotonic_ns`（发送单调时钟） | 本机发送时间，单位为纳秒；只可用于同一机器上的工作进程 |
| `queue_wait_ms`（工作进程排队等待） | 本机发送到工作进程取包的间隔，包含传输、套接字等待和前序音频积压 |
| `lane_wait_ms`（识别通道等待） | 等待共享识别通道锁的时间，单位为毫秒 |
| `executor_wait_ms`（执行线程等待） | 从提交任务到专用原生线程开始执行的时间，单位为毫秒 |
| `native_ms`（原生任务耗时） | 音频转换与模型调用的完整墙钟耗时，单位为毫秒 |
| `model_ms`（模型调用耗时） | `generate`（模型生成入口）的墙钟耗时；包含框架、原生计算和结果回传 |
| `model_calls`（模型窗口调用数） | 本音频包触发的模型窗口次数，包含最终刷新 |
| `worker_service_ms`（工作进程处理耗时） | 工作进程取包至识别返回的完整耗时 |
| `model_warmed`（模型预热状态） | 健康检查中的真实推理预热完成标识 |

`model_ms`（模型调用耗时）是 `native_ms`（原生任务耗时）的子集，不能相加解释。非最终包需要凑齐模型窗口才触发推理，因此零调用的音频包没有模型耗时。`asr.worker.window`（模型窗口日志）记录每次真实调用；`asr.worker.latency`（分段耗时日志）和识别结果回传分段数据。跨主机连接不传递另一台机器的单调时钟。

## 便携程序的加速环境

CPU（中央处理器）版 PyTorch（张量推理框架）不能只通过保存设备偏好切换成 CUDA（图形处理器计算平台）。正式程序必须包含匹配的 CUDA 运行依赖和当前资源清单中的显卡模型。构建与安装规则按[本地模型运行设备](local-model-compute.md)及[程序升级与必需组件更新](model-resource-updates.md)执行。

当前固定运行组合区分：`cu128`（CUDA 12.8 加速依赖组合）使用 `onnxruntime-gpu==1.24.4`（显卡模型推理运行时）；处理器组合使用 `onnxruntime==1.24.3`（处理器模型推理运行时）。两个发行包共用导入模块，运行环境锁定中只安装其中一个；依赖校验可接受显卡发行包满足对应模块要求，但拒绝两种发行包重叠安装。

Paraformer（流式识别）、SenseVoice（整句精修）、PyTorch 版 FSMN-VAD（语音活动检测）与 SmartTurn（语音结束判断）可使用已验证的显卡组件；声纹的实际后端由模型健康状态确认。Sherpa-ONNX（关键词语音推理运行时）继续使用处理器组合。用户选择 `GPU`（图形处理器）或自动模式后，必须完整重启相关工作进程，并核对 `device`（实际设备）、`load_error`（加载或回退原因）及 `model_warmed`（真实推理预热状态）。保存偏好不会热迁移已驻留模型。

## 语音结束判断

SmartTurn（语音结束判断）显卡模式加载 `smart-turn-v3.2-gpu.onnx`（单精度显卡模型）；处理器模式及回退加载 `smart-turn-v3.2-cpu.onnx`（量化处理器模型）。固定模型修订、采样和设备匹配规则见[本地模型运行设备](local-model-compute.md)。缺少显卡运行库、显卡权重或提供程序初始化失败时，重载处理器模型并保留错误；不在每次推理时静默重建另一设备会话。

CPU（中央处理器）推理使用两个内部线程，显卡会话使用一个内部线程；关闭空闲自旋以减少与其他语音模型的处理器竞争。音频归一化、Whisper（音频特征提取）预处理、最后八秒窗口及左侧静音填充保持原逻辑。八秒模型输入包含补齐的静音，不表示必须等满八秒才判断。控制器的 `smart_timeout_ms`（判断超时，毫秒）、`threshold`（结束概率阈值）与 `hard_silence_ms`（连续静音封口兜底，毫秒）由现有语音配置控制；`hard_silence_ms` 默认 1400ms，只决定识别输入何时封口。

待播 TTS（语音合成）队列使用单独的 `tts_hold_fallback_ms`（SmartTurn 未判定结束时待播队列的兜底释放时限，毫秒，默认 2000）。VAD（语音活动检测）的 `speech_ended`（语音结束事件）启动该计时；SmartTurn 判定结束会立即放行队列，未结束、分析失败、超时或未启用时则保持队列至兜底时限。计时期间用户重新开口会取消本轮计时，下一次静默重新计时。该设置只控制待播 TTS 的放行，不改变识别封口时限；放行事件的 `reason`（原因）记录为 `smart_turn`（SmartTurn 判定结束）或 `vad_silence_timeout`（VAD 静默计时到期）。

专项回放基准与现场验收范围见[测试、启动与现场验收入口](../testing/operations-and-quality.md#专项性能基准)。单模型回放不替代整套应用并发、麦克风采集、实时打断及真实设备验收。
