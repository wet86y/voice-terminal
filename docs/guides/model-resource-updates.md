# 程序升级与必需组件更新

程序本体与本地模型分别交付。安装新版程序更新界面、业务代码及随包资源清单，保留工作区模型、运行环境和用户设置。已安装组件的版本或文件内容与当前清单不同时，组件卡片显示“更新、导入、跳转”。`required`（是否必需）用于组件维护及首次安装计划。普通启动只检查必要入口与所选资源，单个模型的问题不阻塞其它功能；缺少解释器、未完成事务或强制修复仍保留管理界面。实际启用的模型由对应工作进程报告格式和设备错误，下载、导入、更新及显式完整性维护保留完整内容校验。

## 组件详情与更新任务

组件卡片显示待更新状态，详情展示当前版本及目标版本；展开详情会刷新资源状态。历史安装没有记录模型版本时，版本保持未知，不把当前目标版本当作已经安装的版本，也不提供旧版推理适配。启动前管理器与运行中的组件页共用更新、导入及来源跳转入口，更新复用原有下载链路，缺失组件使用“下载”入口。用途分类与批量下载清单的交互见[组件设置与分类下载](component-settings.md)。

更新使用随包清单中的固定来源、文件大小及 SHA-256（安全散列摘要）。任务先在工作区暂存目录准备候选内容，已经安装且摘要匹配的文件可以复用，新增或变化的内容才需要重新获取。取消或校验失败会保留旧目录供恢复和重试；旧组件不满足当前版本要求时，对应能力保持不可用，整体启动继续沿用必要组件门禁。

DSH（代理执行宿主）的清单还锁定官方桌面安装器摘要和组件来源。管理器只有在已安装元数据声明 `source_kind: official_desktop`（官方桌面来源），且版本与安装器 SHA-512（安全散列摘要）都匹配时才显示为最新；所以同版本的旧物理运行包也可能显示待更新。此状态表示当前发行策略要求迁移到官方桌面运行包，不单独证明旧文件损坏。后端保留了符合版本、提交及桥接协议的物理运行包兼容分支，但原生启动门槛仍按组件管理器结果拦截整体服务。若改变为允许旧包启动，必须同步调整这项启动门槛并验证旧、新运行方式；不能只把界面状态改为“最新”。

模型文件选择结合用户的运行设备。SmartTurn（语音结束判断）明确选择显卡，或自动选择且存在兼容显卡环境时，显卡权重属于该安装的必需文件；缺失时要求更新并补齐。已经安装且仍属于当前清单的可选权重随更新保留并校验，避免替换目录后丢失原有显卡能力。纯处理器的新安装可以省略尚未安装的显卡权重。

进入切换阶段后任务不可取消。桌面宿主暂停原本运行的服务，释放模型文件占用，交换新旧目录并刷新资源登记。候选校验通过后提交当前组件；其他组件仍需安装或更新时，整体服务保持停止。全部必需组件就绪后才恢复此前运行的服务，最后一次切换保留备份至服务恢复检查通过。恢复失败则回滚模型和资源登记，并再次按全部组件的当前版本要求判断启动资格。原本没有运行服务的管理页不会因组件安装完成自动启动后台服务。

模型文件的完整性校验和服务入口就绪是不同检查。服务入口就绪不等同于所有模型都完成实际音频推理；真实模型的流式输出及内存占用另由推理验收覆盖。

## 模型版本登记

下载、导入及更新任务提交组件后，页面立即刷新最新清单；活动任务每两秒、空闲每十秒仅补查任务快照，迟到任务事件不会覆盖最新状态。组件状态在挂载、维护提交及手动刷新时读取，不随轮询或窗口焦点反复扫描。首次安装就绪后点击“启动程序”立即显示统一启动动画，宿主重新解析组件路径并做必要入口检查；模型和代理的完整内容摘要统一由安装或显式完整性维护执行，普通启动不重复扫描，也不按七天期限自动全扫。共享依赖只在同一宿主中且本次验证记录仍有效时复用。原流程见[下载与首次启动修复](../testing/download-startup-flow-20261010.md)，最新缓存与显卡兼容边界见[启动与显卡环境排查](local-model-compute.md)。

每个新安装的模型目录包含 `resource-install.json`（模型安装收据）。收据记录安装时的版本及文件摘要，根模型清单继续供工作区完整性检查使用。旧安装没有收据时，读取 `models/manifest.json`（模型根清单）中的对应记录识别待更新状态；启动与更新校验始终以当前随包清单为准，文件损坏仍报告不完整。分发器不安装或重装组件；普通更新保留现用组件并显示问题，随包离线兼容迁移由本体组件任务执行。主动强制完整性校验确认非法或损坏的受管组件时，先持久化交接，再清除故障内容，由本体组件任务重新下载修复。同长度内容损坏的校验结论持续保留，直到对应组件经过完整验证并成功启用或确认可复用后清除。

| 字段 | 中文说明 |
| --- | --- |
| `update_available` | 已安装模型、代理组件或语音运行依赖是否需要更新；启动阻塞继续按必要组件及所选功能判断，可选增强不阻塞无关能力 |
| `installed_version` | 已安装模型或代理组件版本；旧安装未登记时为空 |
| `version` | 模型与代理行表示随包目标版本，语音服务行保留解释器版本含义 |
| `resource_id` | 模型资源稳定编号 |
| `content_sha256` | 收据内排序文件记录的内容摘要，不包括版本号或收据自身 |
| `files` | 已安装必需文件及实际存在的可选文件 |
| `path`、`size`、`sha256`、`optional` | 模型内相对路径、字节数、文件摘要和可选标记 |

同版本号的必需文件变化也会触发更新。当前清单的必需文件必须全部安装并校验；曾安装的文件被新版清单移除时，会在更新事务中清理。整个旧目录在成功切换后删除，避免遗留已不再使用的权重或文件。普通启动按所选资源检查必要文件、版本元数据与路径安全，不遍历运行环境/代理目录，不读取模型完整摘要；静态内容问题由显式完整性维护检出，实际模型格式及设备错误仍由加载器报告。语音环境、模型与代理的安装、导入及更新继续核验完整摘要。

启动发现所选组件缺失、待更新或运行依赖未就绪时，在对应功能显示原因并引导到管理或完整性维护入口，其他功能继续启动。解释器缺失和未收尾事务保留管理界面。普通启动不使用“七天后重新全量检查”的规则，也不在界面就绪后自动补做全量扫描；运行环境和资源在安装、导入或更新的写入边界仍验证完整内容。

关于页“检查更新”获取最新发行；“校验完整性”仅运行本地版本及构建匹配的长期分发器。缺失时先显示“下载校验程序”，下载完成后再次点击才进入完整校验与修复。分发器将现有大组件合并为一轮有界并行读取，把问题写入 `data/state/component-maintenance.json`（组件校验交接记录）；正式程序管理页挂载后通过原有组件任务修复，下载和候选启用仍完成各自验证。普通更新不自动下载模型，未安装的可选组件不进入自动修复；双路精修等增强模型不可用或待更新时关闭对应开关，由用户在组件列表更新后重新启用。
