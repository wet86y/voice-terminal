# 国内镜像与原站回退

桌面组件管理器对 GitHub（代码托管平台）文件默认比较加速节点与原站，优先使用当前网络下较快的来源；其他资源先按清单尝试已登记的镜像或代理，再回退原站。加速节点不一定托管在中国境内。资源的原始地址、版本、文件大小与 SHA-256（文件摘要）仍来自原有模型清单和运行依赖锁；切换传输渠道不会改变组件身份，也不会仅因镜像配置变化要求重新安装。

统一策略保存在 `config/download-sources.json`（下载来源配置）。Python（后端语言）、JavaScript（脚本语言）和 PowerShell（构建脚本）读取该配置；Rust（原生语言）在构建时嵌入同一份配置。调整策略后需要重新构建并发布完整程序，不能只替换已发布程序中的配置文件。

| 资源 | 首选来源 | 备用来源 |
| --- | --- | --- |
| Python（后端解释器）嵌入包 | 华为云镜像 | 官方发行文件 |

emotion2vec+ base（基础版情绪模型）在魔搭副本中，`model.pt`（模型权重）、`config.yaml`（模型配置）和 `configuration.json`（模型元数据）与固定资源清单一致。副本的 `tokens.txt`（标签表）只比上游多一个末尾换行；FunASR（语音模型框架）的标签读取会去除每行末尾空白，因此推理标签相同。资源清单为魔搭的这一种已知字节版本固定了大小和 SHA-256（文件摘要），仅匹配魔搭来源时接收；校验后会移除这一个末尾换行并再次核对上游文件摘要。其他内容仍需匹配固定文件摘要；镜像版本校验或规范化不通过时会回退到固定 Hugging Face 原仓库。

`hf-mirror.net`（社区加速代理）不是 Hugging Face 官方服务，也不保证文件由中国境内节点托管；它可能通过全球边缘 CDN（内容分发网络）转发。这里只把它作为 YAMNet（声学事件模型）的可替换传输入口，固定文件摘要仍来自资源清单，下载内容必须通过完整校验才会启用。emotion2vec+ base 和 YAMNet 在资源清单中均为 `required: false`（非必需组件），也不会自动进入必需或初次下载批次；用户可在组件管理中单独下载，缺失、下载失败或待更新不会阻断基础语音服务。

安装计划显示来源域名，进度显示当前下载源及切换原因。桌面普通下载对单次连接和无数据等待分别设置 12 秒与 20 秒上限；下述上游加速路径沿用其 5 秒探测/连接、20 秒无数据等待参数。不设置整个大文件的总下载时限。来源失败后按顺序尝试备用地址；用户取消立即停止，不继续切换。

桌面断点身份由预期大小与摘要组成，同一内容可跨来源续传。摘要校验失败会移除无效暂存文件；候选内容通过完整校验后才进入既有事务安装。Python（后端语言）的维护工具逐来源重新下载暂存文件并校验，以避免混合未校验片段。已有组件、模型收据及两个运行依赖锁的内容身份保持不变。

## GitHub（代码托管平台）节点管理与四路加速

应用更新安装器、唤醒资源归档、原生语音归档，以及原始来源为 GitHub 或其原始文件域名的其他原生文件下载，共用 DesktopUpdateKit（桌面下载组件）节点入口。配置位于 `github_download`（统一节点配置），默认启用节点与自动择优，界面不显示开关。节点模板、优先级、启用状态、强制原站回退和上次成功节点排序复用锁定上游实现。原生版没有内置镜像列表，宿主显式提供当前配置的三个加速站和原站。

每次新下载对启用来源做有限探测和下载采样，每节点默认最多两秒、最多 1 MiB（1 兆二进制字节）测速样本，另有上游 64 KiB（64 千二进制字节）范围及网页校验探测。探测和采样合用同一总时限。按本次采样速度排序，上次成功缓存不能压过当前结果；连接超时的节点仍保留为后续回退候选。使用 VPN（虚拟专用网络）时，原站实测更快即可优先直连。测速样本只提供短时估算，不能保证整个大文件的持续速率。

新文件传输复用上游单路和四路算法：达到 16 MiB（16 兆二进制字节）且服务器支持范围时使用四个连接，否则单路；四路失败后在同一来源回退单路。该来源传输或摘要校验失败后自动尝试其他节点，成功通过完整摘要后才保存上次成功节点。更新与组件共用缓存，命名互斥保护上游固定临时文件的跨进程写入。

加速资格根据原始地址判断，避免镜像重写后再次套代理。加速文件一次预留四个全局下载通道，其他任务等待，确保整个原生下载器仍最多使用四个通道；测速顺序执行，不额外占用连接。进度显示测速、实际节点、滚动传输速率、四路或单路回退说明。完整缓存直接复用且不测速；已有有效连续断点优先继续原有顺序续传。

通道预留采用保守策略：达到四路大小阈值的文件，在节点测速、完整缓存核验或连续断点续传期间也预留四个通道，其他下载需要等待；小文件及显式只读取少量内容的轻量探测占用一个通道。节点加速配置关闭时仅使用原站，仍可使用原站四路分段。

桥接文件 `integrations/downloader/locked_kit_transfer.inl`（锁定源码传输桥接）和 `locked_kit_nodes.inl`（节点与测速桥接）与上游源码在同一编译单元中构建，直接复用节点校验、排序、缓存、进度计量、探测、并行和单路函数。上游高层更新客户端强制读取独立摘要附件，不能直接替代本项目的通用资源接口；可信清单、SHA-256 / SHA-512（完整文件摘要）、原子缓存启用和断点身份仍由现有公共下载流程承担。自动测速由宿主桥接补充，上游检出及锁定版本未变；升级时需要重新验证内部接口及回退语义。

更新清单继续直连官方来源，不走文件加速。构建准备中的 Git（源码管理工具）克隆、Python（后端语言）维护脚本和脚本包管理器下载属于各自工具链，不使用这条桌面四路入口。

## 包安装与用户配置

代理宿主安装时，实际注册表与头文件地址传入安装工具及其子进程。运行收据中的 `registry_url`（规范注册表）保持原值，`download_source`（实际传输来源）单独记录。公开注册表在网络、缺失版本或损坏归档等来源错误时回退；安装脚本的构建错误不盲目重新安装。

私有注册表不进入公开源回退。持久配置中的作用域注册表、认证及用户插件配置继续由包管理器使用；子进程环境中明确选择了私有注册表时保留该选择。代理启动时只为缺少插件管理配置的工作区追加公开备用源，不重新序列化已有用户补丁。已有显式插件管理配置保持原样。

注册表按环境变量、当前项目 `.npmrc`（包管理器配置文件）、用户配置和全局配置的顺序解析。构建代理宿主时按实际源码目录解析项目配置，避免运行脚本时所在目录遮盖源码自己的私有源。显式的私有 PyPI（Python 包索引）环境配置同样只使用该来源，不自动添加公开备用索引。

| 字段 | 中文说明 |
| --- | --- |
| `origin_prefix`、`mirror_prefix` | 原始地址与镜像地址的前缀映射 |
| `repo_id`、`revision` | 镜像仓库编号及固定提交号，不替换原资源版本 |
| `download_sources` | 安装计划中的来源域名；后端文件传输计划中为候选地址列表 |
| `registry_url` | 安装收据中的规范注册表来源 |
| `download_source` | 安装收据记录的实际传输注册表，不参与版本兼容判断 |
| `tokenizer` | 固定词表的原始地址、随包路径及摘要 |

esbuild（构建工具）优先使用安装的可选平台包，缺失时会先调用继承镜像配置的包管理器；该工具最后仍有硬编码原站兜底。node-pty（终端组件）的本机构建可能下载头文件，使用随安装尝试切换的头文件地址。第三方新增安装脚本仍需随依赖升级复查，不能承诺任意插件的自定义下载都受注册表设置约束。

## 开发安装与离线使用

前端依赖使用 `scripts/install-frontend.ps1`（前端依赖安装入口），支持镜像失败后回退；加 `-Offline`（离线）时只使用本地缓存。直接运行包管理器原生命令仍采用其自身配置。

运行环境构建工具与原生构建脚本已接入同一镜像策略。源码克隆在独立候选目录完成，成功后恢复官方来源记录，再按原规则检查固定提交。离线准备缺少源码、精确版本包管理器、解释器或依赖缓存时明确失败，不为补齐缺失内容改走在线安装。

## 验证边界

更新清单没有独立签名，因此继续直接从官方发行地址获取；只有拿到可信清单中的摘要后，安装器附件才使用公共加速。WebView2（微软网页运行引擎）保留官方在线及离线安装入口。

公共加速入口不等于境内托管，服务可用性会变化。自动回归使用独立临时目录与本机测试服务器，覆盖来源缺失、网页冒充文件、错误摘要、中断、续传、取消及原环境保留；真实镜像抽查只对实际读取的文件报告完整摘要。关闭 VPN（虚拟专用网络）的新设备全量安装需要另行实机验收，不能由本机小文件验证替代。

本轮测试命令、真实文件摘要验证、打包包含性和未完成验收项目见[国内镜像与原站回退验证](../testing/download-sources-20261018.md)。
