# Voice Terminal v0.2 当前主实时链路

v0.2 是建立在 v0.1 稳定基线之上的当前主开发和验收链路，代码已经接入并通过确定性测试和本机 Worker 回放。运行时仍由 `v02.enabled` 控制：`config/default.yaml` 暂时保持关闭，以便在真实设备和自然语音验收完成前保留稳定回滚入口；使用启用 v0.2 的配置时才会创建 `RealtimeController`。

当前已确认：轮次身份隔离、Smart Turn、SenseVoice 结束后精修、连续讲话期间的预测、只读文件工具预取、TTS 播放进度调度、ASR/Analysis 降级和重连恢复。当前未确认：真实麦克风/设备表现、自然语音统计和默认启用后的发布收益。

## 启用方式

```powershell
.\scripts\start.ps1 -Python D:\DevTools\Python312\python.exe -Config config\v0.2.yaml
```

配置开关彼此独立：

| 开关 | 作用 |
| --- | --- |
| `v02.enabled` | 使用 `RealtimeController` |
| `v02.smart_turn` | 使用 Smart Turn 判断结束候选 |
| `v02.sensevoice` | 结束后使用 SenseVoice 精修文本和语音线索 |
| `v02.predictions` | 讲话期间发送预测快照 |
| `v02.tools` | 启用只读文件工具预取和最终复用 |
| `v02.tts_pacing` | 按整轮待播放 PCM 控制后续 TTS 文本发送 |
| `v02.tts_lead_ms` | 允许发送下一段文本的剩余音频窗口，示例为 2000 ms |

Analysis readiness 只检查实际启用的 lane；关闭的 lane 不会阻塞启动。

## 轮次身份模型

- `turn_id`：用户的一次完整语音轮。
- `generation_id`：同一轮中的一次输入封口/回答尝试。续说会递增 generation。
- `input_revision`：当前转录快照的修订号。partial 回改或新增稳定片段会递增 revision。

所有 ASR、Analysis、预测、工具、LLM 和 TTS 结果必须同时满足适用的 turn、generation 和 revision。旧身份的结果可以完成清理，但不能覆盖当前 workspace、当前 UI、当前工具状态、历史或播放器。

## 实时生命周期

```text
LISTENING
  ├─ 稳定转录和预测
  ├─ Smart Turn / hard silence / VAD 结束
  ▼
FINALIZING
  ├─ ASR final 与 SenseVoice 精修并行
  └─ 达到 60 秒上限时封口
  ▼
THINKING → SPEAKING → IDLE
```

播放前续说会撤销旧 generation、关闭旧回答和 TTS 播放门，在同一 `turn_id` 下创建新的 ASR 子段。播放已经开始后续说，或达到 60 秒硬上限后继续讲话，会创建新的 `turn_id`。旧回答、旧 TTS、旧工具任务和旧 PCM 不能进入新轮。

停止、ASR 断连、采集失败和超时会取消相关任务、清空队列、关闭连接或播放器，并回到可恢复的 IDLE/ERROR 状态。预测取消、过期和工具无效返回属于正常控制流程，不应升级成 Voice Server 崩溃。

## Analysis 和最终文本

Smart Turn 使用最近的有界 PCM 判断讲话是否结束。SenseVoiceSmall 在结束后对本轮音频做最终文本、语言、情绪和声音事件精修；它不是独立的“情绪模型”，情绪标签只描述音频线索，不代表心理状态。

精修结果进入最终 LLM user 包：

```json
{
  "final_text": "最终采用的文本",
  "provisional_transcript": "Paraformer 草稿",
  "audio_cues": [],
  "speech_emotion": {
    "status": "READY",
    "source": "SenseVoiceSmall",
    "model_loaded": true,
    "segments": []
  },
  "final": true
}
```

精修失败、不完整或不可用时使用 Paraformer fallback，并将 `speech_emotion.status` 标记为 `UNAVAILABLE`；模型没有结果时不推断情绪。精修预算为 3000 ms，原生分析结束前不会复用同一 Analysis lane。

## 预测和只读工具

预测调度器只保留最新快照，默认间隔 800 ms，单在途。预测可以返回 `LISTEN`、`ACT` 或 `READY`，但这些决策不能结束语音轮，也不会直接进入 TTS 或历史。

工具能力仅限许可目录中的文件名搜索和文本读取：

- 默认许可根为 `docs`；
- 最多搜索 20 项，单文件最多读取 16 KB；
- 并发 2，单任务超时 5 秒；
- 无 shell、无写操作、无外部账号；
- 参数规范化、文件版本和 turn/generation/revision 必须在复用前再次检查；
- 续说或新轮会取消并清理旧 generation 的工具状态和缓存。

最终 LLM 请求不等待旧预测完成；如果预测过期或工具结果失效，最终请求仍按当前完整输入独立执行。

## TTS 播放进度

启用 `tts_pacing` 时，第一段完整文本立即进入当前 MiniMax TTS 任务，后续文本进入有界队列。只有当前轮所有已返回但尚未播放的 PCM 总时长不超过 `tts_lead_ms` 时，才释放下一段文本。

`audio_returned_ms` 是 provider 已返回 PCM 的总时长，`audio_played_ms` 是播放器回调实际消费的时长，`audio_remaining_ms` 是两者之差。它表示整轮已返回但尚未播放的音频，不按单段文本计算。TTS 网络失败可以将状态降级为 `DEGRADED`，但已完成的完整 LLM 文本仍要进入历史；已收到的 PCM 继续按可用时间排空。

## 事件和快照

v0.2 使用 v0.1 的 Envelope、`subscribe`、`session.start`、`session.stop` 和基础事件，并增加：

```text
turn.started
turn.endpoint_candidate
turn.semantic_state
turn.finalizing
turn.resumed
transcript.segment
transcript.refined
speech.emotion
agent.prediction.requested
agent.prediction
agent.prediction.discarded
agent.tool
turn.committed
tts.progress
```

`runtime.snapshot.current` 包含当前 workspace 摘要、服务状态、TTS 进度和 latency。前端先按 seq 去重，再按 turn/generation/revision 过滤。旧客户端可以忽略 v0.2 扩展字段而继续显示 v0.1 主链。

完整字段见 [WebSocket 协议](websocket-protocol.md)。

## 验收边界

当前确定性和本机进程证据覆盖：

- ASR health、partial/final、断连和重新 health；
- Analysis READY/DEGRADED、SenseVoice fallback 和单槽资源；
- 60 秒封口、续说、播放中断和旧身份丢弃；
- 预测过期、工具预取/复用、文件变化和路径限制；
- TTS 部分音频、网络异常、文本降级、播放计数和 pacing；
- WebSocket snapshot、重连、旧消息丢弃和慢订阅者。

尚未完成的验收是自然语音 CER/误结束率、真实耳机/扬声器和默认配置切换判断。完成这些验收前，v0.2 仍是当前主路径，但不替换 v0.1 默认配置。

不在 v0.2 范围内：AEC、自动插话、长期记忆、RAG、shell 工具、文件写操作和外部账号操作。
