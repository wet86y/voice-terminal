# 本地实时语音终端 v0.2

当前阶段：可选实现已接入，阶段 1–3 已完成；阶段 4 已补齐配置化 ASR Worker health、真实 WebSocket 回放、Analysis 降级和长音频分段验证，并在完成检查后暂停。真实自然语音、耳机/扬声器和默认启用仍未开始。执行入口见 [后续实施交接](v0.2-next-steps.md)，证据与未验收范围见 [阶段验证记录](v0.2-validation.md)。

## 目标与基线

持续收听 → 实时理解与只读查询 → 判断结束 → 精修文本与语音线索 → 最终校准 → 流式回答。

v0.1 已包含 Windows Voice Server、Paraformer Worker、DeepSeek、MiniMax、取消和 Vue 控制台。浏览器仍只发送监听命令，不采集音频、不推算指标。

## 实施顺序

1. 文档、轮次 Workspace、采集样本位置、取消与播放门。
2. Analysis Worker：Smart Turn CPU 与 SenseVoice CPU；独立有界执行通道。
3. 稳定转录分段、多轮预测、最终优先调度。
4. 本地只读文件工具、Future 复用、最终回答与 TTS。
5. 协议快照、控制台、确定性测试和真实设备验收。

## 生命周期

`turn_id` 是用户轮次；`input_revision` 是预测快照；`generation_id` 是结束/回答尝试。候选判断使用请求标识及语音版本，静音帧不会使候选失效。预测和工具与 LISTENING 并行，不增加主状态。

播放前续说关闭播放门，撤销当前 generation，保留音频和草稿，另开 ASR 子段并回同轮。以播放器实际回调判断是否已播放；播放后续说中断旧轮并开启新轮。60 秒强制封口。历史只提交完整 user/assistant 交换，预测和撤销的回答不提交。

回答播放采用可选的播放进度调度。第一段完整文本立即进入同一个 MiniMax TTS 任务；后续文本保留在有界队列中。当当前轮所有已返回但尚未播放的 PCM 总时长降到 `tts_lead_ms`（v0.2 示例为 2000 ms）以内时，释放下一段已经以标点结束的文本。首段音频尚未返回时不连续发送所有待定文本，避免快速 LLM 输出造成 `task_continue` 突发。`audio_remaining_ms` 计算的是整个待播放队列，不是单个文本片段。

## 分析与降级

Smart Turn 读取最近 8 秒、16 kHz 单声道音频，使用官方 Whisper 特征预处理。默认候选静音 700 ms、阈值 0.5、复查 400 ms、超时 500 ms、硬静音 1800 ms。

结束后 Paraformer flush 和 SenseVoice 并行。SenseVoiceSmall 同时提供最终文字、语言、情绪和声音事件标签，没有额外独立的情绪模型。SenseVoice 用 FSMN 分段，单段最多 30 秒，短段合并目标 15 秒。保留分段及其原始标签；情绪只是辅助信号，不是心理状态结论。精修预算 3000 ms，失败或不完整整轮回退 Paraformer；有效无语音不触发普通回答。迟到结果不得修改已提交输入。

最终请求的当前 user 消息会保留兼容字段 `audio_cues`，并增加明确的 `speech_emotion` 对象：其中 `status=READY`、`source=SenseVoiceSmall`、`model_loaded=true` 表示精修模型已加载且本轮结果进入 LLM；精修失败时为 `UNAVAILABLE` / `paraformer_fallback`，模型不得据此猜测情绪。情绪信息只在结束后的最终请求出现，不参与讲话期间的预测轮。

## 预测与工具

连续 partial 公共前缀稳定，标点优先，6–20 字切段；回改撤销受影响段。预测间隔 800 ms、单在途、只保留最新快照。LISTEN/ACT/READY 均不能决定结束；预测绝不进入 TTS 和正式历史。最终请求不等待旧预测。预测请求、采用和丢弃原因通过扩展事件记录，工具时间线区分选中、实际执行和完成。

文件工具仅搜索文件名和读取文本，默认根为仓库 docs；真实路径必须在许可根中，不执行 shell。搜索最多 20 项、读取最多 16 KB、并发 2、超时 5 秒、最多 4 次工具交互。按 turn、工具和规范化参数复用；最终重新选中同一调用后才使用结果，读取前验证文件版本。工具输出是数据，不是权限指令。

## 验收与发布

确定性测试覆盖：800 ms 停顿、候选迟到、播放前续说、播放后中断、ASR 回改、最终抢占、精修失败/空文本/长音频、工具复用与路径逃逸、停止及断线、快照恢复，以及返回音频、实际播放和剩余播放时长监控。运行 Python 测试与前端 typecheck/test/build。

真实验收另行记录耳机/扬声器、相同音频 v0.1/v0.2 的 CER、误结束次数、首音 p50/p95、回退率和资源峰值。模拟最终调度 p95 目标 ≤50 ms，不包含云端时间。未真实验证前保留新能力默认关闭，不把测试桩结果当作模型性能。

不包括 AEC、自动插话、长期记忆、RAG、外部账号或写操作。
