# 本地语音、独立音色库与通用提前合成

实施基准为主线 `a424cd7`（含热词替换）。实验来源为 `codex/audio-cpp-evaluation` 的 `d8722e8`；采用功能与经验证的原生资源，逐项接入主线。生产代码与回归代码由主会话修改，辅助代理仅做只读审阅和验证。

## 运行与音色

- 界面在“语音与音色”页选择在线 API（网络语音接口）、VoxCPM1（第一代本地语音模型）、VoxCPM2（第二代本地语音模型）。在线模型、音色、情绪配置沿用模型管理中的设置。
- 设置格式为第 14 版。`backend`（语音后端）的 `voxcpm1` 是历史兼容路由名称，两款本地模型由 `local_model`（本地模型）区分。缺少偏好时推荐二代；默认推理步数为一代 10、二代 20，范围为整数 1–30。
- 数据目录分别使用 `tts/voxcpm1/voices` 和 `tts/voxcpm2/voices`，独立索引、素材、默认项和启用项。`active_voice_by_model`（各模型启用版本）仅作为设置快照投影，实际选择来自各库索引。
- 两个默认项各有独立的 5.68 秒参考素材和准确转写；默认项不可删除。关闭或删除当前自定义项回到默认项。更新已启用项原子创建新版本，后续回答使用新版本。
- 一代仅支持有准确转写的音频克隆。二代支持纯音频、纯设计、混合设计。设计或混合先生成目标样音，正式回答只克隆目标样音；设计描述、源音频、源校对文本和生成正文留作编辑资料。
- 已保存设计候选与源素材、描述、正文及步数绑定；界面修改后立即失效，服务端保存时同时校验样音来源与当前推理步数。正式回答创建时固定音色和步数，重试保留原快照，素材租约持续到整个回答结束。
- 参考音频识别调用当前分析工作进程的 `refine`（精修通道），使用其已加载模型和设备，不创建另一套识别模型，不进入对话历史，不做热词或唤醒词替换。30 秒超时；忙碌和失败保留附件，迟到结果不能覆盖人工校对。
- 试音、设计和样音播放仅允许在停止监听且播报已结算时运行，运行中禁止反向启动监听。保存和启用允许热更新。模型切换等待事务与音色任务，保留最后选择，失败恢复旧目标，主动停止后的监听不会被后台恢复。

模型能力参考 [VoxCPM 官方说明](https://github.com/OpenBMB/VoxCPM#-controllable-voice-cloning)。原生二代混合请求使用源参考音频和描述，源转写是编辑资料；正式请求没有逐段设计前缀。

## 通用提前合成与取消

所有语音后端使用同一播报事务管理器。提前合成为内部调度行为，没有用户开关，也没有后端能力标志选择分支。历史 `local_optimization`（本地优化字段）不能关闭这项调度；声学续接单独管理。

生产许可与播放许可分开。用户讲话、端点等待时可以为已受理的正文生成音频；唤醒提示音、端点和播放器身份检查继续控制声音。标准短句调度保留原有效字数下限、当前块加一个预取块、剩余不超过三秒时预取。缓存预算不放宽文字锁定边界。双向流式传输保留时长窗口，不把服务器断句计数当作客户端文本块完成回执，不逐块结束整代任务。

暂停阻止新正文提交；已锁定音频可结束，尚未起播时同时挂起播放器。恢复继续原事务，端点授权不会解除显式暂停。推理保护旧播报的提交边界，新受理播报按请求票据与独立 `speech_id`（播报标识）取得例外。修订仅改未提交尾巴，提交锁中再次校验许可和 `epoch`（文本代次）。

取消或替换先撤销播放器资格并使事务身份失效，清除适配器缓存、读取器持有块与播放器队列，随后关闭合成请求。取消事件唤醒等待任务，实际播放资格仍由事务身份和播放器代次校验决定。在线缓存沿用 8 MiB（二进制兆字节）内存后落盘、64 MiB 总限额，本地限额为 32 MiB。迟到音频、回执和完成事件不能进入下一事务。

送达历史只累加 `heard_text`（播放器确认听到的文字）；已提交字符和缓存字节属于执行状态。未播放正文被取消时不能进入送达前缀，也不能剥除后续相同正文。边界不确定部分继续保留不确定状态。

原生服务断连后在发送回调边界停止请求，不能把应用取消或本地清缓存理解为立即停止显卡计算。本地会话关闭会请求 `/v1/audio/speech/contexts/release`（执行锁及声学上下文释放接口）；经验证的原生实现先取得模型执行锁再返回 `released: true`（释放确认）。首音频前也执行交接检查。

## 资源与迁移

资源仍位于本机 `.local`（资源目录）；正式程序覆盖更新单独处理。本次正式程序包不内嵌这些权重或用户音色。


`scripts/migrate-local-tts.py`（资源迁移脚本）核对上述原生程序摘要，迁入一代、二代必要目录及运行素材，逐文件核对来源和目标摘要，按主项目路径重新生成运行配置。迁移记录保存在 `.local/config/audiocpp/resource-provenance.json`（资源来源清单）。音色标识映射留在各库迁移记录；重复执行保留已有启用选择和其他用户设置。本次重复执行已通过，两个库未重复创建默认项。CPU（中央处理器）运行包保留为资源，当前适配器启动经验证的 CUDA 运行程序。
