## 启动渠道与数据

`LaunchChannel`（启动渠道）由构建特性决定，独立于 `Debug / Release`（调试／优化级别）。

| 项目 | Development（开发） | Distribution（分发） |
| --- | --- | --- |
| 路径来源 | 明确的项目根目录，或从开发产物向上识别源码仓库 | `%LOCALAPPDATA%\VoiceTerminal\workspace.json`（工作区定位记录） |
| 用户数据 | 项目 `.local/data` | 工作区 `data` |
| 模型、运行环境、缓存及临时文件 | 项目 `.local` 内对应目录 | 工作区对应目录 |
| 首次启动 | 使用项目资源 | 原生文件夹选择、基础组件安装 |
| 关于页目录操作 | 展示固定项目路径 | 链接已有工作区、迁移整个工作区 |
| 实例范围 | 项目开发实例 | 定位来源与工作区编号共同确定 |

分发入口拒绝开发路径参数。所有受管子进程使用宿主解析出的启动上下文，并清除继承的项目路径变量。正式定位文件只保存格式、工作区编号、路径及字段说明。凭据仍通过 Windows Credential Manager（系统凭据管理器）使用。

工作区沿用 `portable.json`（布局配置）的 `schema=2`（第二版布局）：`app`（程序）、`runtimes`（运行环境）、`models`（模型）、`data`（用户数据）、`cache`（缓存与日志）、`tmp`（下载、解包及事务）、`backups`（备份）、`releases`（导出产物）。

## 构建与组装

```powershell
npm run desktop:build
npm run desktop:publish
npm run desktop:dist -- -SourceBase https://example.org/voice-terminal/0.8.0
```

上述网址是说明用途的占位地址，实际发布必须指定自己的固定 HTTPS（加密网络协议）附件目录。`desktop:build`（桌面构建）及 `desktop:publish`（本机覆盖发布）始终使用开发渠道。`desktop:dist`（分发组装）生成正式分发渠道的轻量入口和基础组件包。

当前先完成本地安装验收，正式发布地址由维护者后续确定，正式包的 `source_base`（发布来源）保持空值。确定地址后重新组装入口，使内嵌清单与发布包摘要一致。

```powershell
powershell -NoProfile -File scripts/build-desktop.ps1 -LaunchChannel development -OptimizationLevel release
powershell -NoProfile -File scripts/distribute-desktop.ps1 -Qualification -OptimizationLevel release
```

`Qualification`（分发验收）仍执行分发逻辑，仅增加受限制的本地发布源、独立定位记录和无窗口实验入口。该特性不能用于正式发布；验收工作区操作限定在测试目录。

| 输出 | 内容 |
| --- | --- |
| `.local/build/desktop/development` | 最新开发渠道构建及构建戳 |
| `.local/build/desktop/distribution` | 最新正式分发渠道构建及构建戳 |
| `.local/build/desktop/distribution-qualification` | 独立分发验收构建 |
| `.local/releases/distribution` | 正式入口、基础包、清单和摘要 |
| `.local/releases/qualification` | 同结构的验收产物 |

基础包为 `app.zip`（应用包）、`runtime.zip`（Python 后端环境包）、`webview2.zip`（固定网页引擎包）。大于 1 GiB（约十亿字节）的包生成有序分片，逐片及合并 SHA-256（摘要）校验。清单嵌入启动程序，基础包不包含模型、DSH（代理执行宿主）或用户数据。当前 Python 包沿用 `cu128`（CUDA 12.8 显卡环境组合）。

### 构建前置

`desktop:dist`（分发组装）消费已准备好的组件，不负责从零构建 Python（后端环境）、WebView2（网页引擎）或旧物理 DSH（代理执行宿主）运行闭包。组装输入是项目 `.local/runtimes/python`（当前 `cu128` 运行环境）、`.local/runtimes/webview2`（固定网页运行环境）、锁定版本的旧物理 DSH 闭包，以及 `.local/build/dsh/bundles`（项目插件包）。桌面应用收集器只读取旧 DSH 闭包中的运行元数据，并以可信 `manifest.json`（文件清单）交叉核验后提取 Microsoft VC145 CRT（微软 C++ 运行库）；旧 DSH 运行时本身不进入用户安装包。分发包只携带 `app.zip`（应用包）、Python 环境和 WebView2；用户在工作区资源管理界面单独导入或安装官方 DSH。当前仓库已备齐这些输入，且本轮 `desktop:dist`（分发组装）已成功构建。

从源码重建时按以下顺序准备；这是维护者操作流程，不由 `desktop:dist`（分发组装）自动触发：

1. 安装根目录锁定的 JavaScript（网页脚本）依赖：`npm ci`。分发脚本随后自行构建分发桌面主程序、准备固定版本的 7-Zip（完整压缩工具），再调用 `assemble-distribution.py`（分发组装器）。首次准备 7-Zip 需要锁定源码和本机 MSVC（微软 C++ 编译工具）。
2. 准备 `cu128` Python 环境。源码构建入口为 `pwsh -NoProfile -File scripts/setup.ps1 -Gpu -VcRedist <已授权的 MSVC Redist x64 目录> -SkipDsh`；`-Gpu`（显卡组合）选择 `cu128`，`-VcRedist`（C++ 可再分发文件目录）是重建运行环境的必需参数。脚本先在 `.local/tmp`（本机事务暂存目录）生成候选，再通过覆盖发布事务替换当前项目 `.local`（本机程序及运行环境）中的 Python 组件。它会改变开发环境的运行组件，须在停止项目服务并审核候选后由维护者明确执行；不应作为分发构建的自动前置。离线构建还要求已准备锁定的 Python 轮包缓存，可在缓存完整时加 `-Offline`（离线模式）。
3. 准备固定版本的 WebView2 文件。`scripts/prepare-webview2.ps1 -RuntimeDir <包含 msedgewebview2.exe 的固定版本目录>`（固定网页引擎目录）会校验入口并授予应用容器只读执行权限；如由 CAB（安装柜文件）展开，使用 `-RuntimeDir <.local/tmp 下的新候选目录> -Cab <已取得的固定 CAB 文件>`。该脚本不下载 WebView2，CAB 展开目标必须位于本机事务暂存目录。
4. 准备旧物理 DSH 闭包及项目插件包。闭包构建器 `scripts/build-dsh-runtime.py`（旧物理宿主运行环境构建器）要求源码检出与 `config/dsh/runtime.lock.json`（DSH 版本锁）一致，并要求明确的 Node.js（脚本运行环境）、锁定版 pnpm（依赖包管理器）及 MSVC Redist x64（C++ 可再分发文件）目录。其命令形式为：

   ```powershell
   .local\runtimes\python\python.exe -B -X utf8 scripts/build-dsh-runtime.py `
     --source .local/build/dsh/source `
     --node <固定 Node.exe 路径> `
     --pnpm <锁定 pnpm.cjs 路径> `
     --output .local/tmp/dsh-runtime-candidate `
     --vc-redist <已授权的 MSVC Redist x64 目录>
   ```

   `--output`（候选输出目录）必须是尚不存在的 `.local/tmp` 子目录；构建器会安装锁定的生产依赖并校验闭包。缺少 LibreOffice（文档转换引擎）Windows 原生包缓存时，它会访问 npm 官方登记及 tarball 地址下载固定版本资源，因此执行前应确认来源和网络策略。构建出的候选需先核验，再由维护者在停止项目服务后通过 `scripts/publish-desktop.ps1 -DshRuntime <候选目录>`（项目运行环境事务发布）替换开发基线；该发布会修改当前项目程序/运行环境，不应由 `desktop:dist`（分发组装）隐式触发。

   仅重新生成项目插件包且锁定 DSH 源码依赖已就绪时，可单独执行 `node integrations/dsh/voice-terminal/build.mjs`（插件构建入口），产物写入 `.local/build/dsh/bundles/voice-terminal`。`scripts/setup-dsh.ps1`（DSH 配置与插件部署脚本）会准备源码依赖、构建插件并调用 `voice_terminal.dsh.install`（受管配置部署）；即使使用 `-Offline -SkipInstall`（离线且跳过依赖安装），也仍会向当前项目 DSH 配置/配置文件部署插件并更新构建登记。它不是无副作用的打包准备命令；部署会保留已识别的用户补丁，但须先审核并停止受管服务，不能作为分发构建的自动步骤。

如果开发基线切换为官方 Electron DSH（桌面框架宿主），上述分发组装器的 CRT（C++ 运行库）收集仍依赖旧物理 DSH 的元数据格式及 LibreOffice kit（文档转换组件）目录，须先单独适配 CRT 来源。此构建前置不影响正式用户通过资源界面的官方安装器导入路径；官方 DSH 仍是工作区可选资源，不随用户安装包携带。

已完成验收包组装且基础环境未变更时，可以使用 `-ReuseQualificationBase`（复用已校验验收基础包）组装正式包。组装器核对组件清单、文件集合、大小和摘要记录，通过同卷 NTFS hardlink（文件硬链接）复用不可变的 Python、WebView2 目录、归档与分片；程序包、正式清单和轻量入口重新生成。该参数只用于正式渠道。

```powershell
npm run desktop:dist -- -ReuseQualificationBase
```

## 安装与资源

原生启动入口独立于 Python（后端环境）及 WebView2（网页渲染环境），负责中文路径选择、下载、进度、取消和重试。基础包经过暂存、归档路径检查、文件集合及大小摘要校验，再事务启用。移动入口程序后仍由定位记录找到工作区。

资源锁定信息在 `config/resources/catalog.json`（资源清单）。缺失或不完整的原组件卡片提供“下载／导入／跳转”，原生接口可在业务服务不可用时操作。安装任务保存在用户数据区，资源安装前停止受管服务，完成后重新启动。

- DesktopUpdateKit（桌面下载组件）固定提交 `8bfb24c1770098f6bd68aef208fcdfa1f097b92b`，通过 C ABI（C 语言调用接口）静态接入 Rust（原生语言）。支持预期大小、SHA-256 / SHA-512（摘要）、重试、取消及跨进程续传。每段请求从原始地址重新解析重定向。
- Hugging Face（模型平台）使用完整提交号的固定文件地址；公开资源默认匿名访问。
- ModelScope（魔搭模型平台）在独立 SDK（平台开发库）工作进程中按版本和精确白名单下载，资源启用由统一安装事务完成。
- 单模型目录导入校验对应资源；ZIP64（大文件压缩格式）批量包先展示识别结果、整体预校验，再逐资源安装。相同且完整的资源跳过，错误版本及摘要失败返回具体错误。
- SmartTurn（语音结束判断）的预处理配置随程序携带；用户唤醒词在当前数据区生成。

批量包的内部暂存路径使用短目录层级，避免 Windows（操作系统）路径长度限制影响含中文和空格的工作区。外部任务编号与恢复记录保持一致，暂存路径调整不改变必要文件、完整摘要及事务替换检查。实际 50 字符任务编号下的离线 ZIP64（大文件压缩包）预校验已验证七项资源，并核对七项既有安装的完整摘要。

离线验收包生成工具：

```powershell
.local\runtimes\python\python.exe -B scripts/package-resources.py --help
```

资源包仅包含固定静态资源及资源配置，不能携带用户会话、声纹登记、凭据或个人设置。完整导出界面后续增加。

## DSH 与动态端口

新资源下载锁定官方 DSH `0.2.0-rc.2`（固定版本）。官方安装器只做摘要验证和提取，使用固定完整 7-Zip（压缩工具）展开外层 NSIS（安装器容器）及内层负载，保留 ASAR（Electron 应用归档）和原生解包资源。运行使用无窗口命令入口；安装器本身不会执行。可信提取清单与应用发布清单绑定，原有物理 DSH 运行包继续识别。

官方已提取目录及 ZIP64（批量资源包）可由本体内的 `config/dsh/official-runtime.lock.json`（可信提取摘要记录）授权首次导入。记录须同时匹配固定安装器版本、SHA-512（来源摘要）、运行目录元数据及完整清单 SHA-256（文件清单摘要），并继续验证全部文件及摘要。资源包自行声明的来源或摘要不能代替该记录；没有发布记录时仍要求当前工作区已有匹配的安装清单绑定。

维护者可在 `scripts/install-official-dsh.py`（官方负载提取工具）的安装器输入命令上增加 `--export-trust-record <明确的输出文件>`（导出可信提取摘要记录）。只有固定安装器完整校验、实际提取及完整文件摘要验证通过后才生成记录，目录输入不能生成记录。核对记录后将其纳入本体 `config/dsh`（代理宿主配置）再构建。当前缺少固定安装器样本，因此本体未预填真实可信摘要；该路线另列待完整验收。

DSH（代理执行宿主）的临时目录、系统用户目录、包管理器配置和缓存均进入当前 `DSH_HOME`（代理数据目录）。Windows（操作系统）的 `USERPROFILE / HOMEDRIVE / HOMEPATH`（用户主目录／驱动器／路径）同步指向该目录，覆盖 Node（脚本运行环境）的用户主目录接口。

ApplicationHost（应用宿主）协调所有实际端点。自有监听器独占绑定首选端口，冲突时使用端口 `0`（系统分配）；Python 组件先持有监听套接字，再加载模型。DSH 使用 `--port 0` 并从输出解析实际地址，认证令牌不进入普通日志。状态包含 `endpoints`（端点表）及 `endpoint_revision`（端点版本），组件重启后依赖客户端和前端连接刷新。

## 迁移及恢复

迁移目标须为空、可写、空间足够，与来源互不包含。暂停资源任务、刷新并停止当前服务后，外部原生助手复制及摘要校验，重写已知路径，启动目标并验证桌面就绪；仅在成功后切换定位和清理旧目录的受管内容。普通会话文本不进行路径替换，进程登记、端口及浏览器缓存重新生成。

文件复制最多使用四个工作线程，各自复用缓冲区；每个文件仍执行写入摘要、落盘和目标重读摘要核验，主线程汇总进度。暂存文件使用本轮独占目录内的索引名，避免不同后缀的同名文件发生冲突。取消或失败后等待全部复制线程退出，保留原工作区。

事务记录保存在目标 `tmp` 和来源状态目录。恢复核对进程文件与创建时间。未提交事务恢复原定位并重新准备候选；已提交但尚未清理完的事务先恢复目标桌面再继续清理。失败时保留原数据和目标副本，避免删除未识别内容。

正常入口依次检查候选事务，跳过已完成或已失败的旧记录，确保连续迁移时仍能发现新的未完成事务。恢复验收使用移到两个工作区之外的单独 EXE（启动程序），通过定位记录执行正常恢复路径。

模型仓库跳转和 DSH（代理执行宿主）控制台共用隔离的网址辅助进程。外部浏览器使用 Windows（操作系统）的常规用户临时目录，清除工作区、Python（后端环境）、Node（脚本运行环境）及模型缓存变量，并过滤工作区运行包的路径项；受管服务继续使用工作区临时目录。网址仅通过标准输入传递，含令牌的网址不进入辅助进程命令行。正常系统临时目录不会被误认作受管工作区。

## 验收工具与待确认项

`scripts/qualify-distribution.py`（分发验收）提供本地发布源、入口移动、本地续传和故障实验。模型探测单次最多读取 64 KiB（约六万五千字节），包括失败请求在内按最大正文预留预算，总额不超过 1 MiB（约一百万字节）；完整模型通过离线包导入。

`scripts/qualify-resources.py`（资源验收）核对单模型、批量资源、重复导入跳过、错误版本和事务恢复。`scripts/qualify-runtime.py`（运行验收）核对首选端口冲突、实际端点、组件启动和重启。

`scripts/qualify-workspace.py`（工作区迁移验收）使用独立定位记录，核对未受管目录联接拒绝、正常迁移、普通会话文本保留、已知路径重写、旧受管目录清理以及复制中断后从入口恢复。验收解释器必须位于来源工作区之外，避免进程自身锁住待迁移目录。

验收报告保存在测试目录。正式发布地址需要项目维护者提供；缺少固定官方 DSH 安装器离线样本时，官方提取及完整启动记为待验收，不用联网下载替代样本。
