# Voice Terminal V0.3 规格

V0.3 是在 v0.2 音频链路之上的 Agent 控制层。它通过 `config/v0.3.yaml` 独立启用，默认配置不切换版本。V0.3 复用 Paraformer、Smart Turn、SenseVoice、稳定分段、Bidi/legacy TTS、PCM 背压、受保护真人插话和播放快照；它替换的是回答调度与跨 Turn 生命周期。

## Episode、Turn 和输出

首次有效的 `USER_SEGMENT_UPDATED` 或 `USER_INPUT_FINALIZED` 创建 Episode。输入 Turn 仍由实时控制器负责采集、定稿、精修和资源释放；多个 Turn 可属于同一个 Episode。`wait_for_input` 只结束当前 Agent 决策，`finish_episode` 结束 Episode 但继续监听，`session.stop`、致命错误和显式结束也会结束 Episode。下一次有效输入创建新的 Episode，不自动继承旧任务上下文。

身份分三层保存：

| 身份 | 作用 |
| --- | --- |
| `turn_id / generation_id / input_revision` | 音频输入及同一输入的续说、精修隔离 |
| `episode_id / agent_step_id / context_version` | Agent 决策、工具交换和输出授权隔离 |
| `speech_id / generation_id` | 一次语音输出事务及物理播放键 |

`speech_id` 不能用 Episode ID 代替。输出事务开始时固定 Episode、Step、上下文版本、来源 Turn 和输出 generation。输出进度、取消、异常和完成都使用这份固定身份；迟到的旧输出只能写自己的 `speech.completed` 和历史 Trace，不得覆盖新 Step 的 `current_action`。

输入历史通过 `turn.completed` 写入。停止、错误和正常完成都使用 Turn 自己保存的 `episode_id`，同一 Turn 最多提交一次。语音输出是独立记录，`delivery` 区分生成文本和实际听到的 `heard_text`、边界不确定内容及未听内容。

## Agent 工具契约

模型只能使用原生工具调用：

| 工具 | 参数 | 结果 |
| --- | --- | --- |
| `speak` | `emotion?: calm \| happy \| sad \| angry \| fearful \| disgusted \| surprised`, `text: string` | 通过现有 TextBridge、TTS 和 PCM 播放链增量输出；省略情绪时使用 `calm` |
| `wait_for_input` | 无 | 合法等待，不发声，不轮询 |
| `finish_episode` | 无 | 结束当前 Episode，监听保持可用 |

普通 assistant `content` 永远只进入 Trace；它不会触发 TTS。每次请求最多接受一个 `speak`，同批次其它调用返回结构化阻止结果。`SpeechArgumentStream` 按 tool-call index/ID 增量解析：新调用先解析受限的 `emotion` 再释放 `text` 前缀；兼容旧的仅含 `text` 调用时，已确认的默认 `calm` 可以直接流式进入 TTS。它保留 JSON 引号、反斜杠、Unicode 转义和代理对的严格校验；非法后缀、重复字段、超限和断流会关闭后续输出，已经播出的前缀照实结算。

发声门控同时检查 Episode、Step、上下文版本、输入可用状态、真人讲话状态和当前输出事务。`user_speaking` 只能来自实时语音活动；讲话期间的 `speak` 返回 `status=blocked, reason=user_speaking`，本次决策停止且不会静音后补播。新输入或上下文变化撤销旧输出授权，旧模型、工具、TTS session 和 PCM 迟到结果不能恢复它。

## 调度、工具和上下文

一个 Episode 同时最多一个主模型请求。新事件只更新最新上下文和 dirty 标记；旧请求结束后最多合并触发一次新决策。`conservative` 只在定稿、实质精修、工具结果和一次性静音事件触发；`balanced` 默认稳定段间隔 800 ms；`aggressive` 为 400 ms。用户停止讲话后的静音计时默认 5.5 秒，一次真实讲话后的静音机会最多唤醒一次；新讲话、Episode 结束和 stop 会取消计时。

首版只注册现有文件查找、文本读取和可用的 MiniMax 搜索，并标记 `READ_ONLY`。同一批只读调用通过 `asyncio.gather` 并行执行，注册器仍以 2 个执行槽限制实际并发。新的 `web_search` 先以后台预取任务启动：当前 Agent 请求立即结束，ASR、VAD、插话和新的输入事件可以继续处理；结果完成后按原调用身份触发一次续接。已经完成且新鲜的缓存搜索在静默续接时直接提供结果。用户讲话期间或输入状态未知时不会因为搜索结果自动发声。静默时搜索结果在当前身份仍有效的情况下接入下一次模型请求，意图变化则丢弃。

工具交换按完整 assistant call + tool result 组保存原始 Episode、Step、上下文版本和 `speculative` 标记。用户意图发生实质变化时，旧 speculative 组从新请求中隐藏，但缓存可保留；只有当前身份仍有效、原调用明确选择了同名规范化参数且新鲜度检查通过时才复用。删除或筛选始终以完整组为单位，不留下悬空 `tool_call_id`。Episode 结束清理缓存，最大并发为 2、缓存条目上限为 32。网络请求本身在只读工具线程池中运行；“非阻塞”表示它不会占用 Agent 事件循环，依赖搜索结果的回答仍须等结果完成后才会继续生成。

精修比较只忽略中文自然语句中的空白、普通逗号和句末停顿符号。数字的小数点、正负号、日期/版本分隔符，以及 URL、路径、代码和标识符中的符号保留；无法确认是展示变化时按实质变化处理。实质变化递增 `context_version`、撤销输出并触发合并决策，不额外调用 LLM 判断差异。

每个 Agent Step 默认最多 5 次模型请求。`v03.max_context_tokens` 的默认值是 524,288：运行时用 `tiktoken` 的 `o200k_base` 对实际请求有效载荷（messages、工具 schema、thinking 和结构 JSON）作**本地估算**，并不是 DeepSeek 官方精确 tokenizer。最近完成请求若 provider 返回 `usage.prompt_tokens`，会作为独立观测值显示。超过预算时运行时只压缩本次请求投影：先缩短工具结果，再按完整调用—结果组、旧输出详情和旧输入的顺序删除；系统提示、工具 schema、当前 Agent 状态和最新输入始终保留。单条异常大的最新输入会带截断标记后继续请求。完整缓存、Turn、Trace 和传达记录不被删除；`CONTEXT_COMPACTED` Trace 会说明原因和数量。搜索的模型投影最多 2 条 organic 结果、每个结果最多 1,200 字符摘要，单个搜索工具结果不超过 4,096 字符。

`tts.emotion_mode: agent` 允许 `speak` 指定表达情绪，默认 `calm`。MiniMax Bidi 的生产连接以单次独立输出为边界：收到 `task_flushed` 或 `task_canceled` 后，该连接一律标为不可复用，并在输出完成或取消屏障结束后关闭；下一次 `speak` 创建全新会话，并在 `task_start` 带入当前 `voice_setting.emotion`。这会增加下一次连接握手，但避免 provider 已确认 flush/cancel 后继续 `task_continue` 却返回零 PCM 的错误状态。输出记录与 `speech.text_delta`、`speech.completed` 均携带 requested/applied emotion。服务端是否接受 Bidi 的该字段必须以实际端点 smoke 为准；拒绝时记录 `TTS_EMOTION_UNSUPPORTED` 并回退到中性输出。

`session.reset` 取消当前输入、Agent、预执行工具和播放，结束当前 Episode 并清空其上下文/缓存，同时保持监听和历史审计记录。下一段有效输入会创建新的 Episode。

## 配置和兼容

```powershell
python -m voice_terminal.server --config config/v0.3.yaml
```

实际启动脚本仍建议使用：

```powershell
.\scripts\start.ps1 -Python D:\DevTools\Python312\python.exe -Config config\v0.3.yaml
```

V0.3 必须同时启用 `v02.enabled`。不使用该配置时，v0.1/v0.2 控制器和旧事件路径保持不变；共享播放代码的 Bidi/legacy 行为由原有回归继续保护。

## 资源清理约定

取消覆盖等待旧输出屏障、TTS session 启动、文本发送、PCM 接收、播放器背压和首音前后。Bidi 的 `task_flushed`、`task_canceled`、取消失败、超时或不可复用结果都会关闭旧 session。管线记录已发送 TTS 文本及累计 PCM 字节；若已发送文本而本次得到零 PCM，会记录 `TTS_EMPTY_AUDIO` 并只在完全未传达时用全新会话安全重试一次。重试仍为零 PCM 时，记录 `TTS_EMPTY_AUDIO_RETRY_FAILED` 并以 failed 结算，不把它伪报为 completed。所有清理使用 `gather(..., return_exceptions=True)` 等待本地 Task，不遗留未处理异常或无限等待。输出最终只结算一次，结算依据播放器快照和传达解析器。
