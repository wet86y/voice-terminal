# TTS（语音合成）能力驱动的语音调节

主语音链路只登记 `guidance`（语气引导）、`speed`（语速倍率）和 `volume`（相对音量）。`voice_terminal/tts/controls.py`（能力与校验登记）统一生成模型可见协议、参数校验及执行映射。语音与音色设置中的“语音调节”控制整层；`tts.speech_control_enabled`（全局启用）首次使用和旧设置迁移均默认开启，已保存的关闭值保留。该开关适用于在线与本地语音目标，设置格式为第18版。

播放目标设置之后显示对应的音色配置：本地目标展示本地音色库，在线目标展示在线模型和音色 ID（音色标识）、官方音色库入口、试音及保存。其后展示全局“语音调节”开关；仅本地目标显示合成质量档位。演示界面复用相同设置组件和排列方式，在线演示保存只更新当前展示状态，不发起真实音色验证或试听。

| 合成模型 | 语气引导 | 语速 | 相对音量 |
| --- | --- | --- | --- |
| MiniMax HD／Turbo（在线高音质／低时延） | 原生七种情绪枚举 | 服务端原生 | 服务端原生 |
| VoxCPM2（第二代本地） | 自然语言风格描述 | 本地保音高变速 | 本地增益 |
| VoxCPM1（第一代本地） | 不向模型暴露 | 本地保音高变速 | 本地增益 |

语速范围0.8至1.2，音量范围0.6至1.4，默认均为1。默认语气不附加引导，MiniMax 默认省略原生情绪字段。有效能力同时考虑模型、音色、传输方式、总开关和本地处理器实际可用性；未安装保音高处理器时隐藏本地语速入口，音量继续可用。音色创建、克隆和显式设计试音保留独立设计参数。

## 稳定输出与上下文

固定输出容器为 `speak.controls`（参数补丁列表），每项只有 `name`（参数名）、`value`（参数值字符串）。数值也使用字符串编码，例如：

```json
{"speak":{"state":"speak","controls":[{"name":"speed","value":"1.1"}],"text":"接下来我会详细说明。"},"actions":[]}
```

`controls=[]`（空列表）沿用当前会话参数；部分更新只影响指定项；`value="default"`（恢复默认）清除对应调整。重复参数、未登记参数、越界或错误类型使整组补丁失效，保留原值并反馈，合法正文继续遵循队列准入。旧 `emotion`（情绪）字段仅在兼容读取入口归一化；新协议和示例不再要求它。流式解析按对象结构读取，参数字段完整到达前不受理首段正文，支持正文在前、参数在后及跨网络块到达。

每次请求在 `REQUEST_TAIL`（请求尾部）提供当前有效能力说明；运行中切换模型或总开关后，后续请求自然携带新说明。固定指令、既有历史和严格输出结构不随能力变化改写。唯一的 `voice_request_context`（语音请求上下文）中，通过 `runtime.speech_controls`（当前会话有效语音参数）提供请求构建时冻结的非默认值，播放和空闲时都发送。`guidance`（语气引导）保留完整规范化描述，`speed`（语速倍率）和 `volume`（相对音量倍率）使用数值；各默认项省略，全部默认或调节关闭时省略整个字段。内部代次及能力身份不发送给模型。

提示要求以本次参数快照为事实，无需调整时输出空补丁；用户认可或要求保持时不必重复提交。无新要求及明显场景变化时保持语气、语速和音量连贯，不反复改写同一风格描述；明确持续要求优先，临时表达场景结束后由模型结合上下文通过原补丁恢复或调整。长文本可适当提速，无需求不调整音量。会话保持值由语音输出管理器在内存中统一维护，不写入持久设置或语义历史，程序重启后不恢复。

## 队列及合成快照

参数随受理的新播报、尾巴修订及带正文取消重说提交；`wait`（等待）或空正文取消不更新参数。新播报通过准入并冻结音色后同步登记合法补丁，后续网络合成故障不撤销已受理的参数意图。尾巴参数在事务、版本和锁定边界校验通过后才更新。非法、过期及被拒绝的补丁不能覆盖会话保持值。每个新合成冻结一次参数；已提交音频保留原快照。连续队列、尾巴和替换继承有效参数；普通新播报也从会话保持值开始。播放结束、1秒续写窗口结束和用户换轮均不清空参数，保持值不依赖旧播放句柄的存活。

实际进入 KWS（关键词唤醒待机）、有效唤醒恢复监听及停止后重新启动监听，只刷新参数代次和预热，保留本会话保持值与队列参数。会话结束、显式重置、输出管理器关闭、切换模型或音色以及语音调节总开关变化时清空参数。内部 `speech_control_epoch`（参数代次）与能力摘要阻止旧推理补丁跨刷新生效，正文仍按原准入规则处理。待机主动播报自身恢复监听时，只有该次自身触发的单次刷新可向当前请求移交资格，不能复活此前已过期的结果。

MiniMax 在未提交文本边界滚动原生任务，一个逻辑播报保留累计音频字节、分段回执、字幕时间及正文偏移。完整参数组参与预热和双向会话复用匹配。VoxCPM2 仅在正式合成请求前缀中加入受支持的风格描述，原始正文、字幕、字符计数和传达历史不包含前缀，也不改写音色库。

## 本地处理与时钟

`voice_audio_dsp`（内部音频处理包）用 Python 标准库外部函数接口调用 SoundTouch 2.4.0（音频处理库）的节奏接口；增益使用 NumPy（数值计算库）浮点缩放及饱和限幅。两项默认时逐字节旁路。网络块之间保留变速器状态，仅在实际合成段结束时收尾，取消时丢弃旧尾缓冲。

`source_received_bytes`（处理前接收字节）、`buffered_source_bytes`（算法仍持有的源字节）与 `received_bytes`（实际输出字节）分开统计；`audio_transform_spans`（源到输出采样帧区间）记录每段累计边界。回执在尾缓冲全部输出后形成。播放器、字幕估算、剩余时长、调度缓冲、打断及传达判断沿用处理后的实际输出时钟，不能再用原始时长推算。AEC（声学回声消除）仍从播放器最终输出取参考，包含已有淡入淡出和欠载静音。

## 构建与验收

在现有开发环境执行 `python scripts/build-speech-dsp.py --update-lock`（构建并更新依赖锁）。脚本校验官方源码摘要，使用现有编译工具生成动态库、薄包装、许可证、对应源码及构建记录，输出到 `.local/build/runtime-lock`（受管依赖构建目录）。`scripts/build-runtime.py`（正式运行环境组装）按锁核对内部包并交给既有语音共用组件安装；组件下载、更新和修复仍由正式程序组件列表执行。

`python scripts/verify-speech-controls.py --online --local`（真实合成验收）使用相同正文，生成默认、分别调低／调高语速和音量、受支持语气引导样本，以及在线队列内参数变化的任务滚动样本。在线验收会调用已配置接口。本地模型、现用组件和音色库不被覆盖；候选动态库仅解包到受管验收目录。报告包含首音频耗时、实际输出长度、回执与输出一致性以及真实动态库的音高／时长、播放器打断和回声参考检查。附加 `--measure-local-buffering`（同源真实网络流延迟测量）同时旁路及处理同一网络流，记录可归因的首次输出增量；它不等于处理器积累的输入音频时长。自动检查不替代主观听感确认。
