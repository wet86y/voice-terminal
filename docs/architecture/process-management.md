# 项目进程管理

桌面程序与受管后端共用 `VoiceTerminalDesktop.exe`（产品宿主）。后端以 `--worker-host`（工作进程入口）运行，在独立进程内部加载已选环境的 `python312.dll`（解释器动态运行库），不创建窗口，不进入桌面单实例逻辑，不复制或修改现用运行环境。

## 启动入口与运行路径

原生层通过 `process_host::python_command`（解释器命令入口）创建进程，Python（后端语言）侧通过 `paths.python_command`（受管模块入口）或 `process_host.interpreter_command`（受管解释器入口）派生进程。服务管理、模型、声纹、硬件探测和关键词编译复用这些入口；组件检查及安装辅助任务也复用原生入口。

宿主只用于存在相邻解释器动态库的绝对解释器路径。没有相邻动态库的外部环境继续使用原解释器，维持已有导入支持范围。独立脚本未由桌面程序设置宿主时，也继续使用原解释器。

传给 `Py_Main`（解释器标准入口）的首参数保留已选解释器绝对路径，因此 `sys.executable`（解释器身份）、依赖搜索、处理器与显卡环境选择继续沿用原值；操作系统查到的实际进程映像则是产品宿主。退出码、标准输入输出和原有模块参数保持原协议。

后台模块入口在导入业务依赖前调用 `configure_background_subprocesses`（后台子进程策略），组件运行环境检查入口也启用相同策略。Windows（操作系统）下为 `subprocess.Popen`（标准子进程创建接口）统一补充 `CREATE_NO_WINDOW`（不创建控制台窗口），同时保留已有创建标志、输入输出管道和退出码。策略仅安装在这些后台解释器进程内，也覆盖第三方框架导入时的工具检查；主界面及独立开发工具不自动安装此策略。显式传入 `CREATE_NEW_CONSOLE`（新建控制台）或 `DETACHED_PROCESS`（脱离控制台）的调用保留原行为。图形界面宿主不能依赖父进程的隐藏标志抑制后代控制台窗口。

| 参数或环境字段 | 中文说明 |
| --- | --- |
| `--worker-host` | 在初始化桌面框架前进入独立工作进程模式 |
| `VOICE_PROCESS_HOST` | 由桌面主程序设置并传递的当前宿主绝对路径，不持久化到用户设置 |
| `VOICE_PROCESS_START_GATE` | 原生层创建的单次启动门闩名；子进程使用后立即从自己的环境移除 |
| `VOICE_RESOURCE_ROLE` | 现有资源角色；语音服务角色同时维护自己的音频会话显示身份 |

## 所有权与回收

原生父进程先创建 `Job Object`（作业对象），再通过统一受管创建方法建立后台子进程。项目宿主在门闩放行前不加载解释器、不派生业务子进程；父进程加入作业成功后才放行。门闩句柄由所属作业保留，避免子进程尚未打开时事件已经失效。没有宿主门闩的第三方工具和外部解释器使用 `CREATE_SUSPENDED`（挂起创建），加入作业后通过系统线程快照核对并恢复唯一初始线程；不恢复用途不明的其他线程。作业创建失败不启动子进程，分配或恢复失败则结束并等待直接子进程。

后端受管组件仍沿用已有的挂起创建、加入外层和组件作业、恢复执行流程。模型等未主动脱离的后代继承作业归属；关闭最后一个作业句柄时回收所属进程树。组件的正常停止协议、设备回退和业务重试不在此层调整。

DSH（代理执行宿主）的脚本运行环境、原生语音合成服务和 WebView2（网页运行引擎）继续使用各自原生可执行文件。前两者沿用项目启动链和现有所有权管理，网页引擎由桌面框架管理；不改写第三方组件二进制、摘要或图标资源。

## 系统显示身份

主程序与解释器工作进程设置同一个 `AppUserModelID`（应用用户模型标识），并共用产品可执行文件内的名称和图标资源。它们仍是独立进程，保留各自内存与故障隔离。

语音服务的独立原生线程仅维护属于本进程的音频会话，通过系统接口设置项目名称、图标和音量分组。设备切换或音频流重建后重新发现会话；不读取音频内容，不改设备、音量、采样格式或播放协议。无音频服务时不阻断后端运行。

任务管理器的折叠分组由 Windows（操作系统）判断，不能把相同应用标识或作业归属当成必然折叠的保证。第三方网页引擎和原生组件的系统分组、系统进程选择器的显示方式均需在目标系统单独验收；音频会话身份与任务管理器折叠分别验证。

## 验证入口

复用固定原生构建缓存与现有正式解释器，不准备第二套模型或运行环境。`tests/test_process_host.py`（进程宿主测试）覆盖解释器路径、原生扩展、中文管道、退出码、门闩、子孙进程回收及静音音频会话重建。原生集成测试通过 `VOICE_TEST_PROCESS_HOST`（本轮已构建宿主）明确选择产物，避免旧程序误处理新参数；原生作业验收还需 `VOICE_TEST_PROCESS_PYTHON`（私有解释器路径）。

```powershell
$env:VOICE_TEST_PROCESS_HOST = (Resolve-Path .local/build/desktop/product/release/VoiceTerminalDesktop.exe).Path
$env:VOICE_TEST_PROCESS_PYTHON = (Resolve-Path .local/runtimes/python/python.exe).Path
.local/runtimes/python/python.exe -B -X utf8 scripts/test-backend.py -q tests/test_process_host.py
```

音频测试只向默认输出设备写入静音；没有可用输出设备时明确跳过硬件测试。测试不安装、更新或替换本机正式程序；进入本机覆盖发布时继续遵循原有发布、兼容维护和更新日志流程。
