# 局域网正式版本同步

本功能面向正式程序，只按产品语义版本号比较高低。同版本直接连接；开发期同为 `1.0.0` 的不同构建也视为同版。构建编号只用于分发器自身与本体安装身份核验，不参与双端版本关系判断，不新增发行序号。

## 连接顺序

1. 继续使用现有发现、配对与 SSH（安全外壳协议）主机指纹、公钥认证。
2. 在原生管理、任务、语音等业务启动前，经现有 FILE（受限文件）桥接执行独立的第一版更新引导协议。它不依赖管理业务协议、Python（后端运行环境）、DSH（代理执行宿主）或媒体租约。
3. 版本相同继续原连接流程；不同则显示项目确认弹窗，明确双端版本、更新目标及退出重启影响。拒绝仅暂停业务启动，同一目标及版本组合的后台重连不重复弹窗，设备页保留“同步程序版本”入口。
4. 用户确认后重新核对配对目标和双方版本。服务端较新时客户端拉取其维护分发器；客户端较新时客户端上传其维护分发器，服务端本机正式更新入口接管。两种方向均由客户端主动建立安全连接，不向客户端新增监听端口。
5. 接收端逐块核对偏移和内容摘要，完整接收后再次核对长度和 SHA-256（内容摘要）。确认交接前可取消；未完成或失败时清理本次候选并释放维护准入。
6. 复用正式本体更新的工作区身份、旧进程身份、一次性配置、取消门闩及安装器校验。分发器等待旧程序退出，更新本体、保存自身并重新启动；组件继续由正式程序的组件列表维护。
7. 发起端在目标重启后再次检查产品版本，确认一致才恢复业务连接。传输完成或交接回执不代表安装已完成；交接失败可通过引导状态补查，超时保留人工重试入口。

## 正式入口与文件归属

`device_version_check`（版本预检）和 `device_version_sync`（用户确认的版本同步）由正式桌面命令注册表登记，窗口权限和代理调试共用原入口。普通远程管理、资源导入、任务和媒体入口复用原生版本准入检查，不能只依靠前端弹窗约束。

同步源仅来自高版本设备的 `maintenance/VoiceTerminalSetup.exe`（长期维护分发器）及 `maintenance/installer.json`（身份记录），不会临时从互联网获取最新版。维护分发器缺失或与本机身份不匹配时报告原因，由用户通过原正式路径准备。

接收文件复用 `tmp/app-update/VoiceTerminalSetup.exe`（固定更新暂存分发器），与在线更新、工作区迁移和设备切换互斥。传输失败不替换现用维护分发器；成功安装后沿用已有的同版本重复分发器清理规则，不产生按版本或构建命名的安装目录。

协议每帧有界，原始分块为 64 KiB（65,536 字节），只允许状态、上传、下载、分块、验证、应用和取消操作。请求与回执字段携带中文说明。服务端逐次检查当前广播、工作区、账户、桥接构建及设备信任；同步回执必须来自当前配对目标。

## 兼容边界与验证

当前状态为源码接入与自动化验证完成，尚未覆盖本机程序、生成正式分发器或完成真实双机升级重启。验证配置、结果与未覆盖范围见[局域网版本同步验证记录](../testing/lan-version-sync-20261121.md)。

两端必须先具备该稳定引导协议；完全不认识此入口的旧程序需要先经原有正式更新方式升级一次。发现及长期授权桥接协议仍沿用既有规则，关闭广播、撤销信任或切换目标会停止同步。

源码回归覆盖版本数值比较、同版直连、异版业务门禁、项目确认与取消、重启等待、分块和完整摘要检查、失败候选回收及引导协议回环。实际双机传输、安装和重启需要在具备不同正式版本及各自匹配分发器的两台设备上验收；开发期同为 `1.0.0` 的现场不会自动触发升级。
