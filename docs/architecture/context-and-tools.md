# 上下文与工具规范

本文只定义“哪些信息可以给哪个模型、哪些动作可以被调用”。缓存前缀和字段准入见[LLM 上下文缓存契约](llm-context-cache-contract.md)；组件生命周期见[架构文档](architecture.md)。

用户指令、持久设置与历史上下文的适用边界如下：指令默认只适用于当前请求或对应任务，历史中曾要求暂缓、静默或稍后处理，不会自动约束之后独立的新问题。明确的长期范围、重复适用规则、结束条件和恢复条件按原意保留；自定义条目只有在当前意图满足其触发语义时执行，保存条目本身不代表每次请求都会触发，也不延长某一次触发的作用范围。

产品设置中的 `custom_instructions`（自定义指令）保存后更新当前会话快照，后续请求立即采用；已派发的请求继续使用派发时的独立副本。历史记录不扩大指令范围；助手建议、猜测、提交合成或承诺不能替代用户事实、授权或实际传达回执。默认及时回应应服从当前明确的暂缓要求，但旧暂缓状态不能阻塞无关的新问题。

## 两种上下文投影

### 主 Agent

主 Agent 的请求由三层组成：

1. `STATIC_INSTRUCTIONS`（固定指令）：协议、动作目录和日期基准在会话内冻结；人格、用户资料和自定义指令使用显式保存后的快照；
2. `HISTORY`：已提交用户输入、已结算 `voice_delivery`、有效 refinement、工具结果和有语义影响的打断；
3. `REQUEST_TAIL`：当前未提交输入、运行时间、恢复反馈、工具状态和活动 speak。

产品设置中的 `custom_instructions`（自定义指令）保存后更新当前会话快照，后续请求立即采用；已派发的请求继续使用派发时的独立副本。
主模型的静态层包含启用条目的触发语义和执行位置；仅语音链路条目包含执行目标。
影子条目的目标不进入主模型上下文。触发采用完整语义判断，不做关键词硬匹配。
旧 `config/persona/instructions.md`（历史工作指令文档）留在磁盘供查阅，不再加载；
通用对话原则已收进内置提示词，产品界面只编辑人格风格、用户资料和自定义指令条目。

### 一体化助手与动作路由

DSH（后台执行宿主）与 LLM（大语言模型）语音交互链路向用户呈现同一助手，统一使用“我”。
内部工具名、会话和通道仍按现有协议管理，不要求用户区分执行端、转述任务或向另一端重复下达要求。
内置规则由 `voice_terminal/agent/prompts.py`（语音提示词）、`config/shadow_agent/instructions.md`（公共执行规则）
和 `config/dsh/shadow-agent.rules.md`（后台专属规则）维护；后台预设身份及动作说明采用相同原则。

用户要求实际操作、外部资料查询或任何定时任务操作时，语音环节必须提交一次
`request_shadow`（请求后台执行），只包含 `request=true`（固定请求标记）。
不先估计难度，不因语音端工具目录少而拒绝，也不以说明步骤或口头承诺代替实际执行。
缺少参数时仍先交给后台核对上下文，再由后台提出必要问题；后台运行期间的新要求、补充、修改和撤销也触发该动作。
纯闲聊、已有知识解释、提供文本的翻译/改写、直接计算及对话内起草文本直接回答；
明确只讨论、暂不执行或仅引用操作语句时不执行。请求后台与选择语音状态分别决定，等待期间也可提交动作。

| 用户要求 | 语音环节 | 后台执行 |
| --- | --- | --- |
| 三分钟后提醒喝水 | 请求后台，不提前宣称设置成功 | `wake_task_create`（创建链路任务），`after_seconds=180`（延迟秒数） |
| 每天上午九点提醒 | 请求后台 | 创建每日规则，使用当前有效时区 |
| 提醒我喝水，未说明时间 | 请求后台，不先拦截 | 核对上下文后只补问缺失的时间 |
| 把刚才的提醒改到十点 | 请求后台 | 使用已确认任务标识；否则先查询，再更新对应任务 |
| 取消喝水提醒 | 请求后台 | 查询并唯一定位后取消；多个匹配时只补问目标 |
| 只想了解怎样设置提醒 | 直接解释 | 不创建任务 |

语音会话的定时请求默认使用 `wake_task_*`（项目链路任务工具），只有明确限定仅后台会话显示时才使用官方
`schedule_*`（会话任务工具）。到期提醒或结果通过 `publish_voice_event`（投递语音事件）回到语音链路，
不能只停留在后台正文。创建、更新、取消及失败重试均核对既有回执，避免重复创建。
当前项目工具不提供暂停/恢复，不能把暂停请求直接当作取消。
业务工具的成功回执确认实际操作完成，桥接回执只确认结果提交；没有成功回执不得报告定时或操作成功。

未播放的 assistant（助手）草稿、播放器进度和 TTS（语音合成）连接状态不是历史事实。活动语音事务在第2版当前快照的 `speech`（语音状态）中直接投影完整锁定文本和可改文本：

```json
{
  "owner_scope": "current_turn",
  "continuation_mode": "rewrite_tail",
  "locked_text": "会议地点是会议室甲，",
  "editable_text": "三点开始，记得带上笔记本。"
}
```

`locked_text`（锁定文本）是本地已提交前缀、当前短句和预取短句的无损拼接；`editable_text`（可改文本）是尚未提交的尾巴。内部仍保留四段调度边界；同轮事务换头时，此前已交付前沿仍进入模型看到的锁定文本。锁定不等于用户已经听到。

`speech.delivery`（语音传达事实）只在 `state=empty`（队列空闲）时出现，只含 `heard_text`（确认已听文本）、`status`（传达状态）、`termination`（终止原因），不携带播报、轮次或请求标识。活动队列不投影该字段。完整传达历史继续以 `voice_delivery`（实际传达记录）在历史区追加，不把待播文本写成已经听到的事实。

固定队列规则在稳定指令区只保留一份；当前用户输入、背景和恢复／调度信息在当前快照之前独立呈现，快照后是本次决策任务和最终输出约束。`state=revision`（尾巴修订）时，`speak.text`（播报文本）是从锁定边界续写的完整替换尾巴，保留原尾巴仍有效的要点。输出协议字段及本地受理逻辑保持不变，详见[缓存契约](llm-context-cache-contract.md)。

### SenseVoice 精修线索

SenseVoiceSmall（语音精修和声学分析）返回的精修文本进入同一用户轮次的 `transcript_updates.available`（可用转写更新）。有可用情绪或声学事件时，该条 `refinement`（精修更新）可额外携带 `audio_cues`（音频判断线索）。示例中的 `kind`（更新种类）、`source`（来源）、`text`（精修文本）和 `revision`（修订序号）用于标识同一轮次的精修：

```json
{
  "kind": "refinement",
  "source": "sensevoice",
  "text": "精修后的文本",
  "revision": 2,
  "audio_cues": [
    {"start_ms": 0, "end_ms": 900, "emotion": "HAPPY", "events": ["BGM"]}
  ]
}
```

- `start_ms`（片段开始毫秒）、`end_ms`（片段结束毫秒）、`emotion`（语音情绪）和 `events`（声学事件）仅用于描述 SenseVoice 的模型推断；不是用户转写内容或确定事实。`Speech`（普通语音事件）、未知情绪、转写文本、语言字段和原始标签不复制进线索。
- `audio_cues` 只在当前请求由 `USER_INPUT_REFINED`（用户输入精修完成事件）触发时出现。`transcript_updates.available`（可用转写更新）后续仍可保留精修文本，但不重复带入音频线索；如果 ASR 最终稿与精修同窗到达，线索仍只属于精修条目。
- `audio_cues.emotion`（输入语音情绪）与 `speak.emotion`（输出播报情绪）是不同信息，前者为理解语音提供参考，不会设置后者。
- 线索只在当前 `REQUEST_TAIL`（请求尾部）中短暂出现，不追加到 `HISTORY`（会话历史）；历史缓存前缀保持不变。

### Shadow

Shadow 使用独立的 `ShadowContextProjector`，来源仍是 `SessionLedger`，但不复用主模型 prompt。允许内容：

- `user`：已结算用户输入、refinement，以及触发 wake 但尚未结算的当前输入；
- `main_agent`：用户实际听到的 assistant 文本；
- `external_system`：确认过的工具结果和外部变化；
- `runtime`：日期、时区和有语义影响的 interruption/replacement。

会话环境还包含启用的影子 `custom_instructions`（自定义指令）的触发语义与执行目标，
来自与主模型相同的已保存设置快照，显式保存后发布新修订。Shadow（影子代理）须根据完整用户原话复核意图；条目不授予新的工具权限。

排除：主模型 reasoning、未播放 speak、TTS/播放器机械状态、主动作 schema、Shadow 自己的 progress/status/result 和已经存在于 Shadow trace 的输出。

## 用户自定义指令

设置页按条目保存自定义指令，不再把工作指令和影子系统指令的大文档交给用户编辑。每条数据使用以下字段；英文名称是接口和存储字段，括号内是中文说明：

| 字段 | 中文说明 | 取值与约束 |
| --- | --- | --- |
| `id`（标识） | 条目的稳定标识 | 1～80 位 ASCII（美国信息交换标准代码）字母、数字、下划线或连字符；列表中不可重复。 |
| `trigger`（触发语义） | 用户可能表达的完整意图 | 必填，最多 200 字；按整句话的语义理解，不按关键词硬匹配。 |
| `target`（执行位置） | 由哪条运行链路处理 | `voice`（语音链路）或 `shadow`（影子代理）。 |
| `instruction`（执行目标） | 条件符合时须严格执行的完整指令 | 必填，最多 2000 字。语音目标由语音 LLM（大语言模型）读取；影子目标由 Shadow（影子代理）读取。 |
| `enabled`（启用状态） | 是否注入模型提示词 | 布尔值；停用条目保留在设置中，但不注入会话上下文。 |

最多保存 50 条，所有条目序列化后的总大小不超过 32 KB。产品快照由 `GET /api/v1/product/snapshot`（读取产品设置快照）返回；整表保存使用 `PUT /api/v1/product/settings/custom-instructions`（保存自定义指令列表），请求体为 JSON（数据交换格式）：

```json
{
  "custom_instructions": [
    {
      "id": "wait",
      "trigger": "用户希望我先暂停回答，等他继续",
      "target": "voice",
      "instruction": "保持等待，不补充解释；等用户继续说后再响应。",
      "enabled": true
    },
    {
      "id": "lookup",
      "trigger": "用户要求查询附近的地点或服务",
      "target": "shadow",
      "instruction": "根据用户原话查询附近的目标，并把来源和结果反馈给语音会话。",
      "enabled": true
    }
  ]
}
```

人格与自定义指令保存响应中的 `effective_from`（生效时机）为 `next_request`（当前会话后续模型请求），`pending`（尚未应用）为 `false`。保存操作显式更新语音模型的当前提示快照与影子代理的权威环境，并追加 `product_settings`（产品设置修订），供已连接的后台同步读取。会话编号、历史和正在派发的请求保留。固定指令的稳定性检查仅在这次显式保存时重新建立基线，直接编辑磁盘文件仍不自动修改已激活的快照。

用户资料只作事实和偏好参考，当前明确表达及修正优先。文档标题、空白字段、填写提示和示例不算用户事实，缺少资料不触发主动档案补全。人格中的助手名称不能当作用户称呼；助手猜测、一次闲聊、临时任务要求和旧交接建议不自动成为长期偏好。知道一项事实、写入交接摘要和实际保存资料文件分别处理，模型只有依据成功保存回执才报告资料已保存。用户明确要求保存或修改资料时，后台核对现有文档与保存位置，仅更新相关且有依据的事实，保留其他资料，不写入运行状态或任务待办。

语音模型能看到启用条目的 `trigger`（触发语义）和 `target`（执行位置），但只会看到 `target: "voice"`（语音链路）的 `instruction`（执行目标）。对于 `target: "shadow"`（影子代理）的条目，语音模型只根据语义发出既有的 `request_shadow`（请求影子代理）信号，不传递用户编写的执行目标，也不获得新的工具权限。

Shadow（影子代理）在权威会话环境中读取启用的影子条目及其执行目标，独立核对最新用户原话及仍有效的任务条件，再使用自身已有能力处理。当前请求满足触发语义时严格执行完整指令，不能以默认风格、惯常追问或自主补充弱化、替代或扩大；清楚可执行时不额外确认。多条适用要求兼容时一并遵守，仍有影响实际执行的冲突或缺失条件时才必要澄清。条目不扩展工具权限，不改变输出协议、实际语音队列约束及事实边界；影子代理不可用或缺少能力时，不得声称任务完成。

保存的条目持续存在，每次是否适用重新判断；某次触发效果通常具有即时性，只作用于本次请求或对应任务，无必要不延续到后续判断。一般用户指令也遵守相同范围：只有明确长期或重复适用、结束或恢复条件，或仍有效任务的必要条件才延续，不影响无关的新问题。最新用户修正、撤销或恢复优先；例如一次“等一下”不限制用户后来主动提出的新问题，“简单说”不自动成为长期简答偏好。仍有效的明确暂停条件不能仅因默认及时回应规则被忽略。

主会话、公共后台规则、后备规则、后台轨迹压缩和交接整理使用相同的作用范围。交接仅记录仍需承接的任务与范围，不执行历史条目、不重复触发已处理请求、不恢复已修改、停用或删除的设置，也不把一次静默或等待写成后续会话的行为规则。后台采用最新 `product_settings`（产品设置修订）的完整条目列表，空列表表示清除；旧轨迹中的条目不是新授权。

## Revision 与 reset

每个真实输入事实递增 `shadow_input_revision`。wake 只表达“请读取最新 revision”，runtime 负责获取完整 snapshot 或从 `applied_context_revision` 开始的无损 delta。

- 相同 `turn_id + text + refinement` 必须幂等；
- 多次 wake 合并到最新 cursor，不丢中间事实；
- `session.reset` 增加 source epoch 并从 revision 0 开始；epoch 或 cursor 不匹配时返回完整 snapshot；
- 当前未结算输入使用 `current_dispatch_input` 保留原始用户证据，不转换为主模型生成的任务摘要。

实验性 context gate（上下文门禁）默认关闭。DSH（影子代理执行环境）模式下，关闭时沿用现有上下文直通路径；开启后，运行中的后续 `request_shadow`（请求影子代理）可将新引导延迟到下一回合。每次请求都可重新判断完整未引导区间，允许连续多次暂缓；权威正文始终同步且可读取，不删除、改写或重排。门禁异常、超时、关闭或不确定时放行待处理正文。

## 主动作目录

Shadow 可用时，主模型只获得以下本地控制动作：

```json
{
  "name": "request_shadow",
  "parameters": {
    "type": "object",
    "additionalProperties": false,
    "required": ["request"],
    "properties": {"request": {"type": "boolean", "const": true}}
  }
}
```

该动作不携带目标文本、意图摘要、任务 ID 或用户答复，也不直接产生历史项。不可用时不公开该动作。

## Shadow 工具目录

原生后端业务工具：

- `files_search`：只在 `allowed_roots` 内搜索；
- `files_read_text`：只读取允许根目录内的文本；
- `web_search`：可选的外部只读搜索。

本地控制工具：

- `get_latest_context({since_revision})`：返回 unchanged、delta 或 epoch snapshot；
- `publish_progress({text})`（发布进度，`text` 为正文）：更新 Product UI（产品界面），实质变化合并进入二等信箱，按 4 秒检查点或随普通请求评估；
- `publish_voice_information({text})`（发布 Voice 信息）：更新单个全局最新信息槽并触发可合并推理；
- `request_user_input({question, options})`（请求用户输入）：发布唯一终态问题；
- `return_shadow_result({text})`（返回最终结果）：发布自包含的唯一终态结果；
- `finish_shadow_no_action({reason?})`（无动作结束）：结束激活但不写入语义历史。

DSH（影子代理宿主）后端另提供 `request_early_silence({})`（请求提前进入静默）：仅当前用户明确要求，
或本会话已启用的影子自定义指令明确规定当前场景时调用。受理后立即将静默窗口标记为
`final_pending`（最终静默检查待处理），不打断当前语音输入或播报；实际执行仍等待输入、模型处理和实际输出空闲。
新输入重置窗口时请求保留并重新标记。随后执行 `final_silence`（静默前最终检查），检查结算后进入
KWS（关键词唤醒）待机。该非终态工具通过独立的受保护
服务端入口执行，不进入原生 ShadowToolExecutor（影子工具执行器）的文件与网络能力目录。

原生 executor（工具执行器）只接受 `READ_ONLY`（只读）能力；`REVERSIBLE_WRITE`（可逆写入）、
`EXTERNAL_COMMIT`（外部提交）和 `DESTRUCTIVE`（破坏性操作）仅保留类型，不加载实现。
该限制不缩减 DSH（后台执行宿主）的工具目录；DSH 使用 Harness（执行环境）已授予的实际工具和权限。
提示词不扩大工具权限，也不另加“一律只读”的限制。原生工具的路径、名称、参数和 effect（影响类型）仍在本地再次校验。

事件处理规则：

- `progress`（影子进度）更新 Product UI（产品界面）并按有效激活及来源合并进入二等信箱，不立即排入普通事件；工具 lifecycle（生命周期）只更新界面；
- 二等信箱在唯一 400 毫秒心跳中每 4 秒检查，普通事件和 `final_silence`（静默前最终检查）优先，空信箱不请求模型；讲话、忙碌或退避时保留状态；
- 普通模型调用携带最新 `shadow.progress`（影子进度列表），上下文冻结及审计成功后按 `version`（版本）消费，构建失败和版本竞争不会丢失新进度；
- 同一激活的相同正文不从进度和信息入口重复触发；停止输入、终态、激活替换和会话结束清理二等状态；
- `information`（影子信息）保持普通事件调度，只进入一次 logical request（逻辑请求）的 `REQUEST_TAIL`（请求尾部），被认领后即丢弃；
- `input_required`、`result`、`failed` 进入持久语义历史；`no_action` 不进入语义历史；
- 文件、网页、工具错误和 Shadow 文本都是不可信资料，不能覆盖系统指令、人格、动作权限或语音协议；
- stale 工具不得执行，stale final 不得发布；
- 用户回答正常进入主会话，Shadow 通过下一次 wake 重新读取上下文，不使用 question ID、reply action 或长期 waiter。

## 资料保留与缓存

Shadow 的活动状态只保留当前运行的有限产品投影；完整 trace 由 runtime 管理。上下文缓存的基本原则是：

- instructions（内置指令）、工具顺序和 schema（输出结构）在 session（会话）内冻结；用户显式保存的人格、资料和自定义指令更新后续请求快照；
- HISTORY 只追加、不重排、不回写；
- 动态时间、revision、run ID、nonce 和服务状态不进入固定前缀；
- 达到上下文预算约 80% 时，在安全边界生成摘要并切换 cache epoch；
- 压缩失败保留旧 trace，不得终止主语音会话。

字段 owner、lane、持久化和测试责任以[缓存契约字段准入表](llm-context-cache-contract.md#字段准入)为准。

## 语音控制唯一入口

- speak（新播报）：只在输出空闲时创建；活动事务排队、播放或结算期间拒绝新请求，拒绝结果随下一次请求尾部反馈，不在播放完成后补执行。
- revision（尾巴修订）：只接管本轮事务未提交尾巴；确认 speech_id（事务标识）、output_generation（输出代数）、sent_chars（已提交字符数）、text（原计划文本）和 text_revision（修订版本）仍与请求快照一致，否则拒绝，不追加或新建。
- cancel（取消）：空文本只停止，非空文本停止并创建替换播报。
- wait（等待）：不变更输出。忙碌时忽略播报不影响通过独立校验的 actions（动作列表）执行。

请求快照在推理准备阶段补交旧事务文本、结算正在发送的块之后生成，并在结果应用完成前冻结后续提交。补交来自已有本地文本，不是 speak（新播报）的追加入口。修订还要求原播报的模型文本生成与本地分段入队都已结束、没有正在发送的块。上述确认字段仅用于执行层核验，不进入模型可见文本；模型按 `continuation_mode`（尾巴修订权限）、`locked_text`（锁定文本）和 `editable_text`（可改文本）选择决策。完整调度规则见 [TTS 运行模式](../guides/tts-runtime.md#模型推理期间的提交边界)。
