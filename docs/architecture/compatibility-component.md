# 兼容性组件与维护交接

兼容性组件维护本体规则、设置迁移和工作区即时盘点。分发器只安装、更新及修复程序本体，并检查组件；组件下载、安装、更新和修复统一由正式程序组件列表承担。系统组件继续判断运行依赖，普通启动继续使用已有轻量检查，不新增启动前完整维修。

实现位于 `apps/desktop/common/src/compatibility.rs`（规则与盘点）、`compatibility_repair.rs`（本体维护）、`component_maintenance.rs`（组件校验交接）及 `voice_terminal/compatibility.py`（既有设置与资料修复）。本规则适用于首次安装、应用更新、完整性维修、本地覆盖发布和新工作区准备；源码修订重新构建交付后才影响已安装程序。

## 安装、更新与维修

1. 分发器核验程序包，通过原有本体事务换入固定文件，保留组件、收据及用户资料。随包模型种子和语音补丁保留在本体资源中，不在分发阶段安装到现用组件目录。
2. 普通更新只核对组件登记、版本和必要文件大小，记录缺失或待更新状态，不下载、清除或重装组件。可用依赖下保留原有设置及故障资料修复；缺少依赖时记录 `settings_pending`（本次设置维护延期），由系统组件配置或导入后的收尾补做，不移到日常启动。
3. 主动完整性维修对现有组件执行单轮完整内容校验。本体文件由分发器从内嵌包修复；确认非法或损坏的受管组件先保存故障交接，再按当前登记路径清除，由本体重新下载修复。普通版本待更新不作损坏删除；未安装的可选组件保持未安装。清除故障运行依赖前持久化设备回退要求，系统组件重建后补做原有设置维护。
4. 管理页真实挂载后，本体通过原有资源任务修复本次发现的问题，提供进度、取消、失败及重试。普通更新的检查记录不发起自动下载；既有随包离线兼容迁移也由组件任务承接，只使用随包资源及已验证本机基础库。
5. 本体维护完成与业务组件就绪分别登记。必要组件继续参与既有启动及功能门禁，可选组件不阻塞无关能力。双路精修、情绪及声学增强模型缺失、不匹配或已确认损坏时，本体轻量检查关闭对应开关；模型更新后由用户重新启用，匹配模型保留用户选择。

## 组件校验交接

`data/state/component-maintenance.json`（组件校验交接记录）保存本次检查结论，不携带下载地址、安装脚本或任意目标路径。

| 字段 | 中文说明 |
| --- | --- |
| `schema` | 记录格式 |
| `workspace_id`、`build` | 所属工作区和本体构建 |
| `operation` | `update`（普通更新，仅显示）或 `integrity`（主动完整性维修，可交接修复） |
| `issues`、`resource_id`、`reason` | 问题清单、组件编号及中文原因 |
| `content_failure` | 完整内容校验确认的故障，后续大小盘点不能撤销 |
| `target` | 组件目标内容身份，普通本体换版后保留同一目标的既有内容故障 |
| `dispatched` | 对应组件子任务是否已经实际创建；准入失败及尚未执行项不消耗交接，已经执行失败或取消的项保留手动重试 |
| `migrations` | 本次交接的随包离线兼容迁移；不能因此下载一般待更新模型 |

组件经过原有完整验证并成功启用，或任务确认当前内容完整可复用后，才清除对应问题。失败或取消保留问题，用户在同一组件列表重试。新主动检查重新生成结论；过期工作区或构建的记录不自动派发。普通本体更新保留目标未变化的既有内容故障，不继承旧自动派发请求。

## 配置、状态与事务

设置字段定义、默认值和完整范围校验继续由既有配置入口维护。分发器不通过安装环境满足配置检查；原有兼容处理中，已选择在线语音但没有配置凭据时回退到本地选择的行为保留，变更后重新进行权威设置校验，本地组件仍交由本体配置。本体事务内的精确字段迁移及原件保留继续存在。

原有资料修复使用 `data/archives/compatibility/<编号>/`（兼容归档），移动前后记录清单。配置、模型注册、声纹、音色和活动会话原件继续保留；归档不自动恢复，系统凭据、普通历史账本、其它模型和滚动备份保持保护边界，不穿透联接或整体清空数据目录。

规则和即时兼容状态的字段含义如下。`config/compatibility.json`（兼容规则）随本体分发，正式模式下规则路径、大小和 SHA-256（内容摘要）须匹配 `app/release.json`（本体清单）声明；缺失、损坏或未知协议进入本体修复，不能静默回退旧规则。

| 规则字段 | 中文说明 |
| --- | --- |
| `schema`、`revision` | 规则格式版本与修订号 |
| `settings_schema_max` | 当前支持的最高设置格式；未来格式归档后按新版默认值恢复 |
| `upgrade_handlers` | 内建迁移声明；目前保留声纹和原生语音迁移，由正式程序组件任务执行 |
| `settings_rules` | 仅允许登记的精确设置字段迁移，随后由权威配置入口完整校验 |

精确设置规则只支持 `rename_field`（字段改名）、`remove_field`（移除确定旧字段）和 `replace_value`（替换确定旧值）。规则中的 `id`（规则编号）、`min_schema`／`max_schema`（适用的旧格式范围）、`field`（精确对象字段路径）及 `expected`（预期旧值）必须明确；字段改名使用 `target`（目标字段），值替换使用 `value`（新值）。不接受任意文件路径、脚本、通配符或删除指令；改名目标已有值时不覆盖。

`data/state/compatibility.json`（工作区兼容状态）用于诊断与本体维护交接，不能独立充当启动凭据：

| 状态字段 | 中文说明 |
| --- | --- |
| `workspace_id`、`target_build` | 工作区身份与目标本体构建 |
| `rules_revision`、`rules_digest` | 当前规则修订号与内容摘要 |
| `revision`、`checked_at_ms` | 观测变化时递增的代次与最近实际核对时间 |
| `stable` | 本体和组件是否没有未完成事务 |
| `status`、`tasks`、`required` | 整体兼容结论（`needs_check` 待核对、`needs_repair` 待修复、`compatible` 本次盘点通过）、待处理事项及必需标志 |
| `enforcement.phase` | 本体兼容维护阶段（`pending` 待处理、`settings_pending` 设置维护延期、`complete` 本体维护完成）；组件修复另经组件校验交接记录 |
| `enforcement.reset_devices` | 受管计算依赖清除后，由后续设置修复消费的设备回退要求 |
| `settings_sha256`、`observation_digest` | 最近盘点记录的设置摘要与本轮本体、规则、组件观测摘要；完成状态仍须通过权威设置回执 |
| `applied_settings_rules` | 本体事务实际执行的精确设置规则编号 |
| `preserved_record`、`preserved_settings` | 旧派生记录及设置原件保留位置，不是待执行规则 |

`data/state/settings-validation.json`（权威设置校验回执）由正式程序的设置入口生成，绑定设置格式及实际落盘摘要。外部修改不能沿用旧回执；原生层关闭增强布尔开关时只续接原本有效的回执，不为未经校验的设置签发凭据。损坏、未来格式或超大的兼容派生记录先保留原件再重建，不阻断受管运行依赖的修复。

本体、设置及原件保留文件继续通过同一事务提交，失败或未提交中断恢复原组合。历史组件迁移事务仍能恢复，新安装不再生成这类组件变更。组件候选验证、换入与回滚沿用本体资源管理器已有事务。

原有故障资料兼容处理继续保留：`data/config/local.yaml`（本机覆盖配置）加载失败时归档并恢复新版默认值；`data/config/model-registry.json`（模型注册配置）无法迁移时归档并恢复空配置，系统凭据不删除；编码损坏的 `.env.local`（本机环境配置）退出加载并私密归档，不记录原始内容；`data/config/runtime-resources.json`（运行资源策略）在加载重依赖前检查，非法时归档并恢复安全默认值。

声纹注册索引、模板向量或特征格式不兼容时归档对应档案并恢复未注册状态；旧模型的专属档案按上文迁移规则退出活动路径。音色库索引、引用素材或活动版本不合法时归档该音色库，清除悬空选择并由默认音色初始化流程重建。活动会话数据库与其 `-wal`（预写日志）、`-shm`（共享内存文件）同组归档并启动新会话；普通历史账本不自动清空。归档前登记文件组位置，主文件已移动时重试仍会继续处理剩余日志。

业务资料保存在 `data/archives/compatibility/<编号>/`（兼容处理归档），每次移动前后更新 `manifest.json`（归档清单）；早期设置回退与损坏兼容记录也会保留原件。归档不自动恢复到活动目录，也不参与启动扫描。处理不得穿透目录联接或链接；不得整体清空数据根目录、现用组件或滚动备份。

## 随包组件迁移

`component_upgrade.rs`（组件兼容迁移）承接旧安装器的离线能力。CAM++（当前声纹模型）任务使用随包官方种子，校验大小、内容摘要和迁移目标后签发组件收据。旧 WeSpeaker（旧声纹模型）目录、旧模型专属档案及明确登记为旧模型的根档案才进入处置清单；当前声纹档案和身份不明的根档案保留。其它模型的清单变化必须由有效组件收据确认，否则迁移延期，旧模型、档案和原清单保持原状，本体更新仍可完成。

这些任务在真实管理页挂载后由正式程序创建。CAM++ 的清理清单只接受明确登记的旧模型目录及兼容组件列出的精确档案路径；只有根注册索引明确指向 WeSpeaker 时才清理旧根档案。目标模型已完整匹配时可复用现有安装；任何其它已保留模型的内容不符合声明时，整笔声纹迁移延期。迁移延期或失败不会回滚已经提交的本体更新。

audio.cpp（原生语音框架）任务优先使用受管目录，兼容旧 `runtimes/audiocpp`（旧语音运行目录），逐文件确认基础库后离线应用随包补丁。当前收据匹配时复用组件；坏收据可用有效基础库修复。基础库不兼容、空间不足或补丁损坏时保留旧组件并显示任务失败；普通更新交接不下载官方归档，用户在组件列表更新时才允许使用固定网络来源。

本体事务与组件事务分别提交。`tmp/native-install.json`（组件启用事务）把当前组件、模型总清单、本体组件登记及经确认的旧声纹处置项纳入同一恢复过程；未提交中断或启用失败时恢复原组件、原档案及原登记，提交成功后才回收旧内容。旧格式组件事务继续按原路径恢复。组件任务失败不会撤销已成功提交的程序本体更新。

## 完整性维护与单轮校验

关于页“检查更新”查询最新发行；“校验完整性”使用本地版本及构建匹配的 `maintenance/VoiceTerminalSetup.exe`（维护分发器）。缺少时由正式程序下载对应版本，应用更新分发器独立暂存在 `tmp/app-update`（应用更新暂存）。分发器本身不下载组件。

分发器强制完整性检查确认现用受管组件内容非法或损坏时，必须先把检查结论持久化到 `data/state/component-maintenance.json`（组件校验交接记录），再按当前清单登记路径清除该组件。清理只接受固定运行环境目录或当前资源清单登记的具体组件目录；先恢复未完成事务并实际复核，下载或修复失败本身不是删除理由。正式程序随后使用原有下载、校验和启用流程重建它。普通更新只检查登记、版本和必要文件属性；待更新状态本身不是损坏证据，不能触发删除。清除运行依赖前还要持久化设备回退要求；设备设置在系统组件重建并完成权威设置处理后恢复。

只有正式程序实际创建了相应子任务，才将该组件标记为已派发。准入失败和尚未启动的项目留待后续处理；执行失败或取消的项目保留交接并提供重试。组件通过完整验证并成功启用，或任务确认现有内容完整可复用后，才清除相应故障记录。普通更新中的一般待更新问题不会创建自动下载任务；未安装的可选组件仍保持未安装。

普通启动只检查规则、依赖登记、组件收据、必要文件属性与设置身份，不遍历完整运行环境或代理目录，不计算模型完整摘要。实际格式、推理和设备可用性由加载器判断，组件问题沿用功能降级逻辑。双路精修、情绪和声学增强模型缺失、待更新或已确认损坏时关闭对应开关；模型由用户更新后重新启用，匹配模型则保留用户选择。

主动维修保留 `VerificationSession`（单次校验会话）、统一有界文件池和本轮目录变化监视，用检查结果生成交接问题。正式程序修复时继续验证下载缓存、候选写入和目标内容，成功启用后刷新清单；单项完成不把其它失败项标记为已修复。

完整性校验的只读扫描阶段不写入新的维护门禁，也不修改运行资源策略；用户取消或关闭校验窗口时，保留本轮之前的兼容状态及维修交接。扫描完成并开始持久变更后，取消停止尚未开始的组件清除，已经开始的配置与资料处理使用独立收尾令牌完成，随后做轻量最终盘点，再返回 `MaintenanceOutcome::Cancelled`（取消已收尾）。安装器在此期间显示收尾进度，退出请求等待收尾结束，不继续启动正式程序；正常取消不显示为组件损坏。真实设置处理失败仍保留错误及待修复状态；运行环境缺失或已清除时继续保留 `settings_pending`（设置维护延期）和设备回退要求，不能因取消清掉既有维修事项。
