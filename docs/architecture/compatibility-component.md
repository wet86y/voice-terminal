# 兼容性组件与强制升级

兼容性组件统一维护环境、资源组件、持久化设置和启动资料变更。它由 `apps/desktop/common/src/compatibility.rs`（规则与即时盘点）、`compatibility_repair.rs`（安装器强制修复）及 `voice_terminal/compatibility.py`（配置与故障资料处理）组成。安装器和正式程序共用该组件，后续迁移能力继续在这里扩展。

## 强制升级路径

分发器不能把旧配置不合法、未来设置格式或环境不兼容作为拒绝更新的理由。执行顺序为：

1. 核验并换入新版程序，尝试精确迁移旧设置及复用当前组件。
2. 尝试修复环境；失败后恢复未收尾事务，重新检查现用目标，确认仍不符合新版要求的受管资源才清除。
3. 使用新版正式程序的权威设置合并、范围校验及配置应用入口修复配置；仍不合法的部分回退默认值，并持久化有效配置。
4. 从当前版本锁定的来源下载、组装和启用必需组件；已安装的可选组件也尝试修复，缺失可选组件继续保持非阻塞。
5. 复核当前环境、配置、组件摘要、程序身份和未完成事务；全部必需启动条件成立后才能结束修复并交接正式程序。

Node.js（脚本运行环境）继续沿用分发器起点校验，兼容性组件不新增安装、下载、私有环境或发现逻辑。

配置损坏或格式过新时，先保留原件，现用文件强制回退默认输入。原始错误配置不会继续参与加载。完整设置修复复用正式程序的字段定义，避免维护另一套默认值及范围校验。

本体提交后的修复中断保留新版程序、已验证下载缓存和修复阶段，重试继续处理，不回滚到旧的不兼容配置或组件。网络中断、磁盘不足、文件占用及权限错误不能被报告成兼容成功；安装器在实际修复完成前不交接业务启动。组件换入本身保留原有文件事务，防止留下半个组件；事务恢复后继续强制修复。

清除仅接受固定运行环境路径及当前资源清单登记的具体组件目录。先恢复事务并实际复核，避免把提交后的清理报错当作坏组件而删掉已经修好的新目标。下载报错本身不是删除证据。

## 故障资料与会话

配置、注册资料和音色也可能是启动故障来源，不作为强制兼容的豁免项：

- `data/config/local.yaml`（本机覆盖配置）加载失败时归档，恢复新版默认配置；产品设置经过正式程序自身的校验和默认回退。
- `data/config/model-registry.json`（模型注册配置）无法迁移时归档并恢复新版空配置，系统凭据不删除；编码损坏的 `.env.local`（本机环境配置）也退出加载并保密归档，不记录原始内容。
- `data/config/runtime-resources.json`（运行资源策略）在重依赖加载前检查，非法策略撤出并恢复安全默认值，避免修复解释器时反复被同一配置阻断。
- 声纹注册索引、模板向量或特征格式不兼容时归档该档案，恢复未注册状态；退役声纹模型的注册资料退出当前加载路径。
- 音色库索引、引用素材或活动音色版本不合法时归档该模型音色库，清除悬空选择，交由默认音色初始化流程重建。归档后中断的重试也检查缺失索引和悬空引用。
- 活动会话主数据库及其 `-wal`（预写日志）、`-shm`（共享内存文件）同组归档，启动新活动会话；普通历史账本不因升级自动清空。归档先记录组位置，主文件已移走也继续处理剩余日志。

业务资料归档位于 `data/archives/compatibility/<编号>/`（兼容处理归档）。每次移动前后写入 `manifest.json`（归档清单）。早期配置回退与损坏兼容记录另以 `data/state/compatibility-preserved-<摘要>.json`（原件保留文件）保存。归档不自动恢复到现用目录，也不参与启动扫描。不能穿透目录联接与链接；不整体清空真实数据根目录、现用组件或滚动备份。

## 规则与状态

`config/compatibility.json`（兼容规则）随版本分发。正式模式必须有 `app/release.json`（发布清单）中的 `compatibility_engine`（兼容协议声明），规则路径、大小和内容摘要也必须匹配发布清单。缺失或未知协议进入程序修复，不能静默回退旧规则。显式源码调试使用当前源码规则。

| 规则字段 | 中文说明 |
| --- | --- |
| `schema`、`revision` | 规则格式与修订号 |
| `settings_schema_max` | 当前支持的设置格式；超出范围归档并恢复新版默认值 |
| `upgrade_handlers` | 受支持的内建迁移处理器；声纹和原生语音迁移由此统一调度 |
| `settings_rules` | 精确字段迁移，先迁移、再进入权威业务校验 |

精确迁移支持 `rename_field`（字段改名）、`remove_field`（移除确定旧字段）、`replace_value`（替换确定旧值）。每条规则包含唯一 `id`（编号）、`min_schema`/`max_schema`（旧格式范围）、`field`（精确对象字段路径）和 `expected`（必须匹配的旧值）；改名提供 `target`（目标字段），替换提供 `value`（新值）。不接受任意文件路径、脚本、通配符或删除指令。改名目标已有值时不覆盖，交给后续业务规范化处理。

`data/state/compatibility.json`（工作区兼容状态）用于交接和诊断，不能独立充当启动凭据：

| 状态字段 | 中文说明 |
| --- | --- |
| `workspace_id`、`target_build` | 本次工作区身份及程序构建 |
| `rules_revision`、`rules_digest` | 当前规则修订与内容摘要 |
| `revision`、`checked_at_ms` | 观测变化时递增的代次及本次实际核对时间 |
| `stable` | 是否没有未完成本体或组件事务 |
| `status` | `needs_check`（待核对）、`needs_repair`（继续修复）、`compatible`（本次盘点通过） |
| `tasks`、`required` | 当前处理事项及必需标志；可选组件缺失仍不阻塞业务 |
| `enforcement.phase` | 强制升级阶段，只有 `complete`（完成）允许交接 |
| `enforcement.reset_devices` | 旧环境清除后必须回退计算设备，撤销过期显卡能力登记 |
| `settings_sha256` | 实际校验过的配置内容摘要 |
| `observation_digest` | 本次程序、规则、组件及配置观测的摘要 |
| `applied_settings_rules` | 本体事务实际执行的精确设置规则编号 |
| `preserved_record`、`preserved_settings` | 旧派生记录及设置原件位置，不作为待执行规则 |

`data/state/settings-validation.json`（设置校验回执）由权威配置入口生成，绑定格式及实际落盘摘要。安装器修复和正式程序正常保存都会更新。外部修改不能继承旧回执，失败盘点不能把未经验证的新内容摘要升级成成功凭据。损坏、未来格式及超大兼容派生记录采用流式摘要保留后重建，不能因此阻断环境修复。

## 即时性与事务

普通启动只读取当前规则、依赖锁、环境记录、组件收据、必要文件存在性与大小及设置身份，不递归盘点环境/代理目录，不计算模型完整摘要。组件问题按功能降级并引导手动校验完整性，不阻塞其它功能启动；缺少解释器、未完成事务或强制修复仍保留管理界面。宿主已经发现的失败在同次盘点内合并。模型推理、云端连通和硬件能力仍由各自的实际加载检查负责，不能从静态记录推导为已验证。

同一进程内扫描与写回共用互斥锁，防止旧扫描晚写覆盖新结果。安装和强制修复持有产品工作区互斥句柄。组件换入前先建立事务并使旧结论失效，任务成功、失败或取消后重盘。相同观测不重复刷盘，接口核对时间仍来自本次读取。

本体准备阶段的产品设置候选、兼容记录和原件保留文件进入同一更新事务。本体未提交时中断，恢复原组合；提交后进入强制修复，不因旧配置格式错误回滚旧版。恢复器只允许明确登记的精确数据路径，不放开整个数据目录。

## 后续维护

环境依赖、组件版本、持久化格式及启动资料变化优先在本组件新增检查或处理器。验证应覆盖损坏输入、默认回退、重复执行、中断恢复、事务收尾及最终成功门槛。普通版本匹配已自动参与盘点，无需为每次版本变化添加空迁移。

配置默认值和完整字段校验继续以正式程序为依据；原生层只承担启动修复所需的最小结构检查。新增协议与动作必须同步支持、中文说明和验证，不能让规则获得任意执行能力。复杂模型资料转换继续使用内建处理器和文件事务；已知业务代码缺陷仍需代码修复，不能通过反复清理数据掩盖。

## 完整性维护与单轮校验

“检查更新”查询最新发行；其右侧“校验完整性”只接受本地版本及构建。`maintenance/VoiceTerminalSetup.exe`（长期维护分发器）与 `maintenance/installer.json`（已验证发行身份）固定覆盖；旧 `tmp/app-update`（应用更新下载缓存）仅在摘要匹配后移入。缺少匹配分发器时显示“下载校验程序”，固定请求对应版本，不回退最新版本。下载完成后由用户再次点击启动维护。

`--repair-config`（当前构建维修交接入口）沿用一次性工作区及进程身份配置，停止旧进程后取得独占锁。`data/state/product-identity.json`（已提交本体身份）独立于待修复的 `app/release.json`（本体清单）；旧工作区可使用兼容状态中的目标构建，避免清单损坏反而无法启动修复。

现有环境与已安装模型、代理汇总到单轮最多四线程的内容验证池。`VerificationSession`（单次维护校验会话）只在本次维护内复用结果，目录变化监视及目录身份检查使外部写入、添加文件或整体替换撤销旧结果；无法监视时不缓存。写入或替换前显式失效，修复后的新内容仍需验证。最终兼容盘点复核组合、配置及事务，不再重读刚验证过的未变化组件。安装包的两层清单使用完整路径、大小及摘要映射比较，拒绝重复及遗漏，不为验证第二层清单再读取程序文件。

组件页面轮询只读任务快照；挂载、维护提交及手动刷新才读取轻量组件状态。显卡新检测记录增加 `validation_identity`（解释器及受管清单的轻量身份），日常启动不再重算环境与模型树指纹；旧登记保留历史检测结果，设备实际可用性仍由当前后端确认。完整内容判断由分发器维护负责。
