## 实际目录与入口

```text
项目根目录/
├─ apps/、voice_terminal/、integrations/  当前业务源码
├─ config/、tests/、scripts/、docs/       模板、测试、工程工具和资料
├─ node_modules/                        包管理器标准开发依赖
├─ package.json、package-lock.json 等    工程配置与依赖锁
└─ .local/                              不纳入版本控制的本机资源
   ├─ VoiceTerminal.exe                 唯一正式启动入口
   ├─ VoiceTerminalUIDemo.exe           前端演示入口
   ├─ portable.json                    第二版唯一组件路径配置
   ├─ Verify-Package.ps1               当前安装的完整摘要校验

   ├─ runtimes/python/                 唯一后端环境
   ├─ runtimes/dsh/                    唯一生产代理宿主，含脚本解释器
   ├─ runtimes/webview2/               唯一网页渲染引擎
   ├─ models/                          六类必要业务模型
   ├─ data/                            当前真实用户数据和迁移导入内容
   ├─ backups/user-data/               一份滚动持久数据备份

   ├─ tools/rust/、testing/            原生工具链和轻量测试工具
   ├─ cache/                           可回收日志、开发缓存和验收记录
   ├─ tmp/                             验收完成后为空
   └─ releases/                        当前为空；明确导出后保留最新交付包
```

正常入口都使用 `.local/portable.json`（便携配置）的 `schema=2`（第二版格式）。程序、后端解释器、模型、代理宿主、网页引擎和用户数据分别固定在上述位置，Node（脚本运行环境）从代理宿主运行清单解析。正常运行不读取旧启用记录，也没有另一套解释器、模型搜索退路或旧路径联接。旧路径仅在一次性迁移、清理代码及标明历史的检查记录中保留。

正式程序、源码开发和无界面后端共用同一业务环境和真实数据。代理上游源码、类型工程与开发依赖仅作为固定构建缓存保留；业务统一使用生产组件和一套持久状态。测试复用正式 Python（后端解释器）及独立轻量测试工具，不再保留完整计算测试环境。

## 后续使用

双击 `.local/VoiceTerminal.exe`（正式入口）启动；关闭窗口隐藏到托盘，使用应用或托盘的退出操作才能释放业务进程。演示入口为 `.local/VoiceTerminalUIDemo.exe`（仅前端）。源码命令继续保留：

```powershell
npm run dev                  # 源码业务开发，共用正式环境与数据
npm run dev:ui               # 演示开发，不启动业务服务
npm run desktop:publish      # 构建 → 校验 → 停机检查 → 换入 → 验证 → 回收
.\scripts\start.ps1          # 无界面后端
.\.local\Verify-Package.ps1  # 当前安装的完整摘要校验

# 重要持久数据的唯一滚动备份：先退出业务实例。
.\.local\runtimes\python\python.exe -B -X utf8 scripts/local-admin.py backup

# 只有明确交付时执行，覆盖最新包；不包含真实用户数据。
.\.local\runtimes\python\python.exe -B -X utf8 scripts/package-desktop.py
```

常规更新以源码提交与覆盖发布控制版本，不再主动制作模型、环境或整包备份。组件变化时在项目临时区构建、校验完整候选，再由同一更新事务换入。完整字段、组件参数和缓存规则见[本地目录与覆盖发布](local-layout.md)。
