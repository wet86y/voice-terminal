# 图片与文本统一上下文：修订记录

日期：2026-10-14。代码修订已完成。本文件记录最终契约、实现依据与验收边界。

## 最终契约

图片与文字属于同一有序会话历史。程序负责获取、加载、构造原生视觉内容及同步共享上下文；主 LLM（大语言模型）请求 DSH（后台执行宿主）时自动携带对应图片，不需要模型再决定调用读图工具。

“不重复发送”指不重复追加观察事件、不重复同步已接收消息，并尽量复用已上传字节。无状态模型接口的后续请求仍在原位置携带既有图片块。请求完成、激活结束、停止监听及关闭截图开关都不会删除已经冻结提交的观察消息；正常会话整理或重置可以建立新基线。归档图片不会自行重放进新会话。

用户最新确认允许沿用 DSH 默认附件库；本次不实现截图专属临时库，也不约束该库对真实文件的永久保存。语音主线仍按现有规则保存唯一编码、使用可重建文件缓存并归档。

## 官方协议依据

- Responses API（响应接口）无状态，不支持 previous_response_id（上次响应标识）或 conversation（服务端会话续接）；客户端每次提供完整历史。[官方响应接口说明](https://api-docs.deepseek.com/guides/responses_api/)。
- 图片用原生 input_image（图片输入块），通过 image_url（内联或远程图片地址）或 file_id（已上传图片标识）提供，二者互斥；detail（图像处理方式）在使用文件标识时被忽略。[官方内容块定义](https://api-docs.deepseek.com/api/create-response/)。
- 保留的 Chat Completions（聊天补全接口）使用 image_url（图片地址块）或 file（文件块）；文件块直接携带 file_id（文件标识）。[官方聊天接口定义](https://api-docs.deepseek.com/api/create-chat-completion/)。
- Files API（文件接口）允许复用已上传图片；同一接口密钥下的文件可跨接口家族引用。Anthropic Messages（消息接口协议）引用文件需要文件测试版请求头。[官方文件接口说明](https://api-docs.deepseek.com/guides/files_api/)。
- 缓存是对重复输入前缀的计算复用，不是服务端会话保存，也不保证每次命中。主模型与 DSH 的提示、工具及消息结构不同，本实现不承诺共享推理缓存。[官方上下文缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。

### 消息与提交

message_id（逻辑消息标识）使用截图标识；conversation_id（会话标识）限定附件来源；parts（有序内容块）依次是来源说明、全局图、局部图。图片块保存 attachment_id（附件标识）、mime_type（媒体类型）、sha256（字节摘要）及成品尺寸，编码仍只在图片记录保存一次。

捕获成功先建立气泡；首次有效请求冻结时立即提交观察到台账并认领信箱。此边界与已提交文字一致：网络失败不会撤销逻辑输入，后来到达的文本或截图排在它之后。主模型 HTTP（网络请求）受理后更新“已发送”；随后响应解析失败不倒改该受理事实。尚未冻结的截图可以被新结果替换或随生命周期取消。

观察的模型内容只含固定捕获事实，不含随后变化的发送状态。双图第一轮就属于历史区，下一轮不会从请求尾部移动到别的位置。重试复用同一截图身份，原请求结束只释放派发引用。

### 上传及恢复

主模型首次展示前按图片成品摘要选择稳定来源。文件上传成功后历史复用该文件标识；第一次上传不可用则本凭据作用域固定内联传输，避免以后反复更换来源。映射检查点只保存摘要、文件标识、有效期及凭据作用域摘要，不保存凭据和重复编码。

过期或服务端确认删除的文件会失效并重建；网络恢复仍受现有重试次数约束。重建保持逻辑消息和成品字节不变，实际传输前缀可能改变，日志明确标识缓存重建。DSH 沿用其原生适配器的上传缓存，不与主模型私有映射混用。

### DSH 自动同步与去重

request_shadow（后台请求动作）继续只负责唤醒；完整快照、增量、未领取消息合并、门禁、压缩后的接续与 get_latest_context（最新上下文工具）共用图片转换。内部 attachment.read（附件读取回调）自动执行，不暴露为需要模型选择的读图动作。

同一绑定的上下文操作串行，双图全部收纳后才注入；每次异步等待后检查代次与取消状态。epoch（代次）与观察消息标识决定身份；同一身份出现不同正文会报告冲突，不能通过重新编号绕过去重。两次不同观察即使像素完全相同，仍是两个事件；字节摘要相同时可复用原生附件引用。

来源标记随 user/message（持久用户角色消息事件）保存，最新上下文工具的接收身份随 tool/result（工具结果事件）的元数据保存。每条记录只携带本批身份，不复制全部累计索引。仅宿主投影从完整追加日志折叠身份，通过 sessionProjections.stateOf（会话投影读取）恢复，因此普通压缩后的模型表面不需要再包含原身份标记。没有新增已弃用的全日志扫描调用。

实际请求前依据最终 provider（模型提供方）及 model（模型标识）检查视觉能力，明确拒绝纯文本路由。该检查覆盖正常模型切换；适配器注册恰在查询与派发之间变化的极小竞态未另行改造宿主分发器。

### 预算与正常整理

主模型及本地影子循环按图片单独计入保守视觉令牌成本，不对编码执行文本分词。语音会话整理模型会获得有归档及附件标识说明的原图；分段提取后最终合并只使用文字笔记。纯文本整理模型不能默默跳过图片，会保留原材料并明确失败。

DSH 常规压缩继续按整个历史区间处理。额外守卫阻止宿主在图片预算错误后单独记录 image/offload（图片卸载事件）：普通请求超限明确失败，整理请求超限同样保留完整材料；不会把“只删图”伪装成上下文整理成功。本次未新增自动分段修复 DSH 图片预算的策略；可通过正常会话整理建立更小的新基线。

日志、状态及审计展示只包含描述、摘要、尺寸和字节数；接口回显图片的错误正文也脱敏。请求摘要仍针对实际发送的正文计算。前端现有双图气泡、查看器和当前会话取图通路沿用。
