# 设备连接名称同步修复与验证

日期：2026-11-22（香港时间）。源码修订基于 8a2bf4a。本次完成设备连接页名称同步修复、定向回归、前端构建与文档归档，尚未覆盖正式程序或执行真实双机局域网改名复测。实际已交付版本见[当前交付记录](../releases/current-release.md)。

## 故障与双端链路

用户在局域网互联测试中发现：服务端重命名后，客户端仍显示旧的服务端名称；服务端读取客户端名称则可以刷新。本轮只修订设备连接中的设备显示名称。

- 双端本机名称由设备配置的 server_name（设备显示名称）保存。服务端改名会重新发布服务公告，远程客户端改名会更新客户端存在公告，稳定设备编号和配对身份保持原值。
- 服务端已有 device_inbound_status（入站状态查询）读取可信客户端对应的当前公告名称，设备页沿周期补查和刷新更新入站列表。
- 客户端的已配对服务端名称原先固定读取 paired_host.display_name（配对时保存的名称）；自动发现还会在已连接或已选择搜索目标时跳过，即使断开时查到新公告，也只更新可用状态。因此名称发布正常仍不能更新客户端显示。

对应实现为[设备配置](../../apps/desktop/common/src/device_config.rs)、[局域网发现与公告](../../apps/desktop/common/src/device_discovery.rs)、[桌面设备保存及发布入口](../../apps/desktop/src-tauri/src/main.rs)和[设备连接页](../../apps/frontend/src/management/DeviceSettings.vue)。本轮未修改原生代码。

## 修订行为

客户端在连接中与断开时均沿现有约十秒的周期补查已配对服务端名称；手动刷新和搜索设备也更新同一名称。发现结果只匹配当前 host_id（稳定服务端编号），连接列表、搜索区已有对应条目、连接提示和相关确认弹窗使用一致的名称。

最新名称保存为页面内的显示缓存，独立于原配对配置。轻量配置补查不将它改回旧名称；发现失败或只发现其他设备时保留本页最近名称。重新进入页面且未取得新公告时，仍以配对时名称作为回退。

运行模式或配对目标变化会清除显示缓存并递增 pairedDiscoveryGeneration（配对显示范围代次），自动发现和手动搜索均拒绝过时代次结果，覆盖目标切换后又回到同一编号的情况。名称更新不保存配置、不新增配对、不建立连接，也不启动任务或媒体通道；发现可用性不替代认证连接状态。

## 验证结果

修改前运行新增回归，客户端方向的 4 项用例因持续显示旧名称失败；服务端入站名称刷新用例通过。修复及补齐目标切换竞态用例后，最终结果如下：

| 验证内容 | 结果与范围 |
| --- | --- |
| 设备连接页回归 | 61 项通过；新增覆盖连接中与断开时改名、恢复默认名称、旧配置补查、手动搜索与刷新、搜索选择保留、发现失败及其他设备结果、切换目标及切回原目标后的迟到结果、服务端刷新客户端名称。 |
| 名称显示工具回归 | 3 项通过，保留基础随机名称与同名设备区分行为。 |
| 正式前端构建 | 通过，包含 Vue（界面框架）与 TypeScript（类型化脚本语言）类型检查；产物位于现有受管构建目录。 |

## 验证与交付边界

本轮通过项目专用 instance.status（实例状态）入口尝试查询时，本机代理调试通道不可用，未据此宣称完成正式界面或双机验收。自动化回归使用受控的原生接口响应，验证前端状态更新与名称显示；没有重新执行真实局域网公告收发、双机配对或语音通道全链路。

本轮未覆盖本机正式程序、远端服务端或用户配置，未生成分发安装器或公开发行。后续部署后，应在实际设备连接页分别对服务端和客户端重命名，验证已连接、断开、手动刷新和页面重新进入时的名称表现，并确认原配对与实际连接状态。操作步骤见[设备连接与远程配对](../guides/device-connection.md#设备名称)。
