# 组件更新与启动交接梳理（2026-10-22）

本次只修改源码并验证，没有覆盖本机正式程序、启动真实麦克风或下载大型组件。检查范围为原生资源下载与导入、固定目录换入、业务宿主启动与恢复、前端订阅、组件重试，以及工作区和程序本体的交接边界。

## 生命周期与边界

| 场景 | 当前处理 |
| --- | --- |
| 首次启动、首次安装后手动启动 | 保留启动画面、必要条件和兼容门禁；未曾运行的服务不会因下载完成自动启动 |
| 程序已进入主界面后的组件下载、导入、共享环境替换 | 下载和候选验证使用原任务进度；换入时保留主页面，通过原生恢复状态驱动现有热切换卡 |
| 后端重建 | 必须重新取得原有网页端口及开发代理端口，复用同一窗口的私有会话；新进程仍执行实际模型加载 |
| 恢复失败或宿主异常退出 | 保留主界面，暂停业务连接，状态卡显示失败并提供原生重试入口 |
| 组件或能力单独重试、运行设备及语音后端切换 | 继续使用既有运行操作契约；完成首次入场的页面不会因后续启动快照再次显示全屏启动画面 |
| 工作区迁移、程序本体更新 | 仍由独立目标进程或安装器交接；目标进程从新窗口状态开始，不复用源窗口的内存会话 |

需释放文件占用的资源维护仍可能重建业务进程。此处保证的是主页面和恢复反馈连续，不承诺正在进行的麦克风采样或播报无中断。

## 发现并修复的问题

| 原问题 | 修正与验证依据 |
| --- | --- |
| 每次资源启用先导航管理页，恢复再导航新入口并重做首次启动盘点 | 将首次启动、受控资源激活、运行期恢复分开；完成首次启动后保持页面，通过原生事件和补查报告恢复 |
| `ready`（网页入口握手）被当作模型和业务恢复完成 | 以对应服务代次的 `startup_result`（真实启动尝试终态）为恢复依据，资源事务收尾后才结束状态卡 |
| 本次资源目录已换入、待提交的记录被误判为遗留安装 | 只有持有资源启用锁的内部恢复可以接纳 `swapped`（已交换目录）事务；首次启动、普通故障恢复及本体事务仍阻塞 |
| 初始检查与资源换入可并发 | 启动检查和维护停机共用交接锁；自动启动同样检查资源任务准入 |
| 旧宿主退出后停止状态订阅，或旧鉴权失败将新会话标为失效 | 离线时暂停连接，恢复后重建订阅；请求和监听增加代次隔离，丢失整轮事件后仍能由原生补查接回 |
| 重建宿主随机生成新会话或更换端口，原页面不能连续使用 | 网页来源及会话仅在内存和私有管道中交接；新端口监听必须匹配原来源，离线时禁止重新导航到旧端口 |
| 其它缺失模型阻止原降级服务恢复，逐项补齐可能反复停机 | 恢复既有服务以运行环境及实际能力为准，不要求无关模型全部安装；更新前可用的核心能力仍不能无声退化 |
| 进程状态查询失败被误当成已退出；显卡检测忽略恢复错误 | 无法确认进程状态时拒绝资源激活；显卡检测保留并报告服务恢复失败 |
| 开发代理重启导致 HMR（源码热更新）自动刷新页面 | 同一窗口保留开发端口与派生令牌；经原生确认宿主重新就绪后重建模块关系并重连 |
| 开发服务连续重建后残留文件监听器，测试不能退出 | 拒绝关闭期间的新请求，先等待公开的模块请求排空接口，再关闭开发服务器；重复验证无文件监听器残留 |
