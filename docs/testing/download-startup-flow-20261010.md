# 下载、状态刷新与首次启动修复

本轮修复组件下载完成后卡片状态滞后，以及首次组件安装就绪后点击“启动程序”缺少反馈、必须重进的问题。新版管理页可直接启动：点击后立即显示统一启动动画，展示当前校验组件和共享进度条；Voice Server 快速核对清单、文件集合与大小，模型和 DSH 执行完整摘要复核后才建立服务入口。固定程序与分发安装器的当前构建编号及交付摘要见[当前交付记录](../releases/current-release.md)。

## 原因与刷新规则

原清单请求合并逻辑会把下载完成时的新刷新请求并入已经在途的旧请求，旧请求返回后仍显示下载前状态。页面只在挂载时读取一次任务快照，丢失终态事件后不能主动恢复。原手动启动只请求后台启动，没有先切到加载画面；宿主还持有首次组件安装前解析的代理解释器路径。

现在每次清单请求都有刷新代次，在途请求遇到新刷新要求时丢弃旧结果并重新读取。原生任务事件与补查快照携带创建时间和修订号，迟到事件、旧重试轮次不能覆盖新状态。一个任务先启用共享语音环境、继续下载模型时，也立即刷新已提交环境的组件卡片。

| 时机或字段 | 中文说明与行为 |
| --- | --- |
| 任务完成、失败、取消，或新增已启用组件 | 立即要求重读最新组件清单 |
| 活动任务补查 | 每 2 秒补查轻量任务快照，随后刷新清单；网络进度持续到达也不会推迟计时 |
| 空闲清单刷新 | 每 10 秒刷新；窗口恢复焦点时立即补查 |
| 实际刷新完成时间 | 卡片区域显示最近一次成功读取清单的时刻 |
| `resource_jobs`（资源任务快照接口） | 只读取宿主内存中的任务记录，不重复执行环境检查 |
| `created_at`（任务创建时间） | 毫秒时间戳；同一任务重新下载时递增，用于区分任务轮次 |
| `revision`（任务修订号） | 每次任务状态变化递增；事件与补查共享顺序 |
| `installed_resources`（已启用组件编号） | 事务提交后立即发布，供页面刷新已就绪组件 |

补查间隔是触发请求的计时规则，实际显示还需等待磁盘清单读取。页面卸载后清理监听和定时器，请求不叠加；保留全部活动任务和最近八条终态记录。普通进度事件最多每 100 毫秒广播，状态文件最多每秒持久化一次；阶段切换、安装提交与任务终态立即广播并持久化。

## 首次下载后的启动

“启动程序”在组件、接口配置与任务状态允许时可点击。界面先显示启动动画并防止重复点击，原生宿主随后导航到随包启动页，在后台线程执行组件校验。首次安装的 DSH（代理执行宿主）路径会重新解析，开发模式和工作区身份保持原值，不依赖退出重进。

启动页只显示当前组件名称，不显示文件计数或校验阶段细节。Voice Server（语音服务）核对清单、完整文件集合、链接与文件大小，不读取 31,000 余个文件的内容；其进度按已盘点文件数推进。模型和 DSH（代理执行宿主）仍执行完整 SHA-256（文件摘要）复核，按摘要已校验字节累计到全组件共用的进度条。同长度内容损坏会被模型和 DSH 摘要校验拦截；Voice Server 的同长度内容变化由安装、导入或更新时的完整摘要校验发现。已有缺失或待更新组件时直接返回管理页，避免扫描不能运行的旧组件。校验可取消，取消后可再次启动；失败也不会残留重复启动锁。

全部组件下载完成后仍由用户手动启动；此前已有服务的维护任务则按原恢复意图，在全部组件校验通过后恢复。后台启动失败继续显示安全错误信息，接口配置门禁保持有效。

## 下载、复制及校验优化

固定依赖包和模型文件共用最多四条全局下载通道。单请求缓冲区复用，分段请求上限由 4 MiB（兆二进制字节）增加到 8 MiB，顺序传输按批次写入并刷新；网络缓冲区上限约 32 MiB。范围响应、总大小、下载后完整 SHA-256 / SHA-512（安全散列摘要）、缓存摘要和断点续传仍逐项验证。服务器不支持分段时回到完整传输路径，阻塞网络请求也响应取消。

每次组件复制最多四个线程，各复用 1 MiB 读取缓冲区。复制时计算源内容摘要，写入并同步后读回目标复核，省掉复制后的第二遍源文件读取。模型复制还匹配固定清单摘要；模型安装收据使用已经验证的目标记录，不再为写收据重新读取全部权重。新版本未变的模型文件可从已安装目录校验后复用，旧目录在成功切换后清理。代理目录导入仍在复制后按可信清单全量复核，防止源内容在预校验与复制之间变化。

目录清单只遍历一次；全量校验和新清单生成最多四个工作线程，各复用 1 MiB 缓冲区，调用线程统一报告进度。目录链接、越界路径、重复记录、文件集合、大小及内容摘要检查继续有效。

同一宿主中的模型任务共享语音运行环境：首次完整验证后，后续任务只有在运行依赖锁仍匹配、环境清单摘要及受管文件路径、大小、修改时间指纹未变化时复用已验证环境，避免每个模型再运行一轮解释器检查与全量扫描。任何环境切换都会使该记录失效，宿主重启不保留该缓存。程序启动时 Voice Server 只做文件清单与大小盘点，模型和代理组件仍核验完整内容摘要。GPU（图形处理器）运行库的兼容复用及失败保留规则继续有效。

## 实测与验证边界

从 `用户测试工作区/runtimes/python`（用户测试目录语音环境）只读提取 1,004 个真实文件，总计 38,008,421 字节。样本包含一千个小文件及四个较大文件，在独立缓存目录按相反执行顺序进行两轮对照。每次计时均包含完整复制、目标同步和读回摘要复核；计时后还另外核验目标文件集合及全部摘要。

| 轮次 | 旧串行复制及分别读取源、目标摘要 | 新并行复制及流式源摘要、目标读回复核 |
| --- | --- | --- |
| 第一轮 | 8.56 秒 | 1.93 秒 |
| 第二轮，反转顺序 | 7.76 秒 | 1.96 秒 |

该样本平均约快 4.2 倍，取消复制并收集线程约 0.13 秒。真实语音环境的完整文件集合及内容摘要复核本轮为 84.86 秒，报告了 784 次进度；不能把小样本复制速度或此前缓存校验速度外推成冷盘全组件启动耗时。源组件清单保持原值，完整结果见真实文件实测报告。首次误选开发目录作为完整校验样本时，其已有未登记的解释器字节码文件被严格集合检查拒绝，未删除或放宽这些检查；最终对照使用文件集合一致的用户测试环境。

前端 255 项测试及类型检查通过，覆盖首次安装完成时的清单竞态、丢失终态两秒恢复、连续进度不推迟计时、慢磁盘不叠加补查、迟到事件、重试轮次、空闲与焦点刷新、部分组件提交及启动动画。原生公共模块 57 项、桌面宿主 20 项通过；包含隔离下载验收的公共模块共 65 项通过，其中包含缓存校验取消、服务器忽略范围请求、阻塞请求取消、多批下载共用并发上限及代理缓存同长度损坏拒绝。普通构建不开放隔离网络来源。

提交前后端全量复核为 1058 项通过、1 项跳过、1 项失败；唯一失败仍是此前冻结基线复现的 `test_secondary_and_final_prompts_are_mutually_exclusive`（次级与最终提示互斥用例）。本轮未修改该后端业务链路，完整回归结果与已知问题见[运行与质量门槛](operations-and-quality.md)。

本轮程序包、安装器内嵌包、现有工作区数据保留及全新工作区安装的结果见发布验收报告。用户测试目录仅核对并更新程序本体，未自动开启真实麦克风或云端会话；管理页启动与退出验收在缺失必需组件的开发工作区和独立全新工作区执行。
