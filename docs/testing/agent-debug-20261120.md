## 复现与确认范围

起点为实际安装的 Voice Terminal（语音终端）1.0.0、构建 `product-fa09b4f3491c3135`。正式接口重新确认了代理调试模式、主窗口就绪及组件页“运行正常”。仓库开始时保留的系统功能恢复与更新收尾改动未被本会话暂存、提交或覆盖；期间其他会话将其提交，并继续修改设置同步，相关变动均保留。

自动复现中，Python（脚本解释器）30 次、PowerShell 7（脚本环境）30 次及 Windows PowerShell 5.1（系统脚本环境）18 次单次调用均成功；2、8、16、32、64、128 条混合请求也成功。因此，交接中单次调用的偶发触发条件未单独复现，不能断言所有历史错误都由同一条件引起。

更大的即时请求流确认复现了相同的 `os error 232`（管道正在关闭）及静默丢失回执：

| 请求条数 | 修复前收到回执 | 退出结果 |
| --- | --- | --- |
| 512 | 102 | 退出码 0，错误地宣称完整成功 |
| 2048 | 30 | 退出码 1，管道正在关闭 |
| 8192 | 36 | 退出码 1，管道正在关闭 |

确认的故障链为：宿主向容量 64 的回执队列执行 `try_send`（立即入队），队列暂满便跳出连接循环，丢弃后续处理；标准流转发端继续写请求，触发正在关闭的命名管道错误。若转发端先观察到读端结束，原实现又会把文件结束及部分管道错误视为成功，即使从未收到 `transport.finished`（传输完成确认）。这解释了同一故障在不同调度顺序下表现为显式错误或“成功但回执不全”。

## 实现与保护边界

- 将传输生命周期集中到 `agent_debug::session`（原生共用调试连接），由原宿主回调进行授权、参数校验及正式业务分发，不新增旁路服务。
- 标准输入结束发送 `transport.finish`（输入结束通知）；宿主释放本连接介入，等待已接受请求完成并排空回执，最后发送传输完成确认。转发端收到确认才成功结束。
- 回执队列使用有界等待，不因瞬时拥塞断开；单帧写出超时 10 秒。请求以运行任务编号关联原始请求编号，异步乱序、异常和 150 秒请求等待超时均有对应编号回执。真正断连与授权撤销取消仍在等待的调试请求。
- 连接结束仍会释放介入；原有 20 秒介入保护、最多 16 个异步请求、24 个连接及单帧 8 MiB（兆二进制字节）上限保留。超大结果转换为错误回执，订阅积压发出遗漏提示。
- `scripts/agent-call.mjs`（轻量调用工具）只启动正式入口的标准流连接。支持参数文件、超时、失败退出码、原始回执与截图保存；终端省略图片编码。已收到回执先保存，再判断连接是否完整结束。
- 工具同时导出 `AgentClient`（持续连接客户端），按编号匹配回执，支持后续请求、事件、介入及正常结束输入。超时只结束工具所属转发进程，不终止正式宿主，不承诺取消已提交业务。
