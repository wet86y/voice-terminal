| 授权公钥文件 | 原逻辑按账户是否管理员直接推测文件。现读取实际配置，识别默认普通账户文件及默认管理员条件块；未知存储、外部包含或复杂条件停止自动登记并说明原因，避免写到服务不读取的位置。写入时再次限制为微软默认两种位置，保留非项目授权行及原有权限保护。 |

SSH（安全外壳协议）仍复用系统名为 sshd（安全外壳服务进程）的服务，不另建第二套服务。关闭广播继续保留既有服务、配对和网络许可；项目授权公钥仍有来源子网、受限命令与设备信任约束，不改变用户其他 SSH 用途。

## 客户端与服务端的验证口径

系统服务端和连接客户端不是两项都需要本项目安装的后台服务。共享主机依赖微软 OpenSSH.Server（系统服务端功能），其 sshd（接收连接的服务）已完成真实移除、正式程序重装及启动验收；最终检查为运行中、自动启动、监听端口 22，版本 9.5.6.4。

项目远程客户端随程序提供 russh（原生 SSH 连接库），配对后通过正式客户端运行流程建立连接，没有单独下载或安装 Windows OpenSSH.Client（系统连接客户端）的分支。本机另行只读执行系统 ssh.exe（连接客户端）的版本查询，返回 OpenSSH_for_Windows_9.5p2（客户端版本），文件版本 9.5.6.4，退出码 0（成功）；这只证明现有程序可运行，不代表完成过连接客户端的重新下载安装。

ssh-agent（系统密钥代理服务）当前为停止及禁用状态，本项目连接不依赖它，不需为本项目启用。客户端代码及自动准备流程已有回归覆盖，本轮没有重新进行双机完整配对、管理连接、任务和语音通道全链路实测，不将服务端重装通过写成双端全链路验收通过。长期依赖与准备职责同步记录在[分布式设备运行架构](../architecture/distributed-device-runtime.md)。

- 本程序选择一个有效 SSH（安全外壳协议）端口用于发现和项目规则；保留其他既有监听，不自动将全部端口开放到局域网。
- 自定义公钥路径、复杂 Match（条件配置）及无法安全核验的外部配置保留原状，需要人工核对；不能把服务基础就绪等同于任意自定义配置都能自动完成项目公钥登记。
- 安装源不可用、组织策略阻止下载或维护要求重启时明确失败或等待维护；不切换到未核验的下载渠道，也不强制重启系统。
