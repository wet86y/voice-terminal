# DSH 0.2.1-rc.2 升级与分发验收

本轮将项目目标宿主从 DSH（代理执行宿主）`0.2.0-rc.2` 更新到上游预发布版 `0.2.1-rc.2`。官方源码标签为 `dsh-v0.2.1-rc.2`，提交为 `687f282e8625c6b8d11ff58211a90524be2e4317`。本轮正式程序产品版本仍为 `0.9.0`，项目插件包版本更新为 `0.2.1`。

## 上游改动与插件影响

- RC2（第二候选版）增加 DeepSeek-V4.1-Flash-1017（模型版本）及 Search/Fetch API（搜索与网页抓取接口）。
- RC1（第一候选版）调整插件依赖管理、子路径导出和兼容性检查，并调整 V4（第四代会话格式）会话日志及附件读取、导出行为。
- 项目插件的宿主 `peerDependencies`（宿主依赖版本）与 `devDependencies`（开发依赖版本）锁到 `0.2.1-rc.2`；Cordis（插件服务容器）维持 `~4.0.5`，桥接协议维持 `2.0`。
- `dsh-compatibility.json`（宿主兼容记录）升级为格式 `schema: 2`（记录格式版本），声明插件版本、桥接协议及 `bridge`（桥接入口）、`wake_tasks`（唤醒任务入口）、英文元数据和简体中文元数据四个包导出路径。
- npm（包管理器）解析目标版本时使用 `prefer-online`（在线刷新版本元数据），避免旧缓存缺少预发布版本而返回 `ETARGET`（目标版本不存在）。安装仍按固定版本和完整归档校验执行。

| 桌面程序包回归 | 25 项通过 |
| 资源安装弹窗定向前端回归 | 6 项通过 |

| 全量前端测试 | 307 项通过、19 项失败，失败分布在 4 组未修改的界面夹具或断言中；全量前端测试未全绿 |

分发升级验收使用保留旧 DSH 的隔离工作区：先换入新程序本体，确认旧组件登记和目录保留，再由用户从组件页面手动点击下载更新。升级后实际 DSH 版本为 `0.2.1-rc.2`，项目插件版本为 `0.2.1`，适配记录格式为 2，桥接协议为 `2.0`，四个导出入口均存在。随后组件检查显示就绪、更新标记清除，语音服务启动进入工作台。该项没有启动麦克风语音会话或验证真实扬声器播放。

本轮本机 `.local`（本地工作区）程序本体与普通分发安装器共用构建 `product-ee05746262971e1d`（正式构建编号）。当前本机工作区已安装 DSH `0.2.0-rc.2`，新程序目标为 `0.2.1-rc.2`；按设计由用户在组件页面手动更新 DSH。程序包原生固定文件校验通过，分发安装器构建戳与交付记录中的程序包摘要与本机程序包一致。具体字节数和 SHA-256（安全散列摘要）见[当前正式程序与分发安装器交付](../releases/current-release.md)。

## 验收边界

插件自动化回归及隔离分发升级通过，不等于全量前端测试全绿；目前有上述 19 项前端失败需要单独处理。语音服务启动成功不等于真实麦克风、真实模型对话或播放设备现场验收完成。
