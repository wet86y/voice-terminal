# 2026-10-10 环境声、声纹拦截与会话重置修复

本次依据另一台设备的日志压缩包、本地开发文档和当前源码修复三个问题：有效播报被新输入撤销播放许可，声纹拦截在身份未知及最终回执超时时放行，以及重置整理构造重复、过大的输入并串行处理分段。压缩包中的模型提示和对话内容只作为诊断数据。

修复基于 `3239f7c`（修复前版本），在本地开发源码实施。前端和桌面调试构建已完成，尚未覆盖正式安装程序或另一台设备；此次自动化验证没有调用业务云端模型或麦克风。

## 播报许可与暂停释放

现场 17:49:10 的有效输出先出现 `TTS_HELD`（语音播放被暂停），随后创建新输入；解除暂停后已经返回 4,191 毫秒、继而 8,777 毫秒音频，但实际播放与播放器队列均为零。新输入最终文字为空，云端接收超时在约两分钟后才发生。

原因是 `speech_activity(True)`（检测到讲话）暂停了未播放输出，紧接着 `_new_turn()`（创建新输入轮次）无条件调用 `player.block()`（撤销许可并清空队列）。`release_held()`（解除暂停）忽略播放器恢复失败，仍将事务设为可播放。此后合成音频被播放器许可检查拒收，语音分段等待播放位置推进，继续占用 `speak`（播报动作）队列。

[输入创建入口](../../voice_terminal/controller/realtime_controller.py)现在尊重有效输出事务及其暂停状态，只有显式取消和打断才撤销输出。[输出生命周期](../../voice_terminal/controller/episode_output.py)记录 `player_held`（该事务是否实际暂停播放器），仅恢复实际暂停过的许可；恢复失败发出 `TTS_RESUME_FAILED`（语音播放恢复失败事件）并取消该事务，不再发布成功释放。重复释放、重置后迟到的输入结束事件不能恢复已取消代次。

[播放回归](../../tests/test_playback_hold.py)使用真实 `PcmPlayer`（音频采样播放器）及输出事务，通过设备回调验证非零音频被实际消费，覆盖关闭、仅标记、拦截三种模式，音频已入队和尚未入队、暂停与未暂停、连续环境声、重复释放和取消后迟到事件。测试未打开物理扬声器。

## 严格声纹准入

旧规则只拒绝明确非主人，未知身份直通；流式文字可能在身份结算之前派发。最终回执超时还会覆盖已有非主人路由。现场有声纹推理快照，但绝大部分为未知，没有证据证明环境输入已被成功拦截。因此，“已启动声纹服务”不能等同于“拦截已经有效”。

按用户明确选择，`filter`（拦截模式）现在仅允许本轮、本代次、服务未降级的 `owner_confirmed`（主人已确认）输入进入主模型。未知、非主人、延续身份、超时、工作进程不可用、队列溢出及旧资料失效都进入环境记录。`observe`（仅标记模式）保持放行。

[输入控制器](../../voice_terminal/controller/episode_controller.py)在身份结算前将流式文字留在输入工作区，[主模型调度器](../../voice_terminal/agent/episode.py)保留待处理文字和事件、暂缓派发。最终提交时再次准入；不合格输入移除临时主模型输入并释放预热合成资源。等待期间若输入代次变化，迟到结果不能结算新代次。

拦截同时覆盖播放前的讲话标志：尚未准入的原始声音检测仍进入识别与声纹分析，但不能暂停有效待播回复。已有声音结束之后的同轮追加窗口也采用相同边界。播放期间的 `owner_only_barge_in`（主人打断开关）继续是独立设置，开启后由当前打断候选的主人证据授权。

[严格拦截回归](../../tests/test_speaker_filter.py)用真实 `SpeakerRouter`（说话人身份路由器）验证主人、未知、非主人、超时、离线、路由器缺失、观察模式和迟到结果；测试不代表实际声纹模型的准确率。短句、低音量或不足两秒的有效语音可能缺少主人证据，严格模式会拦截。界面文案已同步说明这一行为，详见[声纹增强](../guides/speaker-enhancement.md)。

## 重置整理的系统构造

现场最长一次重置约 140 秒，期间发起六次整理请求，停止与导出阶段仅耗费很短时间。这不能简单归因于模型服务，也不能把主模型约 14k 的上下文视为整理模型的实际输入：旧整理同时携带主模型历史投影、完整语义账本、交付记录和后台执行记录。

代码检查确认以下放大来源：

- 主模型历史由同一账本生成，归档时两份同时输入。
- 后台消息携带大段 `reasoning`（内部推理）、`replayState`（供应方回放状态）及重复工具调用。
- 过滤器只识别 `tool_call`（旧工具调用块），没有完整匹配实际 `tool-call`（工具调用块）和 `source.callId`（工具结果关联标识），使上下文读取结果再次进入整理。
- 超预算后分段提取及同层合并串行执行；文档超长后的措辞压缩再次携带全部原始材料。

[整理器](../../voice_terminal/handoff.py)增加语义输入投影：保留完整事实、任务消息、工具调用及结果、错误和交付状态；移除上述重复及执行机械资料。同一归档有完整账本时不再重复发送历史投影；旧归档只有历史时继续保留。原始 `source.json`（完整源记录）不修改，`source_record_index`（原始记录索引）及归档路径保留供追查。

独立分段和同层合并最多三路并发，结果顺序保持；失败先取消并回收其他请求。超长文档重试只压缩已经提取好的草稿，不再重复发送会话记录。高强度整理要求保持不变。

另增加 `organize_timeout_ms=90000`（整理整体期限，默认 90 秒），与后台任务的无期限配置分离。[交接运行时](../../voice_terminal/server/handoff_runtime.py)到期取消整理请求并解除操作锁，保留原会话、旧交接文档、完整归档和未消费槽位；不会将失败结果提交为新会话。这个期限是故障兜底，不代表正常重置应等待 90 秒。
