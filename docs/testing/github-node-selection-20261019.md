# GitHub（代码托管平台）统一节点与测速择优验证（2026-10-19）

## 最终行为

按用户最终确认，界面不显示加速开关。默认允许使用加速节点，下载时自动比较当前网络下的原站与启用节点；作者显示 `wet86y`，项目仓库按钮固定打开 `https://github.com/wet86y/voice-terminal`。

应用更新安装器、GitHub 发行附件和原始文件域名的原生组件下载，共用同一节点入口。更新清单始终直连，通用下载入口也显式排除 `update.json`（应用更新清单），含带查询参数的地址。源码克隆、Python（后端语言）维护脚本及包管理器保持各自构建工具链，不属于原生文件下载入口。

## 上游复用与补充

- DesktopUpdateKit（桌面下载组件）继续锁定提交 `8bfb24c1770098f6bd68aef208fcdfa1f097b92b`，上游检出没有修改。
- 锁定原生版没有内置加速站列表，也没有当前网络的测速择优。节点由 `config/download-sources.json` 的 `github_download`（统一节点配置）显式提供：`gh-proxy.org`、`gh.llkk.cc`、`ghproxy.net` 和官方原站。
- 桥接直接复用上游节点模板校验、优先级与上次成功节点解析、节点缓存、范围探测、单路/四路传输和滚动速率计量。通用组件已有可信 SHA-256 / SHA-512（文件摘要），无需伪造高层更新接口强制要求的独立摘要附件。
- 桥接补充有限测速：每节点默认最多两秒，先做上游 64 KiB（64 千二进制字节）探测，再读取至多 1 MiB（1 兆二进制字节）样本；两者共享总时限。按新鲜采样速率排序，原站更快时优先直连；旧成功缓存不能压过当前结果。采样只提供短时估算，不代表大文件的持续速率。
- 当前来源传输或完整摘要失败后尝试下一来源。四路失败先在同一来源回退单路；取消会停止探测/传输，不继续切换来源。只有完整摘要成功后才记录上次成功节点。
- 更新与组件共用节点缓存。由于上游使用固定临时文件名，保存时使用 Windows（操作系统）命名互斥协调进程与线程。
- 大文件整个过程保守预留四个全局通道，包含测速、缓存检查及连续断点续传；小文件和显式轻量探测预留一个。节点测速顺序执行。配置关闭加速站时仍允许原站使用四路分段。

## 进度与界面

实际下载阶段显示节点、滚动速率和四路/单路回退说明；测速字节不计入正式传输进度。缓存摘要检查保持非终态，只有明确确认命中后才标记缓存完成，避免测速期间误报下载完成。批量资源、运行环境和应用更新均识别这些传输阶段。

“关于”页在更新卡片底部显示作者及项目仓库按钮。按钮通过固定目标的原生命令打开系统浏览器；产品页和组件管理页均有对应权限，外部页面、演示模式和悬浮窗不获得该原生命令。演示只显示目标提示，不实际打开浏览器。

## 复验入口

- 前端：`npm run test --workspace @voice-terminal/frontend -- src/product/panels/WorkspaceSettings.test.ts src/interface/AppUpdateCard.test.ts src/ui-demo/UiDemoApp.test.ts`（相关交互），以及 `npm run frontend:build`（类型检查与生产构建）。
- 原生：使用仓库工具链，指定 `--offline --locked`（离线锁定依赖），对 `voice-desktop-common`（公共模块）与 `voice-terminal-desktop`（桌面宿主）开启 `qualification`（隔离验收），测试参数 `--test-threads=1`（顺序运行夹具）。
- 正常构建：桌面宿主开启 `custom-protocol`（正式本地协议），不包含隔离来源映射能力。
