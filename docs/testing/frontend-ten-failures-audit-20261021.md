## 不能仅按“测试过时”处理的两处实际边界

### 全局错误互相遮蔽

`ManagementApp.vue:227` 的 `resourceError`（资源页面全局错误）依次选择 `enhancementFailure`（音频增强失败）、资源错误、凭据错误。因此音频增强读取失败与启动阻塞/凭据保存失败同时发生时，全局只显示前一项。即使正式宿主接口存在，接口调用报错也能触发这条路径。

这解释了第 3—5 项失败为何一并出现。补齐测试替身能让正常路径测试准确，但不能修复这条真实的并发错误展示问题。建议把音频增强错误放到对应功能区域，或允许同时显示多种错误；凭据保存错误断言应定位到对应服务表单，而非全页第一个错误。

### 分析进程资源缺少未归属兜底

`component-resources.ts` 只把分析进程余量分配给能以进程编号及创建时间匹配的模型，显存再要求设备字段为显卡。若模型状态未返回或设备字段缺失，剩余资源不会保留在其他分组。

追加两个独立诊断探针，均复现：

1. 分析进程已知常驻内存 600 字节、提交内存 900 字节、显存 50 字节；模型身份匹配但设备字段缺失时，常驻内存仍分配 600 字节，模型显存合计为 0 字节，遗漏已知的 50 字节。
2. 同一进程采样存在但模型状态暂未返回时，组件资源分组结果为空，已知内存没有归属兜底。

这影响采样不齐或状态交错时的组件资源展示，不代表宿主原始总量丢失，也不影响模型权重或启动完整性。正常设备信息齐全的显卡样例已通过对照验证。建议保留“未归属共享资源”统计或其他明确兜底，避免已知量消失；无需恢复已经取消的重复卡片。

诊断探针断言只记录观察到的异常边界，不应直接作为认可该行为的正式回归测试。

## 修订验收

用户授权后，主会话已修订业务源码及原始测试：

1. 资源任务错误、音频增强设置错误和凭据错误分别呈现。音频增强读取失败不再遮蔽启动门禁或凭据保存说明；刷新成功时清除已恢复的增强错误，缺组件门禁仍有效。
2. 分析进程尚未归属到模型的资源余量暂计入现有 Voice Server（语音服务）卡片。模型进程身份及设备状态同步后，重新计算资源归属，扣回暂计余量；不创建重复卡片，不把显存强行分配给 CPU（中央处理器）模型。卡片说明同步解释暂计规则。
3. 同步原十项失败涉及的摘要查询位置、卡片数量、接口替身和设备样例。凭据保存错误定位到对应服务表单。原有共享资源界面测试同时检查暂计资源可见，以及迟到的模型身份信息使资源正确转归。
4. 新增九个回归测试实例，覆盖设备未提供/使用处理器的两种显存边界、模型状态缺失/停用/身份过期及重复进程采样、未知内存指标、增强读取失败后的刷新恢复，以及增强设置与凭据同时报错。其中三项专门覆盖模型身份已匹配、其他余量为零，但某项指标未知的边界，只有三项余量全部明确为零时才省略兜底分组。
