## 根因与修复

旧原生组件会在完整解码试听后保留覆盖整段音频的大型解码器计算图，后续小句段沿用大图，计算成本明显增加。修复版本 `v0.9.1-1895381df44b` 已在完整解码请求退出时释放该图，程序摘要为 `cf691668249763a922108e572355ee0a436160c42c6606b37872aa2b2a19efcf`；生命周期与既有真实模型验证见[解码器修复记录](voxcpm2-decoder-graph-lifecycle-20261016.md)。

此前本体覆盖安装保留独立模型组件，仅迁移声纹组件，因此分发包虽然带有原生修复补丁，旧语音组件仍然留在工作区。后端可用性检查又只验证组件与自身安装收据一致，允许旧组件继续参与合成。这解释了修复已提交、应用已更新，现场仍然复现的问题。

本轮补齐交付链路：

- 覆盖安装发现已有本地语音组件时，按当前清单核验基础库，从随包补丁提取并验证原生程序和模型规格，离线生成候选组件；基础库不需要重新下载。
- 应用、原生组件、安装收据、模型总清单与应用内的模型登记一起启用，失败时在同一事务中恢复。与声纹迁移同时发生时合并清单，避免重复替换总清单。
- 现有组件已是目标版本时核验后跳过复制。基础库缺失、损坏或组件暂存空间不足时保留原组件，允许本体升级以便修复，并记录 `deferred_migrations.tts_audiocpp`（语音组件暂缓升级记录）。
- 本地候选选择核验当前目标版本与实际文件内容，原生进程启动再次核验版本及实际程序／模型规格摘要。旧组件不能再仅凭旧收据进入本地合成。
- 启动身份日志新增 `target_version`（目标原生版本）与 `binary_matches_target`（实际程序与目标摘要一致）。保留原生首包、音频就绪到入队、入队到设备提交和音频块间隔日志，起播储备仍为零。
