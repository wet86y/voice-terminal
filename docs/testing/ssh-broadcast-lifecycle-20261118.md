# SSH（安全远程连接）广播生命周期与项目身份审计

## 对照范围

本轮以上一次实际安装的 1.0.0 / product-ffd59ded42d46a2d（产品版本／构建编号）为起点。按正式构建阶段保存的输入清单与本次源输入逐项对照，记录位于受管诊断目录的 ssh-lifecycle-source-delta.json（源差异记录）。此前 DSH（代理执行宿主）、提示条居中、终端隐藏、网络掩码和跨页面任务修订继续保留，没有回退其他未提交改动。未修改设备配置格式或依赖锁，未安装组件或公开发行。

## 原因与修订

- 广播开关原先被并入核心运行模式变化，必经停止整个后台进程和重新加载模型；设备网关又只能靠启动参数开启。现由语音进程内的独立回环监听控制器交接网关，原生宿主通过带请求编号的私有控制管道获取完成回执。本地广播与相同模式命令不重启健康核心，模式或设备身份变化仍执行必要交接，缺失的核心可恢复。
- 前端预检、网络规则准备、规则后的检查、公告发布、配对码生成原先反复调用同一完整系统查询。现运行路径只查询官方服务、实际端口和项目三条规则，批量读取这些规则及过滤器，不枚举全机规则；并发检查合并，十秒内复用结果。显式检查绕过缓存。管理员脚本内完成实际规则复核，成功后复用已验证结果，不再额外启动一轮完整查询。当前广播生命周期内的公告与配对复用同一验证快照，停止入口时清除。
- 配对码生成原先读取 ProgramData（系统共用数据目录）下的主机公钥，当前未提权账户被文件访问权限拒绝。现只对已验证服务的实际回环端口进行 Ed25519（椭圆曲线密钥算法）握手，取得运行中服务证明持有的公钥；不认证账户、不读取私钥、不调用外部 SSH 命令或修改系统密钥权限。
- 第 3 版设备配置仍被旧的第 2 版共享角色门禁拒绝，并且旧门禁依赖启动时的网关参数。现第 3 版明确保存的本地广播可动态开关，保留的远端配对信息不影响本机广播；第 2 版旧入口继续要求原启动意图。
- 广播失败与核心启动失败分别记录。迟到的网关回执不能完成另一轮请求；无效配置在管理员授权和停止服务之前拒绝。

## 项目身份与清理边界

- 正式程序的新设备私钥和导入的连接私钥写入 data/state/device-keys（项目设备密钥目录），只保存当前 Windows 账户 DPAPI（数据保护接口）密文；设备配置仍保留原稳定引用。旧系统凭据仅按实际使用的同一引用迁移，项目密文读回解密核验后才移除旧条目。原件损坏或解密失败保持明确错误，不回退掩盖损坏；迁移清理中断可再次补做。
- 私钥不进入界面、日志、分发包或明文暂存。该目录被既有持久数据备份白名单覆盖。密文绑定账户与设备，跨账户或设备复制数据不能自动解密。在线模型接口密钥不属于本次设备私钥迁移。
- 微软系统服务仍需要对应账户授权文件中的受限公钥行，以及程序自己的局域网防火墙规则。只维护项目标记的行和三条独占规则，不修改其他程序授权、系统主机密钥或网络类别。公钥写入失败会清理本轮生成的临时文件。
- 配对码与认证窗口不写磁盘；过期或完成后停止监听并释放认证材料。广播关闭释放配对、公告、原生管理与文件入口，保留本地语音核心。模式及工作区交接清除上轮发现设备缓存。
- 启动结果只作为活动实例的瞬时快照，正常退出仅移除实例编号和进程编号匹配的记录，保留新实例记录与无法确认的异常原件。诊断日志保留以供定位，不把历史快照当作实时运行状态。
