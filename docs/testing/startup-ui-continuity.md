# 启动与维护界面连续性验收

本文说明启动、完整性维护及窗口交接的显示边界。流程依据见[应用生命周期](../guides/application-lifecycle.md)。源码验证与现用正式程序验收分别记录；构建成功不代表已更新本机安装，也不能代替实际窗口的逐帧视觉检查。

## 显示与交接约定

- 主窗口、分发器和迁移窗口使用与启动页一致的深色底色，本地页面加载完成后显示。分发器自动安装、更新及完整性校验在首屏加载后派发，同一次进程不因页面重载重复派发；组件维修和随包离线迁移在正式程序真实管理页挂载后通过组件任务执行。
- 产品、组件管理和样例入口保留静态启动内容。构建与开发服务内嵌共享启动样式及独立错误处理，界面模块加载失败时仍显示错误与重新加载操作。
- 网页入口的 30 秒计时用于原生身份读取、配置与界面模块加载等待，超时后拒绝迟到挂载。真实界面挂载后立即结束计时，原生交接确认延迟不能清除已显示的界面。此计时不限制分发器的大组件校验或正式程序的组件任务、模型加载时长。
- 首轮组件渲染异常或空渲染不能报告界面就绪；失败先卸载实例，再显示重试。页面挂载后的维护交接若失败，保留真实管理页并显示状态错误，组件问题仍可从原组件列表重试。
- 组件管理页核对产品身份，业务未就绪或报错仍可进入。临时启动窗口保留到新管理页实际挂载、经过绘制帧并确认交接之后。
- 悬浮窗在界面挂载并请求模型之后才隐藏主工作台；仅网页加载完成不构成交接。悬浮页面重新加载时恢复主工作台，避免空悬浮窗成为唯一可见界面。
- 共享启动页区分安装、更新、完整性维护和迁移，显示真实阶段、字节进度及适用操作。状态读取 10 秒超时后显示错误；入口身份未知时，“重试”先重新读取状态，不发送未经确认的业务启动命令。
- 产品启动遮罩只显示当前启动或排队组件名称，不展示启动进程与阶段详情。状态行固定“正在启动：”前缀，组件名限一行，超出可见宽度后滚动；进度条仍按宿主报告的组件完成计数显示整体进度。

## 自动化回归

在仓库根目录执行：

```powershell
npm run typecheck
npm test --workspace @voice-terminal/frontend
node --test tests/frontend-dev.test.mjs
npm run frontend:build
```

定向故障回归入口为 `apps/frontend/src/runtime/boot-page.test.ts`（共享维护页）、`startup-fallback.test.ts`（错误兜底及挂载）和 `desktop-preflight.test.ts`（原生身份预检），后两项同属该目录。原生测试沿用项目受管工具链与共享构建缓存，覆盖 `voice-terminal-desktop`（桌面宿主）、`voice-terminal-installer`（分发器）及 `voice-terminal-bootstrap`（启动入口），不得为测试覆盖现用安装。

| 场景 | 预期结果 | 验证范围 |
| --- | --- | --- |
| 入口脚本加载失败 | 静态画面切换为错误页，保留重新加载操作 | 独立错误处理故障注入 |
| 原生身份读取或模块加载超时 | 显示超时提示；迟到响应不挂载界面 | 计时与异步响应回归 |
| 预检失败后重试 | 重新启用等待计时，不无限停留在加载页 | 预检重试回归 |
| 已挂载界面等待原生确认 | 超过模块等待期限仍保留真实界面 | 慢交接回归 |
| 多组件并行启动或组件名超出状态行宽度 | 固定显示“正在启动：”，只滚动组件名称，不显示进程或阶段详情 | 启动状态摘要与实际窗口验收 |
| 首轮组件渲染失败 | 卸载实例，显示错误与重试，不报告空界面就绪 | 组件异常回归 |
| 业务故障下打开组件管理 | 授权产品可进入，错误入口身份被拒绝 | 管理预检回归 |
| 完整性维护执行或失败 | 显示校验标题、实际阶段和字节进度，不出现目录重选入口 | 共享维护页回归 |
| 首次状态读取失败后重试 | 先重新识别入口，不误向安装器发送启动业务命令 | 共享维护页重试回归 |
| 组件维修子任务准入或启动失败 | 已创建任务保留运行状态；尚未创建的交接项保留，用户仍可在正式程序组件列表重试 | 组件校验交接回归 |

构建后还应检查产品页、管理页的静态启动内容、内嵌样式及独立错误处理均进入产物，维护页保留对应操作文案，并核对前端交付依赖闭包无缺失或额外文件。

## 实际窗口验收

使用明确指定的隔离工作区和测试产物；保留现用组件与真实数据。按以下顺序录像或逐帧截图：

1. 冷启动和热启动：从首个可见窗口到产品界面，检查是否闪白、出现空窗口或阶段断档。
2. 组件缺失及服务失败：打开管理页，检查加载画面、错误提示、重试和退出；确认管理页不依赖业务服务成功启动。
3. 同版本完整性维护及更新：检查等待旧进程退出、本体检查、组件校验、修复、重启交接各阶段；长任务保持真实进度，不受网页模块等待计时限制。
4. 临时启动窗口交接：让管理界面延迟加载或失败，确认旧窗口在新界面挂载并绘制前仍保留；挂载后的维护交接失败时，真实管理页仍可操作。
5. 悬浮窗首次打开及重新加载：让脚本加载失败，确认主工作台仍可见；恢复后再确认正常切换。
6. 系统网页引擎不可用：确认仍有原生安装引导或错误对话框，不能把没有业务窗口误判为启动成功。

报告应注明源码、构建与实际运行产物的对应关系，以及执行了哪些自动化和实际窗口场景。未运行的干净设备、系统网页引擎异常或逐帧场景不得写成已通过。
