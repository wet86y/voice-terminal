# 声纹缺陷修订与 CAM++ 接入准备（2026-10-11）

本记录描述 CAM++（上下文感知掩码声纹模型）准备阶段的源码与模型结果。后续已发布修订调整了主人判断规则和设置字段，当前行为以[正式交付记录](current-release.md)及[声纹增强说明](speaker-enhancement.md)为准。

## 当前启用状态

截至本次源码提交，`speaker.model_id`（声纹模型编号）的默认值仍为 `wespeaker-cnceleb-resnet34`。CAM++ 仅完成权重下载、ONNX（开放神经网络交换格式）导出和可选后端接入，尚未正式切换用户配置，也未重新注册主人声纹。现有 WeSpeaker 路径会使用本轮声纹流程修复。

本记录对应源码修订和本机准备结果，未执行正式程序重建或发布。模型权重、导出文件及本机清单保存在 `.local`（本机资源目录），不随 Git（版本控制）提交；其他机器需要执行下文的准备脚本生成运行文件。正式启用 CAM++ 需显式选择模型、重启相关服务、重新注册，并按真实短句样本校准阈值。

## 已修订的缺陷

| 缺陷 | 修订后的行为 | 对应实现 |
| --- | --- | --- |
| 不足 2 秒的收尾窗仍按 2 秒计算人声占比；750ms 全人声被算为 0.375，低于 0.40 门槛 | `speech_ratio`（单窗人声占比）改为人声样本数除以真实窗口样本数；750ms 全人声得到 1.0 | `voice_terminal/speaker/worker.py` |
| 设置页测试遗漏未对齐 500ms 步进的最后完整窗，结果与实时处理不同 | 设置页与实时收尾共用窗口边界规则；2.3 秒片段均分析 0–2 秒和 0.3–2.3 秒 | `voice_terminal/speaker/windows.py`、`voice_terminal/server/speaker_runtime.py` |
| 早期滚动结果认定非主人后被永久记入否决集合，心跳调度还可能提前删除待提交转写，后续最终聚合确认本人仍无法提交 | 身份未结算时保留并暂缓输入；最终准入使用当前轮次、当前代次、未降级的最终聚合判断 | `voice_terminal/controller/episode_controller.py` |
| VAD（语音活动检测）延迟报告并回溯起点时，ASR（自动语音识别）有前滚音频，整轮声纹工作进程漏掉这部分 | 新轮次和恢复代次补送候选起点至当前帧前的缓存，裁掉起点前的声音，当前帧由正常路径发送；采样起点为 0 时也保留 | `voice_terminal/controller/realtime_controller.py` |

`filter`（拦截模式）仍只接受 `owner_confirmed`（主人已确认）；最终未知、非主人、超时、服务异常以及错误轮次／代次不会放行。750ms 的修订只是让有效短窗能够产生声纹向量，整轮至少 2000ms 有效人声的门槛仍然存在。

以上缺陷可以用代码和回归测试直接复现。此前日志未包含故障机器的完整配置和实际运行代码版本，因此不能据此断言它们解释了该机器的所有低分或丢弃现象。

导出使用固定版本的 [3D-Speaker（说话人模型工具库）源码](https://github.com/modelscope/3D-Speaker/tree/065629c313eaf1a01c65c640c46d77e61e9607b4)。CAM++ 的平均池化在不足一个分段的尾部存在 PyTorch（张量框架）与 ONNX Runtime（模型运行时）的导出边界差异；准备脚本显式排除补齐位置，并将修订后的 PyTorch 输出和 ONNX 输出都与原版 PyTorch 对照。

在 0.75、1、2、3 秒合成信号上，80 维特征与官方前端逐值一致，导出补丁后的 PyTorch 输出与原版输出最大绝对误差为 0，ONNX 输出与原版的最大绝对误差不超过 `1.13e-5`，余弦相似度约为 1。实际工作引擎对 750ms 收尾窗和 2.3 秒首窗／末窗都能产生有限的 192 维单位向量。数值一致性验证只能证明导出与接入实现正确，不能代表真人中文短句的识别准确率。

## 已贯通的代码路径

`create_speaker_engine`（声纹引擎工厂）按 `speaker.model_id`（声纹模型编号）选择后端。实时工作进程、本地注册／测试兜底以及资料指纹均使用选中的引擎。启动资源检查也按所选模型编号检查资源。

WeSpeaker 保持原有 256 维输出和 Hamming window（汉明窗）前端；CAM++ 使用官方 Povey window（Povey 窗）、80 维 FBank（梅尔滤波器组）和 CMN（按时间去均值）。两种模型的 `frontend_version`（特征前端版本）及模型编号不同，旧档案不会被直接拿来与新模型的向量比较。

计算设备暂时复用 `compute.devices.wespeaker`（声纹引擎计算设备）及 `compute.fallback_devices.wespeaker`（声纹引擎回退设备）这两个既有字段。本次真实模型验证使用 CPU（中央处理器）；没有验证 CAM++ 的 CUDA（显卡计算）性能。

资源清单把 CAM++ 列为可选模型。组件下载提供官方权重，ONNX 运行文件需要执行准备脚本生成；本轮没有加入设置页的模型选择控件，也没有自动切换用户模型。

## 复用和试验方法

在仓库根目录可重新下载、校验和导出：

```powershell
.\.local\runtimes\python\python.exe -B -X utf8 scripts/prepare_campplus.py
```

已有经过固定摘要校验的权重时，可以跳过下载：

```powershell
.\.local\runtimes\python\python.exe -B -X utf8 scripts/prepare_campplus.py --skip-download
```

`--model-dir`（模型输出目录）可以指定其他模型目录。脚本不会安装或升级依赖，使用当前运行环境的 ModelScope（下载客户端）、PyTorch、torchaudio（音频特征库）、onnx（模型交换格式库）和 onnxruntime（模型运行时）。

准备好 ONNX 文件后，试验配置可指定：

```yaml
speaker: # 声纹配置
  model_id: campplus-zh-cn-common # 模型编号
  mode: observe # 仅标记模式
```

该片段应合并到实际启动所用的本机配置文件。界面中保存过的模式可能覆盖 YAML（配置文件格式）中的模式，试验时应在设置页核对“仅标记”。变更模型后须重启声纹及语音服务，并用新模型重新注册。现有资料使用同一个用户目录保存；提交新注册会替换该目录的主人资料，比较模型时应使用独立测试目录或先完整备份原声纹资料。

CAM++ 的余弦分数不保证与 WeSpeaker 的分数同尺度。`confirm_threshold`（主人确认阈值）和 `continuity_threshold`（连续保持／非主人分界阈值）仍是既有值，应通过真实样本重新校准后再开启拦截。

## 后续声纹能力规划

1. 对同一组真实录音分别建立两种模型的注册向量，比较 0.75、1、1.5、2、3 秒本人短句、异人短句以及噪声／距离变化。按误拒和误接收统计，而不是用合成信号分数评估真人识别率。
2. 统一实时 FSMN-VAD（记忆网络语音活动检测）与注册／设置页 WebRTC VAD（实时通信语音活动检测）对有效人声区间的定义，核查句尾等待区间是否被误算成人声。
3. 将长注册音频中的多个有效子窗纳入评估，核对 5–10 秒整段注册与 2 秒运行窗之间的分布差异。
4. 明确身份判断对应 ASR（自动语音识别）轮次还是每个独立 VAD 片段。当前整轮聚合与滚动判断范围不同，不能让同一识别轮次里的不同说话人互相污染证据。
5. 单独设计少于 2 秒短句的准入策略。更换模型不会自动移除 `min_turn_speech_ms`（整轮最低有效人声时长）门槛；需依据真实短句测试决定证据累计、等待预算与阈值。

## 最终验证

两组最终回归共 **212 项通过，无失败或跳过**：

| 回归范围 | 结果 |
| --- | --- |
| 声纹窗口、最终准入、心跳恢复、前滚补送、真实 WeSpeaker／CAM++ 推理、后端选择、资料隔离、启动资源、KWS（关键词唤醒）与会话恢复 | 157 项通过 |
| 模型资源更新、产品接口、实时设置与运行资源管理 | 55 项通过 |

新增的心跳回归使用真实暂缓／准入回调，验证临时非主人时保留待提交输入，最终聚合确认本人后只派发一次；最终非主人、未知或回执超时仍清理输入。实际 CAM++ 工作引擎验证了 750ms 收尾窗及 2.3 秒首窗／末窗的音频边界和 192 维有限单位向量。

权重及 ONNX 文件的 SHA-256（校验摘要）已重新核对，与准备清单一致。代码差异通过 `git diff --check`（差异格式检查）。本轮没有采集真人录音，也没有启动常驻服务或切换现有主人资料。
