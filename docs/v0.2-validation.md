## 长语音截断修复验证（2026-09-05 夜间）

- MiniMax 接收改为独立顺序 PCM 缓存，内存阈值 8 MiB，超出后落盘；慢播放不再通过 64 块队列阻塞网络读取。结束和取消释放缓存。
- `is_final` 只用于确认当前文本分段完成；仅 `task_finished` 确认整轮合成成功。部分音频后断线或限流保留已收 PCM，播放后报告 `DEGRADED`。
- v0.2 pacing 等待当前分段完成，并按全部已接收音频减去已播放音频计算提前量；修正以前其他分段的 PCM 会放行新文本的问题。v0.1 保留完整回答文字，播放排空期限随缓存时长调整。
- 回归覆盖超过 8 MiB 的顺序输出、缓存失败、分段/整轮完成的区分、20 秒缓存的异常排空、停止释放落盘缓存及下一轮拒绝旧音频。Python 88 项通过；本次还通过 compileall 和 diff 检查，前端检查结果沿用此前基线。

真实 MiniMax + v0.2 控制器 + PortAudio 输出测试使用固定的 568 字流式文本，跳过麦克风、ASR 和 LLM。测试设备为当前可打开的 `扬声器 (N-613), MME`；配置中的 Realtek MME 输出无法打开 32 kHz 流，项目配置未改动。

证据为忽略目录中的 `logs/evaluation/long-tts-physical.json`、`long-tts-physical.log` 和 `long-tts-physical-check.py`。首次物理测试遇到 RPM 限流，已收到的 98.536 秒音频全部排空并正确报告 `DEGRADED`，记录在 `long-tts-physical-rpm.json`；修正分段节奏后得到上述完整结果。

程序侧验证了全部音频交给真实输出设备；用户随后确认“我听到了，清晰，完整”，本次 108.579 秒长语音的真实扬声器听感验收通过。此结果不替代自然麦克风端到端验收。此次独立测试退出后未启动常驻 Voice Server。

## 当前配置状态

- `config/default.yaml`：`v02.enabled=false`、唤醒词关闭，作为默认 v0.1 链路。
- `config/v0.2.yaml`：显式打开 v0.2、Smart Turn、SenseVoice、预测、只读工具和 TTS pacing。
- ASR Worker：最终地址来自配置的 `asr.worker_url`，启动、health probe 和回放脚本不使用硬编码探测地址。
- Analysis readiness：只检查实际启用的 endpoint/refine lane，关闭的 lane 不会阻塞启动。
- 现有服务在本机保持运行时，审计和回放不会强制停止它们。

## 仍未完成的验收

1. 真实麦克风、耳机和扬声器：验证播放前续说、播放中断、连续多轮、停止和重启。
2. 自然语音统计：至少 20 条人工核对文本，比较 v0.1/v0.2 的 CER、误结束率、结束至首音 p50/p95、精修回退率和 CPU/内存峰值。
3. 第三方服务稳定性：在限流窗口稳定时复测 MiniMax 部分音频、close frame、长文本和 TTS pacing，区分 provider 限流与本地调度问题。
4. 单 lane Analysis 真实回放：分别只启用 Smart Turn 或 SenseVoice，确认脚本 readiness、降级和控制器状态与配置一致。

在这些项目完成前，v0.2 继续作为当前主路径推进，但默认配置暂不切换，也不把内存播放器时间当作真实设备播放延迟。
