# 连续播放固定等待的影响检查与处理结果

日期：2026-10-07。目标：移除上一句播放完成后的 1 秒固定等待，核实续句追加、音频交接、打断、历史记录和耗时统计的影响。

## 处理结论

已在项目源码中移除播放完成后的固定宽限期。上一句的 PCM（原始音频采样）及设备尾部输出完毕、播放快照冻结、送达文字记录保存、事务结算结束后，立即释放已排队的续句。

迟到的续句通过已保存的文字边界继续；它不需要旧播放任务额外保持活跃 1 秒。本次保留了实际音频完成检测及结算顺序。

本次修改消除固定等待。两个独立语音事务之间仍有新连接建立和语音合成耗时。提前准备下一句音频需要扩展当前只保存文字的待播放队列，是另一项范围更大的改动。

## 原因与影响范围

原流程：

```text
上一句合成结束
  → 本地音频队列及设备尾部输出完成
  → 冻结播放快照
  → 固定等待 1 秒
  → 保存送达记录、完成事务结算
  → 释放续句
  → 续句建立连接、发送文字、等待首块音频
```

修改后：

```text
上一句合成结束
  → 本地音频队列及设备尾部输出完成
  → 冻结播放快照
  → 保存送达记录、完成事务结算
  → 立即释放续句
  → 续句建立连接、发送文字、等待首块音频
```

| 检查项 | 修改的实际影响 | 保留的边界与验证 |
| --- | --- | --- |
| 已经排队的连续追加 | 提前约 1 秒开始下一句的语音合成 | 上一句完成后才切换播放器的播放权限，防止清掉剩余采样 |
| 上一句完成后才到达的追加 | 更早走已完成语音的续写分支 | `delivered`（已送达文字边界）及 `last_completed_speech`（最近完成语音）在释放句柄前保存；已播放前缀只用于对账，新事务只合成新增文字 |
| 模型生成期间上一句先结束 | 请求中缓存的旧句柄标识可能已经失效 | 缓存的前缀仍能剥离重复内容；追加接口可为已完成基准创建新的续句事务 |
| 用户说话时暂缓播放 | 没有额外削弱用户的播放优先权 | `hold_unplayed`（暂缓尚未播放输出）及 `release_held`（释放被暂缓输出）继续控制续句许可 |
| 用户打断与回答替换 | 原有取消行为继续生效 | 排队续句一并取消；播放器只接纳当前播放标识的采样，旧事务的迟到音频被拒绝 |
| 已听见文字与历史记录 | 播放完成记录提前约 1 秒落下 | 继续冻结不可变快照，保存送达边界后再结算；连续追加后的累计文字不会退回到单独的第二句 |
| 设备输出延迟 | 仍等待设备尾部真正输出完成 | 不能只依据本地队列为空切换事务，否则已听见文字会被高估；增加了非零设备尾部的验证 |
| 当前播放状态 | 上一句完成后的逻辑活跃状态更早结束 | 有排队续句或结算中的事务时，输出忙碌状态仍保留；完成后的前缀通过持久记录继续提供 |
| 代理调度计时 | 成功播放的完成通知仍来自实际音频完成边界 | `playback_completed`（实际播放完成通知）早于历史结算；没有用删除宽限期代替或移动实际播放边界 |
| 耗时统计 | `turn_total_ms`（回合总耗时）与完成记录可能缩短约 1 秒 | 第一块音频延迟、语音识别推理耗时不因本改动直接改善；比较旧日志时应注意旧总耗时包含这段宽限期 |
| 前端进度事件 | 不再发出已删除宽限期的两个诊断事件 | 检索前端和文档未发现依赖；`append_window_opened`（追加宽限期开启）、`append_window_expired`（追加宽限期结束）及其等待耗时不再产生 |

## 没有合并进本次修改的音频提前准备

当前待播放队列只保存文字。`_wait_then_run`（等待许可后启动播放事务）等续句获得许可后，才进入语音合成流程。因此，删除固定等待不能保证两个独立事务之间完全没有静音。

此前实际日志样本中，两句之间约 1956 毫秒的间隙包含约 1047 毫秒的本地等待与结算，以及约 909 毫秒的新连接和合成。移除固定等待能去掉其中约 1 秒；剩余部分取决于外部语音服务及连接状态，不能直接宣称已消除。

MiniMax 的 Bidi（双向流式语音连接）在收到 `task_flushed`（本次合成结束确认）或取消后，被标记为不可复用。直接在已结束的连接上追加文字会破坏现有的零音频防护，不能以强行复用连接来解决间隙。

如果后续要求独立语音事务之间也能直接接播，应采用明确隔离的下一句提前合成，并同时处理：

1. 新旧事务的连接、情绪设置、字幕时间轴和送达记录分别归属各自事务。
2. 设置待播放音频缓冲上限，避免长句和连续修订积累音频。
3. 用户开始说话、打断、替换、重置或候选被覆盖时，取消提前合成并回收缓冲。
4. 提前生成的音频在正式获得播放许可前不得进入当前播放器或被记为已听见。
5. 提前合成会消耗服务调用额度；被改写的候选可能已经产生合成费用。
6. 对本地语音提供方，还要评估同时合成对 CPU（中央处理器）、GPU（图形处理器）和内存的竞争，以及对 ASR（自动语音识别）的影响。

本次先保留现有事务模型，实施已经确认可安全移除的固定等待。

## 验证结果

新增 6 个覆盖完整输出流程和真实播放器队列的用例，外部合成服务使用可控模拟：

1. 排队续句在上一句音频完成后及时启动，历史结算先于播放权限交接。
2. 本地队列已经为空时，仍等待非零设备尾部输出完毕。
3. 历史结算期间用户开始说话，续句保持暂停，结束后正确释放。
4. 打断取消当前句及排队续句，替换后的播放器拒绝旧音频。
5. 上一句已完成后，同回合决策只合成新后缀。
6. 模型流式生成途中上一句结束，缓存的旧前缀仍可正确接续。

原版本在前 4 项及时交接或完成断言中失败；移除固定等待后通过。之后补充了设备尾部与缓存前缀的验证。

隔离交接基准：同一播放队列、同一文字、零设备延迟，模拟合成立即返回；每个版本采样 3 次。测量上一句回调消费完成至续句音频已经入队的本地耗时。

| 版本 | 3 次耗时，毫秒 | 中位数，毫秒 |
| --- | --- | --- |
| 修改前当前提交版本 | 1047、1031、1031 | 1031 |
| 移除固定等待后的工作区版本 | 32、31、32 | 32 |

这个基准验证本地流程减少约 999 毫秒；它排除了外部网络及合成等待，不能当作真实服务的完整句间间隙。

两组相关测试分别为 105 项通过和 94 项通过，去除重复用例后覆盖 195 个不同用例，包括续句、文字改写、合成调度、播放器、可靠性、协议、调度阶梯、旧合成事务回收和会话记录。

第一组组合测试退出时曾出现后台任务未回收及事件循环已关闭的提示，测试本身均通过。对修改前输出模块另行运行了 101 项既有用例及其中 53 项协议用例，均通过且没有复现该提示；新增续句用例与第二组测试也没有此提示。目前没有稳定复现，不能将它宣称为已解决，也不能据此确认是本次修改导致。
