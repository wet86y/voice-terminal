# 主语音双后端与共享凭据

产品设置第 20 版包含 `inference.backend`（主语音推理后端）。旧设置默认使用 `deepseek`（深度求索）；`minimax` 对应 `MiniMax-M3.1-Flash`（M3.1 闪速版）。两条主语音链路使用 Responses（响应）接口。MiniMax 所有主语音请求固定 `low`（低思考），包括关键词确认、静默检查、协议恢复和传输重试。DeepSeek 新设置默认使用 `fast`（快速）模式；快速／深度选择在当前运行中切换，运行中切回时恢复已保存的选择。

输出预算继续为 393,216；这项是本产品沿用的请求预算，不是对模型能力上限的声明。图片能力通过模型登记决定：DeepSeek 保留文件上传和内联回退；MiniMax 使用内联图片。账本保存中立图片附件，文件标识及缓存按供应方和凭据隔离。

## 保存与请求边界

`PUT /api/v1/settings/inference`（保存推理选择）只接受 `backend`（后端标识）。启动管理页通过 `inference_selection_save`（原生推理选择保存命令）调用同一 Python（业务后端语言）设置入口；无须启动业务服务。

切换先标记待处理，暂缓新的普通模型请求，继续接收输入和后台事件。当前派发准备、活动请求、协议恢复及有界传输重试全部结束后，再保存设置和替换推理客户端。恢复出队到派发的异步间隔也计入等待。提交与其他设置应用共用会话锁；候选安装前重新读取凭据。构造或保存失败时保留原客户端和原设置；供应方网络失败遵循自身重试策略，不自动改用另一家。

切换保留会话标识、历史、播放事务、待处理事件及 DSH（后台执行宿主）任务。停止倾听后不再留下无法派发的恢复／重试等待项。切换本身不会创建一次模型请求。

`runtime.inference`（运行时实际推理状态）提供以下字段：

| 字段 | 中文说明 |
| --- | --- |
| `backend`、`model` | 实际生效的后端及模型 |
| `pending_backend` | 等待当前逻辑请求结束的目标后端，空值表示没有待切换 |
| `reasoning_effort` | 有效思考强度 |
| `reasoning_mode_selectable` | 是否显示运行模式选择 |
| `dsh_sync_pending` | MiniMax 共享凭据是否待同步到后台宿主 |

设置卡片分别显示草稿供应方、实际模型与待切换状态。草稿决定下方密钥和余额／套餐组件；实际模型来自运行时快照。MiniMax 生效时隐藏运行模式并移除对应网格行。正式界面、启动管理页及独立演示入口复用相同组件。

## 共享密钥

DeepSeek 与 MiniMax 分别保存凭据。MiniMax 主语音和在线 TTS（语音合成）共用原有 `minimax_api_key`（MiniMax 接口密钥）和 `MINIMAX_API_KEY`（进程内凭据引用），不新增第二份输入。

任一入口保存会刷新两处配置状态和用量；用量查询以代次识别迟到回包。供应方切换清除旧余额，密钥草稿不跨供应方。仍沿用 MiniMax 原有“不支持查询”说明，不据此生成余额。

主语音请求在请求作用域中冻结认证，图片上传和响应流使用同一凭据；后续请求读取新凭据。语音合成摘除旧预热／可复用连接，在途合成由原事务继续持有。

## DSH 一次初始化

仅修改 `llm-pi-ai.providers.minimax-cn`（指定模型适配器的 MiniMax 中国路由），采用 `anthropic-messages`（Anthropic 消息协议）、`https://api.minimaxi.com/anthropic` 和 `MINIMAX_API_KEY`（共享凭据引用）。不改全局默认模型、已有会话选择、旁路观察器或交接模型。

`host.minimax.sync`（宿主 MiniMax 同步入口）沿用本机桥接令牌认证。密钥写入 DSH 自带凭据存储；每次后续后台请求重新解析引用。接口不返回密钥或原始配置异常，不记录密钥正文，不取消任务、不下载组件。

首次同步覆盖连接与 M3.1 条目，其他显式模型原样克隆；目录模式转换为模型标识条目并展开原 `modelOverrides`（模型覆盖参数），由适配器继承同名内置模型的完整默认值。路由不存在时先挂载不替换目录的连接，再读取目录并合并。写入带 `revision`（并发修订号）；冲突重新读取后有限重试。配置与运行目录读回成功后才记录 `data/config/dsh-minimax-bootstrap.json`（初始化版本标记）。后续同步密钥，保留用户修改的模型参数；仅对本程序上版自动添加的模型名称翻译作一次清理，用户自定义名称保持原值。标记损坏保持待处理，避免静默重做初始化；额外非版本字段不影响已完成标记。

M3.1 登记 1,000,000 上下文、393,216 输出预算、文本及图片输入，仅开放 `low/medium/high/xhigh/max`（低／中／高／更高／最高）五档思考。`forceAdaptiveThinking`（强制自适应思考）只设置在该条目；不额外启用未经验证的兼容参数。

同步失败不影响系统密钥保存。启动完成时补做，并进行 1、2、5、15、30 秒的有限退避重试；耗尽后保留待处理状态，下一次保存或后台启动继续尝试。关闭宿主会取消同步定时任务。

## 动作协议与验证入口

`actions.items.anyOf`（动作数组项的任选分支）由实际动作参数定义生成，提示中的合同和动作包装示例使用同一来源。MiniMax 同时收到明确提示，不依赖接口结构字段代为传达规则。每份输出允许多个不同动作，`request_shadow`（后台请求）最多一次，`continue_listening`（持续倾听）沿用次数与容量限制。

完整动作列表校验通过后才产生动作副作用。`ActionContractError`（动作合同错误）携带类型、字段路径和稳定错误码进入有界恢复；合法流式语音前缀继续受理。等待状态的空文本在两种传输接口保持一致；仅显式旧合并格式入口清理已知跨工具填充，未知字段仍拒绝。
