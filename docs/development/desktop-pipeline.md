# 开发、构建与同包交付流程

本文是开发编译、本机更新、分发与 GitHub（代码托管平台）发行的统一操作依据。源码调试复用当前组件；正式交付只准备一份程序包，本机与安装器消费同一份内容。更新日志仍遵循[更新日志填写规范](release-notes.md)，目录与数据边界见[本地目录与覆盖发布](../guides/local-layout.md)。

## 按目标选择一个入口

在仓库根目录执行。组合任务直接使用组合入口，无需把多个默认完整流程串起来。

| 目标 | 命令 | 实际行为 |
| --- | --- | --- |
| 日常业务开发 | `npm run dev` | 运行源码与前端热更新，复用当前环境与模型 |
| 界面演示 | `npm run dev:ui` | 按需构建调试宿主和演示启动器，不构建正式产品包 |
| 只编译正式程序与前端 | `npm run desktop:build` | 前端类型检查与构建，两个正式原生入口一次编译调用，不安装 |
| 准备完整产品包 | `npm run desktop:prepare` | 按内容复用或更新插件、前端、原生程序和统一程序包，不安装 |
| 只更新本机 | `npm run desktop:publish` | 准备一次产品包，安装一次并完成强制兼容处理 |
| 只生成分发安装器 | `npm run desktop:dist` | 准备产品包，将同一包嵌入一次安装器，不更新本机 |
| 同时更新本机与分发安装器 | `npm run desktop:deliver` | 准备产品包、构建安装器，再安装同一包一次，不上传 |
| 只发布公开发行 | `npm run github:release` | 核对源码状态、准备分发资产、上传并完成公开回下载核验 |
| 本机更新、分发与公开发行一起完成 | `npm run github:release:local` | 核对源码状态、准备分发资产、本机安装同一包、上传并核验 |

本机更新和组合交付会请求现有业务正常退出，保留原有事务、兼容迁移及数据保护规则。正式安装仍执行完整组件检查和实际依赖加载；有效组件不重新下载，不表示跳过内容核验。缺失可选组件继续不阻塞。需要保留正在运行的业务时，只执行编译或产品包准备入口。

正式流程默认只构建正式入口和桌面宿主。显式 `scripts/publish-desktop.ps1 -BuildDemo`（同时准备演示）才额外准备调试宿主和演示启动器。普通调试或构建不运行资产容量审计，不清空编译缓存，不复制模型或环境。

## 复用、重试与输入变化

阶段记录固定保存到 `.local/build/desktop/stages/`（构建阶段状态），记录输入内容与产物摘要。输入包括对应源码、依赖锁、构建脚本、编译配置、工具链及上游产物；不以版本号、文件大小或修改时间单独判定有效。输出缺失、内容被改写、输入变化或状态记录缺失时，默认入口重新执行相应阶段，并打印失效原因。构建过程中输入变化时拒绝登记结果，待编辑完成后重新执行。

已有原生依赖缓存继续交给 Cargo（原生包管理器）复用。两个正式入口使用同一次构建调用与统一特性；前端没有变化时避免清空和重写其输出。首次使用新流程没有阶段记录，会完成一次构建和登记；不复制或清空现有缓存。

| 命令或参数 | 中文说明 |
| --- | --- |
| `scripts/publish-desktop.ps1 -SkipBuild` | 核验并安装已有产品包，不编译、不组包 |
| `scripts/distribute-desktop.ps1 -SkipProductBuild` | 核验已有产品包，只准备相应安装器 |
| `scripts/distribute-desktop.ps1 -SkipProductBuild -SkipInstallerBuild` | 核验已有包和安装器后导出交付记录，两者均不重建 |
| `scripts/publish-github-release.ps1 -SkipBuild` | 核验已有产品包、安装器及交付记录后上传并公开核验 |
| `scripts/verify-github-release.ps1 -Tag v版本号` | 仅重试公开回下载、正文、标签、最新入口及摘要核验，不重新编译、安装或上传 |

精确复用模式遇到输入不一致时停止，不隐式补建。组合流程持有同一构建锁；同一仓库的其它构建进程立即给出占用原因，避免多个会话同时覆盖固定产物。失败会释放构建锁，已完成阶段保留可核验结果。用户工作区的安装互斥锁与事务恢复规则继续独立生效。

程序包采用固定条目顺序、时间和权限生成归档；相同归档内容不替换已有文件。安装已有包不会修改归档及其信息记录。源码改变后重新执行正常入口，不能强行复用。

## 公开发行顺序

1. 核对实际交付区间，完成对应版本的用户更新日志和目标源码审阅。
2. 按任务授权提交并推送源码与版本说明，保证 `main`（主分支）干净且与远端同步。构建流程不自动暂存、提交或推送源码。
3. 选择只发行或同时更新本机的入口，执行一次。已经完成同包交付时，可使用精确复用参数。
4. 脚本核对本体、安装器及交付记录，生成更新清单和摘要列表，上传后自动回下载四项资产，核对正文、标签提交与最新发行入口。
5. 以固定核验报告补录内部交付记录；纯文档补录不改变已经核验的发行标签。

同版本重新发行仍按[GitHub 发行流程](github-release.md#同版本撤回与重新发行)核对标签，不自动移动已有标签。公开核验失败时，上传可能已经成功；先重试核验入口，不能因此再次运行本机安装。核验入口要求标签绑定当前核对的源码提交，进行发行后文档补录前完成该核验。

## 进度与诊断

- `.local/cache/reports/desktop-pipeline-latest.json`（最近一次流水线耗时报告）：各阶段结果与毫秒耗时；嵌套阶段会重叠，不能相加当作总用时。
- `.local/cache/logs/desktop-install-latest.log`（最近一次本机安装日志）：持续记录本体换入、组件完整性、环境加载、配置处理及完成进度，终端定期提示仍在运行。开始组件核验时即更新持久阶段。
- `.local/cache/cargo/build-latest.log`（最近一次原生编译日志）：原始构建输出。镜像配置通过独立文件传入，只有来源访问失败才尝试原站；配置或编译错误直接停止。
- `.local/cache/reports/release-public-latest.json`（最近一次公开核验报告）：标签提交及四项资产大小、完整摘要。失败的回下载暂存保留供诊断，成功后仅回收本轮已知文件。

编译失败查看编译日志；兼容处理失败保留事务并继续修复；公开核验失败只重试公开核验。不能通过删除模型、重建环境、跳过断言或盲目重跑完整流程掩盖原因。

当前实现的隔离回归、真实构建与重复执行结果见[流程验收记录](../testing/desktop-pipeline-20261023.md)。
