# 2026-10-10 尾巴修订上下文接入记录

本次将会话测试支持的 L（布局优化版）接入正式请求构造，并作必要的字段与提示修正。主代理默认运行选项由 fast（快速）改为 deep（深度）；用户仍可切换，既有 fast→none（快速关闭思考）、deep→low（深度低强度思考）和唤醒确认关闭思考的映射保持原样。已经派发的请求继续使用派发时冻结的强度。

## 正式改动

- 固定队列规则进入 STATIC_INSTRUCTIONS（固定指令区），保留完整动作路由、人格和配置规则；动态可选字段和模式切换不改变固定指令。
- HISTORY（历史区）继续完整、按原顺序追加。当前未提交输入、恢复反馈、衔接背景和调度场景保留各自来源，位于当前快照之前。
- voice_request_context（当前请求快照）使用第2版原生 JSON（结构化数据），独立提供 runtime（本轮运行信息）、speech（语音事务）、shadow（后台信息）和 tool_availability（工具可用性），去掉条目正文中的嵌套 JSON 字符串。
- 模型直接获得完整 locked_text（锁定文本）与 editable_text（可改文本）。锁定文本是内部前三段的原样拼接，可改文本来自未提交尾巴；两者作为整体保留，不参与预算截短。锁定不等于确认已听。
- 将 revision（尾巴修订）定义为从锁定边界续写同一段话，speak.text（播报文本）提交完整替换尾巴，保留原尾巴仍有效的后续要点。边界在句中时继续该句。修正不存在的 revision.text（旧错误字段路径），移除容易被当作完整重答的通用修订示例。
- 请求尾部以当前快照、本次任务、最终输出约束收尾。voice_decision_v06（语音决策输出结构）及动作字段保持原样。
- 补齐请求、修订受理／拒绝／无操作、最终语音传达的关联日志和码点长度。没有新增本地语义去重、重写、过滤或根据内容重发的规则；现有事务与边界受理逻辑继续生效。

详细字段和日志说明见[上下文缓存契约](llm-context-cache-contract.md)，运行选项见[会话命令协议](websocket-protocol.md)。
