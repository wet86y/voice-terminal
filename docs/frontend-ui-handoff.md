### 2.3 会话消息

### 2.4 语音主体与会话动效

- 将圆形主体恢复为 **45° 圆角正方形**，主体圆角比例为 32.65%，中心声波保持竖直。
- 背景两层轮廓同步改为圆角菱形，与主体共用旋转角度、圆角和中心位置；边长比例为主体的 1.13 与 1.26 倍。
- 主体下方只保留一个运行状态：等待中、聆听中、思考中、说话中；离线和故障显示对应的关闭／检查状态。
- 状态颜色：等待为蓝色，聆听为青蓝色，思考为紫色，说话为薄荷绿色；离线降饱和，故障使用红色。
- 五条中心线接受归一化音量数据驱动。聆听使用麦克风输入，说话使用实际 TTS（语音合成）播放；等待和思考不制造假播放波形。主体与轮廓仅以同一音量数据作轻微缩放。
- 点击开始语音会话后，同一操作按钮下移至底部，运行模式收起；底部并排显示“停止当前会话”和延迟计时，主体继续居中并放大。停止后恢复开始状态和模式选择。
- 快速连续点击时取消过期布局动画；尊重减少动态效果的系统设置。

**演示与真实音频要区分：** `useVoiceSessionDemo.ts`（语音会话展示逻辑）使用固定音量样例和状态周期，不采集或播放真实音频。共享主体已能消费真实音量，但产品适配器尚未向它提供音量数据，见第 5.2 节。

### 2.5 唤醒与静默

- 唤醒词的“移除”改为完整紧凑按钮，不再拆成上下两行或单独的叉号；与其他操作按钮统一。
- 静默等待的滑条和数值框放在同一行，垂直中心一致，并共享同一个秒数值。
- 滑条前半段为 **5–180 秒**，中点为 180 秒；后半段为 **4–30 分钟**，按整分钟选择。180 秒即 3 分钟，是两段共同边界。
- 数值框显示数值及“秒／分钟”单位；滚轮和上下方向键在秒段每次增减 1 秒、分钟段每次增减 1 分钟，可跨越边界：180 秒向上为 4 分钟，4 分钟向下为 180 秒。禁止出现原先滚轮每次 0.1 分钟或卡在 180 秒的行为。
- 静默值内部统一保存整数秒；直接编辑多位数字期间保持当前单位，防止输入第一位就突然切换单位。滑条、滚轮与键盘调整后立即同步两侧控件。
- 每日静默的时间选择使用共享时间控件，保持暗色界面、边框和选中态一致。

新增 `SilenceTimeoutControl.vue`（静默时限组件）和 `silence-duration.ts`（分段换算与步进函数）。**当前新静默组件只用于演示；正式页面及服务端仍有 90 秒旧限制。**

### 2.6 人格与自定义指令

- 人格文档默认编辑高度为 110 像素，与左侧两个 52 像素标签及 6 像素间距一致；可向下拖动增高，文本框内部滚动。
- 文档增高时左侧标签保持垂直居中；路径和辅助说明不将标签挤偏。
- 自定义指令行尽量利用宽度：触发语义、执行位置、执行目标和启停开关合理分配空间。
- 执行目标默认采用紧凑输入高度，可手动增高；其他组件随该行高度保持居中。
- 启停选项仅保留统一开关，不再显示“启用”文字及独立外框；通过控件说明保留可访问的名称。
- 产品的人格保存、自定义指令增删改和生效时点继续沿用原有业务逻辑。

### 2.7 下拉、时间、日期和星期选择

- 原生下拉菜单改为可定制的暗色样式，选中项用紫色文字与浅色背景标识；删掉右侧对勾。
- 日期、时间、星期采用统一输入框和浮动面板，避免系统默认灰色选择窗口与应用风格冲突。
- `DatePicker.vue`（日期选择）、`TimePicker.vue`（时间选择）、`WeekdayPicker.vue`（星期多选）采用 `Popover`（原生浮动面板）和 `CSS Anchor Positioning`（样式锚点定位）；面板处于顶层，适配边缘、窄宽度和低高度。
- 星期收起时显示“周一、周二”等摘要；展开后可多选，不再平铺七枚大按钮。
- 三种面板共用 `picker-scroll.ts`（面板滚轮约束）：允许内部列表滚动，到边界或无可滚动内容时阻止滚轮传给背景设置页；关闭面板后背景正常滚动。
- 保留鼠标、方向键、确认、退出键、制表键与外部点击的选择／关闭行为。
- 下拉样式受 `appearance: base-select`（可定制原生下拉外观）支持条件控制；旧引擎可能退回默认下拉外观。正式更新必须在实际 WebView2（嵌入式网页引擎）中确认下拉、浮动面板和锚点定位能力。

### 2.8 唤醒任务

- “重复规则”排在日期和时间前：**每天只显示时间；每周显示星期多选和时间；单次显示日期和时间**。
- 正常空间下，规则、日期／星期、时间的宽度上限分别为 180、280、160 像素。日期与星期占同一列，切换规则后不会突然把日期框拉满整行。
- 编辑容器宽度不足 644 像素时，规则单独放在首行，日期／星期与时间保持一致的后续布局；不足 380 像素时使用单列。
- “修改／收起”“取消任务”“添加”“刷新”和表单操作统一为紧凑按钮，状态和操作垂直居中；添加位于刷新左侧。
- 演示支持手动添加、修改、取消和列表状态更新，动作只发生在演示内存中。**产品当前只接通刷新、修改和取消，尚无手动添加入口或对外创建接口。**
- 产品现有固定间隔及 `Cron`（定时表达式）编辑入口保留，不因界面精简而移除已有任务能力。周期任务原有秒数和时区继续保留；界面以小时和分钟展示，不应无意改写已有秒数。

共享排期表单位于 `WakeTaskSchedule.vue`（任务重复规则表单）；产品业务仍由 `useProductAdapter.ts`（产品数据适配器）和原有接口负责。

### 2.9 声纹录制

- “主人声纹模板”使用简洁标题和一行录制说明，删除重复英文小标题。
- 已有模板按“名称与时间／纳入状态／操作”排列：名称和时间分行，状态与按钮整齐靠右；长名称省略并保留完整提示。
- 三段录制按“序号、朗读内容、操作”排列，状态位于段落标题旁。开始／停止／重新录制按钮为紧凑尺寸并垂直居中，不再占据半个卡片宽度。
- 底部完成计数和进度标记靠左，取消与保存靠右。正在录制时禁止操作其他段和保存；三段完成后才能保存。
- 演示可通过开始与停止动作更新片段状态；收起再展开保留已完成进度，取消恢复初始样例。演示的“现场测试”等操作只给展示反馈。
- 产品页面复用新布局，保留服务端采集、客户端采集回退、录制时长、第三段标签、测试结果、模板移出主中心和删除等原有操作。
- 卡片在窄空间自然换行；修复旧样式造成的巨大标题空白。实际场景仍需验证录音、取消、保存和失败恢复。

### 2.10 本地组件

- 将“本地计算”和“系统运行”合并为 **本地组件**，统一呈现模型与 DSH（代理执行宿主）等基础组件。
- 页面顶部只保留三张资源卡片：**常驻内存：已用／全部；提交内存：已用／全部；显存：已用／全部**。删除重复的可用内存和可用显存摘要。
- 默认组件行显示名称、统一位置的状态、运行时、常驻内存／提交内存及必要的显存数据。状态固定在名称右侧，各行上下对齐；详情／重试按钮另占操作列并垂直居中。
- “运行时：Sherpa-ONNX（唤醒引擎）”等信息采用单行形式；不显示运行时间；CPU（中央处理器）推理不显示显存项。
- 可用组件显示“详情”，可展开基础指标和支持的运行位置；不可用组件显示“重试”，是否可点击取决于真实重试能力。
- 运行位置只先提供基础配置和限制说明，不构造模型尚不支持的高级选项。当前模型支持自动、处理器和显卡选择，禁用实际不支持的设备。
- 单位仅显示 **MB／GB（内存显示单位）**，删掉二进制单位长说明。现有字节换算仍按 1024 进位；没有可靠指标时显示“未提供”，不显示伪造的零。
- `system`（旧系统分区）继续兼容到“本地组件”，`silence`（旧静默分区）继续兼容到“唤醒与静默”；`ApplicationSystem.vue`（旧系统页面兼容壳）转为本地组件。

共用 `LocalComponents.vue`（本地组件页面）、`local-components.ts`（呈现数据和内存格式）；演示使用 `useLocalComponentsDemo.ts`（组件状态样例），产品使用 `ComputeSettings.vue`（真实组件数据映射）。

### 2.11 应用图标

- 窗口、任务栏、系统托盘、程序启动入口、启动页和页面图标统一采用圆角菱形加中心声波，来源于主界面主体的静态蓝色版本。
- 图标源为 `apps/frontend/src/assets/app-icon.svg`（矢量标识）；`scripts/generate-app-icons.mjs`（图标生成脚本）生成桌面图标、页面备用图标和启动页矢量副本。

## 4. 业务数据契约

### 4.1 工作台

`WorkbenchModel`（工作台呈现数据）新增／使用的关键字段如下。类型定义在 `interface/workbench.ts`（工作台数据定义）。

| 字段 | 含义与约束 |
| --- | --- |
| `state`（运行状态） | 等待、聆听、思考、说话、离线或异常；用于状态名称、颜色和声波可用性。 |
| `sessionActive`（会话开关） | 与瞬时状态独立；等待唤醒时会话仍可保持开始后的布局。产品当前取连接成功且监听已开启。 |
| `audioLevels`（音频频带音量） | 五个 0–1 数值；仅聆听／说话且会话开启时呈现。缺失、非有限值或越界值均安静处理或限制在有效范围。 |
| `latency`（首音延迟文案）、`latencyPending`（计时进行中） | 产品继续使用既有感知延迟逻辑；界面显示毫秒，不能以样例固定延迟替代真实计时。 |
| `conversation`（会话消息）、`partial`（未完成识别文字） | 保留服务端顺序和稳定消息标识，避免音量帧导致消息重建与滚动位置重置。 |
| `delivered`（已实际播报内容）、`speaking`（消息正在播报） | 保留被打断／未完整交付的状态反馈。 |

### 4.2 时间和设置

- 静默组件的 `modelValue`（绑定值）是整数秒，目标范围 5–1800；正式接口继续提交 `seconds`（秒数），服务运行配置内部使用 `final_silence_ms`（最终静默毫秒数）。
- 日期值采用 `YYYY-MM-DD`（年-月-日），界面显示年／月／日；单次任务的 `when`（本地日期时间）拼接为日期加小时、分钟。
- 时间选择使用 `HH:mm`（时:分）；周期任务已有 `HH:mm:ss`（时:分:秒）通过排期组件保留秒数。
- `weekdays`（星期集合）采用 1–7 对应周一至周日，编辑草稿为逗号分隔字符串；提交业务时沿用现有数组转换。
- `ruleKind`（规则类别）的常见值为 `at`（单次）、`daily`（每天）、`weekly`（每周）；产品已有 `every`（固定间隔）与 `cron`（定时表达式）保留。
- 不从界面样例的日期、固定指标或已完成声纹片段生成真实业务默认值。保存后的实际生效时点由已有业务结果决定。

### 4.3 本地组件

- `LocalComponentsModel`（组件页面数据）只负责呈现；刷新、重试、设备草稿和保存通过事件交给适配器。
- `residentMemory`（常驻内存）和 `privateMemory`（私有提交内存）当前显示进程占用，不代表单个模型独占量；`vram`（显存占用）仅在显卡运行时提供。
- 重试映射：Paraformer（流式语音识别）对应 `asr`（识别进程），SenseVoice 与 SmartTurn（识别分析与语音结束判断）对应 `analysis`（分析进程），KWS 与 FSMN-VAD（关键词唤醒与语音活动检测）对应 `voice`（语音进程），WeSpeaker（声纹识别）对应 `speaker`（声纹进程）。其他组件按自己的标识重试。
- 设备字段区分 `value`（草稿）、`current`（实际运行位置）和 `pending`（尚未应用），不能保存后立即冒充实际已迁移。
- 现有每行设备“保存”仍调用整份计算配置保存方法，尚不代表单模型在线切换；后续根据运行时能力确定应用方式。

## 5. 下一阶段必须补齐或确认的事项

### 5.1 发布前必做：静默范围及正式页面

演示已经使用新静默组件，产品 `product/panels/WakeSettings.vue`（唤醒设置）仍是旧数值框与滑条，最大 90 秒。后端 `voice_terminal/server/product.py`（产品设置存储与投影）的 `MAX_SILENCE_SECONDS`（最长静默秒数）也仍为 90，并在默认投影、设置归一化、校验、保存和运行配置转换中限制范围。

下一阶段将产品页面接到 `SilenceTimeoutControl.vue`（静默时限组件），保留 `silenceSeconds`（静默秒数草稿）和 `saveSilence`（原有保存动作）；同步将后端允许范围扩展至 1800 秒，并核对前端归一化、持久化与重启读取，避免保存失败或被静默截断为 90 秒。保留“下一次会话生效”的业务约定，勿改变 SmartTurn（语音结束判断）的短语结束阈值。

验收：5、90、180、240、1800 秒均能保存并回读；180 秒与 4 分钟可双向滚轮跨越；分钟段按整分钟步进；已有配置无需重置。

### 5.2 发布前必做：真实音量驱动

产品 `useProductControls.ts`（产品控制适配）的工作台数据目前没有填入 `audioLevels`（音频频带音量）。因此产品即使切换到聆听或说话状态，也不会产生与真实声音一致的五条波形。

下一阶段在既有麦克风采集和 TTS（语音合成）播放链中取得实际音量／频带数据，通过业务适配器填入五个归一化值。播放音量须以实际播放为准，不以文本长度、模型生成进度或演示定时器代替。前端不另外建立重复录音链；采样频率、事件字段、节流及数据过期清零规则由真实链路确定。

验收：输入声音时线条变化，安静时归零；思考阶段不跳假波形；开始播放、播报打断、停止会话、断开连接和切换状态后，颜色、状态和波形一致。启动／停止布局由真实会话开关控制，不能按演示周期自动切换。

### 5.3 发布前必做：手动创建唤醒任务

“添加”与完整创建表单当前只在 `ui-demo/DemoSettings.vue`（演示设置页）实现。产品 `WakeTasksSettings.vue`（唤醒任务设置页）只有刷新、修改和取消；`product/api.ts`（产品接口封装）只有读取、修改和删除任务方法。

服务已有 `/api/internal/wake-tasks`（DSH 内部任务创建入口），它面向受控插件调用；产品公开任务接口尚无对应创建动作。下一阶段应增加经过产品会话校验的创建链，并继续委托现有 DSH（代理执行宿主）任务存储和调度，不能在前端再建立一套真实任务存储。需确认手动任务的投递目标、当前语音关联会话及参考上下文规则，不把演示值带入正式数据。

验收：从界面分别创建单次、每天、每周任务，刷新和重启后仍存在；修改／取消继续可用；周几与时区正确，到期投递到对应真实会话。固定间隔、定时表达式及原有任务不被改坏。
