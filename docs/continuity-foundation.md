# 待传达槽位、被动静默与成对会话交接

## 一小时共同静默

Voice（语音）主线与当前关联的 DSH（后台代理执行环境）会话共同静默一小时后，系统先完整归档两侧记录，再结合旧交接文档和待传达槽位生成最多 6,000 字符的交接文档。文档通过既有入口作为背景注入下一轮语音请求和新的 DSH 会话。其他普通 DSH 会话不参与共同静默判定。

用户输入或关联 DSH 会话恢复活动会废弃尚未提交的整理结果。提交前还会核对模型请求、语音队列及 DSH 的实际空闲状态和完整记录水位。双方再次空闲后重新计时。模型或落盘失败时保留原会话、归档、槽位和旧文档，并在继续静默时重试。交接标记保存在 `config/continuity-handoff.json`（会话交接恢复标记），进程重启后先完成未结束的提交。

交接文档保存在 `config/continuity-state.json`（交接文档文件）。没有需要延续的信息时允许空文档；旧文档中的未解决事项必须依据完成、答复、撤销或失效证据才能删除。

手动重置也走成对归档、整理和提交：先停止新输入，结算并取消当前语音与后台运行，再取快照。整理失败时保留历史并恢复原来的监听状态；已取消的工作不会自动重跑。普通停止监听继续保留当前逻辑会话。

## 私有待传达槽位

槽位永久存在，条目按追加方式累积。它保存原会话的延伸材料，交接整理仍需结合完整上下文判断最新用户意图和事项状态。

准入来源：

1. 被动静默期间，被阻止的合法模型输出先持久保存原文，再由唯一主模型调度循环进行一次文本整理。保留事实、待确认问题和必要背景，移除寒暄、过时开场白和重复进度；整理请求禁止动作。失败、取消或输入作用域已关闭时追加带 `unorganized`（未整理）标记的原文。
2. 会话回收整理从完整记录提取仍需传达的结果、尚未答复的问题及未完成事项，与槽位材料共同生成文档。新增提取材料在文档提交前追加保存。

“唯一主模型调度循环”指复用实时语音主模型的既有供应方与串行调度路径，追加一次受限文本整理请求。该请求只输入本次未播放正文，不重放原始任务，不读取槽位快照，要求 `actions=[]`（动作数组为空），输出不进入语音播放。原请求中的动作只执行一次。这一步只整理单次未播放材料；一小时交接或手动重置时，再由独立配置的高强度整理模型结合完整成对归档、槽位和旧交接文档进行综合核对。

同一次输出使用稳定标识去重。实际听到的前缀与未播放正文分开保存；合成提交不代表用户听到。原文落盘失败时先保留内存材料并重试，持久保存前不启动文本整理。

槽位没有正文接口、读取工具或界面面板，主语音模型和 DSH 请求均不注入槽位快照。DSH 现有通用文件和终端权限继续保留。槽位仅由交接整理消费；文档成功落盘后移除本次明确吸收或有证据消解的条目，不等待后续播放，整理期间新增条目继续保留。

### 跨多次交接的逐项核对

槽位条目被消费表示材料已由交接文档承接。后续每次整理仍输入旧交接文档，并逐项核对其中的待执行、待传达、待答复和用户暂缓事项。执行完成、实际传达、有效答复分别依据会话记录判断，任何一个环节完成都不能代替其他环节；写入文档或消费槽位均不构成事项结束的证据。

- 未执行的事项继续保留必要背景、最新进展、下一步和归档引用。
- 已执行但结果未传达的事项继续保留结果和待传达说明；不得因此再次执行原任务。
- 已提出但尚未获有效答复的问题继续保留问题和阻塞背景。
- 用户暂缓的事项保留暂缓意图和恢复条件，不自动重跑。
- 本轮未提及或证据不足的事项继续保留；只有所需环节均有完成证据，或明确撤销、失效时才移除。

正文以自然语言说明尚欠缺的环节，不增加槽位状态管理。例如“报告已生成，路径……，尚未向用户传达结果”在下一次仍未传达时继续保留；实际传达后若另需用户确认，则继续保留待确认问题，直至有效答复或撤销。

即使槽位为空、服务已重启或连续多轮没有提及该事项，后续整理仍读取持久保存的旧交接文档，并结合本轮归档核对。承接链路是“槽位材料 → 交接文档 → 后续逐项核对 → 未解决事项继续写入新文档”，无需把已经吸收的条目重新加入槽位。

`pending-transfer.json`（槽位与原文承接文件）中的字段：

| 字段 | 中文说明 |
| --- | --- |
| `schema_version` | 存储结构版本 |
| `entries` | 尚未消费的条目，按追加顺序保存 |
| `seen` | 已接收标识，防止重试复活已经消费的条目 |
| `captures` | 被拦输出的原始归档材料，消费槽位后仍作为证据保留 |
| `id` / `text` | 条目标识 / 待传达文本 |
| `voice_session_id` / `source_ref` | 来源语音会话 / 输出或归档引用 |
| `unorganized` / `heard_text` | 原文尚未整理 / 已实际传达的前缀 |

## 被动静默设置与运行状态

网页设置中的“静默”页新增“被动静默时间”，默认关闭，预填每日本地时间 23:00—07:00。开始时间包含、结束时间不包含，支持跨午夜，起止时间不能相同。

开启要求 KWS（关键词唤醒）已启用并在当前运行配置生效。禁用 KWS 前必须先关闭被动静默。保存被动静默设置立即生效。

- 时段内普通待机抑制主动语音，后台任务继续执行。
- KWS 命中后打开用户交互窗口，允许唤醒确认、回复及相关后台反馈；跨入静默时段也继续完成该窗口。
- 沿用既有静默梯子；窗口到期、输入作用域结束后按当前时间恢复被动静默或普通待机。
- 系统发声启动的 ASR（语音识别）窗口不被当作用户主动交互。
- 静默结束恢复普通策略，槽位仍等待交接整理。

输出策略覆盖流式首段、TTS（语音合成）提交及 PCM（脉冲编码音频）播放器出口。播放器在设备线程冻结被阻止事务的播放位置，事件循环据此取消并结算；用户再次唤醒时通过新事务正常回复，旧被阻止队列不会继续播放。

`PUT /api/v1/product/settings/quiet-hours`（保存被动静默设置接口）接收：

```json
{"enabled": true, "start": "23:00", "end": "07:00"}
```

`enabled`（启用开关）为布尔值，`start`（开始时间）和 `end`（结束时间）使用 `HH:mm`（小时:分钟）。运行快照的 `quiet_hours`（被动静默状态）只有 `passive_quiet`（当前抑制主动语音）、`user_interaction`（用户交互窗口开启）和 `within_quiet_hours`（当前处于配置时段）三个布尔值。

## 完整成对归档

项目本地 `.runtime/continuity/archives/<archive_id>/`（成对会话归档目录）包含：

| 文件 | 内容 |
| --- | --- |
| `manifest.json`（归档清单） | 两侧身份、工作目录、完整记录范围与文件路径 |
| `voice.md`（语音记录） | 用户原话与精修、实际传达、打断与未播放正文、语义事件 |
| `dsh.md`（后台记录） | 任务消息、工具调用及结果、错误、产物路径、完成信息与澄清 |
| `source.json`（原始记录） | 保留程序过滤前的两侧完整资料 |
| `voice-*.txt` / `dsh-*.txt`（长记录附件） | 大型单条记录的完整文本，主体保存绝对路径 |

清单使用 `archive_id`（共同归档标识）、`voice_session_id`（语音会话标识）、`dsh_session_id`（后台会话标识）、`dsh_present`（是否创建后台会话）、`cwd`（工作目录）、`voice_record_count` / `dsh_record_count`（两侧原始记录数）、`voice_record_range` / `dsh_record_range`（两侧从 `start` 起点到不包含 `end` 终点的范围）、`source_path` / `voice_path` / `dsh_path`（原始与两侧归档绝对路径）。后台读取失败会令整理失败，不能记作未创建会话。

完整导出使用鉴权后的 `session.export`（会话导出端点），按 `export_id`（冻结导出标识）、`offset`（记录起点）、`limit`（页大小，1—500）、`total`（冻结记录上界）分页，返回 `records`（本页完整记录）和 `next_offset`（下一页起点，结束为 null）。交接不再走旧的最近 240 条、10 万字符摘要路径，大型工具结果不受旧 2 MiB（兆字节）响应截断限制。程序过滤机械状态、重复进度与重复语音上下文注入；保留的 `source_record_index`（原始记录索引）可定位到原始记录。

新会话使用既有 `read`（文件读取工具）按行分段读取归档，主体与长附件将超长行拆分便于读取；无损原始结构仍在 `source.json`。归档采用目录提交，提交后保持不可变。`archive-backlog.json`（归档整理目录清单）的 `pending`（待整理归档）和 `consumed`（已整理归档）支持中断恢复，模型失败后旧归档继续参与后续整理。

## 整理配置与提交恢复

`continuity`（交接整理配置）独立于实时语音配置，`provider`（整理供应方）未设置时继承影子模型供应方。每次请求固定发送 `reasoning_effort=high`（高强度思考），服务拒绝时报告整理失败并保留原材料，不自动降低强度。

默认 `max_document_chars=6000`（文档字符上限）、`max_output_tokens=16384`（输出词元预算）、`max_context_tokens=524288`（上下文词元预算）。应按实际模型上下文容量设置后者；程序采用保守字符预算，超出时沿连续记录分段提取，再合并。文档超长重新要求压缩一次，仍超长则失败，不直接截断。

整理顺序固定为任务及修正识别、关联两侧证据、判定执行进展与用户答复阻塞、区分完成与传达及有效答复、吸收静默未播放材料、更新旧文档、输出提交结果。外部引用保持历史数据属性。返回 `document`（新交接文档）、`extracted_items`（本轮提取正文）和 `consumed_entry_ids`（本快照可消费标识），服务端验证结构及标识范围并负责写文件。

提交在既有会话交接锁内按顺序完成：成对归档 → 新提取材料 → 文档保存 → 明确消费 → 旧会话退役与成对身份轮换。恢复标记固定目标身份并记录 `phase`（提交阶段）：`prepared`（准备提交）、`document_saved`（文档已保存）、`consumed`（消费已确认）。重复恢复幂等；文档落盘失败不消费，后续失败则继续原事务。归档缺失会阻止提交，避免文档产生缺失文件引用。

当前活动会话使用 `history/archives/.journals/active-session.sqlite3`（当前会话数据库）持续保存完整模型语义历史、有界聊天视图、上下文代次和语音身份，重启恢复同一会话，不重新播放语音或执行旧动作。`active-voice-session.json`（当前语音身份镜像）继续用于旧版本身份迁移和交接事务关联，同时兼容既有两种会话标识格式。启用 DSH 时沿用其运行数据目录中的身份镜像；没有启用 DSH 时保存到 `.runtime/continuity/`（交接运行目录），未创建后台会话也能继续原交接。数据库检查点先提交依赖正文，再更新身份镜像；恢复检查点损坏时报告错误并保留数据，禁止回退到空历史。

## DSH 原生定时任务与项目唤醒任务

两套定时任务分别服务于 DSH 会话和 Voice（语音）链路，使用不同工具名、存储及投递目标，可以同时启用，互不导入。2026-10-05 共存修复已在便携应用 `apps/20261005-dsh-task-coexist`（桌面程序目录）完成重启和实际验收；详细结果见[本机共存验收记录](../.runtime/dsh-coexist-20261005/acceptance.md)。

DSH 原生 Schedule（会话定时任务）由可选官方 Automation Bundle（自动化功能包）
`@deepseek-ai/dsh-experimental-schedule-bundle` 提供。该 Bundle（功能包）默认关闭，用户可在 Web（网页）侧栏的
Plugins（插件）页面启用；启用后提供 `schedule_create/list/update/delete`（创建、列出、更新、删除会话任务工具）及原生任务页。
每项原生任务绑定创建它的 DSH Session（会话），由官方调度器在该会话中投递；其数据留在 DSH 自己的 Schedule
存储中，不进入项目唤醒任务目录。

统一插件中的 `voice-terminal-wake-tasks`（保留的唤醒任务加载行）组件独立保存并调度项目任务。任意 DSH 根会话均可用
`wake_task_create/list/update/delete`（创建、列出、更新、删除语音链路任务工具）管理项目任务，快捷工具
`schedule_wake`（创建简易唤醒任务）和 `cancel_wake`（取消简易唤醒任务）仍可用。任务与创建会话的存活状态无关，
保存在 DSH home（DSH 用户数据目录）的 `storages/voice-terminal-wake-tasks.json`（项目任务文件）。插件在创建时
冻结该会话的文本上下文，任务到期时只在消息中提供 `task_id`（任务标识），模型需要背景时调用
`read_wake_reference`（读取冻结参考工具）。

项目任务到期时，插件请求桥接层在 Voice 会话交接锁内解析当前语音关联 DSH 会话，并将任务作为普通
`user/message`（用户消息）持久投递到该会话。旧会话已退役时使用新会话；投递暂时失败时保留项目任务并重试。
任务投递不直接控制 Voice 侧的语音模型。DSH 模型需要另外通知 Voice 时调用 `publish_voice_event`
（投递语音事件），将自由文本及可选附加内容写入 Voice 持久信箱。Voice 手动停止监听时，事件留待下次手动启动处理。

### 投递幂等与执行状态

- 每次触发复用 `occurrence_id`（任务发生标识）作为 `request_id`（请求标识）和 DSH `message.id`（消息标识）。同一任务发生重复投递时返回 `duplicate`（重复确认），不再生成第二条任务消息。
- 项目任务的定时消息 `source.kind = schedule`（来源类型为定时任务）表示普通 DSH 消息，不代表 Voice activation（语音激活），也不表示它由原生 Schedule（会话定时任务）创建。它可以使用 DSH Harness（执行环境）的全部现有工具和子代理能力。目标包含 Voice（语音模型）时，任务应调用 `publish_voice_event`（投递语音事件）；仅面向 Shadow Agent（影子代理）的任务可以普通完成。
- `publish_voice_event`（投递语音事件）没有显式 `event_id`（事件标识）时，Wake Tasks（定时任务插件）使用现有 DSH 会话标识和 `callId`（工具调用标识）生成稳定事件标识。同一工具调用被恢复或重放时，Voice 持久信箱只收下一份事件。
- `activation_id`（语音激活标识）只标识当前 Voice activation（语音激活）。`turn`（回合号）、`step`（步骤号）和 `callId`（工具调用标识）沿用 DSH 执行记录关联回合过程；不增加 `run_id`（运行标识）或任务字段。
- 任务 `status`（任务状态）只表示调度状态，如 `pending`（待触发）、`archived`（已归档）和 `cancelled`（已取消）；`delivery_history`（投递历史）只表示任务消息已持久投递。这两者都不表示执行成功、失败或运行中。任务存储 `schema_version`（结构版本）保持不变。未来如需展示单次执行结果，应使用独立的执行记录。
- Voice terminal tool（语音终端工具）在 Voice 确认结果已收下后调用 `exec.concludeTurn`（结束当前回合）。Bridge（桥接层）只清理该工具开始时捕获、且仍与当前相同的 `activation_id`（语音激活标识）；普通 `tool/result`（工具结果）不会取消 DSH Agent（代理）。只有显式 `session.cancel`（取消会话）或 `session.retire`（退役会话）才取消整个 DSH Agent（代理）。

项目插件提供 `schedule_wake`（创建简易唤醒任务）、`cancel_wake`（取消简易唤醒任务）、`read_wake_reference`（读取冻结参考）、`wake_task_create`（创建项目任务）、`wake_task_list`（列出项目任务）、`wake_task_update`（更新项目任务）、`wake_task_delete`（取消项目任务）及 `publish_voice_event`（投递语音事件）。原生 `schedule_create/list/update/delete`（创建、列出、更新、删除会话任务工具）属于官方 Bundle（功能包），处理 DSH 会话任务；两套工具名不同。

项目任务存储位于 DSH home（DSH 用户数据目录）的 `storages/voice-terminal-wake-tasks.json`（项目任务文件）。插件迁移旧 Voice `wake-tasks.json`（旧语音任务文件）中的可转换项目任务，并保持已有项目任务和历史不变；它不导入官方 Schedule（会话定时任务），也不改写 DSH 的原生任务存储。安装及构建会保留用户已启用的官方 Automation Bundle（自动化功能包）。Voice Terminal（语音终端）的“唤醒任务”页只展示项目任务。

## 安装

停止当前 Voice Server（语音服务端）及其受管 DSH 进程后，运行 `scripts/setup-dsh.ps1`（DSH 安装脚本），然后按项目日常方式重新启动 Voice Server。安装脚本会备份现有 DSH home、预检旧 Voice（语音）任务、构建两个项目插件并更新 Web profile（网页配置）；用户已启用的官方 Automation Bundle（自动化功能包）会保留。
