# CPU（中央处理器）与内存资源管理

当前版本将模型加载、按需导入、声纹实例释放和处理器轻量检测纳入正式运行路径。Paraformer（流式识别模型）与 SenseVoice（整句精修模型）仍在独立工作进程；推理精度、队列容量、播放时钟、实际交付结算和有效模型上下文保持原约定。逐项测量和模型输出对照见[2026-10-10 内存优化报告](memory-optimization-20261010.md)。

## 默认行为与未启用候选

`config/runtime-resources.json`（资源策略文件）当前为 `policy_schema: 2`（策略格式版本），文件内存映射、按需导入及声纹实例释放已是代码默认行为；轻量语音检测由 `vad_backend`（检测后端）选择。共享音频和历史落盘仍关闭，单模型独立测量不能视为整套应用收益。

| 字段 | 中文说明 | 默认值 |
| --- | --- | --- |
| `native_threads` | 各工作进程原生数值库线程预算；空对象保留继承环境 | `{}` |
| `policy_schema` | 策略格式版本 | `2` |
| `vad_backend` | 主服务语音活动检测后端；自动模式仅在 CPU 且资产、依赖校验通过时选 ONNX（开放神经网络交换格式） | `auto`（自动选择） |
| `shared_audio` | 进程内音频范围复用、转换缓存及协商后的共享音频候选 | `false`（关闭） |
| `disk_history` | 完整账本、交付记录、影子上下文和内置后台代理归档落盘候选 | `false`（关闭） |
| `history_cache_bytes` | 会话读取缓存预算；活动请求和未落盘记录另计 | `8388608`（8 MiB，二进制兆字节） |

`mmap`（文件内存映射）加载和 FunASR 按需导入仅在锁定框架版本及源码摘要匹配时应用；遇到未知版本或模块结构时回退到上游完整导入/原版权重加载器。更新了模型路径后才会再次加载权重。它们减少重复主机内存与无关模块，不改变模型张量原有的运行设备。

声纹工作进程在识别或评分任务结束、身份设置关闭及进程清理等生命周期边界释放缓存的引擎引用；进行中的原生推理仍由局部引用持有，避免使用中销毁会话。释放模型对象不保证已经加载的 CUDA（显卡计算平台）动态库、运行上下文或显存缓存即时卸载。

资源策略仍用于线程环境、缓存位置、共享音频、历史持久化及检测后端选择。各推理引擎继续使用原生分配器；资源登记不接管原生堆或图形处理器分配器，也不把模型内存限制到一个人为上限。

角色值 `bootstrap`（启动检查）、`asr`（流式识别）、`analysis`（结束判断与整句精修）、`voice`（主语音服务）、`speaker`（声纹工作进程）可以分别配置。当前 `native_threads`（原生数值库线程预算）为空对象，不强行降低所有进程线程数；分析进程内的两个模型共享数值库预算，线程调整仍需整进程实测。

宿主在启动与重启工作进程时，于数值库首次导入前配置 OpenBLAS（线性代数库）、OpenMP（并行运行库）和 MKL（数学内核库）的环境变量。模型自身的 `ncpu`（模型内部线程数）及 ONNX Runtime（模型推理运行库）的显式线程设置不被覆盖。`MODELSCOPE_CACHE`（模型社区缓存）、`HF_HOME`（模型仓库缓存）、`TORCH_HOME`（张量框架缓存）、`PIP_CACHE_DIR`（包安装缓存）统一到有效模型根目录下；已有用户环境覆盖优先。

`VOICE_RESOURCE_POLICY`（资源策略文件路径环境变量）可为隔离对照指定另一策略文件；策略在宿主启动及工作进程重启时生效，不会热改现有工作进程。`shared_audio`（共享音频）与 `disk_history`（历史落盘）仍为关闭，不属于本次已启用的内存优化。

## 必需组件与运行依赖

分发本体的 `config/runtime/voice-runtime.lock.json`（语音运行依赖锁）固定 Python（后端解释器）3.12.10 和全部依赖；工作区由 `runtimes/python`（语音运行环境）承载，开发工作区对应 `.local/runtimes/python`。下载或更新语音环境始终校验完整六组依赖，而不是只写入请求模型所属的一组：

| 依赖组 | 中文说明 |
| --- | --- |
| `voice-core` | 语音服务基础依赖 |
| `torch-cpu` | PyTorch（深度学习框架）及语音识别运行依赖；兼容 GPU（图形处理器）组合另行校验复用 |
| `onnx-cpu` | ONNX Runtime（模型推理运行时）处理器组合 |
| `sherpa-cpu` | Sherpa-ONNX（唤醒推理运行时）处理器组合 |
| `modelscope-download` | 固定模型下载所需依赖 |
| `onnx-vad` | 轻量语音活动检测所需依赖 |

所有模型、代理组件和语音运行环境都是必需组件。新安装按当前程序随包清单安装；旧版显示为待更新，缺失、损坏或待更新都会阻止整体语音服务启动。程序启动前会对每个已安装组件执行完整摘要复核；只有六组依赖、所有组件版本及全部文件摘要都通过后才启动或恢复服务。旧版本模型没有推理兼容层；应从组件卡片更新、导入或打开固定来源，不可绕过版本门禁。

语音环境更新在独立候选目录组装、按当前锁验证后，再以资源事务替换旧目录。已登记且仍有效的 GPU 环境会参与复用判定；PyTorch（深度学习框架）、torchaudio（音频扩展）和 ONNX Runtime（模型推理运行时）的显卡构建必须通过当前版本、完整文件及加载检查。检查不通过时保留旧环境并报告失败，不以 CPU（中央处理器）依赖覆盖经验证的显卡依赖。独立的 `runtimes/python-gpu`（专用显卡环境）不属于 CPU 运行环境的替换目标。

更新前和导入后的完整文件校验会显示文件清单核对及摘要进度，并响应取消。目录只遍历一次，最多四个线程复用缓冲区进行全部摘要核验；取消后收集校验线程，配置入口不会继续下载或替换环境。速度受磁盘与文件缓存影响，完整实测及边界见[语音环境校验修复](runtime-validation-20261010.md)。

组件下载、复制和新环境清单生成共用有界并发及可取消进度。一个宿主内的后续模型任务，在清单与受管文件指纹未变化时复用本次已经完整验证的共享环境；正式启动仍复核全部内容摘要。管理页在任务终态和部分组件提交后立即重读清单，活动任务每两秒补查，空闲每十秒刷新，显示实际更新时间；首次下载就绪后可直接进入启动动画。规则、实测与验收边界见[下载与首次启动修复](download-startup-flow-20261010.md)。

更多组件版本、更新事务及故障恢复约束见[程序升级与必需组件更新](model-resource-updates.md)。

## 轻量 FSMN-VAD 检测资产

当前随包资源包含由原 `funasr/fsmn-vad/model.pt`（流式检测权重）导出的未量化 ONNX（开放神经网络交换格式）资产，保留原权重与配置。导出使用原模型和精度、动态特征帧轴及 CPU（中央处理器）执行提供程序；完成会话加载、不同帧长输出和流式缓存数值对照后才进入组件清单。

FSMN-VAD 资源清单记录 `source_sha256`（原权重摘要）、`quantized`（是否量化）、`files`（资产摘要）和 `numerical_validation`（数值对照）。运行时只读取随包或已安装资产，不下载、不自动导出。`policy_schema: 2`（策略格式版本）默认 `vad_backend: auto`（检测后端自动选择）：只有 CPU 模式且资产、运行依赖与摘要均可用时才使用轻量 ONNX；明确选择 GPU（图形处理器）时仍用 PyTorch（深度学习框架）原后端。轻量模型加载失败或资产不匹配时回退原后端；但旧/损坏组件仍须先通过整体组件摘要门禁。

检测接口仍使用 200 毫秒模型窗口及原端点参数。适配器独立维护前端、模型缓存、端点判定器和待消费样本；支持短输入、空最终刷新和重置。空最终刷新沿用原检测器的关闭事件语义，并释放候选流式状态。SmartTurn（结束判断模型）及其特征提取器仍位于分析进程。

实现依据 [FunASR（语音处理框架）官方流式检测路径](https://github.com/modelscope/FunASR/blob/main/runtime/python/onnxruntime/funasr_onnx/vad_bin.py)，处理器运行依赖固定为已验证的 0.4.3 分发版本。新程序清单将模型作为必需组件更新，不再要求用户先运行安装导出脚本。

## 音频所有权与释放

资源登记使用弱引用观察缓冲所有者，租约持有正在使用的数据。原生推理线程或执行器实际结束后释放租约；请求取消、连接断开或语音轮重置不提前释放正在读取的输入。

候选音频范围复用缓存有界且追加时失效。转换键包含采样率、样本范围、幅值约定和数值精度。声纹前端保持原始16位幅值与64位浮点计算，分析输入保持32位浮点及原归一化规则；转换缓存不承担重采样。声纹模板指纹、判定阈值与模型输入约定不变。

`shared_audio: false`（共享音频默认关闭）。显式启用候选时，整句分析和声纹完整窗口可协商共享内存；实时识别分块和声纹实时帧保留既有正文传输，旧客户端、外部工作进程和不支持共享的连接继续兼容。

`audio_ref`（音频租约引用）包含版本、宿主实例、接收进程代次、双方进程标识与创建时间、请求标识、采样率、声道、数值格式、映射名和范围，并使用宿主凭据签名。接收端在推理提交前校验。只有明确返回 `AUDIO_REF_REJECTED`（引用在提交前被拒绝），创建方才回退正文传输；模型已运行的错误不重试，避免重复推理。Windows（操作系统）虚拟环境可能另起实际业务进程，因此身份必须由工作进程自己报告。

创建方结束请求时关闭自己的映射句柄；接收方已打开的映射仍保持有效，直到原生调用结束并关闭。进程崩溃由宿主的进程组管理确认并回收，操作系统释放死亡进程句柄。本轮不复用仍被推理读取的共享内存槽位。跨进程候选当前只对受管 Windows（操作系统）进程启用，遵循 [Python（程序运行环境）3.12 共享内存生命周期](https://docs.python.org/3.12/library/multiprocessing.shared_memory.html)。

原录音窗口、队列容量、合成音频上限及8 MiB（二进制兆字节）磁盘溢写阈值保留。合成临时文件沿用原关闭回收；播放器设备回调只读已准备好的内存，不访问记录存储或溢写文件。

## 完整历史与归档

`disk_history: false`（历史落盘默认关闭）。显式启用候选时，SQLite（本地数据库）日志存储可把账本、交付记录、影子上下文、完整交付去重身份和内置后台代理归档接入同一个会话读取缓存预算。索引支持迟到精修、交付查重及历史记录查找，不需要为了查一条记录重建完整历史。

位置与正文冻结规则保留；迟到精修更新补充材料而不改写已经提供给主模型的正文。影子上下文修订号及重置代次保持原约定。有效上下文仍完整读取，活动模型请求构造完整上下文时的临时内存不受读取缓存预算限制。

写队列只保存记录键，同一活动记录的新修订合并。未持久化材料保留活动引用，写入失败可重试；关闭失败返回未完成并记录错误，不清空待写正文。重置切换存储命名空间，保留旧原始材料，且不重放旧任务。日志关闭时生成同名完整可读文档。持续存储故障期间的待写内存与错误会显示在资源状态中。

原成对归档仍在 `.runtime/continuity/archives`（成对会话归档目录），保留 `voice.md`（语音文档）、`dsh.md`（后台文档）、`source.json`（完整原始记录）、`manifest.json`（归档清单）及长文本附件。新会话日志位于该目录下 `.journals`（记录存储子目录）。既有交接提交和恢复机制保留。

归档采用记录视图、逐记录文档写入与流式摘要计算，去掉完整账本的中间复制和整份文档字符串。归档标识逐字节兼容原规则。原整理器仍需要一份完整语义材料，模型请求也仍会构造完整输入；本轮没有通过截断历史获取内存收益。

## 资源状态接口

原计算状态新增可选 `resource_status`（资源状态），旧返回字段继续存在。

| 字段 | 中文说明 |
| --- | --- |
| `processes` | 按进程标识与创建时间去重的工作进程清单 |
| `complete`、`missing_roles` | 采样覆盖是否完整及缺失角色；旧工作进程缺少指标时不能报告完整提交量 |
| `private_commit_bytes` | 私有提交字节；任一进程无法提供时，合计为空 |
| `rss_bytes` | 常驻内存字节；合计可能重复计入不同进程共享的物理页面 |
| `gpu_dedicated_bytes` | 进程专用显存字节；不代表整张显卡显存用量 |
| `thread_count` | 当前线程数量 |
| `managed_cache_bytes` | 已登记的缓存字节；不等于整个进程内存 |
| `active_leases` | 正在持有的数据租约数量 |
| `leased_bytes` | 单进程内按数据对象去重的租约字节 |
| `caches` | 各用途缓存计量 |
| `owners` | 所有者状态，含会话存储错误、待写材料及读取预算 |
| `leases` | 租约用途、容量、活动引用数量与释放条件 |

两个分析通道报告同一进程时只计一次。角色覆盖缺失时，私有提交合计为空，其他合计只代表已采样进程。计算状态的范围是主语音服务与模型工作进程，宿主整棵进程树的指标继续由应用状态提供。进程私有提交与物理驻留必须分别报告；不能将减少的线程栈提交量全部解释成释放物理内存。原生引擎的分配器缓存由进程内存指标观测，不能误记作已登记的应用缓冲。

## 内存口径与验收

常驻工作集 `rss_bytes`（常驻内存字节）是进程此刻驻留的页，包含共享映射，跨进程相加可能重复计入同一物理页。Windows（操作系统）`peak_wset_bytes`（历史峰值工作集）是进程启动以来的高水位，不是周期采样最大值。`private_commit_bytes`（私有提交字节）是进程私有提交量近似值，不是物理驻留量，也不是系统总提交量。Windows PDH（性能计数器接口）的 `gpu_dedicated_bytes`（进程专用显存字节）按进程计量，不以整张显卡已用内存代替应用显存。

基准在 PyTorch CUDA 已初始化时还记录 `torch_allocated_bytes`（PyTorch 已分配的张量显存）与 `torch_reserved_bytes`（PyTorch 缓存分配器保留的显存）。保留量可以高于张量已分配量；这些数不等价于驱动报告的专用显存，也不覆盖 ONNX Runtime 等其他运行时的全部显存。不可取得的值标记为 `null`（未知），不可当作零。

`scripts/benchmark_runtime_resources.py`（单侧真实模型资源测量工具）在独立进程中固定本地音频，记录导入、加载、预热、推理和释放阶段；角色为 `vad`（语音检测）、`speaker`（声纹）、`asr`（流式识别）、`refine`（精修）及 `endpoint`（结束判断）。`scripts/benchmark_model_memory.py`（串行基线/候选对照工具）以相同输入、设备、线程和预热设置分别启动两侧进程，不访问麦克风或云端，并保存音频摘要、实际运行设备、原始输出与输出对照。周期采样的峰值可能漏掉短暂峰值；RSS、Windows 高水位工作集、私有提交和专用显存分别报告，不混作一个“内存”值。

`scripts/validate_vad_streaming.py`（流式检测功能对照工具）覆盖长录音、不同输入分块、短输入、空最终刷新和重置；输出错误与事件原文，不隐藏失败。

本轮轻量 ONNX 检测及前三项加载/生命周期改动的真实模型测量，使用固定本地样本在独立进程串行对照；角色测量不能直接相加推断整套应用节省。SenseVoice 量化候选出现文本差异，没有设为默认；声纹有限线程候选虽完成测试，也未设为默认。完整多进程应用的并发、首字、首音、打断、精修完成和长会话表现仍应单独验收。测试数量及唯一冻结基线失败的复现依据见[内存优化报告](memory-optimization-20261010.md)和[组件更新说明](model-resource-updates.md)。

`native_threads`（原生线程预算）、`shared_audio`（共享音频）和 `disk_history`（历史落盘）仍分别保持默认空预算、关闭和关闭；不能把这几项未启用候选算作本轮收益。`mmap`（权重文件内存映射）、FunASR 按需导入、声纹缓存实例释放及 CPU 模式 `auto`（自动选择）的未量化 FSMN-VAD 轻量后端则属于已采用实现。
