# CPU（中央处理器）与内存资源管理

本轮把启动策略、资源计量、音频所有权和完整会话存储接入现有应用宿主。Paraformer（流式识别模型）与 SenseVoice（整句精修模型）保持独立工作进程。现有模型内部线程、推理精度、队列容量、播放时钟、实际交付结算和有效模型上下文保持原约定。

## 默认行为与候选开关

`config/runtime-resources.json`（资源策略文件）默认使用原推理和历史路径。以下性能候选需要逐项取得完整应用对照证据后再成为默认值，不能把单模型收益直接视作整套应用收益。

| 字段 | 中文说明 | 默认值 |
| --- | --- | --- |
| `native_threads` | 各工作进程原生数值库线程预算；空对象保留继承环境 | `{}` |
| `vad_backend` | 主服务语音活动检测后端 | `funasr`（原后端） |
| `shared_audio` | 进程内音频范围复用、转换缓存及协商后的共享音频候选 | `false`（关闭） |
| `disk_history` | 完整账本、交付记录、影子上下文和内置后台代理归档落盘候选 | `false`（关闭） |
| `history_cache_bytes` | 会话读取缓存预算；活动请求和未落盘记录另计 | `8388608`（8 MiB，二进制兆字节） |

默认接入启动前资源策略、下载缓存目录、版本清单检查、硬件能力报告、进程与租约计量。各推理引擎继续使用原生分配器；资源登记不宣称接管原生堆或图形处理器分配器。

角色值 `bootstrap`（启动检查）、`asr`（流式识别）、`analysis`（结束判断与整句精修）、`voice`（主语音服务）、`speaker`（声纹工作进程）可以分别配置。4 线程只是候选起点。分析进程内的两个模型共享原生库预算，不能只凭 SmartTurn（结束判断模型）的改善就启用分析进程预算。

宿主在启动与重启工作进程时，于数值库首次导入前配置 OpenBLAS（线性代数库）、OpenMP（并行运行库）和 MKL（数学内核库）的环境变量。模型自身的 `ncpu`（模型内部线程数）及 ONNX Runtime（模型推理运行库）的显式线程设置不被覆盖。`MODELSCOPE_CACHE`（模型社区缓存）、`HF_HOME`（模型仓库缓存）、`TORCH_HOME`（张量框架缓存）、`PIP_CACHE_DIR`（包安装缓存）统一到有效模型根目录下；已有用户环境覆盖优先。

候选应使用单独的策略文件。`VOICE_RESOURCE_POLICY`（资源策略文件路径环境变量）指定该文件，下一次宿主启动时生效；运行中不自动更改现有工作进程预算。不要同时打开多个候选后归因内存收益。

## 依赖安装与回退

Python（程序运行环境）限定为 3.12。`apps/server/runtime-constraints.txt`（运行依赖锁）固定当前业务依赖及传递依赖版本；两个张量框架安装组合文件分别固定 CPU（中央处理器）和 CUDA（图形处理器计算运行库）12.8 版本。安装器、启动检查与诊断工具共用清单。

正常安装创建独立 `.runtime/environments/runtime-candidate`（业务候选环境），不修改全局程序运行环境，也不自动替换现用启动环境。`-EnvironmentDir`（业务环境目录参数）可以指定其他目录。只有完成版本校验和依赖一致性检查的业务环境，才写入 `voice-runtime-ready.json`（环境就绪标记）；安装更新开始时撤销旧标记。启动脚本与双击入口读取同一份 `.runtime/application/runtime.json`（业务环境激活记录）；未激活时沿用原环境，明确传入 `-Python`（指定程序运行环境参数）或 `--python`（宿主指定程序运行环境参数）优先，用于独立对照及回退。激活环境缺失或未就绪时报告错误，不静默选择另一个环境。环境就绪标记只表示依赖校验完成，不能代替完整应用性能验收。

```powershell
# 安装本地分析与轻量检测候选；不会启用任何资源候选开关。
.\scripts\setup.ps1 -Python D:\DevTools\Python312\python.exe -Analysis -OnnxVad -TorchGpu -SkipDsh

# 共用版本清单诊断，包含 pip check（包依赖一致性检查）。
.\.runtime\environments\runtime-candidate\Scripts\python.exe -m voice_terminal.dependencies --candidate

# 回退到现用环境；同一资源策略可另行恢复默认文件。
.\scripts\start.ps1 -Python D:\DevTools\Python312\python.exe
```

`-Analysis`（安装分析模型）、`-OnnxVad`（安装并导出轻量检测候选）、`-TorchGpu`（仅安装已验证的张量框架图形处理器组合）、`-SkipDsh`（跳过后台代理安装）属于安装参数。上例保留本机的张量框架图形处理器组合及 CPU（中央处理器）语音推理运行库组合；没有图形处理器参数时，仍沿用安装器既有 CPU（中央处理器）默认行为。既有 `-Gpu`（安装完整可选图形处理器后端参数）另外安装语音推理库的图形处理器版本。图形处理器推理性能验收前，不应自动把现用模型切换到新环境。

主服务首次选设备和查询计算状态，读取已加载工作进程的能力报告；独立调试入口必要时执行一次性隔离探测。查询不在主服务中加载张量框架或建立 CUDA（图形处理器计算运行库）上下文。模型实际设备、加载失败回退和重启生效规则保留。

本次独立验证环境位于 `.runtime/resource-validation/full`（完整依赖验证环境）。它由现用已安装业务分发文件复制而来，再安装缺少的锁定包和修复依赖冲突；不是从空目录重装全部大型安装包。安装解析器、依赖一致性检查和后端回归分别验证版本关系、分发完整性及业务行为。现用全局环境未改动。`ml-dtypes`（多种数值类型支持库）在验证环境中固定到 0.5.4，修复 ONNX（开放模型交换格式）1.23.0 所需最低版本冲突。

2026-10-03 用户授权直接替换后，激活上述已验证环境，下一次启动使用它。独立应用重新打包并替换 `.runtime/launcher/VoiceTerminal/VoiceTerminal.exe`（双击启动入口）；原完整启动器保留在同级 `VoiceTerminal-before-resources-20261003`（替换前启动器备份）目录。原全局环境保留，资源候选开关继续按验收结论关闭，模型权重与设备选择沿用原配置。本次不自动启动应用或开启监听。

环境激活记录字段 `python`（业务环境路径）、`previous_python`（原环境路径）、`activated_at`（香港时间激活时间）和 `dependency_lock_sha256`（依赖约束摘要）记录切换信息。回退到原环境可运行前述明确指定环境的启动命令；撤销激活记录后，双击入口也恢复原环境。若需回退启动器，将当前启动器目录另存后，把同级完整备份目录恢复到原目录名；必须连同 `_internal`（启动器随附运行库）一起恢复。

## 未量化检测资产

安装器从现有 `funasr/fsmn-vad/model.pt`（流式检测权重）导出 `onnx`（候选资产目录），保留原权重与配置。导出使用原模型、原精度、动态特征帧轴和 CPU（中央处理器）执行提供程序。语法校验、会话加载及多种帧长的模型输出/流式缓存数值对照完成后才原子提交目录。

`manifest.json`（资产清单）包含 `source_sha256`（原权重摘要）、`quantized`（是否量化）、`files`（资产摘要）和 `numerical_validation`（数值对照）。运行时先校验权重与所有必需文件，不下载、不自动导出。候选资产不匹配时记录原因并回退原后端。明确选择图形处理器时继续使用原后端。

检测接口仍使用 200 毫秒模型窗口及原端点参数。适配器独立维护前端、模型缓存、端点判定器和待消费样本；支持短输入、空最终刷新和重置。空最终刷新沿用原检测器的关闭事件语义，并释放候选流式状态。SmartTurn（结束判断模型）及其特征提取器仍位于分析进程。

实现依据 [FunASR（语音处理框架）官方流式检测路径](https://github.com/modelscope/FunASR/blob/main/runtime/python/onnxruntime/funasr_onnx/vad_bin.py)，运行依赖固定为已验证的 0.4.3 分发版本。

## 音频所有权与释放

资源登记使用弱引用观察缓冲所有者，租约持有正在使用的数据。原生推理线程或执行器实际结束后释放租约；请求取消、连接断开或语音轮重置不提前释放正在读取的输入。

候选音频范围复用缓存有界且追加时失效。转换键包含采样率、样本范围、幅值约定和数值精度。声纹前端保持原始16位幅值与64位浮点计算，分析输入保持32位浮点及原归一化规则；转换缓存不承担重采样。声纹模板指纹、判定阈值与模型输入约定不变。

整句分析和声纹完整窗口可协商共享内存。实时识别分块和声纹实时帧保留既有正文传输；旧客户端、外部工作进程和没有共享能力的连接继续兼容。

`audio_ref`（音频租约引用）包含版本、宿主实例、接收进程代次、双方进程标识与创建时间、请求标识、采样率、声道、数值格式、映射名和范围，并使用宿主凭据签名。接收端在推理提交前校验。只有明确返回 `AUDIO_REF_REJECTED`（引用在提交前被拒绝），创建方才回退正文传输；模型已运行的错误不重试，避免重复推理。Windows（操作系统）虚拟环境可能另起实际业务进程，因此身份必须由工作进程自己报告。

创建方结束请求时关闭自己的映射句柄；接收方已打开的映射仍保持有效，直到原生调用结束并关闭。进程崩溃由宿主的进程组管理确认并回收，操作系统释放死亡进程句柄。本轮不复用仍被推理读取的共享内存槽位。跨进程候选当前只对受管 Windows（操作系统）进程启用，遵循 [Python（程序运行环境）3.12 共享内存生命周期](https://docs.python.org/3.12/library/multiprocessing.shared_memory.html)。

原录音窗口、队列容量、合成音频上限及8 MiB（二进制兆字节）磁盘溢写阈值保留。合成临时文件沿用原关闭回收；播放器设备回调只读已准备好的内存，不访问记录存储或溢写文件。

## 完整历史与归档

候选采用 SQLite（本地数据库）日志存储。账本、交付记录、影子上下文、完整交付去重身份和内置后台代理归档接入同一个会话读取缓存预算。索引支持迟到精修、交付查重及历史记录查找，不需要为了查一条记录重建完整历史。

位置与正文冻结规则保留；迟到精修更新补充材料而不改写已经提供给主模型的正文。影子上下文修订号及重置代次保持原约定。有效上下文仍完整读取，活动模型请求构造完整上下文时的临时内存不受读取缓存预算限制。

写队列只保存记录键，同一活动记录的新修订合并。未持久化材料保留活动引用，写入失败可重试；关闭失败返回未完成并记录错误，不清空待写正文。重置切换存储命名空间，保留旧原始材料，且不重放旧任务。日志关闭时生成同名完整可读文档。持续存储故障期间的待写内存与错误会显示在资源状态中。

原成对归档仍在 `.runtime/continuity/archives`（成对会话归档目录），保留 `voice.md`（语音文档）、`dsh.md`（后台文档）、`source.json`（完整原始记录）、`manifest.json`（归档清单）及长文本附件。新会话日志位于该目录下 `.journals`（记录存储子目录）。既有交接提交和恢复机制保留。

归档采用记录视图、逐记录文档写入与流式摘要计算，去掉完整账本的中间复制和整份文档字符串。归档标识逐字节兼容原规则。原整理器仍需要一份完整语义材料，模型请求也仍会构造完整输入；本轮没有通过截断历史获取内存收益。

## 资源状态接口

原计算状态新增可选 `resource_status`（资源状态），旧返回字段继续存在。

| 字段 | 中文说明 |
| --- | --- |
| `processes` | 按进程标识与创建时间去重的工作进程清单 |
| `complete`、`missing_roles` | 采样覆盖是否完整及缺失角色；旧工作进程缺少指标时不能报告完整提交量 |
| `private_commit_bytes` | 私有提交字节；任一进程无法提供时，合计为空 |
| `rss_bytes` | 常驻内存字节；合计可能重复计入不同进程共享的物理页面 |
| `thread_count` | 当前线程数量 |
| `managed_cache_bytes` | 已登记的缓存字节；不等于整个进程内存 |
| `active_leases` | 正在持有的数据租约数量 |
| `leased_bytes` | 单进程内按数据对象去重的租约字节 |
| `caches` | 各用途缓存计量 |
| `owners` | 所有者状态，含会话存储错误、待写材料及读取预算 |
| `leases` | 租约用途、容量、活动引用数量与释放条件 |

两个分析通道报告同一进程时只计一次。角色覆盖缺失时，私有提交合计为空，其他合计只代表已采样进程。计算状态的范围是主语音服务与模型工作进程，宿主整棵进程树的指标继续由应用状态提供。进程私有提交与物理驻留必须分别报告；不能将减少的线程栈提交量全部解释成释放物理内存。原生引擎的分配器缓存由进程内存指标观测，不能误记作已登记的应用缓冲。

## 验收与复测

`scripts/benchmark_runtime_resources.py`（真实权重资源对照工具）在独立进程中固定本地音频，记录启动、预热、整段推理分位延迟、原始输出、私有提交和常驻内存。`--role`（模型用途）、`--threads`（候选原生线程数）、`--baseline`（改动前源码）、`--onnx`（轻量检测候选）、`--iterations`（复测次数）、`--soak-seconds`（持续回放秒数）、`--output`（结果文件）控制测试。

`scripts/validate_vad_streaming.py`（流式检测功能对照工具）覆盖长录音、不同输入分块、短输入、空最终刷新和重置；输出错误与事件原文，不隐藏失败。

后端完整回归、真实本机共享协议测试、前端测试、类型检查、构建和差异检查是代码门槛。真实权重独立进程对照和持续检测回放提供候选证据，但不代替完整应用的并发、首字、首音、打断、精修完成和60分钟长会话验收。完整应用应使用固定云端响应隔离网络波动，逐项交错运行；超过原版本重复测量波动且稳定变慢的候选继续关闭。

麦克风现场验收在用户开启监听后进行。没有完整证据的线程、轻量检测、共享音频和历史落盘候选继续沿用默认关闭配置。测量原始结果和当前启用结论见 `reports/运行资源优化实施与验收-20261003.md`（本机实施与验收报告）。
