# Voice Terminal（语音终端）v0.9.5

发布日期：2026-10-21。本版本为 Paraformer（流式语音识别）、emotion2vec（情绪模型）和 CAM++（声纹模型）增加 CPU（中央处理器）与 GPU（图形处理器）运行设备热切换，并修正保存请求和模型进程生命周期的衔接。

## 主要变更

- **单模型即时切换**：详情行点击“保存”只提交当前模型编号和目标运行设备。切换在应用内完成，无需重启应用；尚未保存的其他模型行草稿不会被一并提交。
- **统一切换状态**：保存接口快速接纳后台操作，由现有运行状态卡显示检查、暂停输入、释放旧模型、加载和预热、核验、回滚及监听恢复阶段。真实模型加载耗时由后台状态报告，不再阻塞保存按钮。
- **失败保护与运行核验**：在目标模型真实预热、实际设备及服务就绪状态通过核验后才保存偏好。切换或设置保存失败会恢复原模型；恢复失败时保持停听并明确报告错误。显式请求 GPU 但实际落在 CPU 时按失败处理。
- **模型进程回收**：Paraformer 流式模型和按发言轮次维护的缓存进入可回收模型子进程；CAM++ 与情绪模型按需重建各自模型进程。已启用的 Paraformer 离线精修跟随主路切换到相同设备。
- **资源计量**：新识别模型进程按实际加载状态计入运行资源与启动状态，避免应用状态卡、模型可用性和已分配显存之间出现互相矛盾的结论。

## 设备切换范围

热切换开放给 Paraformer、emotion2vec 和 CAM++ 三个模型。FSMN-VAD（语音活动检测）、KWS（关键词唤醒）和 SmartTurn（语音结束判断）继续使用现有设备设置生效规则。设备偏好结构保持为 `compute.devices`（各模型运行模式）及 `compute.fallback_devices`（最近成功设备回退值）。

点击保存会立即返回操作已接纳标记；这表示加载任务已交给运行状态卡跟踪，并不表示模型已完成预热。切换详情、HTTP（网页接口）字段和回滚顺序见[CPU/GPU 设备热切换生命周期](../guides/compute-device-hot-switch.md)。

## 兼容与数据

本版本不迁移设备偏好结构。切换前后的监听状态按原值恢复；原先未监听时仍保持未监听。模型资源、用户数据和运行环境由原有组件管理及发布事务保留。
