# TTS（语音合成）运行模式

Voice Server（语音服务）当前固定使用 MiniMax API（在线语音接口）合成已提交的文本块，并负责文本分段、调度、播放、中断结算和历史记录。当前产品模型配置继续使用 `speech-2.8-hd`（语音模型）和 `female-shaonv`（音色）。设置页不提供服务商切换，模型分配也不能更改当前 TTS profile（语音配置）。

TTS API（在线语音接口）未配置或不可用时，服务会报告错误。

连接或 `task_started`（任务已启动）确认前发生临时网络故障，或 MiniMax 返回可重试的 `408`、`425`、`429`、`5xx` 状态码时，客户端会丢弃失效连接并新建连接重试一次。文本提交后不会自动重发，避免网络中断时重复播报；认证、参数等明确拒绝不会重试。只有错误明确指向不支持的音色情绪字段时，才会去掉该可选字段后重新建连。

## 锁定文本块的最小长度

`sentence_window`（短句窗口调度）保持当前块和最多一块预取文本，`sentence_prefetch_ms`（预取提前量）默认 2000 毫秒。每次从可改队列取下一块时，按原顺序合并完整文本段，达到 `tts.sentence_min_effective_chars`（锁定文本块最少有效字符，默认 10）后一起提交。中文、字母和数字逐字符计数，标点、空白与符号不计；原文和标点全部保留，恰好 10 个有效字符即满足下限。模型文本生成结束后，不足下限的最后一块正常提交，短回答不等待补字。

未凑齐下限的文本仍留在本地可改队列，只有语音合成成功接受合并块后才推进 `sent_chars`（不可修改前缀字符数）。LLM（大语言模型）可见的 `current_clause`（当前锁定块）和 `prefetched_clause`（下一预取锁定块）按同一提交块投影，各块可能包含多个短句；`revisable_tail`（可改尾巴）从实际提交边界之后开始。尾巴改写后重新入队的文本使用相同的合并规则。首段的 400 毫秒分段兜底只释放分段缓冲，尚未达到有效字符下限时仍等待后续文本或生成结束；其他调度模式继续使用原有规则。

例如“明白，老大。我这边一切正常，运行稳定，随时听你调度。”依次提交为“明白，老大。我这边一切正常，”（11 个有效字符）和“运行稳定，随时听你调度。”（10 个有效字符）。该下限保证每个非结束块的文本长度；实际播放时长仍由语音合成结果决定。

参数必须为正整数，读取后传给在线语音客户端；修改本地配置后重新启动程序生效。正式程序未设置本地覆盖时使用程序包中的默认值 10，已有个人设置继续保留。该能力只控制文本合并与锁定边界，不负责检验模型改写内容是否与已播内容语义重复。

## 只读状态

`GET /api/v1/tts/status` 返回固定的 `backend: "minimax"`（当前语音后端）和 `worker: {"state": "stopped"}`（兼容旧客户端的已停止状态）。产品快照中的 `tts_worker`（本地语音工作进程状态）也固定为已停止。历史 CosyVoice（本地语音合成）实现已归档，当前运行时不创建本地合成工作进程。

`TtsBackendRouter`（语音后端兼容路由）与 `EpisodeSpeechOutput`（语音事务输出）的 `bind/release`（绑定／释放）接口仍保留，供本地 TTS 调试完成后接入。当前产品启动和设置接口不会启用该路由的本地分支。

模型分配接口保留 `tts_profile_id`（当前 TTS 语音配置 ID）用于读取和恢复现有配置。请求可以省略该字段以沿用已保存的配置；尝试更换时会被拒绝。
