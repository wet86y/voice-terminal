# Voice Terminal v0.1 基线规范

v0.1 是项目当前仍在使用的稳定运行基线。它强调控制链清晰、依赖可替换、故障可恢复和指标可追溯；v0.2 已经是当前主开发和验收路径，运行时通过单独配置启用，暂不改变 v0.1 默认配置。

## 目标

提供一条可以在 Windows 本机运行和测量的中文实时语音对话链路：

```text
开始监听 → VAD 检测讲话 → 流式 ASR → 确认结束
→ 流式 LLM → 文本桥接 → MiniMax TTS → PCM 播放
```

默认 `wake.enabled=false`，`session.start` 后直接进入 VAD/ASR。开启唤醒模式时使用 sherpa-onnx KWS，关键词配置为 `hei claw` / `HEI_CLAW`，并保留采集前置 Ring Buffer。

## 运行组件

| 能力 | 实现 | 运行位置 |
| --- | --- | --- |
| 音频采集 | PortAudio / `AudioCapture` | Windows Voice Server |
| 讲话检测 | FSMN-VAD + 静音规则 | Windows CPU |
| 可选唤醒 | sherpa-onnx KWS | Windows CPU |
| 实时识别 | Paraformer Streaming | 独立 ASR Worker |
| 文本生成 | DeepSeek 流式客户端 | 云端 |
| 语音合成 | MiniMax T2A WebSocket | 云端 |
| 音频播放 | `PcmPlayer` | Windows Voice Server |
| 控制台 | Vue 3 + Vite + WebSocket | 浏览器 |

Voice Server 负责完整语音主链，ASR Worker 独立运行以便单独 health、重启和诊断。浏览器不是音频主链依赖。

## 状态和轮次

控制器状态如下：

```text
STARTING      初始化中
IDLE          已连接且未处理当前语音轮
LISTENING     正在采集和识别
FINALIZING    等待 ASR final 或确认结束
THINKING      等待 LLM 输出
SPEAKING      正在播放回答
INTERRUPTING  正在取消当前回答并处理续说
ERROR         需要通过错误信息恢复或重新启动
```

每一轮都有唯一 `turn_id`。轮次结束、停止、ASR 断连、超时或异常时，旧轮的 completion task、TTS session、播放器队列、ASR final waiter 和迟到结果必须失效。重新 `session.start` 时不得消费上一轮采集帧或 PCM。

历史只在完整交换完成后提交：用户文本和助手文本不能因为取消、超时或 TTS 失败而留下半条上下文。服务端通过 `turn.completed` 发布完整记录；前端不会从其他事件自行写入历史。

## 前端边界

页面加载后自动连接 `ws://127.0.0.1:8765/ws`，也可通过 `VITE_VOICE_WS_URL` 修改。前端提供一个主要操作按钮：

```text
开始说话 → 发送 session.start
停止监听 → 发送 session.stop
```

按钮不会乐观改变后端状态，只根据 `runtime.snapshot` 和 `session.state` 展示真实状态。前端展示：

- Audio、KWS、ASR、LLM、TTS 服务状态；
- 当前 `turn_id`、partial/final 转录和流式回答；
- TTS 文本、状态、已返回/已播放/待播放时长；
- 后端 latency 节点和错误；
- 最近 10 条已完成历史。

浏览器不调用 `getUserMedia`，不上传 PCM，不运行模型，不计算延迟，不生成 fallback 数据。连接断开时清理当前轮显示并禁用启动操作；刷新页面后重新连接。

## 协议约束

服务端 Envelope 必须包含：

```json
{
  "type": "session.state",
  "seq": 1,
  "timestamp": "2026-09-05T12:00:00.000Z",
  "turn_id": "turn_000001",
  "payload": {}
}
```

客户端命令必须包含非空 `request_id`、命令名和对象 `payload`。服务端 `seq` 在单个连接内从 1 开始递增，重连后重新从 1 开始。前端先按 seq 丢弃重复/乱序消息，再按 `turn_id` 丢弃旧轮消息。完整字段和 v0.2 扩展见 [WebSocket 协议](websocket-protocol.md)。

## 延迟指标

以下值由后端计算并通过 `latency.snapshot` 发送，未产生时为 `null`：

```text
wake_detection_ms
asr_first_text_ms
speech_end_confirmation_ms
llm_first_token_ms
llm_request_to_first_tts_text_ms
tts_text_to_first_audio_ms
first_audio_to_playback_ms
speech_end_to_playback_ms
turn_total_ms
```

前端只显示后端数值，`null` 显示为 `—`。Envelope timestamp 仅用于日志和诊断，不参与延迟计算。

## 故障恢复要求

- ASR health 未 READY 时，Voice Server 不允许进入可启动状态。
- ASR final 超时后，当前轮必须失效并回到可恢复的 IDLE。
- 音频采集、VAD 或 ASR 写入异常后，必须停止当前采集循环并清理旧轮资源。
- `session.stop` 必须取消音频采集、ASR 连接、LLM、TTS、播放和未完成任务。
- TTS 失败可以降级为文本完成，但 UI 必须看到可见的降级状态，历史仍只提交完整文本交换。
- 慢 WebSocket 订阅者不能阻塞音频主链；积压达到上限后由服务端断开并要求重新订阅快照。

## 当前验收状态

v0.1 的自动化状态机、协议、ASR health、音频队列清理、停止/断连恢复和前端控制台路径已覆盖测试。当前仍需要真实麦克风、耳机和扬声器验收，以及自然语音 CER、误结束率和 p50/p95 统计；这些工作不会自动改变默认配置。

不属于 v0.1 主链的能力包括 AEC、降噪、长期记忆、RAG、外部账号操作、shell 工具、文件写操作和浏览器音频采集。
