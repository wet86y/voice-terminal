# 2026-10-11 启动校验与显卡环境迁移

## 问题与证据

本机开发工作区的语音环境仍使用 `schema: 1`（第一版登记格式）及 `profile: cu128`（显卡运行组合）。新版程序要求六组完整依赖及当前依赖锁登记，因此必须迁移。旧更新器在迁移前要求环境的文件集合与发布清单完全一致，把开发命令生成的 Python（后端解释器）字节码缓存误判为损坏，并隐藏了实际差异。

实际盘点发现 4,054 个清单外文件，全部为标准字节码缓存；没有缺失文件或文件大小变化。30,919 个发布文件、共 5,403,159,465 字节，完整 SHA-256（内容摘要）复核全部一致。当前所有依赖版本均通过兼容规则：PyTorch（张量框架）及 Torchaudio（音频张量库）均为 `2.11.0+cu128`（显卡构建），ONNX Runtime GPU（显卡模型推理运行时）为 `1.24.4`。不是模型升级导致现用显卡运行库损坏。

此外，环境迁移会登记 `profile: compatible-private`（已验证的兼容显卡环境），旧后端却只认可 `cu128`（旧显卡运行组合）。没有单独登记显卡环境时，迁移成功后可能将显卡能力标成不可用。已修正为认可依赖锁仍匹配的新版兼容环境；明确的显卡登记过期时仍要求重新检测，实际硬件和模型加载检查继续决定可用能力。

实际模型检查进一步确认：原更新器无条件跳过可选文件，SmartTurn（语音结束判断）的 `smart-turn-v3.2-gpu.onnx`（显卡权重）被列为可选，因此更新后的模型目录仅有处理器权重和预处理配置。用户设置仍为 `compute.devices.smart_turn: cuda`（语音结束判断使用显卡），实际加载会报告显卡权重缺失。GPU（显卡）框架的实际矩阵计算已经通过；这一失败来自模型资产选择，不是推理库不兼容。

## 修复范围

解释器组件容许清单外的标准 `__pycache__/*.cpython-312.pyc`（Python 3.12 字节码缓存）以及标准优化级别缓存，且对应源码必须已在发布清单中。链接、未知文件、动态库及源码缺失继续拒绝；清单已经登记的字节码仍核验摘要。其它组件的文件集合规则不放宽。

更新候选只复制已通过复核的发布文件，清单外缓存不进入新环境。所有受管子进程继承 `PYTHONDONTWRITEBYTECODE=1`（禁止写入字节码缓存）。更新失败提示保留缺失、新增及具体损坏文件，取消仍终止更新。显卡核心库复用不通过时仍保留原环境。

模型资源清单按现用设备选择确定文件：明确选择显卡，或自动模式具有兼容显卡环境时，SmartTurn（语音结束判断）的显卡权重成为本次安装必需文件；缺失时显示待更新并补齐。已安装且仍在当前清单中的可选权重在后续更新中保留并核验。纯处理器安装仍可省略尚未安装的显卡权重。导入、安装收据和启动盘点使用同一文件选择结果。

## DSH（代理执行宿主）校验

当前开发代理环境有 24,553 个文件，共 564,954,403 字节。采用与正式程序相同优化级别的原生公共模块测量，文件集合与大小盘点约 0.333 秒，全量摘要复核约 86.775 秒。调试构建的独立测量约 106.616 秒；这些是组件诊断数据，不能视为整套应用启动耗时，也没有清空操作系统文件缓存。

安装、导入、更新及未知组件首次启动保留完整摘要校验。普通启动每次核对文件集合与大小，并以组件绝对目录、清单摘要、文件路径、大小、创建时间、修改时间匹配近期完整复核结果；命中时复用该结果。缓存最多保留七天，清单、文件或目录变化、缓存缺失、无效、过期时重新进行全量摘要校验。仅完整校验成功且校验期间文件未变化才写入缓存；缓存不可写时，本次完整校验仍有效，下次继续全量复核。

缓存位于 `cache/component-validation/dsh.json`（代理启动内容复核缓存），删除该文件即可要求下次完整复核。缓存命中检查不会读取所有内容，因此无法立即发现文件元数据全部保持不变的底层内容损坏；七天期限为此保留周期完整复核。此方案适用于由本机更新器管理的运行组件，不作为对恶意文件篡改的安全证明。

修复后的实际缓存命中为 1.544 秒。首次签发缓存的一轮完整校验为 149.958 秒，同期有本机程序发布等磁盘操作；此前独立完整复核为 86.775 秒。不能把不同负载的全量校验数据当作同一条件的重复试验，也不能把这个单组件结果外推为整套启动加速比例。

本机完整环境已经通过原生事务配置器完成迁移，六组依赖均已就绪，新增依赖下载量为零；包括候选复制、完整内容及实际导入检查、生成清单和切换在内共 391.232 秒。登记为 `schema: 2`（第二版格式）、`profile: compatible-private`（兼容显卡环境）、`compatible_gpu: true`（已保留受支持显卡运行库）。新版 FSMN-VAD（语音活动检测）八项资源已更新，SmartTurn（语音结束判断）的 32,411,198 字节显卡权重已补齐。8 项用户配置前后内容摘要一致。

在本机 RTX 4060 Laptop GPU（笔记本显卡）上，FSMN-VAD（语音活动检测）和 SmartTurn（语音结束判断）均完成实际显卡推理，正常运行模式也能识别两项显卡能力。模型工作进程检查分别耗时 114.015 秒和 31.125 秒，包含环境初始化和模型加载，不能作为单次推理延迟。检查使用合成静音输入，没有覆盖麦克风采集、云端接口或完整对话。实际更新完成记录已写入本机组件任务历史，保留此前的失败记录。

本机程序已经发布为 `product-7e302b31efa2a6af`（构建编号），版本仍为 `0.9.0`。正式入口、宿主、业务及界面固定文件校验通过。当前模型和语音依赖均已就绪；整体服务仍被 DSH（代理执行宿主）的组件更新状态拦截。

此 DSH 状态来自发行来源策略：本机旧物理运行包是 `0.2.0-rc.2`（版本号），与随包清单版本相同，版本提交也符合兼容检查；但元数据未登记 `source_kind: official_desktop`（官方桌面来源），也没有随锁定官方安装器签发的来源摘要。组件管理器因此按来源要求标记待更新。代码中的 Python（后端运行环境）代理运行器保留旧物理包兼容分支，会核对版本、提交、桥接协议和必要文件；原生启动门槛另行要求官方桌面来源，所以即使兼容检查通过，仍会拦截整体服务。现有证据不表示旧 DSH 已损坏。这项官方来源迁移早于本轮显卡修复，与显卡环境和模型权重无关；若要允许保留旧包启动，应调整原生启动政策并验证两种组件来源，而不是单独隐藏待更新状态。
