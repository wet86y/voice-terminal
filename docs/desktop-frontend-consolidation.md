## 当前交付修正：正式程序与前端演示

用户已明确撤销“保留隔离数据产品”的交付方式。当前只提供 `.runtime/delivery/VoiceTerminal/VoiceTerminal.exe`（正式程序）和 `.runtime/delivery/VoiceTerminalUIDemo.exe`（前端演示程序）两个入口。正式程序在原安装目录更新，保留原有完整数据、设置、凭据和历史；演示不启动业务后端，只加载当前前端源码，用于后续界面修订。此前“只复制旧凭据、其他设置保持独立”的安排已被本次完整数据要求取代。

`npm run desktop:publish`（构建并更新正式程序）构建产品界面、正式宿主、根入口与演示启动程序，同时准备演示使用的调试宿主，然后更新已有正式目录并同步演示入口。它不创建空白数据候选。界面在共享组件和样式中修改，先在演示窗口检查；确认后退出正式程序并关闭演示窗口，执行该命令，再用正式程序进行业务验证。双击演示直接使用已构建的宿主，保留界面热更新；修改原生源码后，使用明确的开发或发布命令增量构建。

## 已实施的边界

前端目录统一为 `apps/frontend`（前端工程），包名为 `@voice-terminal/frontend`（统一前端包）。主产品与样例只在 Tauri 2（桌面框架）窗口运行，继续使用 Vue 3（界面框架）和 WebView2（嵌入式渲染引擎）。DSH（代理执行宿主）控制台保持独立管理网页，通过原生命令在系统默认浏览器打开。

| 根命令 | 固定行为 |
| --- | --- |
| `npm run dev` / `npm run desktop:dev`（真实开发） | 构建当前调试宿主并启动业务桌面，受管界面服务使用 5173 端口 |
| `npm run dev:ui` / `npm run desktop:ui`（样例开发） | 构建当前调试宿主并启动独立样例，使用 5174 端口，不启动业务后端 |
| `npm run desktop:start`（静态启动） | 构建当前静态产品界面与调试宿主，再启动桌面 |
| `npm run build` / `npm run desktop:build`（正式构建） | 构建正式产品界面、桌面主程序及根启动程序 |
| `npm run desktop:publish`（更新正式程序） | 构建并更新原正式目录，保留完整数据，同时同步演示启动程序 |
| `npm run frontend:build`（内部界面构建） | 只构建产品静态界面，供桌面构建流程调用 |
| `npm run test` / `npm run typecheck`（回归与类型检查） | 前端回归、受管服务集成验证及类型检查 |

源码开发命令启动前执行增量原生构建；双击正式或演示入口直接运行已构建的程序。真实开发和样例开发命令不构建静态产品页面，也不自动打开浏览器。直接 Vite（界面开发工具）服务和浏览器静态预览命令已撤销。构建开关在 Windows PowerShell 5.1（系统脚本环境）中采用明确的参数映射，相关脚本带 UTF-8 BOM（编码签名）。

源码业务默认读取 `.runtime/delivery/VoiceTerminal`（正式安装目录）的 `portable.json`（便携配置）和 `active.json`（启用组合），沿用完整正式数据及运行组件。显式 `InstallRoot`（正式安装目录参数）和 `DataDir`（数据目录参数）受支持。缺少正式安装且未明确指定数据时拒绝启动，不创建隔离产品。正式与源码渲染缓存分开，业务数据共用，启动业务调试前应退出正式程序。演示使用 `.runtime/desktop-ui-preview`（独立渲染缓存目录），不读取产品数据、不需要 Python（后端运行时）或模型、不调用麦克风。

## 会话与初始化

宿主仅通过私有进程管道发送 `launch_token`（一次性桌面入口凭据），有效期 60 秒。桌面访问 `/desktop-entry`（受控入口），服务原子消费凭据，设置按实例命名的 HttpOnly / SameSite=Strict Cookie（脚本不可读、限制跨站请求的会话凭据），返回无缓存、无来源传递的过渡页，再替换地址进入界面。凭据不进入访问日志、实例登记或后续页面来源。

普通首页不签发会话，只显示“请通过桌面程序打开”。业务资源、运行配置和宿主管理接口要求当前实例会话；开发服务也验证 HMR（热更新）升级连接。受管服务采用 [Vite JavaScript API（编程接口）的中间件模式](https://vite.dev/guide/api-javascript.html)，外层认证通过后才转交请求和升级连接。

产品与样例都先调用 `desktop_status`（桌面状态命令），验证 `ready`（就绪标识）、`error`（启动错误）、`frontend_mode`（前端模式）和 `development`（开发标识），再动态导入界面。样例只接受调试构建，只拥有状态与退出命令。产品随后获取宿主配置，语音接口与实时通信地址只来自当前宿主；业务接口就绪前不启动连接。

宿主状态端点返回 HTTP 401/403（会话被拒绝）时，产品关闭事件流、轮询和语音连接，清空连接配置，并提示退出后重新启动；HTTP 5xx（服务暂时故障）保持可恢复。核心语音能力失败而业务接口仍运行时，可进入设置修复。内置诊断页同样先完成原生握手。

5173 端口的源码开发服务必须先通过 PID（进程标识）、`created_at`（进程创建时间）和回环监听归属核验，再发送会话与核对就绪结果。端口属于其他进程时明确失败，不向未知服务发送本实例 Cookie（会话凭据）。Vite（界面开发工具）初始化完成前，就绪端点返回等待状态。

## 清理与分发

产品查询参数不再提供事件回放旁路。固定事件夹具和回放场景移入桌面样例，依赖检查覆盖静态导入与字面量动态导入。旧根界面入口、未引用的样例样式、浏览器启动器和 Python（后端运行时）托盘链已清理；共享组件与声纹采集回退保留。`scripts/start.ps1`（旧启动脚本）现在仅提供无界面的后端调试。

正式构建只生成 `index.html`（产品入口）。便携组装根据 `desktop-manifest.json`（界面产物清单）验证动态依赖闭包和实际文件集合，拒绝样例入口、事件夹具、开发辅助服务和陈旧文件。程序组件、解释器、模型与用户数据仍沿用已有分发机制。

生命周期验收读取无凭据的 `instance.json`（实例登记）和 `startup-result.json`（历史启动快照），核对进程路径、父子关系、PID（进程标识）与真实创建时间。正常退出检查等待实际桌面操作，不通过公开首页领取会话，也不以历史快照冒充实时状态。
