# 上下文引导一致性检查（2026-10-11）

本次检查覆盖项目源码实际组装的模型输入、本机已保存的个性化设置及 DSH（后台执行宿主）构建提示，未调用真实模型、修改个人资料或替换正式程序。检查目标是避免自定义指令执行被弱化、一次性指令跨请求污染、历史交接覆盖当前意图，以及提示词与配置生效机制矛盾。

## 指令的适用与时效

当前用户指令满足已启用自定义条目的触发语义时，执行环节必须严格遵照完整内容，不以默认风格、惯常追问或自主补充替代、弱化或扩大。语义清楚且可执行时不额外确认；多条兼容要求一并遵守，仍影响执行的缺失条件或冲突才必要澄清。

条目保存持续存在与某次触发效果持续生效分别判断。一般用户指令具有即时性，只作用于本次请求或对应任务，无必要不影响后续判断。只有用户或条目明确规定持续范围、结束或恢复条件，或仍有效任务的必要条件才延续；无关新问题独立处理，最新修正、撤销与恢复优先。

输出和桥接协议、实际语音队列约束、工具权限、事实与外部资料边界始终遵守。默认表达风格、惯常追问和及时回应规则服从当前适用的用户要求；仍有效的明确暂缓条件不能被默认“及时回应”覆盖。历史中存在一次静默要求也不能据此忽略后续独立问题。

## 本机配置核对

本机 `.local/data/config/product-settings.json`（本机产品设置）的自定义条目共有两条，均已启用且由后台执行：提前静默与定时操作。第一条的触发是用户要求进入静默，第二条处理定时操作；保存条目本身不意味着静默持续限制后续问题，也不意味着以后每次调度都创建定时任务。定时任务已成功创建后仍按实际任务规则执行，不能因一次性指令边界被取消或重复创建。

本机 `.local/data/persona/personality.md`（人格文档）与 `user.md`（用户资料）实际加载。现有资料中允许必要追问的偏好不是强制追问规则，不能覆盖当前自定义指令或“只有必要才补问”的规则。本次未修改这些用户数据。

`instructions.md`（历史人格指令文档）当前不加载。`instructions_file`（历史兼容配置字段）保留解析兼容性并明确标注不进入模型上下文；新工作区只补齐人格和用户资料，不再复制未使用的历史指令模板。已有历史文件保留。源码 `config/persona`（旧资料目录）与 `config/templates/persona`（初始模板目录）不等同于当前工作区保存的资料。

## 已处理的矛盾

1. 自定义条目的“执行目标”原先未明确要求严格执行完整内容，现在主会话与后台规则都已明确。
2. 后台公共规则与 DSH（后台执行宿主）附加规则原先称设置是“本会话冻结快照”，与保存后下一请求生效冲突，现在采用当前设置与最新修订。
3. 默认及时回应可能与当前明确暂缓要求竞争，现在主提示、深度模式与尾部决策任务均说明适用前提。
4. 轨迹压缩原先只要求保留未决意图和用户问题，现在同时保留作用范围，清理已失效临时要求，不把可选问题变为后续阻塞。
5. 交接保留历史条目可能被当成新授权，现在明确不恢复旧设置、不延续一次触发效果，也不覆盖当前用户意图。
6. 新工作区曾复制不加载的指令模板，现在只复制有效资料，历史字段与模板均明确标记。
