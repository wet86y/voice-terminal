# Voice Terminal DSH 插件

一个项目内 Bundle（功能包）`@voice-terminal/dsh-plugin`，包含桥接、项目唤醒任务、浏览器界面和影子代理预设。组件职责及依赖见 [`components.json`](components.json)（组件声明），完整维护流程见[DSH 插件维护手册](../../../docs/dsh-plugin-maintenance.md)。

安装只操作项目 `.runtime/dsh`。工具名、HTTP（网络接口）路径、Loader（加载器）行标识、设置命名空间、消息来源和任务存储格式保留历史契约。

- 根入口：桥接 `voice-terminal-shadow-bridge`（语音会话桥接）。
- 子入口 `./wake-tasks`：`voice-terminal-wake-tasks`（项目唤醒任务）。
- `lib/client.js`：官方浏览器模块闭包（设置页与消息渲染）。
- `cordis.patch.yml`：两个宿主组件及 `preset-shadow-agent`（影子代理预设）的组合补丁，由构建生成。

在插件目录运行 `npm test`：执行类型检查、组件依赖检查、官方浏览器构建和回归测试。项目安装使用 `scripts/setup-dsh.ps1`；已有锁定宿主可使用 `-Offline -SkipInstall`（离线且跳过宿主依赖安装），最后用 `-Offline -ValidateOnly`（离线只校验）。

项目唤醒任务使用 `storages/voice-terminal-wake-tasks.json`（任务存储），与官方 `schedule_*`（会话调度工具）独立。已有官方 Automation（自动化）功能包选择会保留。冻结参考上下文只在 `read_wake_reference`（读取任务参考）调用时读取，不自动注入模型。

桥接协议保持 2.0；8 个桥接工具仍只用于其绑定的根代理，终结型回执保留激活水位与幂等规则。预设保留原有默认工具、压缩、子代理和工作流能力。

运行轨迹通过根代理公开实时流的 `reasoning-delta`（思考增量）及 `tool/call`、`tool/result`（工具开始与结果）回调到工作台固定单槽。`action_seq`（动作序号）统一排序思考、工具和运行状态；旧会话、旧激活及乱序动作拒收。工具仅显示名称与状态，思考正文仅留在有界界面内存中。字段、取消方式和拒收规则见 [Bridge 2.0（桥接协议）活动端点](../../../docs/bridge-2.0-protocol.md)。

| 组件 | 保留能力 |
| --- | --- |
| 桥接 | 上下文合并与安全门禁、旁路文字读取、进度与信息发布、提前静默、澄清、结果与无需动作终态、状态观察、会话导出与解绑 |
| 项目唤醒任务 | 规则解析、创建／查询／修改／取消、持久删除确认、旧项目任务迁移、重启恢复、冻结参考按需读取、语音事件发布 |
| 浏览器 | 官方设置表单、工作区和模型选择、推理强度、恢复提示、桥接消息渲染及语言资源 |
| 预设 | 原有官方文件、命令、后台作业、技能、子代理、网页、压缩及工作流能力 |

终态工具只在 `accepted`（接受）或 `duplicate`（已接受的重复回执）时结束回合。进度进入二等信箱；信息与终态进入普通事件路径。20 秒软提醒只在下一步安全边界注入。工作区及模型设置作用于新建会话，恢复会话保留其原选择。功能和现场验收边界见[项目隔离 DSH 控制台](../../../docs/dsh-console.md)。

配置维护 `host.patch.yml`（宿主组合补丁）与 `preset/`（预设源码），构建生成一个 `cordis.patch.yml`（安装组合补丁）；不要直接修改生成产物。共享鉴权、协议、网络传输和取消作用域位于 `src/shared/`（共享目录），宿主服务使用公开依赖与类型，浏览器状态使用官方注入钩子。
