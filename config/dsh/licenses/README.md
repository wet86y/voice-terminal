# 第三方许可快照来源与链接维护

本目录保留 DSH（代理执行宿主）的许可证及第三方软件声明，来源仓库、版本和提交以[运行锁](../runtime.lock.json)为准。这里只维护来源和引用，不改变上游对依赖范围、许可证或分发条件的声明。

- [LICENSE（许可证）](LICENSE)：保留上游原始字节及版权声明。
- [THIRD_PARTY_NOTICES.md（第三方声明）](THIRD_PARTY_NOTICES.md)：保留上游正文，将上游仓库内相对引用改为固定提交的链接。本地许可证链接仍指向同目录的许可证。
- 声明文件顶部记录源文件的固定提交地址与 SHA-256（内容摘要）。该摘要对应转换前的上游原文，不是本地转换后文件的摘要。

2026-10-22 梳理的 23 处引用均在锁定上游提交中存在，并非应删除的无用内容：依赖锁文件 2 处、内置源码索引及目录 10 处、补丁 8 处、浏览器调试器许可证 1 处、分发设计说明 1 处、共享运行环境锁 1 处。文件使用上游固定提交的文件链接，目录使用对应目录链接，不依赖未来分支内容。

## 同步与检查

从项目根目录执行：

```powershell
.\.local\runtimes\python\python.exe -B -X utf8 scripts/sync-dsh-notices.py
.\.local\runtimes\python\python.exe -B -X utf8 scripts/sync-dsh-notices.py --check
.\.local\runtimes\python\python.exe -B -X utf8 scripts/check-doc-links.py
```

[同步工具](../../../scripts/sync-dsh-notices.py)直接读取现有上游源码缓存中锁定提交的文件，不修改缓存、不切换分支、不自动联网拉取新版本，也不改写许可证。缓存缺失时通过 `--source`（已有上游检出路径）明确指定具备该提交的源码目录。

升级上游时，应审阅目标版本的许可证和声明，再更新运行锁及快照。引用目标不存在、来源不明确或许可证快照与上游不符时，同步会失败，应核对具体内容；不得靠删除版权信息、移除必要声明或排除整份文档检查来消除报错。上游声明中的生成命令需在上游仓库执行，本项目的链接转换通过上述同步工具完成。
