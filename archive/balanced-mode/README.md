# 均衡模式归档

2026-10-07 起，当前源码仅保留 `fast`（快速，默认）和 `deep`（深度）。快速的 `reasoning.effort`（思考强度）为 `none`（关闭思考），深度为 `low`（低强度思考）。均衡模式及其 `request_thinking`（请求追加思考）退出源码界面、配置、会话协议和主代理运行链路，正式程序待统一更新。

## 保留内容

- `backend/`（后端原始实现）：归档前的 `episode.py`（代理运行时）、`context_builder.py`（上下文构建）、`prompts.py`（模型指令）和 `decision_schema.py`（决策结构约束），逐字保留原文件。
- `tests/test_balanced_mode.py`（均衡历史测试）：保留原有均衡结构约束、思考屏障、动作组合、动作可见性与新输入失效用例。
- `scripts/`（历史探测脚本）：原来的两版均衡压力探测及生产频率回放探测，内容保持原样，从当前脚本目录迁入。
- `retirement.patch`（停用改动补丁）：记录本次所有共用源码、配置、协议文档和测试的停用前后差异。只包含本次修订，归档前已有的其他工作区修改不在补丁中。
- `manifest.json`（归档清单）：`source_path`（原始路径）、`archive_path`（归档路径）、`sha256`（原始内容摘要），用于核对原始实现及移动脚本未发生内容变化。

归档目录的 `.gitattributes`（文件换行策略）保留原始后端与历史脚本的字节，避免不同系统的自动换行转换改变内容摘要。

这些文件是历史资料，不属于当前 Python（后端脚本语言）包、桌面构建输入或默认测试；当前运行代码不导入此目录。历史脚本中的原始相对路径和接口依赖保留原样，不能直接拿当前双模式实现运行它们。

## 恢复参考

需要恢复时先在独立分支评估改动。在仓库根目录用 `git apply -R --check archive/balanced-mode/retirement.patch`（检查反向补丁是否可应用）核对当前源码；确认兼容后再用 `git apply -R archive/balanced-mode/retirement.patch`（恢复本次停用前的共用代码）。三份迁出的历史探测脚本需另行从 `scripts/` 归档目录复制回仓库根目录的 `scripts/`，再完成完整回归验收。

重新启用均衡模式需要同步恢复前端、后端、配置与协议，并重新验收。
